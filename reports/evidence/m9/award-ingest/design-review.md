# M9 / award-ingest — 설계 검토 (구현 전)

## 0. 경계 한 문장

이 slice 가 막는 것은 **「승인 범위 밖의 조달청 호출」과 「계약 미등재 식별자의 적재」** 다 — 낙찰 목록
갈래가 새로 열리면서 ⓐ 설정이 주지 않은 기간·상한으로 호출이 나가는 길 ⓑ 낙찰자 사업자번호·대표자명이
원문에 남는 길 ⓒ 다른 일회 러너와 겹쳐 돌아 상한 회계가 서로의 호출을 못 보는 길이 생기지 않아야 한다.
막지 않는 것: 조달청이 주는 값의 진실성, 승격 범위(확정 표본) 자체의 적정성, 보존 창 값.

## 1. 열거인가 구성인가

- **구성**: 개인정보 제거는 기존 allow-list 반전(계약 등재 키만 담는다)이다 — 새 식별자 키가 응답에
  늘어도 계약이 없으면 자동으로 빠진다. 이 slice 는 금지 목록을 더하지 않는다.
- **구성**: 일회 러너 상호 배제는 `ApplicationRunner` 빈 **정의 수**를 세는 기존 guard 다 — 러너의
  종류를 모르므로 새 러너가 자동으로 대상이 된다(등재 행위가 필요 없다는 것을 test 로 고정한다).
- **열거**: 오퍼레이션 경로(공사·용역)와 업종 키는 설정 표의 열거다. 물품·외자는 짓지 않는다(D-1).

| 표면 | 모듈 | 값 획득 | 닫는 자리 |
| --- | --- | --- | --- |

설정에서 온다.

| # | 우회 | 무엇이 막는가 |

| ① | 낙찰 목록 포트에 상세 축 메서드를 꽂아 공고당 호출을 낸다 | 포트에 그 메서드가 없다(컴파일) — 대가는 타입이 공고 목록 갈래와 같아진 것이고, 그 조합은 묶음 타입과 배선이 막는다(알려진 제한) |

| ⑤ | 원문 적재 endpoint 를 다른 토큰으로 적어 승격 슬롯을 바꿔 끼운다 | 계약 `presentIn` 대조가 낙찰 축 키를 전부 떨어뜨린다(변이 RED) |

## 4. 과잉·미달

- **미달 하나를 닫는다**: 수집 use case 참조자 게이트는 타입 **하나**(공고 목록 use case)만 보고 있었다.
  이 slice 가 새 use case 를 더하면 그 길이 게이트 밖이므로, 키를 타입 **집합**으로 넓혀 둘을 함께 닫는다.
  대가는 정밀도다 — 허용 집합이 두 갈래의 러너·배선 넷의 합집합이 되어 「공고 목록 러너가 낙찰 use case 를
  참조」하는 조합은 초록이다. 이 게이트가 막는 위협(컨트롤러·리스너·자동 시작 경로)은 그대로 닫힌다.
- **과잉 금지**: 새 `SourceEndpoint`·새 표·마이그레이션·새 정책 타입을 만들지 않는다. 승격은 계약 행이
  이미 선언한 슬롯을 그대로 쓰므로 `procurement/**` 변경이 0 이다.
- **의도적 미달(알려진 제한)**: 승격 범위는 기존 확정 표본이다. 낙찰 목록은 창 전체를 받으므로 표본 밖
  행은 원문으로만 남는다. 「내 입찰」이 표본 밖이면 화면의 낙찰자 상호는 여전히 비어 있다 — runbook 에
  적고 후속 OPEN 으로 남긴다.

## 5. 개인정보 경로

- 응답이 싣는 식별자: 낙찰자 사업자번호·대표자명(계약 미등재) → 담기지 않는다. `opengCorpInfo` 형태가
  오면 기존 치환 통로가 성분 둘을 버린다.
- 적재되는 업체 식별 값: 낙찰자 상호(계약 등재, `AWARD_COMPANY_NAME`). 보존 창 뒤 마스킹 대상이므로
  **수집→승격을 창 안에 끝내라**는 운영 문장을 runbook 에 적는다(D-5).
- 로그: 러너 줄의 입력 타입이 계수·날짜·업종 이름·열거값만 나른다. E2E 가 상호·서비스 키 표지의 부재를
  로그·표준출력·실행 상태 파일 전수에서 단언한다.
