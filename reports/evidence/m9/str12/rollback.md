# M9/STR12 — 되돌림

## 0. 복원 원천은 base 가 아니다 — **이 브랜치가 병합한 main 의 고정 SHA**

이 브랜치는 main 을 **네 번** 병합했다(`6c38fb32` · `3ad4f3f6` #135 · `97ed49c4` #134 ·
`56bd33ea` #137). 복원 원천은 **마지막으로 병합한 main 의 고정 SHA** 다:

```
56bd33eaeb092bf3157ef921e034b8b4ae948c51
```

**HEAD 가 움직여도 원천은 그대로 두지만, main 을 다시 병합하면 원천도 그 SHA 로 옮긴다**(팀장 지시).
옮기지 않으면 두 main 사이의 남의 변경이 복원 뒤에도 트리에 남아 「되돌린 트리 == 그 main 트리」
등식이 서지 않는다. 이 slice 는 그래서 원천을 세 번 옮겼다(`6c38fb32` → `3ad4f3f6` → `97ed49c4` →
`56bd33ea`).

움직이는 `origin/main` 을 쓰지 않는다. slice base(`79f3e5c4`)나 **첫 병합 SHA** 를 원천으로 두면 그
사이 main 에 들어간 남의 변경까지 지운다 — 이 브랜치에서 그 위험이 실물인 경로는 **넷**이다(양쪽이
고친 파일: 등재 레지스트리 **둘** · runbook 하나 · capability map 하나 — 병합마다 겹치는 집합이
달랐다). 그 넷은 `commands.md` §8 이 병합마다 합집합임을 계수로 확인한 자리다.

## 1. 복원 목록 — 기계 산출, **양방향 등식으로 확인**

```
git log --no-merges --format= --name-only HEAD ^<원천> | sort -u      → 47 경로  (A)
git diff --name-only <원천> HEAD | sort -u                            → 47 경로  (B)
comm -23 B A   (원천과 다른데 내 커밋에 없는 경로 = 복원이 못 덮는 자리)  → 빈 출력
comm -13 B A   (내 커밋에 있는데 원천과 같은 경로 = 되돌릴 것 없음)       → 빈 출력
```

**두 방향을 다 본다.** A 만 보면 목록이 **길어도** 알 수 없고, B 만 보면 **짧아도** 알 수 없다. 둘이
같은 47 이고 차집합이 양쪽 다 비었다는 것이 「목록이 되돌릴 것을 정확히 덮는다」는 뜻이다.

**병합된 main 을 `^` 로 제외하므로 제목 필터가 필요 없다.** 앞 라운드는 `grep -q m9-str12` 로 커밋
제목을 걸러 목록을 냈다 — 남의 비-병합 커밋이 range 안에 들어왔기 때문이다. 조상 제외로 바꾸면 그
필터가 사라지고, 「제목을 다르게 쓴 내 커밋이 목록에서 빠지는」 사각도 함께 사라진다. 대조 실측:
그 31 커밋 중 제목이 `m9-str12` 가 아닌 것 0.

### 1.1 상태(A/M/D) — **원천 대비로** 낸다

```
git diff --name-status <원천> HEAD -- <47 경로>
→ A 29 · M 17 · D 1   (합 47)
```

커밋별 `--name-status` 를 모아 상태를 정하면 **추가된 뒤 수정된** 파일이 `M` 으로 분류돼 틀린다(앞
라운드에서 10 건 오분류를 실측했다). 상태는 원천 대비로만 낸다.

## 2. 명령

```bash
MAIN=56bd33eaeb092bf3157ef921e034b8b4ae948c51

# M·D 경로 18: 그 main 커밋의 내용으로 되돌린다(삭제된 자리지킴 셋이 되살아난다).
git restore --source=$MAIN --staged --worktree -- <M·D 경로 18>

# A 경로 29: 그 main 커밋에 없으므로 복원이 아니라 삭제다.
git rm -f --ignore-unmatch -- <A 경로 29>
```

경로는 **개별 인자**로 준다. `-A`·`.` 를 쓰지 않는다 — 공유 작업 트리에서 남의 미커밋 변경을 함께
끌어가는 자리다.

## 3. 실측 — 버릴 clone 에서 ①~⑥

**실측 HEAD: `b80d0e5e`** (셋째 병합 뒤 마지막 산출물 커밋)

**원천을 `56bd33ea` 로 옮겼다**(팀장 지시) — 이 브랜치가 그 main 을 병합했으므로 그것이 「내 것 없는
판」이다. 원천을 앞 SHA 로 두면 두 main 사이의 **남의 변경**이 복원 뒤에도 남아 트리 등식이 깨진다.

판정 축은 종료 코드가 아니라 **계수와 트리 동일성**이다:

| # | 재는 것 | 결과 |
| --- | --- | --- |
| ① | 명령 exit | `git restore` **0** · `git rm` **0** |
| ② | 되돌린 계수 | `git status --porcelain` → `D 29 · M 17 · A 1` (합 **47** — §1.1 의 `A 29 · M 17 · D 1` 과 **자리바꿈으로 정확히 대응**한다). `A 1` 은 되살아난 자리지킴 셋 |
| ③ | 복원 대상 경로의 트리 | `git diff --quiet <원천> -- <47 경로>` → **exit 0**(동일) |
| ④ | **내 표지 0** | **0 파일** (되돌리기 전 **42** — 양성 대조) |
| ⑤ | **남의 표지 보존** | **36 파일 → 36 파일**(변화 0 — 병합마다 main 쪽 표지를 하나씩 더해 왔다) |
| ⑥ | 게이트 | **트리 동일성으로 갈음** — 전체 트리 `write-tree` 가 `<원천>^{tree}` 와 **같은 해시** |

②의 계수가 §1.1 과 **합·자리 모두 대응**한다(앞 라운드부터 그렇다). 앞 라운드는 `D 27 · M 15 · A 1`
(합 43)과 `A 24 · M 15 · D 1`(합 40)이 **3 건 어긋난 채** 남았다(cr L-9) — 앞 라운드의 계수를 옮긴
것이 원인이었다. 이번에는 같은 원천·같은 HEAD 에서 둘을 함께 냈다.

### ⑤ 의 술어가 **자기 참조로 두 번 틀렸다** — 같은 규율을 형제 파일에 적용하지 않았다

**둘째 사고(셋째 병합 라운드)**: 「남의 표지 보존」이 37 → 36 으로 하나 줄었다. 사라진 파일은
`commands.md` 였다 — 병합을 적으면서 main 이 더한 test 클래스 이름을 **축어로** 인용했고, 그 문서는
복원 목록에서 `A` 라 복원이 지운다. 아래 첫째 사고 뒤에 이 문서에는 「축어로 적지 않는다」를 규율로
적었는데 **형제 evidence 파일에는 적용하지 않았다.** 이름을 설명으로 바꾸니 36 → 36 으로 변화 0 이다.
규율은 이 파일 하나가 아니라 **복원 목록 안의 모든 evidence** 에 걸린다 — 그 문장을 여기 적는다.

### ⑤ 의 술어가 **자기 참조로 한 번 틀렸다**(첫째 사고)

첫 측정에서 남의 표지가 **30 → 29** 로 하나 줄었다. 추적했더니 사라진 파일은 **이 문서 자신**이었다 —
앞 판 `rollback.md` 가 남의 표지로 쓴 문구를 **축어로 인용**해 두었고, 복원이 이 문서를 지우면서 그
인용이 함께 사라진 것이다. 방어가 깨진 것이 아니라 **술어가 자기 자신을 세고 있었다.**

그래서 남의 표지를 **내 파일이 인용하지 않는 셋**(다른 레인이 등재 레지스트리와 capability map 에
더한 식별자들)으로 바꿨고, 그러자 `27 → 27` 로 변화 0 이다. 이 문서는 그 셋을 **축어로 적지 않는다** —
적는 순간 같은 자기 참조가 되살아난다. (앞 라운드에도 ④ 술어가 접두 일치로 19 파일을 거짓 빨강으로
낸 사건이 있었다. 표지 술어는 **양쪽 대조 없이는 믿을 수 없다**는 것이 두 번 측정된 사실이다.)

### ⑥ 게이트 — 트리 동일성으로 갈음

```
git write-tree              → 000169875aea0947975b2b8bcbc0392b1fe52c0c
git rev-parse <원천>^{tree} → 000169875aea0947975b2b8bcbc0392b1fe52c0c
```

되돌린 트리가 그 main 커밋의 트리와 **바이트 동일**하다(전체 트리 — 복원 대상 경로만이 아니다).
그 SHA 는 `main` 의 커밋이고 그 CI 는 초록이었으므로 게이트를 다시 돌리지 않는다. 하네스 규율 그대로 —
**갈음은 「HEAD 초록」이 아니라 트리 동일성으로만**이고, 여기서는 그 동일성이 해시 등식이다.

## 4. 머지 뒤

PR revert 다. 이 문서의 경로 한정 복원은 **머지 전** 수단이고, 머지 뒤에는 `main` 의 이력을 되쓰지
않는다.

## 5. 실측 기록

| 항목 | 값 |
| --- | --- |
| 복원 원천 | `56bd33eaeb092bf3157ef921e034b8b4ae948c51` (고정, **네 번째로 병합한** main = PR #137) |
| 실측 HEAD | **`b80d0e5e`** |
| 판정 SHA | **이 문서를 담은 커밋** (실측 뒤 움직인 것은 이 문서 하나다) |
| 그 사이에 복원 대상이 움직였는가 | **이 문서 한 파일**뿐 — `git diff --name-only b80d0e5e..<판정 SHA> -- <47 경로>` 가 그 한 줄을 낸다 |

verifier 가 대조하는 것은 「실측 HEAD == 판정 SHA」가 **아니다**(evidence 커밋은 언제나 뒤에 온다) —
그 사이에 **되돌림 대상이 움직였는가**다. 여기서는 이 문서 자신 한 줄이고, 하네스 규율 문면대로라면
그 한 줄이 「미검증」이다. 숨기지 않고 적되 **왜 그 한 줄이 측정을 바꾸지 않는지**를 구조로 적는다:

- 이 문서는 복원 목록에서 **`A`**(원천에 없는 파일)다. 그래서 복원이 이 문서에 하는 일은 **내용과
  무관하게 삭제**다 — 실측 트리와 판정 트리에서 이 문서의 내용이 다르더라도 **되돌린 결과는 같은
  트리**가 된다.
- 그 한 줄을 0 으로 만들려면 측정 결과를 evidence 밖(PR 조치 코멘트)에 두어야 한다. 이 slice 는
  **전건 CI 결과만** 그렇게 했다(`commands.md` §6) — rollback 실측까지 옮기면 되돌림 절차의 정본이
  저장소 밖에 있게 되어 그쪽이 더 나쁘다.
