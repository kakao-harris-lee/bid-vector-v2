# M9 / ml-lifecycle — checklist (ML-07 effective date · SET-06 시간축 · ML-05 model_version · ML-08 등재)

계열: `OPEN-M6-RESIDUAL-ML-LIFECYCLE` 의 ML 수명주기 넷. 이 slice 는 **ml-engine 오프라인 축만** 세운다 —
ML 앱 배선과 수집 연장은 사용자 결정으로 보류 상태이고, 운영 반입·실 API·LLM 호출은 범위 밖이다.
**6G 판정(`reports/evidence/m6/6g/verdict.md`)은 읽지도 바꾸지도 않았다** — 재판정 0 · 새 수집 0.

## D-1 (ML-07) — effective date 를 칸이 아니라 거동으로

| 축 | 내용 |
| --- | --- |
| 무엇이 열려 있었나 | acceptance ③ 은 「판정식과 임계가 version·**effective date**·승인 근거를 가진 정책 산출물에 존재」인데, 출하 정책 파일에 effective date **칸이 없었다**. 칸만 더하면 장식이다 — 값이 wire 에 닿지도, 거동을 바꾸지도 않는다. |
| 값의 출처 | **그 정책 표의 승인 날짜**다 — `reports/evidence/m5/5c2/policy-values.md` 머리말 「승인 2026-09-16」(운영자 「둘 다 승인」, M5 종결 판정). 지어낸 날짜가 아니다. |
| 술어 하나 | `window_start >= effective date 의 KST 일 시작`. 효력 시작 **전에 시작한** 창의 판정은 승격 근거로 인용되지 않는다 — 그 창은 정책이 참고할 수 있었던 창이고, 이 capability 가 문면으로 남긴 함정(「관측에서 역산한 상수가 그 데이터의 사후 산물이 된다」, legacy commit `5d38ac1`)의 기계적 방어다. |
| 규칙의 모양 | 특례가 아니라 **하나**다: 점수가 난 판정(`Passed`·`Failed`)이 인용 가능한 창을 요구하고, `NotEvaluable` 은 그보다 앞선다(인용할 판정 자체가 없고, 「못 쟀다」는 데이터의 사실이라 정책 효력과 무관하다). `Failed` 를 예외로 두지 않은 이유: 「이 게이트를 통과 못했다」도 **그 정책에 대한 주장**이다. 숫자는 사라지지 않는다 — `windows[*].outcome` 이 그대로 싣는다. |
| ⑥ 이 측정되는 자리 | 데이터·임계·창 판정이 전부 같고 effective date 만 다른 두 run 이 `Promotable` 과 `PromotionSuperseded` 로 갈린다(홀드아웃 전건 경로에서 실측 — 두 run 의 `windows[0].outcome` **등식**을 함께 단언해 「바뀐 것이 게이트 판정이 아니라 승격 인용」임을 고정했다). |
| 승격 어휘 | `Promotion` 이 네 값이 된다. `PromotionSuperseded` 는 「못 이겼다」·「못 쟀다」와 **다른 사실**이라 접지 않는다. `_promotion_json` 의 암묵적 최종 `else` 는 `match` 전수로 바꿨다 — 그 `else` 가 네 번째 변형을 조용히 `not_evaluable` 로 적던 자리다. |
| wire | `policy_effective_date` 가 report 의 canonical JSON 과 checksum 에 들어간다. 정책 checksum 에도 들어가므로 같은 임계·다른 효력 시작이 **같은 값이 아니다**. |
| KST 로 재는 이유 | effective date 는 운영자 승인 **날짜**(KST)다. UTC 자정으로 재면 월요일 오전 KST 에 시작한 창이 전날로 밀린다 — SET-06 이 실측한 그 함정이다. 평가 층은 추론 층(성숙도 커널)을 import 할 수 없어(forbidden 계약) 상수를 **공유하지 못하므로**, 두 층의 KST 경계가 같음을 **등식 test** 로 닫았다. |

## D-2 (ML-07 ④) — 임계 완화 입력 경로 넷

앞 판의 확인은 **로더 시그니처 한 줄**(`load_evaluation_policy` 의 매개변수가 `path` 하나)뿐이었다. 그 한 줄은
「다른 자리에 완화 표면이 생기는 것」을 보지 못한다.

| 경로 | 술어 | 모집단 |
| --- | --- | --- |
| ① CLI | `add_argument` 의 옵션 문자열·`dest` 전수(AST) | 정책 키(`_SCALAR_KEYS` + 목록 접두)에서 **생성** |
| ② 환경변수 | 환경을 실제로 읽는 모듈(`os.environ`·`getenv`, **별칭 포함**)의 환경 이름 꼴 상수 전수 + `evaluation/**` 은 환경을 **아예** 읽지 않음(import 뿌리 비교) | 같음 |
| ③ 요청 파라미터 | **생성 descriptor 순회** — proto 전 메시지(중첩 포함)의 필드 이름 전수. 텍스트 grep 이 아니라 descriptor 라, 파일을 나누거나 메시지를 중첩해도 범위가 줄지 않는다 | 같음 |
| ④ 생성 자체 | **형태로 닫는다**(수정 라운드 v H-1) — 아래 D-2b. 이름 대조(`src` 생성 자리 하나)는 보조로 남긴다 | — |

**정책 키를 더하면 세 경로의 감시 범위가 같은 커밋에서 자란다**(열거 장부가 아니다). 모집단이 비거나 출하
파일과 어긋나면 네 축이 전부 헛도므로, 그것을 **먼저 재는** test 를 같은 파일에 뒀다.

## D-2b (v H-1) — 완화된 값을 **만드는 형태**를 닫는다

| 축 | 내용 |
| --- | --- |
| 무엇이 열려 있었나 | ④ 축이 「생성 **호출 이름**이 로더 안에 하나」였고, verifier 가 세 경로로 실제 임계 완화를 **전 게이트 초록**으로 통과시켰다: `dataclasses.replace`(복사라 호출이 아니다) · `type(p)(**vars(p))`(이름이 `type(p)`) · `getattr(importlib.import_module(…), "Evaluation"+"Policy")(…)`(이름이 실행 시점에 만들어진다). 주입원도 이름 대조를 비켜 갔다 — 환경 변수 이름이 정책 키를 담지 않았다. |
| 겹 1 — 생성 토큰 | 첫 매개변수가 기본값 없는 `InitVar[_ParsedPolicyFile]`(모듈 private). `InitVar` 는 인스턴스에 저장되지 않아 `vars()`·`fields()`·`asdict()` 에 없고, 그래서 **기존 객체에서 베껴 올 자리가 없다** — 세 형태가 전부 `TypeError`/`ValueError`(각각 test). |
| 겹 2 — 출처 재검증 | 정책이 자기 파일(`PolicySource`: 경로 + 바이트 지문)을 들고, 제품 경로가 **파일을 다시 읽어** 값(`policy_checksum` 등식)과 바이트(지문 등식)를 대조한다. 객체가 **어떻게 만들어졌든** 무관한 겹이라 토큰 이름을 동적으로 훔쳐 위조한 객체도 드러난다(AST 가 볼 수 없는 마지막 경로). |
| 어긋나면 | 조용히 파일 값으로 갈아끼우지 **않는다** — `DetailCode.POLICY_SOURCE_MISMATCH` 로 job 을 실패시킨다. 갈아끼우면 「무엇으로 판정했는가」가 다시 흐려진다. |
| 지문은 한 번 읽기에서 | `registry.policy.Policy.digest` 가 **파싱에 쓴 그 텍스트**에서 나온다 — 호출부가 파일을 다시 읽어 지문을 내면 그 사이에 파일이 바뀔 수 있는 창이 생긴다. |
| 왜 제품 경로인가 | `run_holdout` 은 라이브러리 진입점이고 커널 test 가 승인 밖 조합(seed 재배열·단일 seed)으로도 불러야 한다 — 그런 정책은 로더가 거부하므로 거기서 재검증하면 그 test 들이 **재는 것을 잃는다**. 제품 경로는 하나다(`app.pipeline._run_holdout`). |
| test 정책도 같은 길로 | 조립 자리를 `tests/policy_fixture.py` 하나로 모았다 — `evaluation_policy`(파일 경유, 제품 경로 test) / `kernel_policy`(토큰 직접, 승인 밖 조합이 필요한 커널 test). 앞 판은 여섯 파일이 각자 조립해 칸이 늘 때마다 여섯 자리를 고쳤다(이 라운드에 실제로 두 번). |
| report 가 공시하는 것 | `policy_checksum`(값의 지문)과 `policy_source_digest`(**파일의** 지문)를 함께. |

②는 **술어 범위를 좁혀서** 성립한다: 전 소스의 대문자 상수를 환경 이름으로 보면 enum 값
(`MEASURED_BEFORE_EFFECTIVE_DATE` 등)까지 후보가 되어 술어가 자기 어휘를 고발한다 — 「술어가 모든 것을
잡으면 아무것도 잡지 못한다」(이 저장소의 숫자 리터럴 게이트가 base 36 을 거부한 것과 같은 자리).

## D-2c (v H-2) — 승인된 version 은 그 내용의 지문과 함께만 존재한다

| 축 | 내용 |
| --- | --- |
| 무엇이 열려 있었나 | D-2b 의 두 겹은 「객체가 자기 **파일**과 같은가」까지만 묻고 「그 파일을 누가 승인했는가」를 묻지 않았다. 그래서 임계만 완화한 사본을 코드가 만들어 쓰거나 `ML_ENGINE_EVALUATION_POLICY` 로 가리키면, version 을 그대로 둔 채 전 게이트가 초록이었다(verifier 실측: `paired_t_threshold` 0.1, 전건 1700 passed, 재검증도 통과). **근원은 version 문자열이 내용에 묶여 있지 않다는 것**이고, 그래서 ML-07 수용 문면 둘이 함께 깨졌다 — 「env 로 값을 주입해도 판정이 달라지지 않는다」와 「version 이 바뀌면 전후 판정이 갈린다」(같은 version 에서 판정이 달랐다). |
| 처방의 방향 | **열거를 뒤집는다** — 「무엇을 거부하는가」가 아니라 「무엇이 승인됐는가」를 코드 상수로 적는다(`registry.policy_approvals`: 승인 version → 그 파일 내용 sha256). |
| 묻는 자리 **둘** | ⑴ **조립 근**(`load_approved_evaluation_policy`·`load_approved_inference_policy` ← `app.server._preload`) — 운영자의 선택(env)이 들어오는 자리. ⑵ **게이트 자리**(`verify_policy_source` ← `app.pipeline._run_holdout`) — 게이트에 **닿은 값**이 승인된 산출물의 것인지. 각 자리가 두 갈래를 함께 거부한다: 이름을 유지한 편집 사본(`DIGEST_MISMATCH`)과 이름을 바꿔 단 사본(`UNREGISTERED_VERSION`). 조립 근의 거부는 다른 축과 같은 결과 타입으로 떨어지므로 `_preload_outcomes`·pipeline factory·prediction runtime 이 각자 다시 판정하지 않는다. |
| **왜 조립 근만으로는 모자랐나**(v r3 H-3a) | 조립 근은 **부팅 때 한 번** 묻는다. 그 뒤에 `copy.copy` + `object.__setattr__` 로 객체를 비틀고, 그 객체가 가리킬 **내용이 일치하는 미승인 사본**을 디스크에 써 두면 재검증의 바이트 축·값 축이 **둘 다 성립한다**(verifier MX1b: 전 게이트 초록, t=0.1 이 게이트에 닿았다). 호출 자리 집합 등식도 보지 못한다 — 그 변이는 호출 자리를 하나도 늘리지 않는다. 「게이트에 닿는 정책은 조립 근을 거친 하나」는 **호출 자리** 단일성만 말하고, 그 자리를 지나는 **값**이 승인된 것이라는 사실은 말하지 않았다. |
| 재검증의 세 축 | **승인**(객체의 자기 주장 `version`+`source.digest` 가 등록부에 있다) → **파일 바이트**(로드 뒤 그 파일이 안 바뀌었다) → **값**(`policy_checksum` 등식). 승인을 **재로드한 파일**이 아니라 **주장**에 거는 이유는 둘째 축과 역할을 가르기 위해서다 — 그래야 바이트 축 제거 변이가 조용히 초록이 되지 않는다(그 분리를 실제로 지키는 것은 바이트 축 test 의 **문면 단언**이라는 것도 변이로 실측했다). |
| **안전 성질을 호출자 객체에서 뗐다**(v r5 H-5) | 세 축의 비교는 한쪽 피연산자가 **호출자 객체**였다 — 거짓 `__eq__` 를 가진 `str` 하위 클래스(N1) · `read_text` 가 가로채는 경로 하위 클래스(N2) · 읽을 때마다 달라지는 `source` property(N6). 전부 세 축을 통과하고 **미승인 파일에서 재구성한** 값이 게이트에 닿았다. 처방 둘: 재구성의 **입력**을 `Path()` 로 감싸 호출자 경로 객체의 메서드를 벗긴다(어느 파일을 읽는지는 호출자가 고를 수 있고, 그 결과를 재구성 승인 검사가 받는다 — `str()` 은 주장이 거짓이고 잠기지도 않아 지웠다, cr r6 M-1) · 세 축 뒤에 **돌려주는 그것**에게 승인을 묻는다(`reloaded.version`·`reloaded.source.digest` — 로더가 만든 값이라 손댈 자리가 없다). 세 축은 **진단**으로 남는다. |
| **축 셋으로도 모자랐다 — 반환값을 바꿨다**(v r4 H-4) | 세 축은 객체의 **직렬화**(canonical JSON)를 한 시점에 비교하고, 게이트는 그 값을 **거동**으로 소비한다(`-t` 같은 산술·비교). 둘을 갈라 놓으면 세 축이 **전부 통과한다** — `policy_checksum` 프레임 안에서만 승인값을 돌려주는 property(F6) · `repr`·json·`==` 는 승인값이고 `__neg__` 는 완화값인 **float 하위 클래스**(F7) · 통과 **뒤** 제자리 변경(F8). 축을 더 세는 것으로는 닫히지 않는다(직렬화를 보는 축은 몇 개든 같은 틈을 공유한다). 그래서 **값의 출처를 바꿨다**: `verify_policy_source` 가 **로더가 승인 파일에서 다시 만든 정책**을 돌려주고, `_run_holdout` 이 그 **반환값**을 게이트에 넘긴다. 「조용한 갈아끼움」이 아니다 — 세 등식이 성립한 뒤에만 일어나므로 판정 값은 같고 그 값의 **출처**가 고정된다. 재구성 객체가 **정확한 원시 타입**만 담는지도 단언한다(`type(...) is float`). |
| 검사와 사용을 한 값으로 | 앞 판은 `verify_policy_source` 의 반환값을 `isinstance` 검사에만 쓰고 게이트에는 `self._deps.evaluation_policy` 를 **다시** 넘겼다 — 검사와 사용이 갈리면 처방이 비어 있다. 그 배선을 지우는 변이(O2)가 붉다. |
| 사슬의 단일성 | 호출 자리 집합 등식 **넷**이 진다 — 승인 미요구 로더(policy_source 안 둘) · `build_training_pipeline`(하나) · `run_holdout`(하나) · `EvaluationPolicy` 생성 자리(로더 안 하나). 사슬: env → 승인 요구 로더 → `_preload` → `pipeline_factory` → `_run_holdout` → 재검증. 단일성은 **값 축을 대신하지 않는다**(위 H-3a) — 둘 다 필요하다. |
| 조립 근 test 의 정책 | 제품 경로 test(`tests/app/test_pipeline.py`)는 **출하 승인 정책 그대로** 쓴다. 앞 판은 작은 데이터셋에 맞춘 파생 정책이었고 게이트 자리의 승인 대조가 들어오자 미승인으로 떨어졌다 — **그것이 올바른 거동이다**. 출하 임계로 바꿔도 그 test 들이 재던 것을 잃지 않는다: 그 데이터셋은 `settlements.jsonl` 이 비어 성숙한 주가 0 이라 평가 창이 선택되지 않고, 그래서 `min_evaluation_rows` 같은 임계가 애초에 물리지 않는다(재는 것은 조립·취소 경계·파일 쓰기다). 승인 밖 조합이 **필요한** 커널 test 는 라이브러리 진입점을 직접 부른다. **test 전용 승인 주입 경로는 만들지 않았다** — src 가 같은 주입을 쓸 수 있는 우회 표면이 된다. |
| 계약에서 옮긴 자리 둘 | 계약 문면은 「**로더와 재검증**이 둘 다 거부」였다. ⑴ 재검증(`verify_policy_source`)에 넣으면 **조립 근 test 일곱**이 붉어진다 — 그 test 들은 작은 데이터셋을 쓰려고 승인 밖 임계를 파일로 만들어 쓴다. ⑵ 뿌리 로더(`registry.policy.load_policy`)에 넣으면 **32 failed · 79 errors**(11 파일) — 값 불변식 test 들이 파생 정책에 현실적인 version 이름을 쓰고, 출하 추론 정책이 일부러 불완전해서(`agency_sample_threshold` 미선언) 네 helper 가 **placeholder 를 얹은 사본으로만** 로드할 수 있으며, `test_epoch` 하나는 그 이름이 승격 인용 문면에 나오는 것을 단언한다. 둘 다 **실측 뒤 되돌렸다**. 뿌리 검사가 더 막던 것은 「제품 게이트에 닿을 수 없는 경로의 편집 사본」뿐이고, 출하 파일 자체를 고치는 길은 런타임이 아니라 **CI**(등록부 ↔ 출하 지문 등식 test)가 막는다. |
| 세 자리 등식 | 새 version 을 승인하는 길은 ⑴ `policy/*.yaml` ⑵ 등록부 한 줄 ⑶ 승인 장부(`m5/5c2`·`m5/5d` `policy-values.md` 의 지문 표)를 **같은 커밋에서** 바꾸는 것뿐이다. test 셋이 그 등식을 진다 — 지문 등식 · 장부에 그 지문이 적혀 있음 · 출하 version 전수 == 등록 + 일부러 미등록. |
| 등록 범위 | 이 slice 가 **값을 바꾼 두 축**(`evaluation-v1`·`inference-v1`)만. `serving-v1`·`training-v1`·`strategy-backtest-v1/v2` 는 일부러 미등록이고 **그 사실을 목록으로 잠근다** — 새 정책 파일이 조용히 어느 쪽도 아닌 상태로 들어오지 못한다(6G 판정 입력인 `strategy-backtest-v2` 를 건드리지 않는 제약과 같은 자리). |

## D-3 (SET-06) — 시간축 provenance 와 `Unmeasurable`

| 축 | 내용 |
| --- | --- |
| 무엇이 열려 있었나 | 관측이 `datetime` 하나를 들었다 — 「이 시각이 어디서 왔는가」와 「시각을 모른다」를 적을 자리가 없었다. legacy 는 개찰 시각 결측 시 마감 시각으로 **조용히 대체**했고 대체 사실이 결과에 남지 않았다. |
| 구조로 닫은 것 | `TimeAxis = KnownTimeAxis(값·출처·정책 version) \| UnmeasurableTimeAxis(사유)`. 측정 불가 쪽에는 **시각 필드가 없다** — 「출처를 모르는데 값은 있다」를 적을 자리가 없으므로 그 행을 어느 주에 배정하려면 값을 지어내야 하고, 지어내면 아래 항등식이 어긋난다. |
| 항등식 | **모집단 = 창의 개찰 계수 합 + 사유별 측정 불가 합**. `MaturityTable` 의 **생성 불변식**이라, 사유 없이 분모에서 사라지는 행이 있으면 표를 **만들 수 없다**. |
| 대체 승인 자리 | versioned 정책 파일의 한 칸(`maturity.time_axis_substitute`, 출하 **`NOT_APPROVED`**) — 코드에 승인 목록이 없다. `OPEN-SET-10` 미결의 기계적 표현이고, 결정되면 그 한 칸이 `APPROVED` 가 된다. **닫힌 어휘 두 값만** 받는다 — bool 칸이었던 앞 판은 `yes`·`Yes`·`YES`·`on`·`On`(과 `true`·`True`)을 승인으로 읽었다 — v L-2 실측, 표기 전수는 v r2 M-2 에서 재실측(`y`·`1` 은 PyYAML 이 bool 로 읽지 않는다). |
| 대체의 영향 | 대체 행 계수와 **대체 제외 주별 표**를 함께 낸다 — 승인되는 날 측정이 **그 자리에 이미 있다**(그때 새로 만드는 것이 아니다). 지금은 대체 행이 0 이라 두 표가 같다. |
| 섞임 방지 | 한 표의 모든 행은 같은 정책 version 으로 해석됐어야 한다(provenance 를 손으로 지어 다른 version 을 섞으면 `ValueError`). |
| 어휘 충돌 | `inference.availability.UnmeasurableReason`(예측 응답의 도메인 결과 축, wire enum 으로 사상)과 **다른 어휘**다. 섞으면 응답 어휘에 wire 값 없는 사유가 생겨 `serving.wire` 의 사상 불변식이 깨지고 두 축의 「측정 불가」가 한 이름이 된다 — 그래서 `TimeAxisUnmeasurableReason` 으로 따로 둔다. |

## D-4 (ML-05) — `release_id` 를 model_version 축으로

| 축 | 내용 |
| --- | --- |
| 무엇이 열려 있었나 | acceptance 「학습 표본 정의가 바뀌면 `model_version` 이 올라간다」가 **성립하지 않았다**. 선언 입력이 다섯(dataset·spec version·spec checksum·seed·code version)이고 **학습 표본 범위가 빠져** 있어, 같은 데이터셋·spec·seed·code 로 범위만 다른 두 아티팩트가 같은 식별자를 가질 수 있었다(manifest 에는 `sample_scope` 가 있으니 내용은 달랐다). |
| 왜 그 축인가 | `sample_scope` 는 **피처 공간과 직교하는 축**이고, 기본값을 주면 미학습 공종 가드가 조용히 열린다(legacy `artifact_contracts.py` 의 사유). 범위만 다르게 학습한 둘은 다른 모델이다. |
| 열거하지 않는다 | 전수 민감도 sweep 의 입력 목록이 **`inspect.signature` 에서 나온다** — 입력을 더하고 해시 payload 에 넣지 않으면 그 test 가 붉어진다. 기존 손 열거 단언(`test_residual_release.py`)은 한 줄만 더해 남기고, 전수 축은 새 파일이 진다. |
| 문면 보정 | V2 의 식별자는 순서 있는 번호가 아니라 **결정적 해시**다(같은 입력의 두 학습이 같은 id 를 가져야 재현 대조가 성립, D-5C-10) — acceptance 의 「올라간다」는 「달라진다」로 읽는다. capability map 에 그 보정을 적었다. |
| 식별자 ↔ 공시 | `write_artifact` 의 재파생 단언이 **manifest 가 공시한 값**(`sample_scope` 포함)만 읽는다 — 식별자와 공시가 갈리면 그 단언이 붉어진다. |

## 알려진 제한

1. **평가 report 로 provenance 가 흐르지 않는다.** `WeekMaturity` 는 평가 층 타입이고 provenance 를 담으려면
   그 층이 추론 층 어휘를 알아야 한다(forbidden 계약이 막는다). 지금 경계는 「SET-06 의 리포트는 성숙도 표
   자신」이고, 평가 report 로의 전달은 앱 배선 축과 함께 미룬다. 조립 근 코드에 그 문면을 주석으로 남겼다.
2. **조립 근 경로의 측정 불가 행은 구조적으로 0 이다.** `settlements.jsonl` 의 개찰 시각이 필수라 결측을 들고
   올 경로가 없다 — 커널의 측정 불가 갈래는 커널 test 로만 실측된다. 데이터셋 schema 확장은 이 slice 밖이다.
3. **단일 생성 자리 게이트의 잔여**: 재대입을 **한 단계**만 따라간다(`_A = T; _B = _A` 연쇄는 못 본다).
   이 층은 이제 **보조**다 — 생성 자체는 토큰이, 비튼 값은 출처 재검증이 막는다(D-2b). 문면은 공용 보조
   `tests/ast_sites.py` docstring 에 있다.
3a. **게이트 술어가 환경에 의존할 수 있다**(PR #139 실측, 닫았다): 입구 전수의 「해석 실패 등식」이
   **파이썬 패치 버전**에 따라 갈렸다 — PEP 695 제네릭의 주석이 3.12.3 에서는 `NameError`, 3.12.13
   에서는 해석된다. 로컬 초록·CI 붉음으로 드러났다. `__type_params__` 를 해석 namespace 로 넘겨
   의존을 없앴고(두 인터프리터 실측), 선언 목록의 실패 **사유가 모두 같은 종류**(생성 stub 의 모듈
   속성 부재 → `AttributeError`)임을 test 로 잠갔다. **교훈**: 「전수가 조용히 줄는다」를 등식으로
   막아도, 그 등식의 **입력이 환경에 따라 달라지면** 같은 구멍이 다시 열린다 — 등식과 함께 **그
   항목들이 같은 구조적 사유인지**도 재야 한다.
3a2. **게이트를 고친 커밋이 우연한 방어를 걷어낼 수 있다**(v r7 M-1): 3a 의 처방
   (`localns`)이 PEP 695 입구를 해석시키자, 그 입구를 막던 것이 **해석 실패 등식의 우연**이었다는
   사실이 드러났다 — 그 우연이 사라지며 입구가 모집단에서 조용히 빠졌다(두 인터프리터 GREEN 실측).
   `TypeVar` 의 경계·제약을 펴서 닫았고 변이 둘이 두 버전 모두 RED 다. **교훈**: 게이트 술어를
   고칠 때는 「무엇이 더 닫혔나」만이 아니라 **「무엇이 그동안 우연히 닫혀 있었나」**를 같이 재야
   한다(앞 라운드의 측정 근거가 그 우연이었다).
   **닫힌 범위는 측정한 만큼이다**(v r8 M-1' 로 한 번 더 좁혔다): r7 의 가지는 경계가 **타입
   객체일 때만** 받았고, 같은 경계를 **따옴표로 적으면**(`[P: "EvaluationPolicy"]` ·
   `TypeVar("_P", bound="EvaluationPolicy")`) 다시 조용히 빠졌다(두 인터프리터 GREEN 실측).
   이제 문자열 경계를 같은 namespace 로 풀고, 안 풀리면 **해석 실패로 보낸다**(fail-closed) —
   변이 셋이 두 버전 모두 RED, 통제군 둘 GREEN, 집합(4·12) 불변. **잔여는 닫지 않았다**:
   `-> Self` classmethod · `NewType` 반환 · **무경계** 제네릭 `[P]` 는 셋 다 GREEN 이고 등재다
   (무경계는 반환 타입 술어로는 원리상 못 닫는다). **교훈**: 「닫았다」는 **변이로 잰 모양**에만
   붙는다 — 한 계열을 닫은 커밋이 그 계열 전체를 닫았다고 적으면 다음 라운드가 그 문면을 깬다.
   **그 다음 라운드가 실제로 그 문면을 깼다**(cr r9 M-2·M-4): 경계 **자리**에서만 풀면 문자열이
   한 겹만 깊어도 샌다 — `list["EvaluationPolicy"]` · `Optional[…]` · `tuple[…, int]` · 구식
   `TypeVar(bound=Optional["…"])` · `type Pol = "…"` 다섯이 두 버전 GREEN 이었고, `TYPE_CHECKING`
   전용 경계는 아예 **크래시**였다. 이제 푸는 자리를 **잎**으로 옮겼고(어느 깊이든, `Literal`
   인자는 값이라 제외), 지연 평가가 터지는 경계·별칭은 해석 실패로 보낸다 — 변이 여덟이 두 버전
   RED(그중 둘은 크래시→등식), 통제군 여섯 GREEN, 집합(4·12) 불변. **교훈 둘**: 모양을 하나씩
   더하는 수정은 다음 한 겹에서 또 깨진다 — 술어는 **「어디서 푸는가」**로 고쳐야 깊이가
   무관해진다. 그리고 **크래시는 fail-closed 가 아니다**: 게이트가 죽는 것과 게이트가 거절하는
   것은 다른 신호다.
3b. **완화 경로 술어의 부분 일치**(cr LOW, **등재**): `_matched_keys` 는 정책 키가 후보 이름에 들어 있으면
   잡는다. `effective_date` 는 일반명이고 저장소에 동명 다른 어휘가 있다(`evaluation/backtest/rules.py` 의
   날짜 함수 · `strategy-backtest-v1` 의 `effective.*` 키) — 지금 교집합은 0 이다. 좁히지 **않은** 이유:
   접두·접미를 붙인 완화 이름(`--relax-maturity-threshold`)이 조용히 통과하는 쪽이 더 나쁘고, 지금 형태의
   대가는 「무관한 이름이 정책 키를 담는 날 붉어진다」 — 조용한 구멍이 아니라 사람이 볼 신호다.
3c. **운영자가 고르는 정책 파일**: 어느 파일을 쓸지는 환경이 정한다 — 단 **승인된 산출물 사이에서만**이다
   (D-2c). 완화는 승인 근거와 version·effective date 를 가진 정책 산출물로만 가능하고, 그 파일의 지문이
   report 에 남는다. 앞 판 문면(「어느 파일이든 운영자가 고른다」)은 v H-2 가 실측으로 깼다.
3d. **추론 축도 부팅에서 승인을 묻는다**(v r3 H-3b = cr r3 H-1 로 **닫았다** — 앞 판은 이 자리를
   「런타임 승인 요구 없음」으로 등재했고 그것이 열린 구멍이었다): `load_approved_inference_policy`
   (← `_preload`)가 `inference-v1` 의 편집 사본과 이름을 바꿔 단 사본을 거부한다. `InferencePolicy` 에
   출처 칸을 더하지 않고 닫았다 — 뿌리 로더가 **파싱에 쓴 그 텍스트**의 지문을 들고 오므로 승인 대조와
   값 조립이 같은 바이트를 본다(생성 자리 전수를 넓히지 않는다). 그 사본이 바꿀 수 있던 값에는
   **승격 판정 입력**이 있었다 — `maturity.window_days` 는 `build_weekly_maturity` →
   `plan_evaluation_windows` 로 흘러 평가 창 선택을 바꾼다. **남은 자리**: backtest CLI 의
   `--inference-policy` 는 승인을 묻지 않는다(평가 게이트가 없는 오프라인 분석 경로이고, 그 축의 판정
   정책 `strategy-backtest-v2` 는 일부러 미등록이다 — 6G 판정 입력을 건드리지 않는 제약과 같은 자리).
3e. **동적 절취는 경계 밖이다**(측정으로 등재): 조립 근이 `getattr(module, "load_" + "evaluation_policy")`
   처럼 이름을 **실행 시점에 만들어** 승인 미요구 로더를 부르면 호출 자리 집합 등식이 보지 못한다(변이
   MH5 — GREEN 실측). 같은 잔여가 H-1 라운드에도 있었고(그쪽은 값 대조가 받았다), 여기서는 받지 못한다 —
   이름을 바꿔 단 사본은 자기 파일과 값이 **같아서** 재검증을 지나기 때문이다. 성립하려면 `app/server.py`
   를 편집해야 하고, 이 저장소는 같은 종류의 경계(동적 import)를 이미 app 의 HTTP 금지 계약에서 알려진
   제한으로 적고 있다. **속성 형태**(`__import__(...).load_evaluation_policy(...)`)는 막힌다(MH5c RED).
3f. **거부 사유 어휘가 경계 밖에서 관측되지 않는다**(cr r3 L-4, 등재): 조립 근이
   `PolicyApprovalRejection` 두 값을 `PolicyRejected(INVALID_VALUE, detail)` 로 접어, 두 사유는 **문면
   부분 문자열**로만 구별된다(env 축 test 가 「승인된 지문과 다르다」·「승인 등록부에 없는」으로 단언).
   사유 어휘를 넓히지 않은 근거는 조립 근 로더 docstring 에 있고, 대가는 「문면을 다듬는 날 그 test 들이
   깨진다」 — 조용한 구멍이 아니라 사람이 볼 신호다.
3g. **승인 지문은 「파일 바이트」가 아니라 「줄끝 정규화된 텍스트」의 해시다**(cr r3 L-1, 등재):
   `read_text` 가 universal newline 변환을 하므로 CRLF 사본은 바이트가 달라도 같은 지문이다(실측).
   보안 영향 0 — 파싱도 **같은 텍스트 객체**에서 하므로 지문과 값이 어긋날 자리가 없다. **문면 정정**
   (v r5 L-2): 앞 판은 「어긋날 자리가 없다」를 무조건으로 적었는데, 그 텍스트가 **거짓말하는 `str`
   하위 클래스**면 어긋났다(N2 — `encode` 가 다른 바이트를 돌려준다). 라운드 5 가 읽기 경로를 정확
   타입으로 정규화하고 재구성 객체에게 승인을 다시 물어 닫았다 — 이제 그 문장은 **stdlib 읽기에
   대해** 참이다.
3h. **방어는 런타임 fail-closed 이고, 그 코드의 「유입」을 막는 층은 없다**(cr r4 L-1, 등재):
   MX1b·MXI 류 헬퍼를 src 에 더하는 변이는 **게이트를 하나도 붉히지 않는다**(실측 — 그 코드는
   `ML_ENGINE_GATE_T` 같은 환경 값이 설정될 때만 발화하고 test 는 그것을 설정하지 않는다). 바뀌는 것은
   **판정 값**이다: **코드가 건넨 객체의 거동으로는** 완화값이 판정에 닿지 못한다(실측 다섯 모양 —
   F6·F7·N1·N2·N6). 유입 자체를 막는 자리는 **코드 리뷰**이고, 그것이 위협 모델 경계다(design-review
   §0a·§0b). 방어 **메커니즘**의 제거는 붉다(O1·O2·P1·P2).
3i. **추론 축은 부팅 승인만 있고 게이트 자리 재검사가 없다**(v r4 M-6, 등재): `maturity.window_days` 는
   승격 판정 입력인데(평가 창 선택), 부팅 뒤 그 값을 바꿔치우는 코드(`maturity_window_days=tuned_window(
   …)`)는 게이트를 붉히지 않고 창 길이를 바꾼다(실측: 파이프라인 창 값 1). 평가 축처럼 닫으려면
   파이프라인이 **추론 정책의 경로와 지문**을 들고 게이트 자리에서 재구성해야 하는데, `InferencePolicy` 에
   출처 칸이 없어 `build_training_pipeline` 시그니처와 그 호출자·test 전수가 함께 움직인다 — 이 slice
   밖이다. 지금 닫혀 있는 것: **파일을 고르는 축**(env·사본 전부, r3). 열려 있는 것: **부팅 뒤 코드가
   값을 바꿔치우는 축** — 3h 와 같은 경계(코드 리뷰)다.
3j. **건네지 않은 객체의 메모리에 손을 뻗는 것은 경계 밖이다**(v r5 M-8, 등재): `gc.get_objects()` 로
   재검증의 **반환 객체**를 찾아 `object.__setattr__` 하면 완화값이 판정에 닿는다(실측 N3: 통과).
   프레임 조작·`ctypes` 도 같은 계열이고 in-process 파이썬에서 코드로 닫는 길이 없다(3e 와 같은 자리).
   경계선은(§0a) **코드가 건네준 객체가 하는 일**(안쪽)과 **건네주지 않은 객체에 손을 뻗는 것**(바깥)이다.
3k. **대체 제외 표의 분자는 등식 밖이다**(cr r5 M-2, 등재): 대체 행이 있는 표에서 제외 표의
   `settled_count` 는 `[0, opened]` 안의 아무 값이나 될 수 있다 — 상한만 `Observed` 가 지고, 「대체 행
   중 몇이 정산됐는가」를 표가 들고 있지 않아(출처별 정산 계수가 없다) 등식으로 묶을 데이터가 없다.
   닫으려면 `WindowTimeAxis` 에 그 계수를 더해야 하고 이 slice 밖이다. **분모**는 묶여 있고(창별 출처
   등식) 지금 생산자는 두 표를 같은 집계로 만들어 바르다.
3l. **입구 전수(유입 층)의 오탐 셋과 잔여 둘**(v r10 M-A·M-B, **등재** — 사용자 결정으로 고치지
   않는다): ⑴ **오탐 셋** — 비정책 코드를 통과도 등재도 아닌 **해석 실패**로 붉히는 모양이 셋이다.
   클래스 스코프 이름의 문자열 경계(기존) · **`Annotated` 의 문자열 메타데이터**가 별칭 값이나
   `TypeVar` 경계 **안**에 들어온 경우(`type Meters = Annotated[int, "meters"]` →
   `-> Meters`, `def f[T: Annotated[int, "positive"]]`) · **제네릭 별칭이 자기 타입 파라미터를
   문자열로** 가리키는 경우(`type Box[T] = list["T"]` → `-> Box`). 뒤 둘은 「문자열을 잎 자리에서
   푼다」로 옮긴 마지막 수정 라운드가 만든 **회귀**다(앞 커밋에서 GREEN). 기제는 하나 —
   `get_args(Annotated[X, "x"])` 가 `(X, "x")` 라 **메타데이터가 잎 자리로** 간다. 터지는 자리는
   `get_type_hints` 가 들어가지 않는 구멍뿐이라 매개변수·반환에 **직접** 적은 `Annotated` 는
   통과한다. 셋 다 src 에 **0** 이고(집합 불변) 탈출구가 있다. 후속 처방은 「`Annotated` 면 첫
   인자만 펴고 `__metadata__` 는 버린다」 한 줄이다. **같은 기제가 변이 B23 의 사유**이기도 하다 —
   B23 이 붉은 것은 정책 문자열이 아니라 메타데이터 `"x"` 때문이라, B23 은 문자열 **경계**를
   닫았다는 증거가 아니다(commands.md §4l 표 주에 정정했다). ⑵ **잔여 둘** — 첨자를 단 제네릭
   별칭(`type Pol[T] = EvaluationPolicy` → `-> Pol[int]`)과
   `typing_extensions.TypeAliasType("Pol", EvaluationPolicy)` 는 정책 반환 함수를 모집단 **밖**에
   둔다(두 버전 GREEN, 이 라운드의 회귀가 아닌 기존 틈). 잔여 목록과 「별칭으로 가려도」 주장
   (→ **무첨자** 별칭으로 좁혔다)을 고쳤다. **교훈**: 술어를 「어디서 푸는가」로 고치면 깊이는
   무관해지지만, **그 자리로 오는 것이 타입만이 아니다** — `Literal` 인자처럼 `Annotated` 의
   메타데이터도 타입이 아닌 **값**인데 같은 잎 자리에 섞여 들어온다. 닫는 범위를 넓히는 커밋은
   「무엇이 새로 이 자리에 오는가」를 함께 재야 하고, 그 대가의 **수를 세어** 적어야 한다
   (앞 판은 「대가도 하나 있다」로 적었고 실측은 셋이었다).
4. **effective date 를 과거로 적는 길은 막지 않는다** — 그것이 정책 승인의 뜻이다. 막는 것은 **조용히**
   그러는 길이고, 값이 정책 checksum·report 에 들어가므로 산출물이 달라진다.
5. **출하 effective date(2026-09-16)는 지금 코퍼스의 창들보다 뒤다.** 즉 그 창들로는 승격이 인용되지 않는다 —
   이 capability 가 이미 적은 사실(「승격 여부를 판정할 수 있는 창이 아직 없다」)과 같은 방향이고, 통과를
   만들려면 **정책을 새 effective date 로 다시 승인**하거나 그 뒤의 창이 성숙해야 한다.
6. **ML-08 서명은 코드 축이 없다**(위 D-5). 등재만이다.
7. **effective date 값의 지위 — 승인됨**(v M-2 **종결**, 2026-11-06 사용자 승인): `2026-09-16` 은
   `reports/evidence/m5/5c2/policy-values.md` 머리말·change_history 의 **그 표 승인 날짜**(운영자 「둘 다
   승인」, M5 종결 판정 `reports/evidence/m5/closure/checklist.md` §3 ④)에서 읽은 값이고, 거기까지는
   **구현자의 해석**이었다 — 그 해석에 **2026-11-06 사용자 승인이 붙었다**(팀장 전달). 함께 확인된 거동:
   같은 `evaluation-v1` version 을 유지한 채 칸이 늘어 **같은 version 의 checksum 과 승격 거동이
   바뀐다**(이전 `Passed` 창 → `Superseded`). **값과 파일 지문은 바뀌지 않았다** — 이 승인은 문면만
   바꾼다. 어떻게 정해졌는지의 기록은 장부에 **덮지 않고** 남아 있다(cr M-4).
8. **정책 파일의 YAML 중복 키**(범위 밖 기존 부채, v 참고): `yaml.safe_load` 가 중복 키를 마지막 값으로
   조용히 접는다 — 한 줄 추가로 `effective_date` 를 덮어쓸 수 있다. 값이 정책 checksum·report 에 들어가므로
   **산출물에는 드러난다**. 뿌리 처방(중복 감지 로더)은 네 로더 공통이라 이 slice 밖이다.
