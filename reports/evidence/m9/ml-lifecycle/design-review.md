# M9/ml-lifecycle 설계 검토 (구현 전)

## 0a. 위협 모델 경계 — 경계 안/밖의 구분

승격 판정이 **자기를 만든 데이터로 자기를 승인하지 못하고**, 성숙도 분모에서 사라지는 행이
**사유 없이** 사라지지 못하고, 학습 표본 정의가 바뀐 모델이 **같은 식별자**를 쓰지 못한다.
경계 **밖**: 임계 값 자체의 옳음(승인 문서 소관) · 서명 키 보관·회전(운영자 결정, 등재만) ·
마감 시각 대체의 채택 여부(`OPEN-SET-10`, 등재만) · 앱 배선과 수집 연장(사용자 보류) ·
최종 bid/review/skip 판단(Kotlin 소유).

## 0b. 위협 모델 경계 — 값 축 (라운드 4 명문화 · 라운드 5 정정)

세 라운드가 같은 계열의 우회를 쫓았다. 무엇을 막는 설계인지 한 자리에 적는다.

**막는 것**(측정과 같은 크기로 적는다): 판정에 닿는 값은 **로더가 파일에서 재구성한 객체**의
값이고, 그 객체가 승인 산출물인지를 **호출자 객체가 통제할 수 없는 자리**에서 묻는다 —
비교의 양쪽이 로더가 만든 값(`hexdigest()` 결과와 파싱된 `version`)이다. 그래서 **코드가 건네는
객체의 거동**으로는 판정 값을 바꿀 수 없다: 임계를 비튼 객체(`replace`·동적 생성·토큰 절취) ·
직렬화와 거동을 갈라 놓은 객체(프레임 property · float 하위 클래스) · 비교를 이기는 지문
(`__eq__` 거짓) · 읽기를 가로채는 경로(`read_text`) · 읽을 때마다 달라지는 `source` — 다섯
모양을 실측했다(F6·F7·N1·N2·N6).

**「어떤 모양이든」이라고 적지 않는다.** 앞 네 라운드의 지적이 전부 그 범주 주장의 반례였다 —
장부가 측정보다 한 칸 앞서면 다음 라운드가 그 칸을 짚는다. 여기 적는 것은 **측정한 다섯
모양과 그것들이 공유하는 성질**(건넨 객체의 거동)뿐이다.

**막지 않는 것 — 그리고 그것을 막는 자리**:
- **그런 코드가 저장소에 들어오는 것 자체**는 게이트가 아니라 **코드 리뷰**가 막는다. 측정으로
  확인했다: MX1b·MXI 류 변이는 게이트를 하나도 붉히지 않는다(환경 값이 설정될 때만 발화하고
  test 는 그것을 설정하지 않는다). 방어 **메커니즘**의 제거는 붉다 — 그것이 게이트가 지는 몫이다.
- **승인 파일 자체를 바꾸는 것**은 **CI** 가 막는다(등록부 ↔ 출하 지문 등식 test). 런타임이 아니라
  CI 인 이유는 그 변경이 커밋으로만 들어오기 때문이다.
- **모듈 속성을 실행 중 대입하거나 이름을 실행 시점에 조립하는 것**(동적 절취)은 경계 밖이다
  (알려진 제한 3e — 변이 GREEN 실측).
- **경계선 한 문장**(v r5 M-8): 안쪽은 **코드가 건네준 객체가 하는 일**이다(그 객체의
  `__eq__`·property·`read_text`·하위 클래스 — 위 다섯 모양이 전부 여기 속한다). 바깥은
  **건네주지 않은 객체의 메모리에 손을 뻗는 것**이다 — `gc.get_objects()` 로 반환 객체를 찾아
  `object.__setattr__` 하기(N3 실측: 통과) · 프레임 조작 · `ctypes`. in-process 파이썬의
  한계이고 코드로 닫는 길이 없다(3e 와 같은 계열). 그 선이 기존 판정 전부와 맞는다: F6 은
  **건넨 객체 자신의 거동**이라 안쪽이다.
- **추론 축의 부팅 뒤 값 바꿔치우기**는 지금 열려 있다(제한 3i) — 파일을 고르는 축은 닫혀 있다.

요약하면 이 slice 의 게이트는 **「코드가 건넨 객체의 거동으로는 승인 밖 값이 판정에 닿지
못한다」**를 지고, **「악의 코드가 들어오지 못한다」**도 **「건네지 않은 객체에 손을 뻗을 수
없다」**도 지지 않는다. 앞 네 라운드의 지적은 전부 첫째 문장이 **너무 넓게** 적혀 있던
자리였고(자리 단일성 → 직렬화 → 비교 피연산자), 라운드 5 가 안전 성질을 호출자 객체에서
완전히 뗐다.

## 1. 열거인가 구성인가

- **구성**: 승격 인용(citation)은 「창 시작 ≥ 정책 effective date」 **한 술어**이고, 두 날짜는
  각각 자기 원천(정책 파일 · 창 구간)에서만 온다. 통과 목록도 예외 목록도 없다 — 정책 version 을
  올리지 않고 통과를 만들려면 **창을 미래로 옮기는 수밖에** 없고 창은 코퍼스가 정한다.
- **구성**: 시간축은 `KnownTimeAxis(value, source, policy_version) | UnknownTimeAxis(reason)`
  **합 타입**이다. 「출처를 모르는데 값은 있다」가 타입으로 표현되지 않는다(그 상태를 적을 자리가
  없다) — legacy 의 조용한 대체가 형태로 불가능해진다.
- **구성**: 승인된 시간축 출처는 **정책 파일의 한 칸**(`maturity.time_axis_substitute`, 닫힌 어휘
  두 값)이 정하고, 코드에는 승인 목록 리터럴이 없다. `OPEN-SET-10` 이 결정되면 **그 한 칸**이
  바뀐다. bool 이 아닌 이유는 수정 라운드 v L-2 — YAML 1.1 참값 표기가 승인을 만들었다.
- **열거**: `UnmeasurableReason` 둘·`TimeAxisSource` 둘은 어휘라 열거다. 그 열거가 「분모에서
  사라진 행 전수」와 같은 집합이라는 **항등식**(모집단 = 성숙 분모 + 측정 불가)이 `MaturityTable`
  생성 자리에서 돈다 — 새 사유를 더하고 계수에 넣지 않으면 항등식이 깨진다.
- **열거 아님(구조)**: 「임계 완화 입력 경로 0」 게이트의 모집단은 **정책 키 집합에서 생성**한다
  (`_SCALAR_KEYS` + 목록 접두). 키를 더하면 감시 범위가 같은 커밋에서 자란다.

**「경계로 처리」 행 없음** — 위 전부 실측 대상이다.

## 3. 우회 (≥5)

1. **effective date 를 과거로 적어 전부 통과시킨다** — 막지 않는다(그것이 정책 승인의 뜻이다).
   막는 것은 **조용히** 그러는 길이다: 값이 정책 checksum 과 report 에 들어가므로 report 가
   달라지고, 「어느 정책으로 판정했는가」가 산출물에 남는다. 코드에서 바꾸는 길은 숫자 리터럴
   게이트(`evaluation/**`)와 「정책 객체 생성 자리 1」 게이트가 막는다.
2. **임계를 CLI 플래그·환경변수·요청 필드로 주입한다** — 세 경로 각각을 구조로 잰다:
   `add_argument` 의 옵션·dest 이름 ∩ 정책 키 = ∅(AST) · 환경 변수 이름 ∩ 정책 키 = ∅ 이고
   `evaluation/**` 은 환경을 아예 읽지 않는다(AST) · proto 전 메시지 필드 이름 ∩ 정책 키 = ∅
   (descriptor 순회 — 실제 wire).
3. **`EvaluationPolicy` 를 손으로 조립해 임계를 비튼다**(로더를 우회) — `src` 전체 AST 에서
   생성 자리가 **하나**이고 그것이 `load_evaluation_policy` 안임을 잰다. 테스트 코드는 대상 밖
   (그 자유가 있어야 거부 test 를 쓸 수 있다) — 그래서 「src 안」으로 범위를 적는다.
4. **승격을 창 없이 만든다** — `derive_promotion` 에 `citation` 을 안 넘기거나 `Citable` 을
   지어낸다. 막는 것: `citation` 이 기본값 없는 키워드라 안 넘기면 mypy 가 거부하고, 지어낸
   `Citable` 은 **거동 test** 가 잡는다(홀드아웃 전건에서 승격이 갈리는 등식). **정정**
   (verifier L-1): 앞 판 문면은 「src 생성 자리 전수 test 가 그 자리를 센다」고 적었는데
   `Citable` 을 세는 test 는 **없다** — 세는 것은 `EvaluationPolicy`·`TimeAxisPolicy` 둘이다.
5. **측정 불가 행을 어느 주에 배정해 분모를 채운다**(legacy 의 조용한 대체) — `UnknownTimeAxis`
   에는 시각 값이 **없다**(타입에 필드가 없다). 주를 고르려면 값을 지어내야 하고, 지어내면
   항등식의 모집단 계수가 어긋난다.
6. **대체 출처를 코드에서 승인한다** — 승인은 정책 파일의 **닫힌 어휘 한 칸**이고 코드에는
   목록이 없다. 출하값이 `NOT_APPROVED` 임을 test 가 잠근다(= `OPEN-SET-10` 미결 상태의
   기계적 표현). 어휘가 bool 이 아닌 이유는 v L-2 — YAML 1.1 참값 표기가 승인을 만들었다.
7. **대체가 주 경계를 밀었는데 안 보인다** — 대체 행 계수와 **대체 제외 주별 성숙도**를 함께
   산출한다(둘이 갈리면 표에서 보인다). 지금은 승인 밖이라 대체 행이 0 이고, 승인되는 날
   같은 측정이 그대로 돈다.
8. **학습 표본 정의를 바꾸고 같은 `release_id` 를 쓴다** — `sample_scope` 가 해시 입력에
   들어간다. 전수 민감도 test 의 모집단은 **시그니처에서 생성**되므로, 입력을 더하고 payload 에
   넣지 않으면 그 test 가 붉다.
9. **KST 경계로 하루를 벌어 통과 창을 만든다**(effective date 를 UTC 날짜로 재면 월요일 오전
   KST 창이 전날로 밀린다 — SET-06 이 실측한 함정) — epoch 의 KST 일 시작과 성숙도 커널의
   KST 주 시작이 **같은 경계**임을 cross-layer test 가 잰다(두 모듈이 상수를 공유하지 않으므로
   공유가 아니라 **등식**으로 닫는다).

## 4. 과잉·미달

- **과잉 아님(effective date 를 거동에 묶는 것)**: 칸만 더하면 ML-07 acceptance ③ 은 장식이
  된다(값이 wire 에 닿지도, 거동을 바꾸지도 않는다). 술어는 **하나**이고, ML-07 이 문면으로 적은
  함정(「관측에서 역산한 상수가 그 데이터의 사후 산물이 된다」)을 기계가 막는 가장 작은 형태다.
- **과잉 아님(대체 제외 표)**: SET-06 acceptance 가 요구하는 항목이고, 같은 커널을 걸러 한 번 더
  돌리는 것이라 산식 중복이 없다.
- **미달 자리 둘(알려진 제한으로 등재)**:
  ① `settlements.jsonl` 행은 `opened_at` 이 **필수**라 조립 근 경로에서는 측정 불가 행이
  구조적으로 0 이다 — 커널의 측정 불가 갈래는 커널 test 로만 실측된다(데이터셋 schema 확장은
  이 slice 밖, 앱 배선 보류).
  ② 성숙도 표의 provenance 는 **평가 report 로 흐르지 않는다** — `WeekMaturity` 는 평가 층
  타입이고 provenance 를 담으려면 그 층이 추론 층 어휘를 알아야 한다(import 계약이 막는다).
  지금 경계는 「SET-06 의 리포트는 `MaturityTable` 자신」이고, 평가 report 로의 전달은 앱 배선
  축과 함께 미룬다.
- **미달 아님(ML-08)**: 서명 키 보관·회전은 운영자 결정이라 코드로 만들 축이 없다 — 등재만.


## 5. 수정 라운드 — v H-1 이 뒤집은 설계 (2026-11-06)

위 §2 표의 `EvaluationPolicy.effective_date` 행은 값 획득 자리를 「로더가 `path` 하나만
받는다」로만 적었고, §3 우회 3 은 그 방어를 「src 안 생성 **자리** 하나」로 적었다. **둘 다
모자랐다** — verifier 가 세 경로로 실제 임계 완화를 전 게이트 초록으로 통과시켰다:

| 경로 | 앞 판이 지나간 이유 |
| --- | --- |
| `dataclasses.replace(p, paired_t_threshold=…)` | 생성 **호출**이 아니라 복사라 AST 가 세지 않는다 |
| `type(p)(**{**vars(p), …})` | 호출 이름이 `type(p)` 라 이름 대조 밖이다 |
| `getattr(importlib.import_module(…), "Evaluation"+"Policy")(…)` | 이름이 **실행 시점**에 만들어져 어떤 AST 도 보지 못한다 |

주입원도 이름 대조를 비켜 갔다 — 환경 변수 이름(`ML_ENGINE_GATE_T`)이 정책 키를 담지 않았다.

**처방은 열거 확대가 아니라 형태다**(겹 둘, 둘 다 실측):

1. **생성 토큰** — `EvaluationPolicy` 의 첫 매개변수가 기본값 없는 `InitVar[_ParsedPolicyFile]`
   (모듈 private). `InitVar` 는 인스턴스에 저장되지 않아 `vars()`·`fields()`·`asdict()` 에
   없으므로 **기존 객체에서 베껴 올 자리가 없다** — 위 세 형태가 전부 `TypeError`/`ValueError`.
2. **출처 재검증** — 정책이 자기 파일과 그 지문을 들고, 제품 경로가 파일을 다시 읽어 값과
   바이트를 대조한다. 이 겹은 객체가 **어떻게 만들어졌든** 무관하므로 토큰 이름을 동적으로
   훔쳐 위조한 객체도 드러난다(AST 가 볼 수 없는 마지막 경로).

**경계를 새로 적는다**: 어느 **파일**을 정책으로 쓸지는 운영자가 고른다
(`ML_ENGINE_EVALUATION_POLICY`). 이 두 겹이 막는 것은 「코드가 값을 지어내거나 비트는 것」이고,
완화된 임계는 **승인 근거와 version·effective date 를 가진 정책 산출물**로만 존재할 수 있다 —
그리고 그 파일의 지문이 report 에 남는다(`policy_source_digest`). 그것이 ML-07 ③④ 가 요구한
모양이고, 앞 판은 그 모양을 **이름으로 근사**하고 있었다.

**재검증을 제품 경로에 둔 이유**(라이브러리 진입점이 아니라): `run_holdout` 은 커널 test 가
승인 밖 조합(seed 재배열·단일 seed)으로도 불러야 하고 그런 정책은 로더가 거부한다 — 거기서
재검증하면 그 test 들이 **재는 것을 잃는다**. 제품 경로는 하나다(`app.pipeline._run_holdout`).


## 6. 수정 라운드 2 — v H-2 가 뒤집은 **경계 문면** (2026-11-06)

§5 는 경계를 「어느 **파일**을 정책으로 쓸지는 운영자가 고른다」로 적었고, 그 두 겹이 막는
것을 「코드가 값을 지어내거나 비트는 것」으로 적었다. **그 경계 문면이 ML-07 수용과
모순이었다** — verifier 가 실측했다:

| 경로 | 결과 |
| --- | --- |
| `adapters` 에 헬퍼를 두고 임계만 바꾼 사본을 tempdir 에 써서 부팅이 그것을 로드 | ruff·mypy·lint-imports·래칫 0, 전건 1700 passed, 실제 t=0.1, version 은 그대로 `evaluation-v1`, 출처 재검증도 **통과** |
| 코드 변경 없이 `ML_ENGINE_EVALUATION_POLICY` 를 편집 사본으로 돌림 | 같다 |

같은 `evaluation-v1` 에서 판정이 달랐다. 그러면 「version 이 바뀌면 전후 판정이 갈린다」와
「env 로 값을 주입해도 판정이 달라지지 않는다」가 **둘 다** 거짓이다. §5 의 「완화된 임계는
승인 근거를 가진 정책 산출물로만 존재할 수 있다」도 이 경로에서 거짓이었다 — 사본에는 승인
근거가 없는데 산출물로서 통했다.

**근원**: version 문자열이 **내용에 묶여 있지 않다**. 두 겹은 「객체 ↔ 그 파일」을 묻고,
「그 파일 ↔ 승인」을 묻지 않았다.

**처방은 열거의 방향을 뒤집는 것이다** — 「무엇을 거부하는가」(무한)가 아니라 **「무엇이
승인됐는가」**(유한)를 코드 상수로 적는다. `registry.policy_approvals` 가 승인 version →
그 파일 내용 sha256 을 들고, 묻는 자리를 **하나**로 뒀다:
`load_approved_evaluation_policy` ← `app.server._preload` — 곧 **운영자의 선택(env)이
들어오는 자리**. 그 한 자리가 두 갈래를 함께 거부한다: 이름을 유지한 편집 사본(지문 불일치)과
이름을 바꿔 단 사본(미등록). 세 갈래를 env 축 test 가 잰다(둘의 거부 + 무편집 사본의 통과).

> **이 「하나」는 라운드 2 의 판단이고 틀렸다** — §7 이 게이트 자리를, §8 이 값의 출처를 더한다.
> 현행 설계(묻는 자리 셋 + 재구성 반환)는 §8 과 `evaluation.policy_source` 모듈 docstring 이
> 정본이다. 이 절은 **그렇게 된 사유의 기록**으로 남긴다.

**경계를 다시 적는다**: 운영자는 **승인된 산출물 사이에서** 고른다. 승인은 세 자리를 같은
커밋에서 바꾸는 것이고(yaml · 등록부 한 줄 · 승인 장부의 지문 표), 어긋나면 test 가 붉다.

**한 자리로 충분한 근거는 사슬의 단일성이다**: 게이트에 닿는 정책은 그 자리를 거친 하나다.
env → 승인 요구 로더 → `_preload` → `pipeline_factory` → `_run_holdout`. 그 사슬을 호출 자리
집합 등식 **넷**이 진다 — 승인 미요구 로더(policy_source 안 둘) · `build_training_pipeline`
(하나) · `run_holdout`(하나) · `EvaluationPolicy` 생성 자리(로더 안 하나).

### 계약과 갈린 자리 둘 — **둘 다 실측 뒤 되돌렸다**

계약은 「**로더와 재검증**이 둘 다 거부」로 적었다. 둘 다 실제로 걸어 보고 되돌렸다.

| 어디에 걸었나 | 실측 | 왜 되돌렸나 |
| --- | --- | --- |
| 재검증(`verify_policy_source`) | 조립 근 test **일곱** 붉음 | 그 test 들은 작은 데이터셋으로 돌려고 승인 밖 임계(`min_evaluation_rows` 등)를 파일로 만들어 쓴다 — §5 가 「재검증을 제품 경로에 둔 이유」로 적은 함정이 한 겹 위에서 재발한다 |
| 뿌리 로더(`registry.policy.load_policy`) | **32 failed · 79 errors**(11 파일) | 값 불변식 test 들이 파생 정책에 현실적인 version 이름을 쓴다. 출하 추론 정책은 일부러 불완전해서(`agency_sample_threshold` 미선언) **네 helper 가 placeholder 를 얹은 사본으로만** 로드할 수 있고, `test_epoch` 하나는 그 이름이 승격 인용 문면에 나오는 것을 단언한다 |

**뿌리 검사가 더 막던 것**은 「제품 게이트에 닿을 수 없는 경로의 편집 사본」뿐이다. 출하 파일
자체를 고치는 길은 런타임이 아니라 **CI** 가 막는다(등록부 ↔ 출하 지문 등식 test). 닫는
집합은 같고, 잃지 않은 것은 그 11 파일이 재던 값 불변식이다.

### 우회 — 이 겹이 열어 둔 것과 막는 것

10. **등록부 상수를 코드가 고친다** — 모듈 소스를 편집해야 하고, 그러면 세 자리 등식 test
    셋이 붉다(지문 등식 **MH3 RED** · 출하 version 전수 분할 **MH4 RED** · 장부 문서 대조).
    사상은 `MappingProxyType` 이라 **실행 중 항목 삽입**은 `TypeError` 다(test).
11. **승인을 묻지 않는 로더를 조립 근이 직접 부른다** — 호출 자리 집합 등식이
    `policy_source` 안 둘로 닫혀 있다. 정적 호출 **MH5b RED**, 동적 import 의 속성 호출
    **MH5c RED**. **열린 잔여**: 이름을 실행 시점에 **쪼개** 만드는 `getattr` — **MH5 GREEN**
    (알려진 제한 3e; H-1 라운드의 같은 잔여는 값 대조가 받았지만 여기서는 받지 못한다 —
    이름을 바꾼 사본은 자기 파일과 값이 같아 재검증을 지난다).
12. **재검증·승인을 거치지 않는 두 번째 게이트 경로를 만든다** — 집합 등식 둘:
    `run_holdout` 호출 자리(**MH6 RED**) · `build_training_pipeline` 조립 자리(**MH7 RED**).
13. **승인된 두 version 밖의 정책으로 같은 완화를 한다** — `serving-v1`·`training-v1`·
    `strategy-backtest-*` 는 일부러 미등록이고 **그 목록이 test 에 있다**. 평가 게이트 임계는
    그 파일들에 없으므로 이 slice 의 축이 아니다; 축을 넓히는 것은 각자의 승인 장부와 소비
    경로를 함께 봐야 하는 별건이다(등재).
14. **추론 축에서 사본으로 대체 승인·창 길이를 바꾼다** — 라운드 3 에서 **닫았다**
    (v H-3b = cr H-1): `load_approved_inference_policy` ← `_preload`. `InferencePolicy` 에
    출처 칸을 더하지 않고 닫혔다 — 뿌리 로더가 파싱에 쓴 그 텍스트의 지문을 들고 온다.
15. **부팅 뒤에 정책 객체를 바꿔 끼운다**(MX1b) — 라운드 3 에서 **닫았다**(v H-3a):
    재검증이 객체의 **자기 주장**으로 승인을 묻는다. 아래 §7.

## 7. 수정 라운드 3 — v H-3a 가 뒤집은 것: **자리 단일성은 값 축을 대신하지 않는다**

§6 은 「게이트에 닿는 정책은 조립 근을 거친 하나」를 근거로 승인을 **한 자리**에서만 물었고,
그 단일성을 호출 자리 집합 등식 넷이 진다고 적었다. verifier 가 그 추론의 빈 칸을 실측했다.

**MX1b**: `adapters/` 에 헬퍼를 두고 `copy.copy(승인 정책)` + `object.__setattr__` 로 임계·
version·`source` 를 바꾼다. `source` 는 코드가 써 둔 **미승인 사본 파일**(내용이 그 객체와
일치한다)과 그 sha256 을 가리킨다. `_training_pipeline_factory` 의 정책 인자를 그 헬퍼로
감싸는 **한 줄**. 결과: ruff·format·mypy --strict·lint-imports·래칫 exit 0, **pytest 1719
passed**, 그리고 t=0.1 이 게이트에 닿는다.

**왜 넷이 보지 못했나**: 그 변이는 호출 자리를 **하나도 늘리지 않는다**. 집합 등식은
「누가 부르는가」를 세고 「그 자리를 지나는 **값**이 무엇인가」를 세지 않는다. 재검증의 두 축
(바이트·값)은 객체와 파일이 서로 일치하면 **둘 다 성립한다** — 그 파일을 아무도 승인하지
않았다는 사실은 둘 중 어느 축도 묻지 않는다.

**처방**: 승인을 **게이트에 닿는 자리**에서도 묻는다(`verify_policy_source`). 그러면 호출
자리 수와 무관해진다 — 어느 경로로 왔든 그 자리에 도착한 값의 출처가 승인된 것이어야 한다.

**그 처방이 MX1b 에 대해 무엇을 바꾸는가 — 측정한 그대로**: 재현물을 수정 뒤 HEAD 의 버릴
clone 에 그대로 적용하면 `verify_policy_source` 가 **PASS → MISMATCH(UNREGISTERED_VERSION)**
로 바뀐다(probe 실측). 즉 t=0.1 이 **게이트에 닿지 못하고** job 이 `POLICY_SOURCE_MISMATCH`
로 fail-closed 한다. **그러나 MX1b 는 여전히 어떤 게이트도 붉히지 않는다**(같은 clone 에서
표적 76 passed · ruff·mypy·lint-imports·래칫 exit 0) — 그 코드는 `ML_ENGINE_GATE_T` 가
설정될 때만 발화하고 test 는 그것을 설정하지 않는다. 그래서 이 축의 방어는 **런타임
fail-closed** 이고, 「그런 코드가 저장소에 들어오는 것 자체」를 막는 층은 없다(src 리뷰가 그
자리다 — 알려진 제한으로 등재). 방어 **메커니즘**의 제거는 붉다(N1·N2).

**승인을 「객체의 자기 주장」에 거는 이유**(검사 셋의 역할 분담): 재로드한 파일에 걸면
「로드 뒤 파일이 바뀌었다」와 「애초에 미승인을 로드했다」가 **한 검사로 접힌다** — 바이트
축이 잡던 경우를 승인 축이 대신 거부하므로 그 축의 역할이 사라진다. 주장에 걸면 셋이 각각
다른 것을 보고, 각 축의 제거 변이가 각각 붉다(N1·N4 계열).

**이 추론을 변이로 쟀고 예측이 한 칸 틀렸다**(정직하게 적는다): 「접히면 바이트 축 제거
변이가 조용히 초록이 된다」고 예측해 **역할 접힘 변이(N1b)**를 GREEN 으로 기대했는데
**RED** 였다. 잡은 것은 바이트 축 test 의 **문면 단언**이다(`"파일 바이트" in detail`) —
접으면 거부 문면이 승인 쪽으로 바뀐다. 즉 역할 분리를 지키는 것은 「거부가 나는가」가
아니라 **「어느 축이 거부했는가를 test 가 읽는가」**다. 그 단언이 없었다면 예측대로 조용히
초록이었을 것이다. 주장에 거는 선택의 근거는 그대로 유효하다(의미상 맞는 질문이고 세 축의
문면이 갈린다), 다만 **그 선택을 지키는 것은 문면 단언**이라고 적는다.

**조립 근의 승인 대조는 남겼다** — 중복이 아니라 **빨리 실패하는 자리**다. 미승인 정책을
가리킨 부팅은 job 을 받기 전에 `NOT_READY` 로 서야 한다(게이트까지 가서 실패하면 그 사실이
job 실패로만 보인다).

**조립 근 test 를 어떻게 했는가**(계약이 지시한 대로 test 쪽에서 해결): 제품 경로 test 는
**출하 승인 정책 그대로** 쓴다. 앞 라운드에 그 test 들이 붉었던 이유는 작은 데이터셋에 맞춘
**파생(미승인) 정책**을 썼기 때문이고, 출하 임계로 바꿔도 재던 것을 잃지 않는다 — 그
데이터셋은 `settlements.jsonl` 이 비어 성숙한 주가 0 이라 평가 창이 선택되지 않고, 그래서
임계가 애초에 물리지 않는다. **test 전용 승인 주입 경로는 만들지 않았다**(팀장 지시) — src 가
같은 주입을 쓸 수 있는 우회 표면이 된다.


## 8. 수정 라운드 4 — v H-4: **직렬화를 보는 축은 몇 개든 같은 틈을 공유한다**

§7 은 승인을 「게이트에 닿는 값」에서 묻게 했고, 축 셋이 각각 다른 것을 본다고 적었다.
verifier 가 그 셋이 **공유하는** 틈을 쟀다.

**F6·F7·F8**(단위) — 세 축이 **전부 통과하는** 위조 셋:

| # | 무엇 | 왜 지나가나 |
| --- | --- | --- |
| F6 | `__class__` 를 바꿔 `policy_checksum` **프레임 안에서만** 승인값을 돌려주는 property | 값 축이 읽는 자리에서만 정직하다 |
| F7 | `paired_t_threshold` 를 **float 하위 클래스**로 — `repr`·json·`==` 는 2.58, `__neg__` 는 −0.1 | checksum 이 **동일하다**(실측) |
| F8 | 통과 **뒤** 같은 객체를 제자리 변경 | 검사 시점과 사용 시점이 다르다 |

**MXI**(end-to-end) — F7 헬퍼를 `adapters/` 에 두고 조립 근의 정책 인자를 감싸는 **한 줄**:
전 게이트 초록(1732 passed), `verify_policy_source` PASS, **report 의 정책 checksum 이 승인본과
같다** — 산출물이 「무엇으로 판정했는가」를 거짓으로 공시한다(MX1b 보다 한 점 나쁘다: MX1b 는
적어도 다른 version 을 남겼다).

**근원**: 세 축은 객체의 **직렬화**(canonical JSON)를 한 시점에 비교하고, 게이트는 그 값을
**거동**으로 소비한다. 직렬화와 거동을 갈라 놓을 수 있으면 축을 몇 개 더해도 같다 — 그리고
`_run_holdout` 이 재검증의 **반환값을 쓰지 않고** 자기 객체를 다시 넘겨 검사와 사용이 갈려 있었다.

**처방은 축을 더하는 것이 아니라 값의 출처를 바꾸는 것이다**: `verify_policy_source` 가 **로더가
승인 파일에서 다시 만든 정책**을 돌려주고, `_run_holdout` 이 그 반환값을 게이트에 넘긴다.
그러면 F6·F7·F8 이 **한꺼번에** 닫힌다 — 게이트가 보는 객체는 로더가 만든 것이다.
**다만 「어떤 모양이든」은 아니었다**(라운드 5 가 짚었다): 그 재구성의 **입력과 비교 피연산자**가
여전히 호출자 객체에서 왔다 — §9. 실측(MXI 재적용): 조립 근이 주입한 객체는 `-t = -0.1`, 게이트가 쓰는
객체는 `-t = -2.58`(정확히 `float`).

**「조용히 파일 값으로 갈아끼운다」가 아니다**: 갈아끼움은 승인·바이트·값 세 등식이 **성립한
뒤에만** 일어난다. 어긋나면 여전히 fail-closed 이므로 판정 값은 어느 쪽이든 같고, **그 값이
어디서 왔는지**가 고정될 뿐이다. 그래서 「무엇으로 판정했는가」는 흐려지지 않고 더 분명해진다.

### 라운드 4 가 닫지 못한 것 — 정직하게

- **추론 축의 부팅 뒤 바꿔치우기**(MI1, v M-6): 창 값은 지금도 부팅 뒤 바꿀 수 있다(실측: 창 1).
  평가 축과 같게 닫으려면 파이프라인이 추론 정책의 **경로와 지문**을 들고 게이트 자리에서
  재구성해야 하고, `InferencePolicy` 에 출처 칸이 없어 `build_training_pipeline` 시그니처와
  호출자·test 전수가 함께 움직인다 — 이 slice 밖이라 **제한 3i** 로 등재한다. 파일을 고르는
  축은 닫혀 있다(r3).
- **그 코드의 유입**: §0 의 경계 — 리뷰가 자리다(제한 3h).


## 9. 수정 라운드 5 — 안전 성질을 호출자 객체에서 **뗀다**

§8 은 게이트가 쓰는 객체를 로더 출력으로 바꿨다. 그런데 재검증은 여전히 호출자 객체에서 셋을
읽어 **거동으로** 소비했다:

| 무엇을 읽었나 | 어떻게 이겼나 | 결과 |
| --- | --- | --- |
| `source.digest`(비교 피연산자) | 거짓 `__eq__`/`__ne__` 를 가진 `str` 하위 클래스 — 파이썬이 **반사 연산을 먼저** 부르므로 왼쪽이 진짜 `str` 이어도 진다 | N1: 세 축 통과 · 미승인 완화 파일에서 재구성 |
| `source.path`(로더의 입력 객체) | `read_text` 가 완화 텍스트를 주고 그 텍스트의 `encode` 가 승인 바이트를 준다 | N2: 지문은 승인본, 값은 완화본 |
| `source` 자신(property) | 읽을 때마다 다른 값(첫 읽기 승인·이후 완화). **모든 칸이 정확 타입** | N6: 타입 단언으로 닫히지 않는다 |

**뿌리는 하나다**: 안전 성질(「돌려주는 것이 승인본이다」)이 **주장**에만 걸려 있었고, 주장은
호출자 객체가 만든다. 네 라운드의 지적이 전부 이 뿌리의 다른 자리였다 — r3 주장 축, r4 임계
값, r5 재구성의 입력과 비교.

**처방 둘(코드 네 줄)**:
1. 재구성의 **입력**을 `Path()` 로 감싼다 — `PurePath.__init__` 이 `PurePath` 인자에서
   `_raw_paths` 만 가져오므로 그 객체의 `read_text`·`encode` 가 **벗겨진다**(정확
   `PosixPath`). **어느 파일을 읽는지는 아직 호출자가 고를 수 있고**(`__fspath__`·`__str__`
   류) 그것을 막지 않는다 — 그 선택의 결과를 처방 2 가 받는다.
   **앞 판은 `Path(str(...))` 였고 `str()` 을 지웠다**(cr r6 M-1): `str()` 은 정확 타입을
   보장하지 않고(`__str__` 이 `str` 하위 클래스를 돌려줄 수 있다), 오히려 `Path(str(x))` 가
   `__str__` 의 반환을 쓰는 탓에 **파일 선택권을 호출자에게 넘긴다**(`Path(x)` 는 실제 경로를
   쓴다) — 둘 다 실측이고, 그 줄을 지워도 붉어지는 test 가 없었다(변이 GREEN).
2. 세 축 뒤에 **돌려주는 그것**에게 승인을 묻는다 — `reloaded.version`·`reloaded.source.digest`.
   둘 다 로더가 만든 값이라 **그 비교에 호출자가 손댈 자리가 없다**.

앞의 세 축은 **진단**으로 남는다(어느 축이 어긋났는지 문면으로 가른다). 그래서 역할 분담
test(바이트 축의 문면 단언)가 그대로 선다.

**실측**(verifier forge5 그대로): N1·N2·N6 → MISMATCH · F0·F6·F7·F8 **무변화**(t=2.58, gate
False) · N4·N5 거부 유지 · 무편집 사본 통과(음성 대조). **N3**(gc 로 반환 객체를 찾아 손대기)은
**통과한다** — §0 의 경계 밖이고, 그 선을 이 라운드에 문장으로 적었다.

### 이 라운드가 장부에 한 일

cr 의 진단을 받아들여 **범주 주장을 전부 측정 크기로 좁혔다**(§0·§8·모듈 docstring·checklist).
「위조가 어떤 모양이든」·「어떻게 만들거나 비틀든」을 지우고, 측정한 다섯 모양과 그것들이
공유하는 성질(건넨 객체의 거동)로 바꿨다. 네 라운드 연속으로 **장부가 측정보다 한 칸 앞서서**
다음 라운드가 그 칸을 짚었기 때문이다.
