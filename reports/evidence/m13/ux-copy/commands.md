### ② 내부 용어 — 한글 문면 안의 ASCII 낱말·전문 어휘 **17 행**

필터는 「한글이 한 자라도 있는 문자열」 ∧ (ASCII 낱말 3자 이상 ∨ 전문 어휘 목록 적중)이다.
17 행의 처분 후보는 `checklist.md` 의 표가 정본이고, 자리별 소유는 계약 「소유와 공유 파일」로 가른다.
묶음은 넷이다.

- **13A 가 닫는 것 — 여섯 행 · 다섯 자리**: 결과 확인의 영구 빈 자리 둘(①과 같은 자리) · 투찰가 3안
  사유 표의 label·why(「배선」·「커널」) · 알림함 「준비 중」 절(①과 같은 자리) · 시작하기 「준비 중」
  행의 「API」.
- **유지 추천 — 다섯**: 제품 이름 하나 · 「역산」 셋(금액 출처 표 · 결과 빈 자리의 label · 기초금액
  결정 표) · 마감 힌트의 「KST」. 셋 다 운영자가 쓰는 말이고 개발 코드가 아니다.
- **소유가 갈리는 것 — 넷**: 대사 사유 표의 「법인 표기 토큰」 둘(계약의 「`display/*` 의 사유
  문자열」로는 13A 몫이다) · 워크시트 ML 미가용 사유 표의 「스키마」(같은 파일이지만 계약이 13A 의
  몫을 「3안 사유 문면」으로 좁혔다) · 워크시트 근거 절의 「판정 어휘 version」(13C 소유 파일).
- **DOM 에 닿지 않는 것 — 둘**: 부트스트랩의 던지기 문면 · 입찰함의 **도달 불가** 전이 오류 문면.

### ③ 금지 어휘의 유도 가능성 — `capability-map.md`

- OPEN ID **267 종**(`OPEN-[A-Z0-9-]+` 전수 토큰 훑기).
- capability ID 의 접두사는 **§0.6 「축과 ID 접두사」 표**가 아홉을 선언한다(`COL`·`STR`·`QUAL`·
  `ML`·`DEC`·`NOTI`·`SET`·`OPS`·`BID`). **열거가 아니라 그 표에서 유도할 수 있다.**
- **단순 토큰 훑기는 쓸 수 없다**: 그 문서는 리뷰 지적 ID(`M-1`·`L-2`·`H-1`·`P-8`·`Q-11`)와 조사
  노트 행 ID(`A-01`·`B-01`)도 담고, 그 가운데 `D-0`·`D-1` 둘은 **계약이 음성 대조로 지명한 D-day
  문면과 글자가 같다**. 접두사 표로 좁히면 그 충돌이 사라진다.
- `web/` 에 나오는 OPEN ID **31 종** 가운데 map 에 없는 것이 **13**이고, 그 가운데 **넷**이 진짜
  OPEN(전부 주석에만 있다)이며 **아홉**은 하네스 공고번호의 조각이다(아래 ④).

### ④ 계약이 열어 둔 공고번호 처리 — 전제가 하나 깨졌다

계약은 치환을 추천하며 「그 번호를 축어로 쓰는 spec·하네스 코드는 0 이고 두 fixture JSON 에만
있다」고 적었다. **지금은 0 이 아니다** — 13B 가 머지한 터치 타깃 spec 이 그 번호 **둘을 축어로**
쥔다(자기 공고 목록과 워크시트 경로). 즉 치환의 대상은 fixture JSON 둘 + spec 하나다.

또 하나: 그 번호가 **유일한 음성 대조**다(계약의 음성 대조 목록이 이름으로 지명했다). 치환하면 그
대조는 공허해진다 — 상류가 어휘를 바꾸면 음성 대조가 조용히 비는 꼴이고, 저장소가 이미 겪은
축이다. 설계 검토가 이 둘을 함께 든 제안을 올린다.

### ⑤ 라벨 문면이 걸린 자리

자리 표 라벨(머리 글자 포함)을 **축어로** 쥔 자리는 여정 spec **네 파일 · 여덟 자리**의
`getByRole('link', …)` 이고, 그 밖에 주석 셋이 있다. `src/**` 에는 축어 사본이 0 이다(문서 제목은
13B 가 라벨에서 유도한다). 단위 test 에는 라벨 축어 단언이 0 이다.
