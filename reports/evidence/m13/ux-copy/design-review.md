# M13 / ux-copy (13A) — 구현 전 설계 검토

대상은 **문면 게이트**다(계약 「게이트 — 문면 게이트(13A)」). 문면을 바꾸는 일 자체는 게이트가
아니고, 되돌림을 막는 것이 이 게이트다. 실측은 전부 HEAD `faebac30`(= base + evidence 둘)에서 쟀고
보조 스크립트는 레인 scratch 에 있다(산출물이 아니다).

## (0) 위협 모델 — 이 게이트가 막는 것과 막지 않는 것

**막는 것**: 운영자가 보는 글자에 **개발 코드**(OPEN ID · capability ID · 마일스톤/slice 표기 ·
결정 ID · 요구표 행 ID)가 **저장소 코드에서** 들어오는 것. 되돌림(지금 걷은 다섯 자리가 다시
들어오는 것)과 신규(새 문면이 같은 표기를 쓰는 것) 둘 다.

**막지 않는 것** — 세 경계를 먼저 적는다.
1. **서버가 준 값**. 표 밖 값의 코드 노출(「알 수 없는 상태(코드)」)은 배포 비틀림을 보이게 하려는
   기록된 결정이고(착수 판정 6), 정책 version 문자열처럼 서버가 짓는 글자도 이 축 밖이다.
2. **사람이 읽어서만 판정되는 것**. 「사용자 말인가」는 기계가 못 센다. 게이트가 세는 것은
   **개발 코드의 부재**이고, 바꾼 문장이 운영자에게 통하는지는 캡처 묶음과 운영자 검토(완료 조건 5)가 본다.
3. **내부 용어의 어휘 판정**. 「배선」·「커널」·「스키마」가 내부 용어라는 판단은 열거할 수 없다 —
   이 slice 가 고치는 자리는 짝 test 가 **축어로** 잠그고, 일반 축은 열지 않는다(아래 (3) 미달).

## (1) 열거인가 구성인가

계약은 금지 어휘를 「**등록부 ∪ 꼴**」로 적었다. 실측 결과 **등록부를 금지 판정에서 뺄 수 있다** —
꼴이 등록부를 **포함**한다.

- 유도 집합: capability map **§0.6 「축과 ID 접두사」 표**에서 접두사 **아홉**(`COL`·`STR`·`QUAL`·
  `ML`·`DEC`·`NOTI`·`SET`·`OPS`·`BID`), 파일 전수 훑기로 OPEN ID **267 종**, 그 접두사로 집히는
  capability ID **106 종**.
- **포함 단언 실측**: `OPEN 267 / 267` · `capability 106 / 106` 이 아래 꼴 집합에 걸린다(안 걸리는
  것 **0**).

그래서 설계를 이렇게 뒤집는다.

> **금지 판정은 꼴이 한다. 등록부는 「꼴이 실제 ID 를 덮는다」를 증명하는 쪽에만 쓴다.**

이것이 계약 문면보다 **강하다**. 계약의 완전성 단언은 「DOM 에 닿는 ID 가 유도 집합에 드는가」라
유도 집합이 **줄어드는** 우회(§0.6 에서 접두사 한 줄을 지우는 것)에 열려 있다 — 그 순간 금지
집합도 함께 줄기 때문이다. 포함 단언은 방향이 반대다: 접두사를 지우면 유도 집합이 줄고
**포함 단언이 붉는다**(그 집합이 꼴에 덮이는지만 묻기 때문에 꼴은 그대로 선다). 13B 가 남긴
「허용 쪽 기본값으로 세운 술어는 넓히는 것만으로 빠져나간다」(그 slice 알려진 제한 2)의 반대쪽을 택한 것이다.

**단순 토큰 훑기를 쓰지 않는 근거**(착수 판정이 「그대로 적어라」 한 것): 그 문서는 리뷰 지적
ID(`M-1`·`L-2`·`H-1`·`P-8`·`Q-11`)와 조사 노트 행 ID(`A-01`·`B-01`)도 담고, 그 가운데 **`D-0`·`D-1`
둘이 계약이 음성 대조로 지명한 D-day 문면과 글자가 같다**. 훑은 토큰을 그대로 금지 집합에 넣으면
게이트가 마감 배지를 문다. 접두사 표로 좁히면 그 충돌이 사라진다(실측: 음성 후보 전부 걸리지 않음).

### 꼴 집합

| 꼴 | 무엇을 집는가 |
| --- | --- |
| `\b[A-Z]{2,}-\d+\b` | capability ID 와 같은 꼴 **전수**(접두사 목록에 기대지 않는다 — 두 글자 이상 접두 + 번호) |
| `OPEN-[A-Z0-9][A-Z0-9-]*` | OPEN ID |
| `M\d+/` | 마일스톤/slice 표기. **슬래시가 가른다** — 합성 공고번호 `SYN-M9-0` 이 음성 대조다 |
| `\b[DR]-[0-9A-Za-z]+-[0-9A-Za-z]+\b` | 결정 ID. **둘째 하이픈이 가른다** — D-day `D-0`·`D-14` 가 음성 대조다 |
| `R-\d\b` | 요구표 행 ID |

### 모집단 — 두 층, 둘 다 구성

| 층 | 무엇을 보는가 | 모집단이 구성인 근거 |
| --- | --- | --- |
| **층 1 — 소스 AST** | `web/src/**` 전수의 **DOM 에 닿을 수 있는 문자열**(문자열 리터럴 · 템플릿 조각 · JSX 텍스트). 주석 0 · 생성 타입 설명 0 | 디렉터리 **전수 걷기** + AST **위치 술어**(구조 속성과 던지기·`console` 인자를 차감). 파일을 더해도, 새 컴포넌트를 공용 디렉터리에 두어도 든다 |
| **층 2 — 렌더한 DOM** | 카드 전수 + `display/**` 표 전수 + 빈 자리 전수 + 라우트 오류 | 카드는 **기존 기계**(`collectScreenVocabulary` 의 타입 술어) 그대로, 표는 **`display/**` 디렉터리 전수에서 유도한 모듈 집합의 export 반영**, 빈 자리는 **자리 표 전수** |

층 2 가 읽는 것은 **텍스트 노드 단위**다(요소 경계에 구분자). 그리고 `title`·`aria-label` 속성을
함께 읽는다 — 눈에 안 보이는 사유가 거기 산다.

**결합 대조를 실측했다**(계약이 지명한 자리): 「…차이 금액 R」 요소 다음에 음수 차이 금액
「-4,000원」 요소가 오면, `textContent` 이어붙임은 **가짜 `R-4` 를 만들어 붉고**(실측) 텍스트 노드
단위 읽기는 **걸리지 않는다**(실측). 그래서 구분자 삽입이 선택이 아니라 요건이고, 그 사실을
게이트 안의 **합성 대조 쌍**으로 잠근다.

### 층 2 의 열거가 남는 자리와 그 뒤처짐을 받는 자리

층 2 에 「따로 등재」가 둘 남는다 — ⓐ `display/**` 모듈 import 목록(정적·리터럴이어야 한다:
`src` 밖을 import 하면 W-4 가 붉는다) ⓑ 「준비 중」 표 셋 가운데 **알림함 절은 표가 아니라 JSX
리터럴**이라 꺼낼 수 없다. 받는 자리는 셋이다.

1. **층 1 전수** — 열거 밖 자리의 문자열도 소스에는 있다. 층 2 의 열거가 뒤처져도 층 1 이 센다.
2. **디렉터리 등식** — `display/**` 의 모듈 집합 == 층 2 가 import 한 모듈 집합(층 1 이 AST 로 잰다).
   새 표시 모듈이 조용히 빠지지 않는다.
3. **도달 단언** — 이 slice 가 바꾼 문면 전수가 층 2 의 스윕 텍스트에 **실제로 나타난다**. 열거가
   내 자리를 덮는지 기계로 확인한다(비공허: 하나라도 안 나타나면 붉는다).

알림함·시작하기·설정의 「준비 중」 절은 **그 화면을 마운트하는 기존 짝 test**(셋 다 in_scope)가
렌더된 문면을 든다 — 실제 렌더 경로이고 하네스가 이미 있다. 표를 export 로 꺼내 게이트에 넘기는
쪽은 고르지 않았다: 남의 소유 화면(결과 확인)의 private 표까지 export 를 늘리게 되고, 그것은 문면
slice 가 만들 표면이 아니다.

## (2) 우회 — 열하나

전부 **오늘 출하 트리 사용 0**이고, 각 행의 「막는 자리」는 실측했거나 이 slice 가 세운다.

| # | 우회 | 막는 자리 |
| --- | --- | --- |
| 1 | 새 문면을 층 2 의 열거 **밖** 컴포넌트에 둔다 | **층 1 전수**(디렉터리 걷기) |
| 2 | 새 표시 모듈을 만들어 그 안에 둔다 | 층 1 + **디렉터리 등식**((1) 2) |
| 3 | 문자열을 **런타임 조립**한다(`'SET' + '-03'`) | 층 1 은 조각만 본다 → **층 2 가 렌더한 결과**에서 집는다. 단 그 자리가 층 2 모집단에 들 때만 — **열린 축**, (3) 미달 ① |
| 4 | **§0.6 에서 접두사 한 줄을 지운다** | **포함 단언**((1)) — 유도 집합이 줄면 붉는다. 금지 판정은 꼴이라 줄지 않는다 |
| 5 | 넓은 ID 꼴을 피해 **한 글자 접두**로 적는다(`S-03`) | `[A-Z]{2,}-\d+` 밖이다 → **열린 축**. 다만 저장소의 ID 체계에 그런 꼴이 없고(§0.6 전수가 두 글자 이상) 새로 지어야 한다. (3) 미달 ② |
| 6 | **속성으로 숨긴다**(`alt`·`placeholder`) | 계약이 읽는 속성을 `title`·`aria-label` 둘로 고정했다 → **열린 축**, OPEN 후보 ⓑ |
| 7 | **상호작용 뒤에 서는 자리**에 둔다(토스트 · 쓰기 실패 얼굴 · 다른 탭) | 층 1 이 받는다(문자열은 소스에 있다). 3 과 겹치면 열린다 → OPEN 후보 ⓐ |
| 8 | **던지기·`console` 차감**을 악용한다 — 오류 문면에 개발 코드를 적고 그것을 렌더 | 출하 코드에서 오류 원문을 그리는 자리는 **정확히 하나**이고(실측) **이 slice 가 걷는다**. 걷은 뒤 「그려지지 않는다」를 vitest 로 잠근다 → 차감이 그때 성립한다 |
| 9 | **구조 속성 차감**을 악용한다(`className`·`data-*`) | 그 값은 DOM 텍스트가 아니다. 다만 Tailwind 후보 훑기가 `src/` 에 묶이지 않아 **test 의 class 꼴 글자가 출하 CSS 에 실린다**(13B 제한 27) — 이 게이트는 class 꼴 어휘를 쓰지 않고, 그 사실을 커밋 전 확인한다 |
| 10 | 게이트의 **모집단을 비운다**(필터로 0 을 만든다) | **비공허 하한**(층 1 문자열 수 · 층 2 카드·표 행 수)과 **양성 대조**(심은 문면 하나가 붉는다) |
| 11 | 게이트를 **안 돌린다**(`gate-tests.txt` 등재 누락·수집 제외) | W-7 의 양방향 등식(등재됐는데 안 돌면 붉고, 돌았는데 미등재면 붉는다) |

**게이트 술어가 글자인가**: 판정 대상 자체가 글자이므로 정규식이 그 층이다(스타일·구조를 바꾸는
것으로는 피할 수 없다 — 그 글자를 **렌더하지 않는 것**만이 통과다). 글자에 기대면 안 되는 것은
**모집단**이고, 그것을 층 1 은 디렉터리 전수 + AST 위치 술어로, 층 2 는 타입 술어 + 디렉터리 유도로
닫았다.

「경계로 처리」 행도 실측한다. 새 public 표면은 **둘**이다(층 1 판정 모듈의 export, 층 2 test 의
export 0).

| 길 | 실측 | 처분 |

**수정 라운드마다 이 표를 갱신한다.**

## 공고번호 처리 — 제3안(착수 판정 ⑤ 가 판정을 이 자리로 넘겼다)

계약의 선택지는 ⓐ 값 술어(렌더된 공고번호 값 집합을 빼고 센다) ⓑ fixture 어휘 치환이었다.
**둘 다 「면제」를 만드는 장치**다. 제3안은 면제를 만들지 않는다.

> **게이트에 공고번호 면제를 두지 않는다. 게이트가 렌더에 쓰는 fixture 어휘를 금지 집합 밖에서
> 고르고, 그 사실을 단언한다.**

착수 판정이 요구한 셋.

**ⓐ 게이트 모집단에 상류 하네스 fixture 가 들어가는 경로가 0 — 전수 실측.**
`web/src/**` 전수의 import·re-export 선언에서 `e2e/`·`scripts/` 로 가는 상대 경로가 **0 개**다
(AST, `src/**` 전수 — test 파일 포함). 층 1 의 모집단 뿌리는 `web/src` 하나이고 상류 fixture 는
`web/e2e/harness/fixtures/` 에 있어 **다른 트리**다. 층 2 는 `src/**` 안의 vitest 파일이라 같은
경계 안에 있다.

**ⓑ 그 「0」이 깨지면 붉어지는 자리 — 둘, 그 가운데 하나는 이미 선다.**
1. **W-4(`gate:src-tree`)** — TS 프로그램 전수가 `web/src` ∪ `web/node_modules` 안인지 본다. 층 2 가
   상류 fixture 를 import 하면 그 게이트가 붉는다. **이 slice 가 세우는 것이 아니라 오늘 이미 서 있다.**
2. **fixture 어휘 단언**(이 slice 가 세운다) — 층 2 가 렌더에 쓰는 식별자(공고번호·차수 등) 전수가
   금지 집합 밖임을 스윕 **앞에** 단언한다. import 가 아니라 **런타임 읽기**로 상류 값을 끌어오는
   길(W-4 밖)도 이 단언이 받는다. 비공허 짝: 그 식별자 집합이 비지 않고 **적어도 하나가 실제로
   스윕된 텍스트에 나타난다**(집합이 비면 단언이 공허해지는 꼴을 막는다).

   덧붙여 — 제3안에는 **면제가 없으므로**, 상류 번호가 어떻게든 렌더되면 스윕 자신이 그것을
   `OPEN 꼴`로 집어 붉는다(실측: `SYN-M9-OPEN-REBID` → `OPEN 꼴`). 단언은 **더 나은 진단**이고
   마지막 방어선이 아니다.

**ⓒ 계약이 지명한 음성 대조는 합성으로 그대로 남는다.**
| 음성 대조 | 제3안에서 어디에 서나 |
| --- | --- |
| D-day `D-0`·`D-1`·`D-14`·`D+3` | 마감 배지를 **실제 컴포넌트로** 그려 네 값이 다 나오게 하고 초록을 단언(실측: 넷 다 걸리지 않음) |
| 합성 공고번호 `SYN-M9-0` 꼴 | 게이트 자기 fixture 의 번호가 그 꼴이다 — **문장 안에 끼어**(담기 버튼의 `aria-label`) 렌더되고도 초록인 것을 단언 |
| 음수 차이 금액 요소 쌍 | **합성 쌍**(「…R」 + 「-4,000원」)으로 둔다. 이어붙임은 붉고 텍스트 노드 단위는 초록인 것을 같은 자리에서 잰다(실측) |
| `SYN-M9-OPEN-REBID` | **쓰지 않는다.** 계약은 이 이름을 음성 대조로 지명했지만, 그것을 음성 대조로 쓰려면 먼저 면제를 만들어야 한다. 제3안은 면제가 없으므로 이 이름은 **양성** 쪽 예시다(상류 번호가 렌더되면 붉어야 한다) |

**13D 의 새 fixture 항목과의 관계**(팀장 알림 2026-11-18): 제3안은 **어떤 fixture 치환도 제안하지
않는다**. 따라서 `notice-list.json` 의 기존 항목·새 항목 어느 쪽도 이 slice 가 만지지 않고, 그
파일에 거는 유일성·음성 대조 단언도 **두지 않는다**. 13D 의 항목이 머지 순서상 먼저 오든 나중에
오든 이 게이트의 술어는 그 파일을 읽지 않으므로 **영향 0**이다(위 ⓐ 의 「경로 0」이 그 근거다).
13D 의 번호에 `OPEN` 토큰이 없다는 사실도 이 게이트에는 전제가 아니다.

**계약 문면의 전제가 13B 머지로 깨진 사실**(「그 번호를 축어로 쓰는 spec·하네스 코드는 0」 →
터치 타깃 spec 이 둘 쥔다)은 `checklist.md` 에 사실 기록으로 남긴다. 제3안이 채택되면 그 전제는
결정의 입력이 아니게 되지만, 계약 문면이 틀린 채 남는 것은 따로 적어야 한다.

## (3) 과잉과 미달

### 과잉 — 셋

1. **넓은 ID 꼴(`[A-Z]{2,}-\d+`)은 ID 가 아닌 글자도 문다.** 오늘 위양성 0(2191 문자열 실측)이지만
   규격 번호·법령 표기가 그 꼴로 들어오는 날 붉는다. **탈출구를 어디에 둘지는 그때의 결정**이고,
   13B 제한 15 의 교훈대로 면제는 「다른 자리에서 잰다」와 짝이어야 한다 — 알려진 제한에 적는다.
2. **층 1 이 DOM 밖 문자열도 센다.** 구조 속성과 던지기·`console` 만 차감하므로, 화면에 닿지 않는
   문자열이 모집단에 남는다(보수적 방향). 비용은 0 이다(오늘 적중 0).
3. **표 전수를 최소 wrapper 로 렌더한다** — 실제 화면의 요소 구조가 아니다. 요소 경계에 민감한
   축(결합 대조)은 **카드 전수**가 실제 구조로 들기 때문에 이 과잉이 그 축을 약화하지 않는다.

### 미달 — 넷(전부 알려진 제한·OPEN 후보로 등재)

1. **런타임 조립 + 층 2 모집단 밖**의 조합. 층 1 은 조각을 못 보고 층 2 는 그 자리를 안 그린다.
   오늘 조립 0.
2. **한 글자 접두 ID**(`S-03` 꼴). 저장소 ID 체계에 없다(§0.6 전수가 두 글자 이상).
3. **`alt`·`placeholder` 등 계약이 지명하지 않은 텍스트 속성** — OPEN 후보 ⓑ.
4. **상호작용 뒤에 서는 자리** — OPEN 후보 ⓐ. 13B 제한 13 과 같은 축이다.

## 거동 증가 한 건 — 라우트 오류의 「다시 시도」

문면 slice 인데 **컨트롤 하나가 는다**(착수 판정 5 승인). 공유 `Button` 을 쓰고 기존 오류 얼굴과
같은 말로 둔다. vitest 로 「다시 시도가 실제로 재시도(경계 리셋)한다」를 잠그고, 이 화면이 터치
타깃 게이트의 화면 표에 없어 **44px 이 측정되지 않는다**는 사실을 알려진 제한에 적는다(공유
`Button` 의 규칙으로는 서지만 상자로 재지 않는다).
