# M13 / ux-foundation (13B) — 설계 검토 (Phase 2.5, 구현 전)

게이트를 세우는 slice 이므로 구현 전에 쓴다. 입력은 계약 `milestone-13.md` 의 13B 행·「게이트」 절과
`scope.md` §착수 판정(팀장 2026-11-16, 열 건)이다. 착수 실측의 수치와 조건은 `commands.md` 가 정본이다.

## (0) 위협 모델 — 이 게이트가 막는 것과 막지 않는 것

**막는다.** 모바일 폭(390px)에서 **손가락이 닿지 못하는 상호작용 요소가 화면에 서는 것**. 판정은
렌더된 상자 하나로만 한다 — 390×844 뷰포트에서 `getBoundingClientRect().height` ≥ 44px. 「무엇이
상호작용 요소인가」는 이름·`data-testid`·클래스가 아니라 **선택자 전수**(`button` · `a` ·
`[role="tab"]` · `[role="button"]`)가 정한다. 화면이 늘거나 버튼이 늘면 모집단이 **자동으로** 는다.

**막지 않는다(경계 밖, 알려진 제한으로 등재한다).**
- 시각 디자인 품질 자체 — 운영자의 눈이 본다(계약 완료 조건 5의 캡처 묶음).
- **가로폭**. 계약이 높이로 못박았다. 오늘 가장 좁은 탐색 링크가 44px 폭이라 폭 축은 열려 있다.
- 데스크톱 폭의 타깃 크기, 포인터 정확도 모델, 타깃 **사이 간격**(겹침), 대비·낭독 순서.
- 측정 **시점 이후**에 저자가 상자를 바꾸는 코드(스크롤·애니메이션 중간 상태).
- 단일 spec 파일 **안**에서 단언을 지우는 변이. 여정 등록부의 입도가 「파일」이라는 기존 제한을
  그대로 승계한다(`config/journey-specs.txt` 머리 주석).

## (1) 열거인가 구성인가

| 축 | 열거였다면 | 이 판의 구성 |
| --- | --- | --- |
| 무엇이 상호작용 요소인가 | 버튼 이름·testid 목록 | **선택자 전수** + `getComputedStyle` 가시성 |
| 무엇이 보이는가 | `.sr-only` 클래스 이름 술어 | **computed style 의 `clip`·`clip-path`** 로 시각 은폐를 판정(착수 판정 ⓘ). 클래스 글자가 바뀌어도 선다 |
| 어떤 화면을 도는가 | spec 안의 경로 목록 | spec 의 표와 `src/routes.tsx` 의 `screenSlots` 사이 **AST 등식**. 새 화면이 자리 표에 들어오면 spec 이 모르면 **vitest 가 붉는다** |
| 뷰포트가 390 인가 | 설정 파일을 믿는다 | spec 이 `page.viewportSize()` 를 **단언**한다 — 설정이 데스크톱으로 바뀌면 그 자리가 먼저 붉는다 |
| 집합이 비지 않았는가 | 전수 단언만 | **화면별 계수 하한**(착수 판정의 N)을 전수 단언 **앞에** 둔다 |
| spec 이 돌았는가 | 수집에 맡긴다 | `config/journey-specs.txt` 양방향 등식(기존 기계) |
| 버튼의 크기를 누가 정하는가 | 화면마다 유틸리티 클래스 | 공유 `Button` 의 **규칙 표**(어조 셋 × 크기 둘, `Record` 전수) 한 자리 |

**화면 표 등식이 `web/scripts/` 에 서는 이유는 컴파일 경계다.** `web/src` 안의 test 가 `e2e/**` 를
import 하면 W-4 의 「프로그램 전수가 `web/src` ∪ `web/node_modules` 안」이 붉는다. 그래서 등식 test 는
두 파일을 **AST 원문으로 읽는다**(저장소 선례 `mountedCardsOf`) — 문자열 grep 이 아니고, 여정 spec 을
vitest 가 수집하게 만들지도 않는다.

## (2) 우회 — 열 갈래와 그것을 막는 자리

| # | 우회 | 무엇이 막는가 |
| --- | --- | --- |
| 1 | 작은 버튼에 시각 은폐(`sr-only`)를 걸어 모집단에서 뺀다 | 은폐 판정이 computed style 이고, 그 예외로 집합이 줄면 **화면별 계수 하한 N** 이 붉는다. 더해 **건너뛰기 링크는 포커스됐을 때 ≥ 44px** 인지 따로 단언한다(빠진 모집단을 다른 자리에서 잰다 — 착수 판정 ⓘ) |
| 2 | `<div onClick>`·`<span onClick>` 으로 바꿔 선택자 밖으로 나간다 | **AST 게이트 한 축**(아래 「추가 제안」). **수정 라운드 1 에서 술어를 뒤집었다**(verifier H-2) — 이름 열거가 아니라 「내장 태그에 `on[A-Z]` 속성 또는 spread 가 있으면, 허용 집합 밖인 한 위반」이다. 허용 쪽은 HTML 이 정한 것이고 **좁히는(과차단) 방향**이라 저장소가 늘리는 목록이 아니다: 무조건 허용(`button`·`input`·`select`·`textarea`·`summary`) · 조건부(`a` 는 `href` 가 보일 때) · **태그별 짝 이벤트**(`form` 의 `onSubmit`·`onReset` — 폼이 스스로 내는 이벤트라 누르는 자리를 만들지 않고, 누르는 것은 폼 안의 제출 버튼이며 그 버튼은 이미 모집단 안이다. `form` 을 통째로 면제하지 않는 이유는 `<form onClick>` 이 `<div onClick>` 과 같은 우회이기 때문이다 — 팀장 판정 2026-11-16) |
| 3 | 화면을 spec 의 표에서 뺀다 | 화면 표 AST 등식(위 (1)) |
| 4 | 뷰포트를 넓혀 통과시킨다 | spec 안의 `viewportSize()` 단언 |
| 5 | spec 파일 이름을 바꿔 수집에서 뺀다 | `journey-specs.txt` 양방향 등식 |
| 6 | fixture 를 비워 집합이 빈다 | 화면별 계수 하한 N — **전수 단언보다 앞에** 둔다 |
| 7 | `transform: scale(.5)` 로 시각만 줄인다 | **방어된다** — `getBoundingClientRect` 는 변환 **뒤**의 상자를 낸다. 변이로 실측한다 |
| 8 | 바깥 상자만 44px 로 키우고 진짜 타깃은 안쪽 작은 버튼에 둔다 | 안쪽 버튼이 모집단에 들어 **그 버튼이** 붉는다 |
| 9 | 모바일에서 주 행동 버튼 자체를 숨겨 집합을 줄인다 | 화면별 N 하한 + 기존 여정 ②③(그 버튼을 눌러 전이를 민다) |
| 10 | 게이트 spec 안에서 단언만 지운다 | **막지 못한다** — 등록부 입도가 파일이다(경계 밖, 알려진 제한). 리뷰와 `journey-results` 의 「돈 test ≥ 1」이 보는 자리다 |

**양성 대조**(구현 뒤, 커밋 위에서): 화면 하나의 버튼 하나를 **작게 바꿔치운다**(클래스를 더하지
않고 치환한다 — 더하기만 한 변이는 초록이 된다). 그 커밋에서 터치 타깃 spec 이 붉고, 되돌리면
초록인 것을 같은 조건에서 잰다. **음성 대조**: 보이는 버튼에 시각 은폐를 걸면 전수 단언이 아니라
**계수 하한**이 붉는 것을 확인한다(우회 1 의 짝).

## (3) 과잉·미달

**과잉이면 하지 않는다.**
- 터치 타깃을 데스크톱 폭에서도 재는 것 · 폭까지 재는 것(계약은 높이) · 입찰함 탭 여섯을 모두
  눌러 가며 재는 것(계수 하한이 그 자리를 든다).
- 새 UI 의존성·아이콘 세트(승인 경계) · 토큰 추가(`index.css` 편집 0, 착수 판정 ⓗ).
- 「더 보기」를 모달로 만들고 포커스 덫을 두는 것 — 이것은 **disclosure** 다. `aria-expanded` ·
  `aria-controls` · Escape 로 닫고 포커스를 버튼으로 돌리는 것까지다.
- 로그아웃에 확인 단계를 두는 것(되돌림이 로그인 하나이고 흐름 순서 변경은 승인 경계).

**미달이면 구현이 끝난 것이 아니다.**
- 화면별 계수 하한 없이 전수 단언만 두는 것(빈 집합이 초록이 된다).
- 양성·음성 대조 없이 게이트를 초록으로 두는 것.
- 하단 탭이 `md` 미만에서만 서는 것을 **e2e 양 폭**으로 재지 않는 것(jsdom 은 미디어 질의를 풀지
  않으므로 vitest 로는 그 축이 서지 않는다).
- 승인 쌍과 `signOut` 호출이 **다른 커밋**에 서는 것.
- 문서 제목·머리 포커스·복귀 대상 셋을 test 없이 두는 것.
- 공유 `Button`·`Card` 의 짝 test 를 **만드는 커밋에서** `config/gate-tests.txt` 에 등재하지 않는 것.

## 설계 결정 — 구현이 따르는 모양

1. **두 탐색을 함께 렌더하고 CSS 로 가른다.** 상단 줄은 `md` 이상에서만, 하단 탭은 `md` 미만에서만
   선다(`display:none` 으로 숨는 쪽은 접근성 트리에서도 빠진다 — 기존 여정의
   `getByRole('link', …)` 가 둘을 함께 집지 않는 근거다. **가정이 아니라 전건 실행으로 실측한다**).
   미디어 질의를 JS 로 읽지 않으므로 resize 청취자도, 첫 렌더의 불일치도 없다.
2. **하단 탭은 다섯 칸**(A·B·D·E + 「더 보기」). 「더 보기」는 disclosure 이고 그 안에 알림함·설정이
   있다. 현재 자리 표시는 링크에 `aria-current="page"`(NavLink 기본), 「더 보기」 버튼에는 그 안의
   자리가 현재일 때 `aria-current="true"`. 키보드: 버튼 → Enter/Space 로 펼침 → 링크들 → Escape 로
   닫고 포커스가 버튼으로 돌아온다.
3. **로그인 화면에는 탐색을 그리지 않는다**(착수 판정의 N 단서). 안 읽음 배지 질의도 걸지 않는다.
4. **`Button` 과 `LinkButton` 두 내보내기**가 **한 클래스 생성 함수**를 쓴다. 다형 `as` prop 을 두지
   않는다(타입이 흐려지고 리뷰가 어려워진다). 크기 둘은 44px·48px 최소 높이다.
5. **카드 안 본문 링크는 블록 타깃이 된다**(착수 판정 ⓙ). 이동 대상(`href`)과 동작이 0 변경인 것을
   test 로 잠근다. **문장 속 인라인 링크가 나오면 블록화하지 않고 보고한다** — 착수 실측에서 그런
   자리는 0 이었다.
6. **로그아웃 실패는 침묵하지 않는다.** 버튼은 진행 중 비활성이고, 실패하면 `role="alert"` 한 줄이
   선다. 성공해야만 CSRF 를 비우고 로그인 자리로 간다(실패했는데 끝난 것처럼 보이지 않게).

## 열린 자리 — 구현 중 실측해 보고한다

- **게이트 spec 의 자기 fixture.** 하네스 공고 열둘은 모두 다른 여정이 쓴다. 터치 타깃 spec 이
  자기 건을 담으려면 비어 있는 (공고, 종류) 쌍이 필요하고, 그 쌍은 전건 실행으로만 확정된다.
  데이터에 기대는 N 은 **알림함(묶음 둘이 필요)** 과 **E 결과(건 하나가 필요)** 둘뿐이고 나머지
  일곱은 구조로 보장된다(셸 여섯 + 그 화면의 구조적 버튼). 확정한 쌍과 최종 계수를 동결 보고에
  적는다. 하한을 못 맞추면 **N 을 임의로 낮추지 않고 보고한다**.
- **없는 주소 N=5 는 여유가 0 이다**(셸만 서는 자리라 정확히 5). 그대로 두되 동결 보고에 적는다.

## 추가 제안 — 팀장 판정이 필요한 한 건

우회 2(`<div onClick>`)를 닫는 **AST 게이트 한 축**을 더하고 싶다: `src/**` 의 JSX 에서 포인터·키
핸들러를 든 비-상호작용 내장 태그가 0. 착수 실측으로 **오늘 0** 이라 어느 slice 의 오늘 production
도 붉히지 않는다. 다만 이 게이트는 13C·13D·13E 가 앞으로 쓸 수 있는 모양을 **제약한다**(그들은
div 버튼을 만들 수 없다). 계약의 게이트 목록 밖이므로 팀장 판정을 받고 넣는다 — 기각되면 우회 2 를
알려진 제한으로 등재한다.
