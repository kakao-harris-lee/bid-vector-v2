# M13 / ux-case-exits (13D) — 설계 검토: 내려놓기 둘의 출발 집합 게이트

대상은 **착수 판정 OPEN-3** 이 승인한 새 게이트 하나다. 그 게이트의 술어를 구현 전에 검토한다
(`v2-slice-pipeline` Phase 2.5). 범위는 팀장 판정대로 **`DEFER`·`SKIP` 두 명령의 출발 집합**이다.

실측의 정본은 `commands.md` 다 — 이 문서는 수치를 옮겨 적지 않고 결론만 쓴다.

## (0) 위협 모델 경계 — 한 문장

이 게이트는 **전이표(Kotlin 정본)와 화면의 내려놓기 표가 조용히 갈리는 것**을 막는다. 갈림의
증상은 운영자가 「나중에」를 눌렀는데 409 를 보는 것이고, 반대 방향의 증상은 열려 있는 전이가
화면에 아예 없는 것이다.

**막지 않는 것(경계 밖, 의도된 잔여)**

- **의도적 은닉** — 게이트 자신이나 등록부를 고치는 변경. 리뷰 소관이다(저장소의 읽기 층이 같은
  자리에 같은 경계를 둔다).
- **상태가 아닌 사유의 거부** — 주체 불일치·남의 건·경합·공고 스냅샷 부재. 그 거부는 쓰기 실패
  얼굴이 나르고 이 게이트의 축이 아니다.
- **서버가 전이표 밖에서 거부하는 것** — 요청 본문 판정(사유 공백·상한 초과·알 수 없는 키)은
  별도 축이고 아래 우회 ⑨ 가 받는다.
- **Kotlin 꼴이 읽기 집합 밖으로 바뀌는 것**은 막지 않고 **붉힌다**. 조용히 빈 집합을 내는 제3의
  결과를 두지 않는다 — 그것이 이 층의 성질이다.

## (1) 열거인가 구성인가

**구성이 답인 길이 하나 있고, 계약이 그것을 닫아 두었다.** 서버가 건마다 열린 명령 집합을
응답에 실으면(`BidCase` 에 그 칸이 **없다** — 착수 실측) 화면에 표가 필요 없어지고 이 게이트의
질문 자체가 사라진다. 그것은 응답 필드 신설 = **승인 경계**이고 이 마일스톤은 백엔드 변경 0 이다.
그래서 **새 OPEN 후보로 등재**하고(checklist), 지금은 열거를 구조로 닫는 쪽을 택한다.

택한 것은 **「열거 + 구조적 봉합」**이다.

- 화면은 출발 집합을 표(데이터)로 든다 — 분기가 아니다. 상태 축은 `satisfies Record<BidCaseState,…>`
  로 전수가 서고, 계약에 상태가 늘면 그 자리가 컴파일에서 멈춘다.
- 그 표가 **Kotlin 정본과 같은가**를 게이트가 등식으로 잰다. 읽기는 저장소의 **공유 한 자리**를
  거친다(키를 넘기고 추출 함수를 넘기는 꼴 — 원문이 소비자 쪽에 이름으로 남지 않는다).

**추출 자신은 열거가 아니다.** 명령 토큰을 **표를 짓는 호출의 둘째 인자 자리**에서 찾고, 그 호출을
감싼 묶음이 **조립에 드는지**까지 본다. 출발 집합의 꼴은 둘만 읽는다 — 그 자리의 `listOf(…)` 와,
이름으로 가리킨 `listOf(…)` 선언 하나. **그 밖의 꼴은 넓히지 않고 던진다.** 조각을 읽지 못하면
버리지 않는다(버리면 등식이 공허해지고, 이 게이트가 막으려는 것이 바로 「정본이 늘었는데 화면이
안 붉어진다」다).

선례와 같은 규율이다 — 저장소의 교차 언어 어휘 등식이 같은 이유로 「헤더가 하나가 아니면 던진다 ·
열거가 비면 던진다 · 못 읽는 조각을 버리지 않는다」로 닫혀 있다.

## (2) 우회 — 열 갈래

**게이트가 초록인데 운영자가 409 를 보는 길**을 센다. 각 갈래마다 무엇이 막는지 적고, 막는 것이
없으면 그 사실을 적는다.

| # | 우회 | 무엇이 막는가 | 실측 예정 |
| --- | --- | --- | --- |
| ① | Kotlin 이 출발 집합을 **좁히고** 화면 표는 그대로 | 등식 — 붉는다 | 변이: Kotlin 쪽 한 원소 제거 |
| ② | 화면 표가 **넓어지고** Kotlin 은 그대로 | 같은 등식의 반대 방향 | 변이: web 표 한 원소 추가 |
| ③ | 같은 명령의 행 묶음을 **하나 더** 둔다(살아 있는 집합은 넓어지는데 읽기는 한 묶음만 본다) | 읽기가 「행이 N 묶음이다」로 던진다(정확히 하나를 요구한다) | 합성 원문 대조 |
| ④ | 그 묶음을 **조립에서 뺀다**(val 은 남는다 — 서버는 전부 거부하고 화면은 버튼을 계속 보인다) | 감싼 묶음 이름이 조립 식에 드는지 보는 단언 | 합성 원문 대조 |
| ⑤ | **카드가 표를 보지 않고** 버튼을 직접 그린다(표는 맞는데 화면이 안 따른다) | **오늘 막는 것이 없다.** → 카드 test 를 **상태 전수**로 둔다: 상태 14 전부에서 렌더된 내려놓기 버튼 집합 == 표가 내는 집합. 표본 몇 개로는 이 축이 서지 않는다 | vitest(전수 루프) |
| ⑥ | 출발 집합을 읽기가 **다룰 수 없는 꼴**로 적는다(집합 연산·펼치기 등) | 읽기가 던진다 → RED | 합성 원문 대조 |
| ⑦ | Kotlin 의 **상태 이름**이 wire 어휘에서 갈린다(등식이 서로 다른 어휘를 비교하게 된다) | 추출한 출발 상태 **전수가 생성 타입의 상태 유니온에 드는지** 함께 단언한다 — 둘째 Kotlin 읽기 없이 이 축이 닫힌다 | 같은 test |
| ⑧ | Kotlin 이 그 전이를 **시스템 전용**으로 돌린다(상태는 맞는데 주체가 아니다) | **같은 호출의 넷째 인자**를 읽어 「사용자가 든다」를 단언한다(아래 「미달」의 채택 항목) | 합성 원문 대조 |
| ⑨ | 표는 맞는데 **요청 본문**이 틀린다(지역 시각 문자열을 그대로 싣기 · 빈 사유 보내기) | 전이 시각 변환은 저장소의 한 자리를 그대로 쓰고, 빈 값은 **보내지 않고** 무엇이 빠졌는지 말한다(기존 폼 규약). 그 둘을 vitest 가 든다 | vitest |
| ⑩ | 새 게이트 test 가 **수집되지 않는다** | 게이트 test 등록부와 실행 결과의 등식(W-7) — 만드는 커밋에서 등재한다 | 전건 |

**⑤ 가 이 검토의 수확이다.** 등식 게이트는 표가 옳은지만 재고, 화면이 그 표를 따르는지는 재지
않는다. 그 자리를 **상태 전수 루프**로 닫는다 — 「나중에가 관심 카드에 뜬다」류의 표본 단언은 표를
무시한 카드를 통과시킨다.

## (2b) 값 획득 축 — 새 public 표면 전수

새로 생기거나 넓어지는 표면 전수와 **그 값이 어디서 오는가**다. 「경계로 처리」 행도 실측한다.

| 자리 | 표면의 변화 | 값의 출처 |
| --- | --- | --- |
| Kotlin 읽기 공유 모듈 | **비공개** 경로 표에 항목 +1. 공개 표면(읽기 · 키 목록) **불변** — 소유권 게이트가 그 이름 집합을 정확히 둘로 단언한다 | 경로는 그 모듈 밖으로 나가지 않는다. 소비자는 **키**만 안다 |
| 그 소유권 게이트 | 키 계수 단언 7 → 8(팀장 승인). 키별 읽기 루프는 **자동으로** 새 키를 든다 | — |
| 새 게이트 test 파일 | **export 0.** 추출 커널은 모듈 안 함수이고 양성·음성 대조가 합성 Kotlin 조각을 그 커널에 직접 먹인다 | 원문은 공유 읽기가 **넘긴 함수의 매개변수 하나**로만 들어온다 |
| 입찰함 표시 모듈 | 새 export 셋 — 내려놓기 행동 둘의 종류, 출발 집합 표, 조회 함수. 기존 행동 종류 유니온이 둘 넓어진다 | 출발 집합은 **이 표가 정본의 사본**이고 등식이 그것을 묶는다. 상태 축은 생성 타입의 유니온 |
| 질의 모듈 | `deferCase`·`skipCase` 둘 | 요청·응답 모양을 **다시 선언하지 않는다** — 생성 타입의 스키마를 그대로 흘린다 |
| 승인 목록 | 항목 +2. 좁히는 타입이 그 배열에서 유도되므로 목록 밖 호출은 컴파일에서 멈춘다 | 경로·메서드는 생성 타입의 키로 검사된다 |
| **경계로 처리** — 건너뜀의 확인 단계 | 새 표면 **0**. 카드 안 지역 상태다 | 운영자의 두 번째 누름. 종단 전이라 실행 취소 대신 확인이다 |
| **경계로 처리** — 나중에 토스트의 실행 취소 | 새 표면 **0**. 토스트 컴포넌트는 **편집 0**(분기가 이미 선다) | 되돌릴 건의 식별자는 **서버가 준 응답**의 값이다 — 화면이 지어낸 값이 아니다 |
| **경계로 처리** — 빈 얼굴의 다음 걸음 | 새 표면 **0**. 기존 얼굴의 선택 인자를 처음 쓴다 | 이동 대상은 앱 내부 자리 표의 경로 |

커널 주입 자리는 하나다 — 공유 읽기가 걷힌 텍스트를 추출 함수에 먹인다. 추출은 경로를 쥐지 않고
원문을 반환하지도 않는다(읽기의 후조건이 그것을 거부한다).

### 운영자 입력이 요청 본문에 닿는 길 — 두 축을 따로 잰다 (팀장 조건 1)

| 축 | 입력 → 본문 | 실측 |
| --- | --- | --- |
| 리마인드 시각 | 지역 시각 입력칸 → 카드 지역 상태 → 전송 분기에서 **저장소의 변환 한 자리**를 거쳐 ISO → 본문의 시각 칸 | **새 길이 아니다.** 같은 모양의 시각 전이가 이미 둘 있고(개찰 일시 · 서류 기한) 같은 변환 자리를 쓴다. 읽히지 않으면 **보내지 않는다**(기존 규약) |
| 건너뜀 사유 | 자유 텍스트 입력칸 → 카드 지역 상태 → 본문의 사유 칸 | **새 갈래다** — 아래 절 |

### 새 갈래 — 운영자 자유 텍스트가 wire 에 닿고 **남의 파일**에서 DOM 으로 돌아온다

실측 넷.

1. 입찰함 카드의 입력 꼴은 오늘 **넷**(이동·즉시·시각·선택지)이고 **자유 텍스트가 없다**. 사유는
   그 다섯째 꼴이다.
2. `src/**` 전수에서 입력 **길이를 제약하는 속성 사용이 0 이다** — 자유 텍스트 길이를 화면이
   제약한 선례가 없다.
3. 서버는 **비공백 + 상한**을 요구하고 어기면 400 이다. 상한 수는 **계약에 있고 생성 타입에는
   값으로 오지 않는다**(설명 주석에만 있고 칸의 타입은 그냥 문자열이다). 세는 **단위는 같다** —
   정본과 화면이 둘 다 UTF-16 코드 단위로 센다(계약의 다른 칸 하나는 코드포인트로 세는데 이
   칸은 아니다. 그 차이를 실측으로 갈랐다).
4. 그 값은 지울 수 없는 타임라인에 남고, 되돌아와 **13C 소유 파일**(워크시트 타임라인)이
   「사유: …」로 렌더한다 — 내 소유 자리가 아니다.

처분 셋.

- **상한을 화면이 먼저 본다.** 수를 손으로 적지 않고(매직 넘버 금지) 내가 세우는 게이트에서
  **계약 원문의 그 칸과 등식**을 둔다 — web 의 게이트가 그 계약 파일을 읽는 선례가 이미 있다
  (생성 타입 바이트 등식 검사가 같은 파일을 읽는다). 넘으면 **보내지 않고** 말한다.
- **빈·공백 사유는 보내지 않는다** — 서버와 같은 판정을 화면이 먼저 한다(400 을 얼굴로 받는 것은
  운영자에게 무엇이 잘못됐는지 알려 주지 않는다).
- **되돌아오는 렌더는 손대지 않는다**(13C 소유). 다만 **내 여정이 적는 사유 문자열을 개발 어휘
  밖에서** 고른다 — 그 DOM 이 13A 문면 게이트의 모집단에 들 수 있고, 등록된 교훈이 「표본은
  상류 어휘 밖에서」다.

## (3) 과잉과 미달

### 과잉 — 하지 않는다

- **전이 넷(개찰 대기·개찰 기록·적격심사·결과)까지 등식을 넓히는 것.** 팀장 판정으로 범위 밖이고
  새 OPEN 후보로 등재한다. 추출 커널은 명령을 인자로 받으므로 넓히는 일은 뒷날 한 줄이다.
- **도착 집합·부수 산출을 읽는 것.** 두 명령의 도착은 각각 하나이고 화면이 도착을 고르지 않는다.
  읽지 않는다.
- **Kotlin 파서를 짓는 것.** 두 꼴만 읽고 나머지는 던진다.
- **상태 어휘를 위해 Kotlin 을 한 번 더 읽는 것.** 우회 ⑦ 을 생성 타입 유니온 포함 단언으로 닫으므로
  읽기 집합이 더 늘지 않는다.
- **자동 소멸 토스트·낙관 갱신.** 기록된 결정(사용자가 닫는다)과 낙관 갱신 금지를 그대로 둔다.

### 미달 — 받아들이거나 채운다

| 미달 | 처분 |
| --- | --- |
| 주체 축(사용자/시스템)을 안 읽으면 우회 ⑧ 이 열린다 | **채운다.** 같은 호출의 넷째 인자이고 기계가 같다 — 「사용자가 든다」 한 단언 |
| 게이트가 명령 둘만 덮는다 | **받아들인다**(범위 밖 판정) · OPEN 후보 등재 |
| 390px 터치 타깃 게이트가 새 컨트롤을 보지 않는다(그 자리는 종료 묶음을 연다) | **받아들인다** — 알려진 제한. 크기의 정본은 공유 버튼의 크기 표이고 짝 test 가 든다. 캡처에 **제출 전 카드의 390px 얼굴**을 넣는다(팀장 지시) |
| 여정 등록부의 입도가 「파일」이다 | **받아들인다**(13B 승계) |
| 읽기가 **읽은 꼴**만 막는다 — 전이표를 다른 파일로 옮기면 키의 경로가 낡는다 | 그때 읽기가 **던진다**(파일 부재) → RED. 조용한 초록이 아니다 |
| 등식은 「표가 옳다」만 재고 「화면이 표를 따른다」는 ⑤ 의 전수 루프가 든다 | 두 축을 **다른 test** 로 둔다 — 한 파일에 몰면 하나가 사라져도 다른 하나가 돈다 |

## 구현 순서 (RED 선행)

1. 게이트 test 를 **먼저** 세우고 web 표가 없는 상태에서 붉은 것을 본다(등식의 한쪽이 비었다).
2. 표와 화면을 세워 초록으로 만든다.
3. **바꿔치우기 변이 둘**(팀장 지시): Kotlin 쪽 출발 집합 한 원소 **교체** → 붉음 · web 표 한 원소
   **교체** → 붉음. 더하기만 하는 변이는 쓰지 않는다(그 꼴은 초록이 될 수 있다 — 등록된 교훈).
4. 우회 ③④⑥⑧ 은 **합성 Kotlin 조각**으로 커널에 직접 먹여 던지는지 본다(정본 파일을 고치지 않는다).
5. ⑤ 는 상태 전수 루프, ⑨ 는 본문 꼴 vitest.

## 판정 뒤 반영 (팀장 2026-11-18)

- **주체 축 포함 승인** — 변이에 셋째를 더한다: Kotlin 쪽 주체를 **시스템 전용으로 교체** → 붉음.
- **⑤ 루프의 상태 집합은 유도한다** — 손으로 적은 열넷이 아니다. 저장소의 선례 그대로 상태 표시
  표의 키에서 뽑고(그 표가 생성 타입 유니온으로 `satisfies` 돼 있다), **비공허 단언을 루프 앞에**
  둔다. 그 표의 키 집합이 계약 열거와 같은지는 **게이트 쪽에서 독립으로** 잰다(우회 ⑦ 과 같은
  읽기를 쓰므로 축이 하나 더 늘지 않는다) — 그래야 루프의 출처가 자기 자신을 근거로 삼지 않는다.
  카드가 표를 무시하고 버튼을 직접 그리는 **바꿔치우기 변이**로 붉음을 확인한다.
- **⑤ 의 앵커는 testId 다**(13E 알림 2026-11-18). 13E 가 `why` 있는 배지를 **버튼**으로 바꾸므로
  카드 전체 버튼을 집는 locator 는 **배지까지 집는다** — 그러면 이 등식이 거짓이 되거나 집합이
  넓어진 채 통과한다. 내려놓기 버튼마다 고정 testId 를 달고 **그 집합**을 단언하며, 카드 test·여정
  둘 다에서 **버튼 계수를 쓰는 단언을 두지 않는다**(계수는 13E 머지로 움직인다). 배치도 머리 줄의
  커진 배지와 겹치지 않게 primary·secondary 와 **다른 줄**에 둔다. `StateBadge` 는 편집 0(13E 소유).
- **새 OPEN 후보 둘을 checklist 에 등재한다** — ⓐ 응답에 열린 명령 집합 칸이 없다(서버가 실으면 이
  게이트가 불필요해진다) ⓑ 전이 넷까지의 확대. §12.3 등재 여부는 종결 때 팀장이 정한다.
- **ResultCard 편집 0** — 그 카드에 화면 얼굴이 없다(칸 단위 빈 자리·미판정 문면뿐이고 이미 사유를
  든다). 항목 7 의 결과 쪽은 결과 화면의 얼굴 하나로 닫는다. 근거는 checklist 에 적는다.
