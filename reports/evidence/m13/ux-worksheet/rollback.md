# M13 / ux-worksheet (13C) — 되돌리기

**실측 HEAD: `68265d37`**(머지 차례 **수정 라운드의 마지막 산출물 커밋** — 가드 입구 정리 ·
실행 취소 토스트 예외 · 여정 단언 정정 · 그 evidence 까지 담았다. 앞 판들의 실측(`d59c767e` 외
여덟)은 낡았다).
뒤에 오는 커밋은 evidence 뿐이고, 그 처분은 아래 「전칭식」에 있다.

## 되돌리는 방법 — range revert 가 아니라 **경로 한정 복원**

```
git restore --source=a8b0b9e5 --staged --worktree -- \
  web/src/ web/config/ web/e2e/ web/scripts/ \
  web/playwright.config.ts web/package.json \
  docs/discovery/capability-map.md reports/evidence/m13/ux-worksheet/
```

**머지 차례에 원천이 바뀌었다** — 착수 base(`bd5cd039`)가 아니라 **병합한 main 의 고정 SHA**
(`a8b0b9e5`)다. 움직이는 `origin/main` 을 쓰지 않는다. 경로도 하나 늘었다(capability map §12.3).

**셋째 단언 — 복원 대상 blob 이 두 원천에서 같은가**: **여섯이 다르다**(capability map · 게이트
등록부 · 여정 공용 씨앗 · 어휘 장부 · 13D 의 카드 모듈 · 어휘 짝 test). 전부 13D·chore 가 main 에서
움직인 자리다. 그래서 아래 계수와 실측은 **새 원천(`a8b0b9e5`) 기준으로 다시 세었다** — 착수 base
기준의 앞 판 수를 옮기지 않았다. 나머지는 둘 중 하나다: 양쪽 원천에 **없는 신설 파일**이거나
두 원천에서 같은 blob 이다.

원천은 **병합한 main 의 고정 SHA**(`a8b0b9e5`)다 — 머지 차례를 지났으므로 착수 base 가 아니다.
고정 SHA 를 쓰는 이유는 `origin/main` 이 움직이기 때문이고, 그 SHA 에 이 slice 의 산출물이 없다는
것은 아래 표지 계수가 든다(머지 뒤에 되돌릴 일이 생기면 PR revert 가 그 자리다).

밖은 **0** 이다(같은 명령으로 대조했다).

## 전칭식 — 실측 뒤에 움직인 것

실측 HEAD 이후 판정 SHA 까지 **복원 경로 안에서 바뀐 파일은 evidence 뿐**이고, 그 파일들은 전부
**원천(`a8b0b9e5`)에 없는 신설 파일**이다. 그래서 복원이 지울 뿐 되살릴 base 판이 없고, 이 측정은
그대로 유효하다. 열거와 「원천 부재」 확인은 verifier 가 한다.

그 사이에 **병합 커밋은 0** 이다(`git rev-list --merges 68265d37..<판정 SHA>` 가 빈 출력이다 —
main 병합은 실측 HEAD **앞**에 있다).

## 되돌림이 건드리지 않는 것

- `docs/usecase/captures/` — 캡처는 이 slice 가 **커밋하지 않았다**(앞·뒤 묶음은 레인 scratch 에
  있고, 저장소의 캡처는 실행 뒤 트리를 되돌려 손대지 않았다).
- 서버(Kotlin) · OpenAPI · 의존성 — 변경 0 이라 되돌릴 것이 없다.
