### 통제 실측 — 전건 수집의 5초 timeout (v M-4)

같은 트리에서 **이 파일만** 수집에서 빼고 비교했다(파일을 지우면 다른 게이트가 붉어 무효다 —
한 번 그렇게 재고 버렸다).

| 조건 | 결과 |
| --- | --- |
| 게이트 test 포함 | **1/4 붉음**(`kotlin-read-guard` 5000ms) |
| 게이트 test 를 수집에서 제외 | **0/4 붉음** |

원인은 이 test 가 더한 CPU 압력이다. 줄인 것: 원문 캐시 + 앞 프로그램 재사용으로 **47초 → 13초**,
개별 test 최대 **0.7초**(기본 5초 예산 안). 이 파일에만 시간 예산을 뒀다. 더 줄이려면 남의 test
예산이나 전역 pool 설정을 건드려야 해서 **멈추고 보고**한다.
