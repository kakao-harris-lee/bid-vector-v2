# M14 / wf-bidbox-results (14D) — 설계 검토: 「읽기 화면은 쓰기를 부르지 않는다」 게이트

범위는 **이 게이트 하나**다(팀장 판정 ③). 화면 배치·탭·타일은 검토 대상이 아니다.

## (0) 위협 모델 — 경계 문장

**막는 것**: 읽기 화면이 **자기가 그리고 싶은 값을 얻으려고** 쓰기 operation 을 부르는 것.
계약이 든 실례는 결과 확인 화면이 하한율을 얻으려 `POST /api/bid-price-requests` 를 부르는
것이고, 그 호출은 **알림함에 기록을 낳는다** — 운영자가 보기만 했는데 기록이 생긴다.

**적대자**는 바깥의 공격자가 아니라 **다음에 이 코드를 고치는 사람**(나중 라운드의 나를 포함)이다.
그래서 게이트의 값은 「그 사람이 고를 가장 짧은 길이 게이트 자신을 바꾸는 길이 되는가」로 잰다.

**경계 안**: `web/src/**` 의 TS·TSX 모듈이 이루는 import 그래프와, 그 그래프가 닿는
`src/api/queries.ts` 선언이 내는 **(메서드, 경로)** 쌍.

**경계 밖**(이 게이트가 **주장하지 않는** 것, 다른 층이 드는 것):

| 밖에 있는 것 | 누가 드는가 |
| --- | --- |
| `apiClient` 를 지나지 않는 HTTP(전역 `fetch` · 다른 의존 · `index.html` 인라인) | 번들 모듈 그래프 경계(W-9)와 `gate:src-tree`(W-4) |
| 런타임에 **실제로 불렸는가** | 이 축은 정적이다. 닿을 수 있으면 위반으로 센다(과잉 쪽으로 틀린다) |
| 서버가 GET 응답에 그 값을 실어 주는 것 | 서버·OpenAPI 변경이라 계약의 **승인 경계**가 먼저 든다 |

## (0b) 건전성 경계 — 이 게이트가 **닿는 꼴**과 **닿지 않는 꼴**

라운드마다 JS 의미론의 새 빠져나갈 길이 하나씩 나왔다(별칭 재수출 → 모듈 밖 선언 → 적재 때
실행·단축 속성). 그래서 **어디까지가 이 축의 몫인지** 표로 못박는다. 위협 모델은 「다음에 이
코드를 고치는 사람」이므로, **편집자가 무심코 쓸 수 있는 꼴은 전부 닿아야 하고**, 일부러 숨기는
꼴은 경계 밖으로 선언할 수 있다.

### 닿는다 — 꼴마다 대조가 있다

| 꼴 | 대조 |
| --- | --- |
| 이름 그대로 수입해 부른다 | 결과 화면에 쓰기 질의를 심는다 |
| 수입 별칭(`as`) | 별칭으로 수입 |
| 질의 모듈 안의 별칭 재수출 · `export … from` · 기본 내보내기 | 꼴 셋 |
| 질의 모듈 **밖**에 선언된 쓰기를 가져다 재수출 | 꼴 셋(포장 함수 · `export … from` · 표시층 writer) |
| 무해한 모듈을 거친 재수출 세탁 | 다른 모듈을 거쳐 재수출 |
| 네임스페이스 수입(`import * as`) — **`export *` barrel 을 거쳐도** | barrel × 셈한 키 · `Object.values` |
| **리터럴 동적 수입**(`await import('…')`) — 점 접근 · **셈한 키** · barrel 경유 | 셈한 키 · 동적 + barrel |
| 부작용 수입(`import './x'`)의 최상위 호출 | 이름 없이 수입한 모듈 |
| **적재 때 도는 쓰기**(최상위 식·`then` 콜백) | 적재 때 돈다 |
| **단축 속성**(`{ requestBidPrice }`)으로 건너가는 값 | 단축 속성 |
| **적재 때 객체 속성에 꽂기**(`registry.load = …`) | 적재 때 객체 속성 |
| 고차 인자 · 배열 원소 · 클래스 메서드 · `bind` | verifier 실측(라운드 2) |
| `apiClient` 직접 수입 — 별칭·네임스페이스·요소 접근 | 꼴 넷 |
| 비리터럴 경로·메서드, 해소되지 않는 지정자, 가리키는 선언이 없는 수입 이름 | fail-closed 넷 |
| route `element` 의 리터럴 아닌 prop | 그 꼴 |
| `Outlet`·`useOutlet` 의 context — **그대로 · 별칭 · 네임스페이스 접근 · 낱말을 숨긴 재수출** | 꼴 넷 |
| `useOutletContext` 로 **받는** 쪽 | 그 꼴 |

### 닿지 않는다 — 일부러 둔 밖

| 꼴 | 왜 밖인가 | 누가 드는가 |
| --- | --- | --- |
| `eval` · `new Function` · 문자열로 지은 코드 | 정적 축이 원리적으로 볼 수 없다. **무심코 쓰는 꼴이 아니다** — 이 저장소에 0 이고 lint 가 `no-eval` 로 막는다 | lint · code review |
| 셈한 전역 접근(`globalThis[name]`) · `Reflect` · 프로토타입 사슬로 바꿔치기 | 같은 사유. 이름이 런타임에만 정해진다 | code review |
| **공유 가변 모듈 · React context** 로 값 건네기(적재 때가 **아닌** 자리에서) | import 그래프는 **누가 무엇을 수입하는가**를 보는 축이라 런타임에 옮겨 가는 값을 못 본다. 적재 때 꽂는 꼴은 **닿는다**(위 표) | code review |
| `apiClient` 를 지나지 않는 HTTP(전역 `fetch` · 다른 의존 · `index.html`) | 이 축의 경계 밖이다 | 번들 모듈 그래프(W-9) · `gate:src-tree`(W-4) |
| 서버가 GET 응답에 그 값을 실어 주는 것 | 화면의 문제가 아니다 | 승인 경계(서버 변경) |
| 런타임에 **실제로 불렸는가** | 이 축은 정적이다. 닿을 수 있으면 위반으로 센다 | — (과잉 쪽으로 틀리기로 한 선택) |

### 이 표를 어떻게 읽는가 — **꼴이 아니라 의미로 닫는다**

라운드 0~3 은 보고된 **꼴**을 하나씩 닫았고, 그때마다 한 걸음 바깥의 다음 꼴이 나왔다. 라운드
4 는 그 방식을 버리고 **검사기가 이미 세는 집합**을 쓴다:

| 자리 | 쓰는 정의 |
| --- | --- |
| 네임스페이스 · 리터럴 동적 수입 | **`getExportsOfModule` 이 세는 내보내기 집합**. 재수출(`export *`)이 **이미 평탄화**돼 있으므로 barrel 이 몇 겹이든 같다 |
| 별칭 · 재수출 | `getAliasedSymbol` 로 **선언까지** 푼다 |
| 적재 때 실행 | **적재 폐포** — 값 수입으로 닿는 모듈의 적재 때 도는 최상위 문장 |
| 쓰기인가 | **`apiClient` 심볼 동일성 + 메서드**(이름이 아니다) |
| router 주입 | **react-router 내보내기 심볼**(태그·호출 대상 **식 전체**에서 해소) |

**이 표가 정본이다.** 새 꼴이 나오면 먼저 이 표를 고치고, 「닿는다」로 옮길 때는 **그 꼴이 아니라
그 꼴이 속한 의미 집합**으로 닫은 뒤 대조를 함께 세운다.

## (1) 열거인가 구성인가 — 네 축 모두 구성

| 축 | 어떻게 세우는가 | 열거였다면 어디서 낡는가 |
| --- | --- | --- |
| **화면 모집단** | `routes.tsx` 의 자리 표에서 유도한다. 기존 `scripts/journey-screen-table.mjs` 의 `appScreenSlots` 를 **그대로 가져다 쓴다**(그 파일을 고치지 않는다 — 이미 빈 표에서 던진다). 자리의 **모듈**은 그 자리의 `element` JSX 태그 이름 → `routes.tsx` 의 import 선언 → 해소된 경로로 따라간다 | 화면 목록을 손으로 적으면 새 화면이 조용히 의무 밖에 선다 |
| **정책(어느 화면이 읽기 전용인가)** | 이것만은 **선언**이다 — 「읽기 화면인가」는 사람의 판단이고 코드에서 유도되지 않는다. 대신 **집합 등식**을 건다: 정책 표의 키 집합 == 유도한 자리 id 집합. 새 화면은 선언하지 않으면 게이트가 붉는다 | 선언 자체는 피할 수 없다. 피할 수 있는 것은 **빠뜨림**이고 그것을 등식이 막는다 |
| **무엇이 쓰기인가** | **메서드에서 유도한다** — `GET` 이 아닌 모든 메서드가 쓰기다. 메서드 글자는 `queries.ts` 의 AST 에서 온다 | 쓰기 operation 목록을 적으면 새 POST 가 목록 밖이다. 「`requestBidPrice` 금지」 같은 **이름** 술어면 개명 한 번으로 열린다 |
| **도달** | **폐포 둘이 겹친다**(수정 라운드 3 · v H-2r). ⓐ **적재 폐포** — 값 수입으로 닿는 모듈 전수의 **적재 때 도는 최상위 문장**이 씨앗이다 ⓑ **호출 그래프** — 식별자가 가리키는 선언을 **파일 경계를 묻지 않고** 따라간다. 쓰기인지는 **`apiClient` 호출 자리**에서 심볼 동일성과 메서드로 정한다 | 라운드 1 은 질의 모듈을 **닫힌 세계**로 두어 모듈 밖 선언이 지나갔고, 라운드 2 는 선언 단위로 바꾸며 **적재가 곧 실행**이라는 사실을 잃어 적재 때 도는 쓰기가 지나갔다. 두 번 다 「모르는 것이 조용히 통과」하는 같은 갈래였다 |

## (2) 우회 — 열 가지와 각각을 닫는 자리

| # | 우회 | 무엇이 막는가 |
| --- | --- | --- |
| 1 | `import * as q from '../api/queries'` 뒤 `q.requestBidPrice(…)` | 네임스페이스 import 는 **전체 내보내기에 닿는 것**으로 센다(fail-closed). 오늘 그런 자리는 0 이라 즉시 붉는다 |
| 2 | `const m = await import('../api/queries')` | 동적 `import()` 도 간선이다. 지정자가 리터럴이 아니면 **해소 불가 → 위반** |
| 3 | 재수출 세탁 — 무해한 모듈이 `export { requestBidPrice } from '../api/queries'` | `export` 선언도 간선이다. `export * from` 은 전체 도달로 센다 |
| 4 | 별칭 — `import { requestBidPrice as r }` | 간선이 나르는 것은 **내보낸 이름**이지 지역 이름이 아니다 |
| 5 | `queries.ts` 를 건너뛰고 `import { apiClient } from '../api/client'` | **그 바인딩을 수입하는 자리 집합 == `{api/queries.ts}`** 을 짝 test 가 **실제로 센다**(cr HIGH ② — 앞 판은 이 등식을 어디서도 재지 않았다). 고르는 것은 이름이 아니라 **심볼**이라 별칭 수입도 같은 자리에 선다. 모듈을 통째로 가져오는 간선은 「모르는 것」으로 붉는다(v L-1) |
| 6 | `queries.ts` 안에 얇은 포장 — 읽기 이름이 속으로 쓰기 함수를 부른다 | ⓑ 폐포가 **선언 사이 참조**를 따라간다. 포장의 operation 집합에 피포장의 것이 든다 |
| 7 | 정책 표에서 결과 화면 줄을 지운다 | 집합 등식이 그 자리를 **빠진 키**로 붉힌다 |
| 8 | 정책 표에서 결과 화면을 `WRITES` 로 바꾼다 | 짝 test 가 **결과 자리가 `READ_ONLY` 임을 못박는다**(계약이 요구한 바로 그 주장). 입막음에 **파일 둘**을 고쳐야 하고 둘 다 diff 에 남는다 |
| 9 | 모집단을 비운다 — `routes.tsx` 에서 `element` 를 떼거나 프로그램이 빈다 | 비면 **던진다**. 더해서, `element` 없는 자리의 **수**를 짝 test 가 못박아 조용히 늘지 않는다 |
| 10 | 경로를 리터럴로 두지 않는다 — `apiClient[method](path)` | 그 꼴은 operation 을 **모르는 것**이고, 모르는 것은 통과가 아니라 위반이다(`screen-operations` 의 선례와 같은 처방) |
| 11 | **질의 모듈의 별칭 재수출** — `export { requestBidPrice as readFloorHint }` 한 줄 | **앞 판에서 살아 있던 우회였다**(v H-1 · cr HIGH ① — 두 레인이 따로 찾았다). 키가 **TypeChecker 가 센 내보내기 전수**가 되고 별칭이 `getAliasedSymbol` 로 선언까지 풀린다. 꼴 셋(지역 별칭 · 재수출 · 기본 내보내기)을 양성 대조로 심었다 |
| 12 | 질의 모듈이 내보내지 **않는** 이름을 수입한다 | 전수에 없는 이름은 위반이다. 앞 판은 `?? []` 로 operation 0 을 주었고 그것이 11 번을 열어 둔 자리였다 |
| 13 | 자리 표가 쓰기 함수를 **prop 으로** 내려 준다 | 읽기 전용 화면의 route `element` 는 **리터럴이 아닌 prop 을 받지 않는다**(v M-1 의 싼 축) |
| 14 | 셸의 `<Outlet context={…} />` 로 내려 준다 | **그 요소 전수**가 리터럴 아닌 값을 내리지 않는다(v M-1r). 읽기 화면만 보지 않는 까닭: 셸은 화면 모두의 조상이라 한 번 꽂으면 어느 화면이든 받고, 누가 받는지는 이 축에서 알 수 없다 |
| 15 | **질의 모듈 밖에 선언된 쓰기**를 그 모듈이 가져다 재수출한다 | **앞 판에서 살아 있던 우회였다**(v H-1r · 세 꼴 실측 · 별칭조차 필요 없었다). **특별한 경계를 없앴다** — 도달이 한 심볼 그래프이고 `queries.ts` 는 그 위의 한 마디다 |
| 16 | 이름 없이 수입한 모듈(`import './x'`)의 **최상위**에서 부른다 | 그 모듈의 최상위 전수를 민다(식별자 축만으로는 닿지 않는다) |
| 17 | **적재 때 도는 쓰기** — 쓰는 이름을 수입조차 하지 않는다 | **적재 폐포**가 든다(v H-2r 회귀) |
| 18 | **단축 속성**(`{ requestBidPrice }`)으로 값을 건넨다 | 속성 심볼이 아니라 **값 심볼**을 묻는다 |
| 19 | 적재 때 **객체 속성에 꽂고** 그것을 부른다 | 적재 폐포가 그 대입 문장을 씨앗으로 든다 |
| 20 | 리터럴 동적 수입을 **셈한 키**로 읽는다 | `import(리터럴)` 을 네임스페이스로 대접한다 |
| 21 | `Outlet` 을 **별칭**으로 쓰거나 `useOutlet`·`useOutletContext` 를 쓴다 | 철자가 아니라 **심볼**로 고른다(cr HIGH) |

## (2b) 값 획득 축 — 이 slice 가 더하는 public 표면 전수

「그 표면을 지나 결과 화면이 하한율(또는 다른 쓰기 산물)을 얻을 수 있는가」를 표면마다 본다.
**「경계로 처리」 행도 실측한다.**

| 새 표면 | 값을 얻는 길이 되는가 | 실측·근거 |
| --- | --- | --- |
| `screen-write-reach.mjs` 의 순수 술어 내보내기 | **아니다 — 게이트 쪽 코드다.** 다만 좁은 모집단으로 불러 **공허하게** 만들 수는 있다 | 진입점이 유도한 모집단의 **수와 이름**을 단언한다(비공허) |
| 정책 레지스트리 `SCREEN_WRITE_POLICY` | **선언이라 그렇다** — 위 우회 7·8 | 등식 + 결과 자리 못박기 |
| 「전체」 탭 축(화면) | 아니다 — 지역 state 하나이고 질의를 더하지 않는다 | 거르는 자리만 바뀐다. 새 질의 0 |
| 「페이퍼 따로 보기」(화면) | **질의를 더한다** — `listBidCases('PAPER')`. **GET 이고 이미 승인된 쌍**이라 쓰기 축이 움직이지 않는다 | 승인 쌍 등식은 `(메서드, 경로)` 집합을 재고 그 쌍은 이미 등재돼 있다 — 인자만 다르다 |
| 레일 「이번 주 일정」·「상태 뜻」(화면) | 아니다 — 이미 받은 목록과 `nextCheckpointKind` 열거만 읽는다 | 새 질의 0 |
| 타일 ①③ 과 빈 자리 ②④ | 아니다 — ①③ 은 이미 받은 `aggregate`, ②④ 는 **값을 얻지 않는 것**이 처분이다 | 서버가 그 칸을 내지 않는다(계약 「데이터」) |

**수정 라운드마다 이 표를 갱신한다.**

## (3) 과잉인가 미달인가

**과잉(거짓 붉음)이 실재한다.** 도달은 **호출 경로가 아니라 수입 경로**의 과근사다 — 읽기
화면이 닿는 공용 모듈이 쓰기 질의를 수입하면, 그 화면이 부르지 않아도 붉는다.

- **오늘의 기준선 실측**: 결과 화면은 모듈 27 · `queries` 내보내기 8 · operation 4 · **쓰기 0**.
  즉 이 게이트는 **고치는 것이 아니라 래칫**이다(착수 시점에 이미 초록).
- 그 과잉을 **받아들인다**: 거짓 붉음을 푸는 길은 게이트를 넓히는 것이 아니라 **모듈을 가르는
  것**이고, 그 압력이 이 게이트가 주려는 것이다. 다른 화면들은 정책이 `WRITES` 라 영향이 없다
  (실측: 입찰함 쓰기 7 · 워크시트 7 · 홈 10 · 설정 9 · 시작하기 9 · 알림함 2 · 셸 24).

**미달(놓치는 것)은 셋이고 전부 (0) 의 경계 밖이거나 다른 층이 든다.**

| 놓치는 것 | 처분 |
| --- | --- |
| `apiClient` 를 지나지 않는 HTTP | 경계 밖 — W-9·W-4 가 든다 |
| 닿지만 부르지 않는 것 / 부르지 않지만 닿는 것 | **과잉 쪽으로** 틀리기로 한 선택이다 |
| 서버가 GET 에 그 값을 실어 주는 것 | 승인 경계가 먼저 든다(서버 변경) |
| **런타임에 값을 꽂는 길 전반** — 공유 가변 모듈(registry) · **React context** · **router `Outlet` context** 가 같은 갈래다. 쓰기 화면이 값을 넣고 읽기 화면이 `useOutletContext()`·`useContext()`·`registry.load()` 로 꺼낸다 | **경계 밖이다**(v M-1 · M-1r). import 그래프는 **누가 무엇을 수입하는가**를 보는 축이라 런타임에 옮겨 가는 값을 구조적으로 볼 수 없다. **두 꼴은 닫았다** — 자리 표의 route prop((2) 13 번)과 `Outlet` 의 prop((2) 14 번). 나머지(registry · React context)는 **code review 만** 든다. `gate:src-tree` 는 이 갈래를 **들지 않는다**(실측: registry·Outlet 두 꼴 모두 초록 — 꽂히는 값이 `apiClient` 가 아니라 질의 함수라 호출 능력 간선 등식의 대상이 아니다. 앞 판이 이 층을 든다고 적은 것은 틀렸다) |

## 양성·음성 대조

- **양성**: 결과 화면에 `requestBidPrice` 수입 한 줄을 **오버레이로** 심으면 붉다(디스크를
  건드리지 않는다 — `screen-card-coverage.mjs` 의 `screenProgram` 오버레이와 같은 길).
- **음성**: 같은 자리에 **GET 질의** 수입을 심으면 **초록이다**. 이것이 없으면 「수입 한 줄을
  더하면 무엇이든 붉는다」와 구별되지 않는다 — 붉음이 **쓰기 축에서** 왔음을 이 대조가 가른다.
- **공허 대조**: 모집단을 비운 입력에서 게이트가 **던지는지** 본다(조용한 초록 0).

## 수정 라운드 1 이 바꾼 것

- **(1) 축이 「내보낸 이름」에서 「내보낸 심볼」로 내려갔다.** 앞 판의 도달 축 ⓑ 는 구문
  (최상위 선언 이름)에 매여 있었고, 그래서 별칭 한 줄이 그 아래로 빠져나갔다. 이제 키는
  검사기가 센 전수이고 **모르는 이름은 위반**이다 — 모듈 머리말의 약속과 코드가 같은 말을 한다.
- **(2) 우회 5 행의 전제를 실제로 센다.** 설계 검토가 「등식으로 고정한다」고 적었는데 고정하는
  자리가 없었다(cr HIGH ②).
- **(3) 주입이 경계 밖임을 (0) 이 말한다.** 앞 판은 그 축을 적지도 밖에 두지도 않았다.
- **(4) 타입 전용 지정자를 값 간선에서 뺀다.** 이것만으로는 오늘 아무것도 막지 못한다(실측:
  그 필터만 끄면 초록) — 타입 내보내기가 **키에 남아** operation 0 으로 풀리기 때문이다.

## 수정 라운드 2 가 바꾼 것

- **(5) 특별한 경계를 없앴다.** 라운드 1 의 축은 「질의 모듈의 내보내기 → operation」이었고,
  그 모듈이 **닫힌 세계**라는 전제가 H-1r 이었다. 이제 축은 한 심볼 그래프이고 쓰기 판정은
  **호출 자리**에서 난다.
- **(6) 죽은 층을 걷었다.** 라운드 1 의 변이 12·14 가 초록이었던 자리 —
  `operationsByExport` · `isValue` · 타입 전용 걷어내기 · `moduleEdgesOf` — 는 **결정에 닿지
  않았다**. 전부 지웠다. 지운 뒤 **별칭 해소는 살아났다**: 끄면 19개가 붉는다(앞 판은 초록).
  부작용 수입 갈래도 변이가 초록이라 **지우는 대신 양성 대조를 붙여 살렸다**.
## 수정 라운드 3 이 바꾼 것

- **(8) 적재 폐포를 되살렸다.** 라운드 2 의 선언 단위 축은 **모듈 적재가 곧 실행**이라는 사실을
  잃었다. 이제 폐포가 둘이고, 적재 씨앗은 「적재 때 도는 최상위 문장」으로 좁힌다 — 함수 선언과
  초기값이 전부 함수인 변수 선언은 씨앗이 아니다(그것까지 두면 출하 트리가 거짓으로 붉는다).
- **(9) 적재/닿음 집합을 갈랐다.** 한 집합이면 어떤 선언을 먼저 따라가는 순간 적재 씨앗이
  통째로 건너뛰어진다(실측 — 큐가 LIFO 라 실제로 일어났다).
- **(10) 주입 축을 심볼로** 고른다. 철자 술어는 별칭 한 줄로 열렸다.
- **(11) 건전성 경계를 표로 못박았다**((0b)). 라운드마다 새 꼴이 나왔으므로, 닿는 꼴은 대조와
  함께, 닿지 않는 꼴은 사유와 함께 적는다.

## 수정 라운드 4 가 바꾼 것

- **(12) 네임스페이스를 의미로 정의했다.** 「그 모듈의 **문장** 전수」에서 「그 모듈의
  **내보내기** 집합」으로. `export *` barrel 한 줄이 앞 정의를 깨뜨렸다(v H-3r) — 그 문장은
  재수출 하나뿐이고 함수 선언은 적재 씨앗이 아니다. 새 정의는 재수출을 **이미 평탄화**해 준다.
- **(13) router 주입을 식 전체의 심볼로** 본다. 식별자만 보면 `RR.Outlet` 이 지나간다. 좁히기도
  글자(`includes('Outlet')`)에서 **내보내기 집합**으로 바꿨다 — 그 낱말이 남지 않는 꼴이 있다.
- **(14) 한 파일의 시간 예산을 지키려고 대조를 세 파일로 갈랐다.** 셋 다 등록부에 있다.

- **(7) 경계 밖 선언을 고쳤다.** 「공유 가변 모듈」만 이름하던 행을 **런타임 주입 전반**으로
  넓히고(React context · Outlet context 가 같은 갈래다), `gate:src-tree` 가 든다는 **틀린
  귀속을 걷었다**(실측 초록). 그 가운데 두 꼴은 이 라운드가 닫았다.
