# M14 / wf-bidbox-results (14D) — 처분과 알려진 제한

계약 `milestone-14.md` 의 14D 행과 대조표 D·E 행의 처분이다. 수치와 명령은 `commands.md` 가
정본이고 여기 옮겨 적지 않는다.

## 계약 14D 행의 항목별 처분

| 항목 | 처분 | 근거 |
| --- | --- | --- |
| 상태별 개수 탭(REAL) | **정렬 + 표시 계약 변경 하나** | 와이어프레임 여덟 = 「전체」 + 상태 일곱. 「전체」는 **다른 축**으로 세워 상태 → 탭 표의 전수성을 건드리지 않았고, 「투찰 예정」은 D-7E2-8 의 접음을 **뒤집어** 자기 탭을 가진다(팀장 판정) |
| 「페이퍼 따로 보기」 | **정렬** | 계약이 `kind` 를 필수로 받고 두 종류를 한 응답에 내지 않으므로 서버 변경 0. 보는 동안 머리가 그 사실을 말한다 |
| 카드 = 제목 + 상태 알약 / 기관 · 내 투찰 / 다음 확인 | **정렬** | 제목·기관은 14E 투영. 「내 투찰」은 `BidCase` 에 없어 **이미 승인된 읽기**에서 가져왔다(새 operation 0) |
| 레일 「이번 주 일정」 | **정렬 + 이탈 하나(제목)** | 사건 낱말은 `nextCheckpointKind` 표에서만 온다(「참가신청」은 열거 밖이라 그리지 않는다). 제목은 「다음 확인 시점」이다 — 아래 이탈 ① |
| 레일 「상태 뜻」 | **정렬** | 문면이 **상태 표의 `why`** 에서 온다. 보이는 상태의 것만 서고, 뜻 없는 상태는 줄을 만들지 않는다 |
| 결과 타일 ① | **정렬** | 서버의 표본 수 + 그 **정의**. 와이어프레임의 「최근 90일」은 서버가 선언하지 않는 창이라 적지 않는다 |
| 결과 타일 ③ | **정렬(두 축 병기)** | `tileTwoAxis` 로 두 축을 나란히. `beside` 는 「같은 한 값의 일부」라 둘째 축의 자리가 아니다(14A 인계) |
| 결과 타일 ②④ | **데이터로 막힘** | `aggregate` 에 적격 계수가 없고 `MyBidCase` 에 하한 계열 칸이 없다. 숫자 칸을 **아예 갖지 않고** 사유를 든다 |
| 잠정 1위 경고 카드 | **정렬** | 「낙찰이 아니다」는 **상태 표의 `why`**. 그 상태의 건이 없으면 카드 자체가 없다 |
| 결과 카드 | **정렬 + 데이터로 막힘** | 머리를 공고명으로 바꿨다. 실현 하한 · 하한 대비 bp · 「이 금액이면?」 · 「고른 안」은 응답에 칸이 없다 |
| 열린 결정(13A ⓖ) | **닫힘** | 배지 문면을 사유 쪽에 맞췄다. `kind` 는 그대로 — 그 기능 마일스톤이 값을 낼 때 정한다 |
| 새 게이트 | **닫힘** | 네 축이 구성이고 양성 대조 아홉 · **음성 대조** · 공허 대조를 지닌다 |

## 이탈 (이유와 함께)

**① 레일 제목이 「이번 주 일정」이 아니다 — 「다음 확인 시점」이다.**

**사유를 수정 라운드 1 에서 고쳤다**(v M-2). 앞 판은 「벽시계 읽기를 lint 가 막는다」고 적었는데
**사실이 아니다** — 그 규칙은 시계를 막는 것이 아니라 **한 자리로 몰아 준다**(`readClock()` 으로
읽어 `now` 를 내려 준다). 워크시트와 오늘의 공고가 이미 그 꼴이다.

진짜 사유는 둘이다. ⓐ 「이번 주」는 **KST 주 경계를 새로 셈하는 일**이고(어느 요일에 시작하는가 ·
자정 경계 · 주를 넘는 마감) 그 셈은 이 slice 의 범위 밖이다. ⓑ 그렇게 그은 주는 서버의
`overdue` 판정과 **다른 시점**을 볼 수 있다 — 이 저장소는 브라우저 시계로 「지남」을 말했다가
서버 판정과 어긋난 적이 있어 그 말을 서버 값 하나로 좁혔다.

그래서 거르지 않고 **이른 것부터** 늘어놓는다. 낱말은 카드의 같은 칸과 **같은 것**을 쓰고,
「이번 주 일정」은 OPEN 후보로 등재했다.

**② 「전체」의 수가 사이드바 배지와 다르다.** 와이어프레임은 둘을 같게 두지만(그림의 「전체」는
종단을 뺀 수다) 라벨이 「전체」인데 종료를 빼면 거짓말이다. 배지는 **지금 들여다볼 건**을 세고
이 축은 **전부**를 센다. 그 차이를 레일 「상태 뜻」이 한 줄로 말한다(팀장 판정).

## 알려진 제한

| 제한 | 왜 받아들였나 |
| --- | --- |
| **출하 레일의 상자 좌표가 아직 측정되지 않는다** | 배치 게이트의 레일 축은 로그인 화면에서 **합성 마운트**를 재고, 그 spec 이 가는 자리는 한 곳이다. 14D 가 출하 레일을 처음 세웠다 — 그 축을 넓히는 것은 **14B 몫**이다(팀장 판정 ④). **14D 가 먼저 머지되면 그 사이 레일은 미측정**이다 |
| 「내 투찰」이 **둘째 요청**에 달려 있다 | 입찰함이 결과 조회를 함께 읽는다. 실패·적재 중에는 그 자리가 **서지 않는다**(없다고 주장하지 않는다). 한 건에 행이 여럿이면 고르지 않는다 |
| 도달이 **수입 경로의 과근사**다 | 호출 경로가 아니라 수입 경로를 센다. 읽기 화면이 닿는 공용 모듈이 쓰기 질의를 수입하면 부르지 않아도 붉는다 — 푸는 길은 게이트를 넓히는 것이 아니라 모듈을 가르는 것이고, 그 압력이 이 게이트의 목적이다 |
| 게이트가 **`apiClient` 를 지나지 않는 HTTP** 를 보지 않는다 | 경계 밖이고 번들 모듈 그래프 게이트와 `gate:src-tree` 가 든다(`design-review.md` (0)) |
| 정책 표의 「읽기 화면인가」는 **선언**이다 | 코드에서 유도되지 않는 제품 판단이다. 빠뜨림은 집합 등식이 막고, 결과 자리를 `WRITES` 로 돌리는 입막음은 **파일 둘**을 건드리게 된다 |
| **공유 가변 모듈로 꽂는 쓰기는 보지 못한다** | import 그래프 축이 구조적으로 볼 수 없는 자리다(v M-1). `design-review.md` (0) 의 경계 밖 표에 사유와 함께 적었고, code review 와 `gate:src-tree` 의 호출 능력 간선 등식이 든다. 자리 표가 prop 으로 꽂는 쪽은 **닫았다** |
| 게이트 test 가 **병렬 수집에서 비싸다** | 별칭을 선언까지 풀려면 TS 프로그램이 필요하다. 원문 캐시와 앞 프로그램 재사용으로 한 파일 47초 → 13초(개별 test 최대 0.7초)로 줄였고 이 파일에만 시간 예산을 뒀다. **그래도 통제 실측에서 차이가 남는다**: 이 파일을 수집에서 빼면 4/4 초록, 넣으면 1/4 에서 **다른 파일**(`kotlin-read-guard`)이 5초 예산에 밀렸다. 더 줄이려면 남의 test 예산이나 전역 pool 설정을 건드려야 해서 멈췄다 |
| `kotlin-read-guard` 가 전건 수집에서 가끔 붉는다 | **앞 판의 「base 에도 있는 것」은 측정으로 뒷받침되지 않았다**(v M-4: base 0/10 · head 2/10). 수정 라운드 1 의 통제 실측은 위 행에 적었다 — 원인은 이 slice 의 test 가 더한 CPU 압력이고, 그 test 자신은 예산 안이다(최대 0.7초) |
| 「전체」 탭이 **고르기 상태를 URL 에 쓰지 않는다** | 앞 판과 같다 — URL 은 **초기값**으로만 읽는다. 운영자가 고른 탭을 URL 이 되돌리지 않게 하려는 기존 설계다 |

## 되돌리는 법 (비활성화)

- 표시 계약의 두 변경은 `display/bidBoxDisplay.ts` 한 파일에서 되돌린다 — `BID_PLANNED` 의
  탭 값과 `ALL_SELECTION` 축이다. 짝 test 가 같은 커밋에 있어 되돌림이 조용하지 않다.
- 새 게이트는 `scripts/screen-write-reach.*` 를 걷으면 꺼진다. `config/gate-tests.txt` 의 한
  줄은 **다른 일을 한다**(v L-3): 그 줄만 지우면 W-7 이 더 이상 이 test 를 **단언하지 않을 뿐**
  이고, test 자체는 W-6 에서 계속 돈다(그때 `gate:tests` 는 exit 0 이다 — 실측). 그 줄이 짐을
  지는 자리는 **수집에서 빠질 때**다: 변이 2 가 그것을 쟀다(수집 제외 → `gate:tests` exit 1).
- 화면 배치 전체는 `rollback.md` 의 경로 한정 복원으로 base 로 돌아간다.
