# M14 / wf-shell (14A) — 처분과 알려진 제한

계약 `milestone-14.md` 의 14A 행과 대조표가 요구한 다섯(①~⑤)의 처분이다. 수치와 명령은
`commands.md` 가 정본이고 여기 옮겨 적지 않는다.

## 계약 ①~⑤ 의 처분

| 항목 | 처분 | 근거 |
| --- | --- | --- |
| ① 토큰을 캔버스 팔레트로(`index.css` 한 자리 · 어조 다섯은 값만 · 다크 쌍) | **정렬** | 토큰의 이름과 역할이 그대로라 컴포넌트는 교체를 모른다. 라이트·다크 쌍 전수가 기준을 넘는 것을 대비 게이트가 **그 파일을 파싱해** 잰다 |
| ② md 이상 왼쪽 사이드바(항목 여섯 · 배지 둘 · 사업자명) | **정렬 + 계약의 이탈 하나** | 같은 자리 집합이 md 미만에서 하단 탭 다섯 칸으로 남는다(13B 그대로). 배지 둘 모두 **새 operation 0** |
| ③ 배치 원시 요소(`PageHeader`·`TwoColumn`·`SummaryTile`·`StatusPill`·`KeyValueRow`) | **다섯 정렬** | 넷을 새로 세우고, `KeyValueRow` 는 **이미 있던 `Field`** 를 팀장 판정(소유 예외)으로 제 모듈·제 이름으로 옮겼다(거동 0 · `tsc` 가 전수를 잡는다). 짝 test 다섯을 등재했다 |
| ④ 부재값 어휘 한 자리 | **닫힘(측정)** | 좁힌 전수 **34 → 0**. 부재가 사유를 지닌 값이고 얼굴이 하나다. **「아직 모른다」가 「없다」와 다른 값**으로 남는 것을 알림함 배지의 양방향 단언이 잰다 |
| ⑤ 공유 컴포넌트를 게이트 모집단·짝 test 에 등재 | **닫힘** | 새 test 일곱을 만드는 커밋에서 등록부에 적었다. 새 표시 모듈이 어휘 게이트 모집단 둘에 들어갔다 |
| M13 잔여 ⓑ 배지 버튼의 가로 축 | **닫힘** | 터치 게이트가 **두 변**을 함께 센다. 출하 아홉 화면 전수가 통과했다 |
| M13 잔여 ⓖ 용어 힌트의 터치 경로 | **닫힘** | 용어 라벨이 누를 수 있는 자리가 됐고 문면의 노드는 하나다. 툴팁 속성은 걷었다 |

## 대조표 행의 처분

| 행 | 처분 |
| --- | --- |
| 공통 셸 | **정렬 + 이탈 하나**(항목 여섯 — 시작하기를 빼지 않는다) |
| 배치 | **원시 요소만 정렬** — 각 화면 적용은 14B·14C·14D |

## 알려진 제한

1. **~~선이 와이어프레임보다 진하다~~ — 해소됐다**(팀장 판정 2026-11-20). 선을 **역할로 갈랐다**:
   카드 테두리와 가름선은 와이어프레임 값 그대로이고 **대비 측정 밖**이며, 컨트롤의 경계만 3:1
   로 잰다. WCAG 1.4.11 의 3:1 은 **UI 컴포넌트의 경계**에 걸리는 기준이지 내용을 **묶는** 카드의
   테두리에 걸리는 기준이 아니다. 카드는 이제 와이어프레임과 같은 테두리를 쓴다.
   남는 축은 **면 차이**다 — 카드와 바탕이 같은 값으로 접히면 카드가 바탕에 녹으므로 그 차이를
   래칫으로 센다(접근성 기준을 흉내 내는 것이 아니다).
2. **사이드바의 선택 어조는 새 쌍이다**(`selected`). 상태 어조 다섯과 다른 축이라 `DisplayTone`
   은 그대로 다섯이다. 와이어프레임의 청록 옅은 면을 그 쌍이 든다.
3. **레일을 쓰는 출하 화면이 없다.** 배치 게이트의 레일 축은 합성 마운트로 선다(같은 문서 ·
   출하 CSS · 출하 클래스). 출하 화면의 레일은 **표지 전수**라 뒤 레인이 붙이면 자동으로 든다.
4. **두 단을 컴포넌트 없이 손으로 짜면** 레일 축이 보지 못한다. AST 로 금지하지 않는 쪽을
   골랐다(오늘 위반 0 · 금지하면 레이아웃 두 줄마다 게이트를 설득해야 한다). 드러나는 자리는
   운영자 시각 검토와 각 화면 PR 의 앞·뒤 캡처다.
5. **부재 어휘가 알림 메시지(Kotlin)와 갈린다.** 같은 사실을 화면은 새 사유 문면으로, 알림
   본문은 옛 문면으로 말한다. 교차 언어 등식이 없어 어느 게이트도 이것을 붉히지 않는다.
   그 모듈은 14A·14E 어느 범위에도 없다 → 아래 OPEN ②.
6. **대비 게이트는 줄 머리 선언만 읽는다.** 여러 줄 주석 **안**의 줄 머리 선언은 읽힌다. 그때의
   실패 모양은 **시끄러운 거짓 빨강**(살아 있지 않은 값을 재서 붉는다)이라 조용한 통과가 아니다.
7. **대비 게이트는 토큰 값을 재고 컴포넌트의 고름을 재지 않는다.** 어느 어조를 쓰는지는 짝
   test 의 축(`satisfies` 전수)이다.
8. **배치 게이트의 가로 넘침 축은 보이는 요소의 상자로 잰다.** `visibility:hidden`·`display:none`
   만 빼므로, 0×0 이 아닌 투명 요소는 모집단에 든다(거짓 양성 쪽으로 기운다).
9. **컨트롤 경계는 두 층이 함께 지키고, 둘의 사각이 서로 다르다**(수정 라운드 2).
   - **AST 축**은 소스 **전수**를 보지만 className **리터럴**만 본다 — 상수·헬퍼로 돌리면 못 본다.
   - **그려진 색 축**은 출처를 가리지 않지만 **렌더되는 것만** 본다 — 여정 fixture 가 띄우지 않는
     컨트롤은 그 눈 밖이다(실측: 워크시트의 한 입력칸에 심은 변이가 두 축 **모두** 초록이었다).
   어느 하나도 다른 하나를 대신하지 않는다. 같은 꼴의 새 공유 컨트롤이 생기면 둘 다 본다.
10. **공유 버튼의 어조 표는 값으로 잰다.** AST 축은 JSX 의 className **리터럴**을 보는데 그
   컴포넌트는 className 이 식이라 리터럴이 요소에 붙어 있지 않다 — 표를 되돌리는 변이가 그 축을
   그대로 지나갔다(실측). 그래서 어조 표를 **값으로** 재는 축을 짝 test 에 따로 두었다. 같은
   꼴의 새 공유 컨트롤이 생기면 그 축을 함께 세워야 한다.
11. **`danger` 어조의 테두리는 중립 컨트롤 토큰이 아니다.** 그 색은 경계가 아니라 **그 버튼이
   무엇인지**를 말한다. 그래서 「컨트롤 토큰이거나 **어조 자신의 색**」으로 재고, 어조 이름과
   토큰 이름이 1:1 이 아니라(`danger` 의 색은 `bad`) 이름이 아니라 **토큰의 꼴**로 본다.
12. **캡처는 커밋하지 않는다.** 앞·뒤 비교는 scratchpad 에 두고 트리는 되돌렸다. 「앞」은 base
   에 커밋돼 있던 캡처이고, `web/` 이 M13 종결 main 과 base 사이에서 **무편집**이라 그 캡처가
   base 의 화면과 같은 트리에서 떴다(기계로 확인).

13. **부재 어휘의 렌더 층은 fixture 에 매인다** — 거기 마운트한 자리만 본다. 손으로 적은
   리터럴을 넓게 받는 것은 소스 훑기 쪽이고 둘은 서로를 대신하지 않는다.
14. **사이드바의 선택 면이 바탕과 1.05:1**(cr L-3). 접근성 실패는 아니다 — `aria-current` 와
   글자 굵기·색이 함께 말하고 그 쌍은 6.67:1 이다. 다만 **면 차이 축의 모집단 밖**이라 그 면이
   거의 보이지 않아도 아무 게이트도 말하지 않는다. 운영자 시각 검토가 판정할 자리로 적는다.
15. **`PageHeader.summary` 는 `string` 이다**(cr L-4). 14B 의 상한 초과 공시를 요약 **줄 안에**
   끼우려면 `actions` 로 돌리거나 원시 요소를 비켜 가야 한다 — 14B 착수 전에 맞춰 볼 자리다.
16. **`SummaryTile.beside` 는 둘째 축을 담는 칸이 아니다**(cr L-4). 14D 의 낙찰 타일은 두 축
   병기를 지켜야 하고 계약이 「타일 하나에 한 축만」을 금지한다 — `note` 에 싣거나 14D 가 두 축
   전용 얼굴을 더하는 쪽이 맞다.
17. **워크시트 기초금액의 빈 괄호**(cr L-5) — `provenance` 가 없으면 `1,234,000 ()` 이 된다.
   base 에서 같고 14A 가 만든 결함이 아니며 배치·문면 소유는 14C 다.
