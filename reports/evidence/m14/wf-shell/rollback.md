# M14 / wf-shell (14A) — rollback

**실측 HEAD: `ff96a37f5a646d8f220013d94c8a0e90efec55a4`**(이 slice 의 **마지막 산출물 커밋**).
뒤에 오는 evidence 커밋은 아래 복원 목록 안의 경로를 건드리지 않는다 — 그 사실은 verifier 가
`git diff --name-only <실측 HEAD>..<판정 SHA> -- <복원 경로들>` 로 확인한다.

## 되돌리는 방법

range revert 가 아니라 **in_scope 경로 한정 복원**이다. 목록은 기계 산출이고 라운드마다 다시
뽑는다 — 손으로 적은 목록은 뒤 라운드가 만든 파일을 빠뜨린다.

```
git diff --name-status f6fc06d1061c79bde4b5ba0a18650bec8f17bd20..<판정 SHA> \
  | awk '{print $2}' | sort > /tmp/14a-restore.txt
xargs -a /tmp/14a-restore.txt \
  git restore --source=f6fc06d1061c79bde4b5ba0a18650bec8f17bd20 --staged --worktree --
```

## 복원 원천

**머지된 main 커밋 `f6fc06d1061c79bde4b5ba0a18650bec8f17bd20` 하나다**(고정 SHA — 움직이는
`origin/main` 을 쓰지 않는다). 착수 base 가 아니다: 14E(PR #178)가 먼저 머지돼 이 레인이 그
위로 병합했고, 겹치는 파일에는 **14E 의 내용이 들어 있다**. base 에서 복원하면 그것까지 지운다.

**셋째 단언**(복원 원천을 바꿨으므로 잰다) — 복원 대상 blob 이 두 원천에서 다른가.
복원 목록 **73** 가운데 두 원천에 **모두 있는 것이 45**, 둘 다 없는 신설이 **28**, 한쪽에만
있는 것은 **0** 이다. 그 45 가운데 blob 이 다른 것은 **넷**이고 전부 14E 가 칸을 더한 web
fixture 다. 14E 가 건드린 fixture 는 일곱인데 그 가운데 **셋은 이 목록에 없다** — 머지 뒤 내가
건드리지 않아 원천과 같기 때문이다(내 것이 아니므로 되돌릴 것도 없다).

**공유 파일**: `docs/discovery/capability-map.md` 를 머지 차례에 §12.3 (z) 로 건드린다. 그
복원도 같은 원천에서 이뤄지고, 아래 계수가 「내 절은 사라지고 남의 절은 남는다」를 센다.

**전칭식** — 실측 HEAD 와 판정 SHA 사이에서 복원 대상 경로가 움직였다면, 움직인 경로는 전부
**원천(`f6fc06d1`)에 없는 신설 파일**이다. 열거와 원천 부재 확인은 verifier 가 한다.
