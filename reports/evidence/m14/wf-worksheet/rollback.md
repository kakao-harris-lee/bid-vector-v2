# M14 / wf-worksheet (14C) — rollback

**실측 HEAD: `3037d5602a1f18f0b217f03fb18d4a37aa5b1bbc`** — 이 slice 의 **마지막 산출물 커밋**
(머지 차례의 evidence 갱신을 담은 커밋)이다. 이 파일을 담는 커밋은 그보다 뒤에 오므로 실측 HEAD 와 판정 SHA 는
언제나 다르다. verifier 가 보는 것은 그 둘의 같음이 아니라 **그 사이에 되돌림 대상이 움직였는가**다.

**전칭식** — 실측 HEAD 와 판정 SHA 사이에서 복원 대상 경로가 움직였다면, 움직인 경로는 전부
**원천(`056f405c`)에 없는 신설 파일**이다(이 `rollback.md` 가 그런 파일이다). 열거와 원천 부재
확인은 verifier 가 한다.

## 되돌리는 방법

range revert 가 아니라 **in_scope 경로 한정 복원**이다. 목록은 기계 산출이고 라운드마다 다시
뽑는다 — 손으로 적은 목록은 뒤 라운드가 만든 파일을 빠뜨린다.

```
git diff --name-status 056f405c9e5659b9a068288f1104f9e04a6de016..<판정 SHA> \
  | awk '{print $2}' | sort > /tmp/14c-restore.txt
xargs -a /tmp/14c-restore.txt \
  git restore --source=056f405c9e5659b9a068288f1104f9e04a6de016 --staged --worktree --
```

## 복원 원천

**착수 base `056f405c9e5659b9a068288f1104f9e04a6de016` 하나다**(고정 SHA — 움직이는 `origin/main`
을 쓰지 않는다). 이 레인은 머지 전이고 **다른 slice 를 병합하지 않았으므로** 원천을 바꿀 사유가
없다. 원천을 바꾸지 않았으니 **셋째 단언은 해당 없음**이다(그 단언은 복원 원천을 바꿀 때 잰다).

**머지 차례에도 원천은 그대로다**: `git fetch` 뒤 `origin/main` 이 착수 base 와 **같은 커밋**
이었다(다른 세 레인 가운데 머지한 것이 없다). 그래서 병합하지 않았고 **셋째 단언은 해당
없음**이다. 지도의 §12.3 **(aa)** 는 이 목록 안에 있고, 위 ②' 가 「내 절 0 · 남의 절 보존」을
앞뒤로 센다.
