# M14 / wf-worksheet (14C) — 처분과 잔여

대조표 C 행의 칸마다 **정렬됨 · 데이터로 막힘 · 범위 밖 · 이탈** 가운데 하나로 닫는다.
수치와 명령은 `commands.md` 가 정본이고 여기 옮겨 적지 않는다.

## 대조표 C 행의 처분

| 와이어프레임이 말한 것 | 처분 | 근거 |
| --- | --- | --- |
| 머리 블록 — 상태 알약 · 공고번호 · 제목 | **정렬됨** | 알약 둘(공고 상태 · 건 상태) + 공고번호 · 차수 + 제목 + 발주기관 |
| 머리 블록 — 방식 | **데이터로 막힘** | `NoticeSummary` 에 낙찰 방식 칸이 없다. **자리를 만들지 않는다** — 서버가 가진 적 없는 칸을 부재 값으로 그리면 「이번 답에 빠졌다」로 읽힌다(팀장 판정 ③) |
| 머리 블록 — 기초금액 | **정렬됨** | 용어 줄 하나로 남는다. 아래층 문면의 터치 경로가 거기 걸려 있다 |
| 마감 카운트다운 | **정렬됨(단위는 이탈)** | 자리는 머리 행 오른쪽. **분·시 단위는 이탈** — 아래 OPEN ① |
| 참가 자격 — 판정 + 미판정 축 + 근거 | **정렬됨(두 칸 이탈)** | 본문 첫 카드. **「n/n」은 이탈**(분모를 선언한 표면이 없다 — 계약이 미리 판정). **「근거 원문」도 이탈**: 응답에 공고 원문이 없어 「요건이 온 필드」가 그 자리를 받는다 |
| 다음 확인 시점 | **정렬됨** | 레일의 첫 카드 |
| 타임라인 | **정렬됨** | 레일의 둘째 카드 |
| 본문 차례 — 투찰가 → 「이 금액으로 진행」 → 나라장터 넘김 → 「투찰했나요?」 | **정렬됨** | 그 차례를 문서 순서로 잠갔다 |
| 투찰가 3안의 금액 · 적격 확률 · 기대 승률 | **범위 밖** | `OPEN-ML-ANALYSIS-WIRING` 보류 — 자리와 사유만 선다(계약 「범위 밖」) |
| 「나중에 · 건너뜀」 | **정렬됨** | 레일의 맨 아래 |
| 머리 행이 **카드다** | **이탈** | 원천의 머리 행은 카드가 아니다(맨 글자 + 오른쪽 카드 하나). 구현은 머리 전체를 카드로 감싸고 카운트다운을 그 안의 중첩 카드로 둔다 — 셸의 카드 문법을 모든 화면이 같은 꼴로 쓰기 때문이고, 정보 구조는 원천과 같다 |
| 「투찰했나요?」 카드가 **입력 폼이다** | **이탈** | 원천의 그 카드는 낸 금액 · 제출 시각 · 추첨번호 · 제출확인서 입력을 든다. 구현의 입력은 **투찰가 카드 하나**에 산다 — 초안과 기록이 같은 입력을 쓰는 13C 설계이고, 그것을 둘로 가르면 거동이 바뀐다(계약 「옮기기만」 위반). 기록 카드는 안내 + 행동이다 |
| 카운트다운의 둘째 줄 「… · 개찰 15:00」 | **데이터로 막힘** | `NoticeSummary` 에 개찰 시각 칸이 없다(생성 타입 실측) |
| 옛 「필드명 / 빈 칸」 격자 | **정렬됨** | 다섯 줄 가운데 기초금액 하나만 용어 줄로 남고, 나머지 넷의 사실은 알약 · 제목 곁 · 카운트다운 카드 · 레일이 각자 더 가까운 자리에서 말한다 |

## 13C 기능의 「옮기기만」 (거동 0)

복사 · 한글 병기 · 하한 대비 여유 · 보내기 전 확인 · 다섯 절의 접기 — **주장을 하나도 고치지
않았다.** 그 측정은 기존 단언이 무편집으로 통과하는 것이다(`commands.md` 의 W-6 · W-13).

접기 다섯은 자격 절이 묶음 밖으로 나간 뒤에도 그대로다 — 그 test 가 절을 **전역 표지**로 집고
`details` · 요약 · 공용 클래스를 보기 때문이다. 자격이 사라진 것이 아니라 **자리를 옮겼다.**

## 알려진 제한

1. **14B 머지 전 레일 상자 미측정.** 배치 게이트의 레일 축은 14A 의 **합성 마운트**이고, 그
   spec 은 `/` 한 자리만 연다 — 그 레인에 백엔드가 없어 워크시트는 오류 얼굴로 선다. 출하
   워크시트의 레일이 **상자 좌표로** 본문 오른쪽에 서는지는 14B 가 레일 모집단을 넓힐 때
   측정된다(팀장 판정 ④). 이 레인이 잠근 것은 **문서 순서**다: 두 칸의 소속과 차례, 그리고
   칸 밖에 서야 하는 것(카운트다운)이 칸 밖에 있다는 것.
2. **390px 의 머리 줄바꿈이 게이트에 들지 않는다**(v L-1). 카운트다운 카드가 제목을 한 글자씩
   꺾던 것을 캡처로 보고 고쳤는데, 그 수정을 되돌린 변이가 vitest · 여정 e2e(터치 · 가로 넘침
   포함)를 모두 지난다 — **꺾임은 넘침이 아니다.** 그 축을 재려면 390px 에서 제목 상자의 폭을
   실브라우저로 읽어야 하고, 그것은 **출하 레일의 상자 축과 같은 자리**(아래 OPEN ⓓ · 14B 소유)
   다. 이 레인은 그 spec 을 건드리지 않는다(팀장 판정 ④). 그래서 **잠그지 않고 적는다.**
3. **390px 의 접힌 절은 여전히 상자로 재지 않는다**(13C 의 알려진 제한 그대로). 그 fixture 가
   절을 펼치지 않는다.
4. **투찰가 카드는 요청 전에도 선다.** 그 안에 금액 입력이 있고 그것이 이 화면의 축이기
   때문이다. 와이어프레임의 3안 자리는 값이 없어 그릴 수 없다(범위 밖).
5. **기록 카드는 전이가 남아 있을 때만 선다**(cr L-1 로 좁혔다). 초안 금액을 되읽는 칸이 `BidCase` 에
   없어(13C 의 알려진 제한) 「초안 채워짐」을 말할 근거가 없다 — 카드는 무엇을 할 자리인지만
   말한다.

## 새 OPEN 후보 (§12.3 에 등재 — 글자는 머지 차례)

| 후보 | 무엇이 열려 있나 |
| --- | --- |
| ⓐ 마감 카운트다운이 **날 단위**다 | 와이어프레임은 「1일 22시간 10분」이다. 표시층이 내는 것은 날 단위 하나이고, 그 모듈은 14A 소유다. 더 나아가 이 화면은 벽시계를 **한 번만 읽으므로**(M9 D-1) 분 단위 글자는 열려 있는 동안 조용히 낡는다 — 새 표시 축과 **틱 소스**가 함께 필요하다 |
| ⓑ 머리의 **「방식」을 내는 표면이 없다** | 낙찰 방식(적격심사 · 복수예가)은 공고 요약에 칸이 없다. 서버 변경이 필요한 자리다 |
| ⓒ 자격의 **「근거 원문」**이 없다 | 응답은 요건이 온 **필드 이름**만 낸다. 공고 원문 조각을 내는 표면은 계약에 없다 |
| ⓓ 출하 레일의 **상자 축**이 14B 에 달려 있다 | 위 알려진 제한 1 |
| ⓔ 13D 쪽 「재시도 가드」 잔여는 **그대로 열려 있다** | §12.3 (x) ⓒ 가운데 워크시트의 기억 하나만 이 slice 가 닫았다. `retry: null` 과 `?? retryExit` 의 위치 맞물림, 실행 취소를 가드 밖에 둔 근거, 입찰함 카드 쪽 둘은 받은 범위가 아니다 |
| ⓕ web 수집 전건의 **시간 초과 흔들림** | TS 프로그램을 세우는 test 둘(`kotlin-read-guard` · `screen-card-coverage`)이 부하 아래 기본 5s 한도를 넘는다. **main 에서 재현된다**(검증이 되돌린 트리 = base 바이트 동일에서 같은 서명을 냈다) — 이 slice 의 결함이 아니다. 처방 후보는 그 둘에 명시 timeout 이고 이 slice 밖이다 |
