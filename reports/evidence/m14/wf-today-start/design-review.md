# M14 / wf-today-start (14B) — 설계 검토: 배치 게이트의 레일 축을 출하 화면으로 넓힌다

팀장 판정(2026-11-20)으로 이 넓히기는 **14B 소유**다. 술어는 바꾸지 않는다 — 모집단만 넓힌다.
14C·14D 는 이 spec 을 만지지 않는다.

## (0) 위협 모델의 경계 — 이 축이 막으려는 것

**막는다**: 출하 화면에 선 두 단이 넓은 화면에서 레일을 본문 **왼쪽**에 두거나, 좁은 화면에서
한 단으로 접히지 않는 것. 그리고 **레일을 그려야 하는 화면이 레일을 하나도 내지 않는 것**
(수정 라운드 1 에서 더했다 — v HIGH-1).

**가로 넘침은 이 축이 막지 않는다**(v L3 의 정정): 일부러 가로로 스크롤되는 줄이 출하에 있어
여기서 재면 거짓으로 붉는다. 390px 전수는 터치 타깃 게이트가 **문서 층**으로 들고(요소 층이
아니다 — cr L-3), 1280px 의 넘침은 `/` 에서만 선다(base 의 현상 유지).

**막지 않는다**: 어느 화면이 레일을 **가져야 하는가**(그것은 계약의 대조표가 정한다) · 레일
**안의 내용** · 데이터가 와야만 그려지는 레일(아래 과소 차단).

**오늘의 사각**(착수 시점): 레일 축이 `page.goto('/')` 한 자리만 돌고 거기에 **합성 두 단**을 꽂는다.
14A 가 「출하 화면의 레일은 표지 전수라 뒤 레인이 붙이면 같은 단언이 함께 든다」고 적었지만,
그 문장은 **게이트가 그 화면을 도는 경우에만** 참이다. 오늘 `/start` 에 레일을 붙여도 이 게이트는
아무 말도 하지 않는다(실측 — spec 전체에 `goto` 인자가 `'/'` 하나뿐이다).

## (1) 열거인가 구성인가

**구성이다.** 두 축 모두 출하 선언에서 유도한다.

| 축 | 어디서 오는가 |
| --- | --- |
| 도는 주소 | `src/routes.tsx` 의 `screenSlots` + 표 밖 두 자리 — `scripts/journey-screen-table.mjs` 의 `appScreenSlots` 가 **AST 로** 읽는다(이미 있는 자리. 새 술어를 만들지 않는다) |
| 잴 묶음 | `[data-layout-two-column]` 표지 **전수**(오늘의 술어 그대로) |

**`/start` 를 적지 않는다.** 14C 의 워크시트 레일·14D 의 입찰함 레일은 머지되는 순간 자기 자리
표의 행으로 이 게이트에 든다 — 이 spec 을 고치지 않아도 든다.

경로 인자(`/notices/:noticeNumber/:noticeRound`)는 **자리 하나를 채우는 토큰**으로 바꾼다. 이
레인에는 백엔드가 없어 그 주소가 값을 싣지 못하지만, **셸과 화면은 선다**(기존 셸 스모크가 그
사실을 든다). 자리 표를 못 읽으면 `appScreenSlots` 가 **던진다**(이미 그렇게 적혀 있다) —
조용한 빈 집합이 되지 않는다.

## (2) 우회 — 다섯

| 우회 | 막는 것 |
| --- | --- |
| ⓐ 레일을 **쓰되 표지를 떼고** 손으로 두 단을 짠다 | **막지 못한다**(§12.3 (z) ⓓ 가 이미 등재한 OPEN). 이 slice 가 바꾸지 않는다 — `TwoColumn` 이 표지를 쥐고, 레일 있는 화면은 그 컴포넌트를 쓴다 |
| ⓑ 레일을 **백엔드가 있어야만** 그리게 둔다 | 이 레인이 못 본다 → 그래서 `/start` 의 레일을 **질의 상태와 무관하게** 그린다(아래 과소 차단). 비공허 하한이 그 자리를 지킨다 |
| ⓒ 자리 표에서 화면을 빼고 레일만 남긴다 | `journey-screen-table.test.mjs` 의 **집합 등식**이 자리 표와 터치 게이트 표를 묶어 붉는다 |
| ⓓ 이 spec 에서 주소 목록을 **손으로 줄인다** | 목록이 손에 없다 — `appScreenSlots` 가 낸다. 그 함수가 빈 배열을 내면 **던진다** |
| ⓔ 레일을 `display:none` 으로 숨겨 좌표를 0 으로 만든다 | 비공허 단언이 **비교 앞에** 선다(폭 0 이면 붉다 — 오늘의 술어 그대로) |

## (2b) 값 획득 축 — 새 표면

| 새 표면 | 값을 어디서 얻나 | 경계 |
| --- | --- | --- |
| `appScreenSlots` 를 e2e 에서 쓰기 | `src/routes.tsx` **원문**(읽기만) | 선례가 있다 — `e2e/kotlin-read-guard.spec.ts` 가 `../scripts/*.mjs` 를 들여온다. 새 의존성 0 |
| 경로 인자 치환 토큰 | spec 안의 상수 하나 | 주소를 **만드는** 값이지 판정하는 값이 아니다. 틀리면 그 화면이 404 자리로 떨어지고 레일 계수가 줄어 **비공허에서 붉는다** |
| 출하 레일 계수 하한 | 측정값 | **자리마다 1** 이고, 집합은 소스에서 구성된다. 줄어드는 쪽은 래칫 등식이 막는다 |
| **TS 타입 검사기를 Playwright spec 안에서** | 저장소의 `tsconfig.json` 과 `src` 전수 | 읽기만 한다(프로그램을 세우고 심볼을 묻는다). 쓰기 0 · 네트워크 0. 비용은 파일 하나 **0.7 → 6.4s**, 전건에서는 체감 차 없음 — 수치는 `commands.md` |
| **`getComputedStyle` 을 술어로** | 브라우저가 계산한 값 | 읽기만 한다. 값의 출처가 **출하 CSS** 라 test 가 사본을 들지 않는다 — 클래스 글자를 읽던 앞 판이 스타일 변종을 지나보낸 자리다 |
| **캡처 도구가 쓰기를 한다** | 감시 조건 씨앗 하나(편집 세션 셋) | 그 도구는 **버릴 하네스**에서만 돈다(실 DB·실 계정 0). 쓰기는 출하 API 를 지나고, 씨앗이 통과를 **실제로 세웠는지** 확인한 뒤에만 찍는다 |

## (3) 과잉 차단 · 과소 차단

- **과잉**: 없다. 레일이 **없는** 화면은 묶음이 0 이라 루프가 돌지 않는다 — 「레일을 가져야
  한다」를 주장하지 않는다.
- **과소 ①(해소)**: 백엔드가 있어야 그려지는 레일은 스모크 레인의 눈 밖이다. 처음에는 알려진
  제한으로 적었으나, 팀장 추가 지시로 **같은 술어를 세션 쥔 여정 레인에도** 걸어 닫았다
  (`e2e/journey/layout-rails.spec.ts`). 술어와 모집단 구성은 `e2e/railMeasure.ts` 한 자리다 —
  두 레인이 갈리면 갈린 날 어느 쪽이 맞는지 아무도 모른다.
- **과소 ①의 잔여(해소)**: 「합계 1」이 아니라 **자리마다 1** 로 바꿨다(v HIGH-1). 의무 집합을
  소스에서 구성하므로 14C·14D 가 레일을 붙이면 **아무 줄도 안 적고** 의무에 들어온다 — 머지한
  트리에서 실측했다(`commands.md`).
- **새 잔여**: 술어가 「그 모듈이 `TwoColumn` 을 **JSX 로 그리는가**」라, 레일을 자기 모듈 밖에
  싸면 집합에서 빠진다. 래칫 목록이 그 자리를 받는다(`checklist.md` OPEN ⓗ).
- **과소 ②**: 표지 없이 손으로 짠 두 단(§12.3 (z) ⓓ). 이 slice 가 열지도 닫지도 않는다.

## 양성 대조(변이)

`/start` 의 레일 표지를 떼면(또는 레일을 본문 앞에 두면) 이 축이 **RED** 다. 비공허 하한이
그 변이를 받는다 — 묶음이 0 이 되기 때문이다. **두 레인 각각에서** 쟀다(M11·M12 는 스모크,
M14·M15 는 세션 쥔 여정 레인 — `commands.md` 의 변이 표).

## 착수 실측 정정 (팀장 추가 지시 2026-11-20)

팀장이 전한 전제는 「스모크 레인에 세션이 없어 `/bids`·`/results`·아마 `/start` 가 로그인 얼굴을
낸다」였다. **이 브랜치에서는 성립하지 않는다** — 두 레인 전수 probe 실측:

| 레인 | 아홉 자리가 그리는 것 | `signed-out` | 레일 |
| --- | --- | --- | --- |
| 스모크(세션 없음) | 전부 자기 `screen-*` | **0** | 1(`/start`) |
| 여정(세션 보유) | 전부 자기 `screen-*` | **0** | 1(`/start`) |

세션 조회가 **401 이 아니라 파싱 실패**로 끝나 `signedIn` 이 `false` 가 아닌 `null` 이고, 화면들은
로그인 가지가 아니라 적재 중·오류 가지를 탄다. `/start` 의 레일이 보이는 것은 이 slice 가 틀을
얼굴과 무관하게 세웠기 때문이다(scope 계약 갱신 (3)).

그래서 오늘 두 레인은 **같은 그림**을 본다. 여정 축의 값은 오늘의 결함이 아니라 **뒤 레인이 레일을
데이터 뒤에 둘 때**에 있다.
