## 이 slice 가 남기는 OPEN 후보

| OPEN 후보 | 무엇이 열려 있나 |
| --- | --- |
| ⓐ 「조건 지우기」와 「전체」 칩이 **같은 일**을 한다 | 걷으려면 등재된 게이트 test 의 주장 둘을 바꿔야 해서 승인 경계다. 오늘 해는 없고 중복만 남는다. **덧붙임**(cr L-7): 한 칩 줄 안에서 「전체」는 `aria-pressed`, 나머지 셋은 `aria-expanded` 라 어휘가 둘이고, 눌린 「전체」를 다시 눌러도 해제가 없다 — 보조기기에는 해제할 수 있는 토글로 보인다 |
| ⓑ **스모크 레인**의 하한만 전역 1 이다 | 여정 레인의 의무는 **자리마다 1** 이고 집합이 소스에서 구성되므로 14C·14D 는 수를 올릴 일이 없다 — 레일을 붙이는 순간 자기 자리가 의무에 든다(머지 트리 실측). 전역 1 이 남는 곳은 데이터 없이 도는 스모크 레인 하나이고, 그 레인은 화면마다의 의무를 **지지 않는다**고 자기 주석이 선언한다. **머지 차례의 한 줄**: 유도 집합이 늘면 래칫 등식이 깨지므로, 먼저 머지하는 쪽이 자기 자리 이름을 `RAIL_SCREEN_FLOOR` 에 더한다 |
| ⓒ 「곧 마감」의 경계가 **화면의 값**이다 | 서버가 선언한 축이 아니다(주 경계도 날 수도 계약에 없다). 짝 test 가 방향을 잠그지만 값 자체는 이 화면의 정책이다 |
| ⓓ 모바일 카드가 **기관을 싣지 않는다** | 와이어프레임의 선택이다. 기관은 제목을 눌러 워크시트에서 본다 — 좁은 폭에서 그 사실이 보이지 않는다 |
| ⓔ 레일 미리보기의 줄 수가 **화면의 값**이다 | 제안 operation 에 쪽·정렬 인자가 없어 곁다리 크기를 화면이 정한다. 전체는 오늘의 공고가 든다 |
| ⓕ 금액 부속 문면이 **basis 를 두 번** 말한다 | 라벨 「기초금액」과 provenance 글자의 첫 토막이 같다. 이 slice 가 만든 것이 아니고(M9 D-3 의 조립), 건드리면 표시 계약을 바꾸는 일이다 |
| ⓖ 준비 중 절의 **약속 문면**이 걸리지 않는다 | 팀장 판정 ① 이 「약속을 그리지 않는다」를 조건으로 걸었는데, 「곧 제공됩니다」를 심은 변이가 **초록**이다(실측). 입력칸·버튼·링크는 구조로 막았지만 문면 판단은 열거할 수 없다 |
| ⓗ 레일 의무를 **자기 모듈 밖**에서 그리면 못 본다 | 술어가 「그 모듈이 `TwoColumn` 을 JSX 로 그리는가」라, 레일을 별 파일의 하위 컴포넌트에 싸면 집합에서 빠진다. 래칫 목록이 그 자리를 받는다(한 줄) |
| ⓘ 머리 요약이 **「감시 조건 통과 0건」**을 센다 | 감시 조건이 없는 계정에서 그렇다. 바로 아래 빈 얼굴이 「조건이 없으면 어떤 공고도 통과하지 않습니다」라고 가르치므로 거짓은 아니지만, 같은 말을 한 뼘 안에서 두 번 한다. **그대로 두기로 한다**(cr L-8 이 준 선택지 둘 가운데 「적는다」) — 요약을 지우면 `total` 이 서는 자리가 상태마다 갈린다 |

## 장부 정정 — 앞 보고가 틀린 자리

**준비 중 절 단언의 이득을 잘못 적었다.** 앞 보고는 「앞 test 는 셋 중 하나에 버튼이 생겨도 다른 둘이 상자를
비워 주면 지나갔다」고 적었는데, verifier 가 base 에서 그 상자에 버튼을 심어 **RED** 를 냈다.
버튼 축은 앞 판도 들었다.

**진짜 이득은 절마다의 「준비 중」 알약 검사**다(`notReady` 를 한 절에서 떼면 RED). 그리고 두 꼴
모두 놓치던 것이 둘 있었다 — **링크**(이 라운드에서 막았다. 보강 전 변이 초록 → 보강 후 RED 3)와
**약속 문면**(여전히 안 걸린다 → OPEN ⓖ).

**`SectionCard` 주석이 교정과 어긋났다** — 그 주석이 「준비 중이 `steps` 의 구조에서 나온다」고 적어 (4) 의 교정과
어긋났다. 주석을 정정했다.
