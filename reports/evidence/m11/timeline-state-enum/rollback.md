- **실측 HEAD**: `d0d0281da2f96d7db167bcc8be669418bcd5e552` — 원천에 **존재하는** 복원 대상을

- 머지 뒤에 되돌릴 때는 range revert 가 아니라 **PR revert** 다.

## 복원 명령

```
git restore --source=92cbf5819f5a9027a56065213c9326f1f2fdfaea --staged --worktree -- <목록>
```

목록은 **기계 산출**이다 — `git diff --name-only <원천>..<실측 HEAD> -- .` 이고 **13 경로**다
(M 9 · A 4). `comm -23 <목록> <in_scope>` 가 **빈 출력**이다(목록 ⊆ in_scope). 라운드마다
재산출한다. `checkout --` 은 쓰지 않는다(미커밋 산출물을 함께 지운다).

## 공유 파일의 절 계수 — 「내 절 0 · 남의 절 보존」

복원 원천이 바뀐 파일이라 **항목 집합으로 센다**(어휘 grep 이 아니다). 되돌린 트리에서:

- §12.3 의 절 머리가 `(a)`…`(l)` 이고 **내 `(m)` 은 0 건**이다.
- `(k)`(11A) · `(l)`(11E) 는 **각 1 건**이고 **본문 해시가 원천과 같다** — 남의 절이 한 줄도
  움직이지 않았다.

같은 계수를 **병합 직후에도** 쟀다(충돌 0 자동 병합이 본문을 접는 꼴을 가르려고): 절 수 13 ·
글자 중복 0 · `(k)`·`(l)` 본문 해시가 원천과 같음 · 내 본문은 **머리 한 줄만** 달라짐. 자동 병합이
내 절을 `(j)` 뒤에 놓아 `(k)(l)` 앞이 됐으므로 **끝으로 옮기고** 글자를 `(m)` 으로 정했다.

## 비활성화 — 되돌리지 않고 끄는 길

이 slice 는 **새 wiring 을 만들지 않는다**. 더한 것은 ① 계약 문서의 `enum` 선언(스키마 강화)
② 그 선언을 재는 test ③ web 쪽 유니온 유도와 표시 조회 한 자리다. 런타임 경로에 분기·플래그·
마이그레이션이 0 이므로 **끌 것이 없다** — 거동 변경은 표 밖 상태의 표시 문면 하나이고, 그 한
자리를 되돌리려면 위 복원이 전부다.
