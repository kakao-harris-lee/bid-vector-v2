# M11 / gates-adapters-2 — 설계 검토 (Phase 2.5)

입력: `scope.md` 착수 실측 · 팀장 착수 판정 2026-11-13(ml (나) · deny→allow 승인 · ⓐⓒ 닫는 안 · ⓑ 는 이
문서가 처분안을 내고 팀장 판정 · 두 층 단일 출처화는 범위 밖) · 계약 변경 둘(§12.3 글자는 병합 시점에
덧붙인다 · 「경계 밖 등재」는 팀장 판정).

## (0) 위협 모델 경계 문장

**방어하는 것 — 셋이다.**

1. **판정 모집단의 구멍.** adapters 의 dependency test 열넷 가운데 어느 축도 「두 층 가운데 한 층만」
   가지지 않는다. 열넷 전부가 바이트코드 층(`javap` 상수 풀)과 이름 층(`source.scoped-packages` +
   `source.scoped-allowed-roots.<축>`)을 **둘 다** 갖고, 두 층의 허용 뿌리가 **집합 등식**으로 묶인다.
2. **술어 종류의 미달.** 축의 판정이 **소스 텍스트 import 정규식**이 아니다 — import 없이 전체 한정
   좌표로 직접 부르는 꼴을 보지 못하기 때문이다(`OPEN-PERSISTENCE-GATE-PREDICATE-TYPE` 이 persistence 에서
   닫은 그 사각).
3. **표와 실물의 어긋남.** 두 층 등식의 바이트코드 항이 **그 축의 게이트가 실제로 판정에 쓰는 집합
   그 자체**다 — 표가 그것과 다른 값을 들고 등식이 성립하는 자리를 만들지 않는다(10C 가 등재한 ⓐⓑⓒ).

**방어하지 않는 것.**

- **두 목록이 「옳은가」** — 둘이 **함께** 넓어지면 조용하다. ADR·리뷰 자리다(§12.3 (i) · 10C 와 같다).
- **두 층의 단일 출처화** — 팀장 판정으로 범위 밖(ADR 자리).
- **게이트 자신을 고치는 저자** — 정책 파일·parity test·축 test 를 **의도적으로** 고쳐 숨기는 것. 그 편집은
  diff 가 평면으로 보여 주는 자리이고, 여기 단언들의 몫은 **게이트를 의식하지 않은 편집**을 붉히는 것이다.
- **값이 흐르는 경로 일반** · 다른 모듈·패키지(이 축의 모집단이 아니다).

## (1) 열거인가 구성인가

열넷 전부에서 **구성**이다. 이 slice 가 더하는 것은 열거 항목이 아니라 **등식의 항**이다.

- 모집단은 손으로 적은 목록이 아니라 `source.scoped-packages` **값**이고, 표의 key 집합과 집합 등식이다
  (10C 가 세운 자리 — 이 slice 는 그 등식의 양변에 여섯을 함께 넣는다).
- 표의 값은 문자열이 아니라 **컴파일되는 심볼 참조**다 — 축의 `ALLOWED_ROOTS` 를 지우거나 이름을 바꾸면
  컴파일이 깨진다.
- 이 slice 가 더하는 두 단언도 **구성**이다: 표 값이 소유 getter 호출 결과 **그 자체**인가(리플렉션
  `===`), 그 축 패키지의 `ALLOWED_ROOTS` **보유자가 하나이고 그것이 표의 소유자인가**. 둘 다 소유자를
  산문이 아니라 **상수 풀**에서 얻는다.
- **열거가 남는 자리 하나**: 축별 허용 뿌리의 **내용**(`bidvector.procurement` 등). 그 목록이 옳은가는
  위 (0) 「방어하지 않는 것」이고, 두 층이 **같은** 목록을 들었는가만 구성으로 닫힌다.

## (3) 과잉·미달

### 과잉 후보 — 하지 않는다

- **「허용 뿌리가 실재하는 패키지인가」 단언.** 위 (2) 의 「`bidvector.ml` 을 허용 뿌리로 더한다」와
  10C 가 등재한 「유령 축 + test 파일 신설」을 함께 닫는 처방이다. 하지 않는 이유: ① 허용 뿌리는 adapters
  **밖**의 모듈 좌표(`bidvector.procurement`·`bidvector.workflow.*`)가 대부분이라 「adapters main 출력에
  실재」로는 재지 못하고, 전 모듈 출력을 뒤지는 축이 된다 ② 장래의 정당한 선행 등재(패키지를 만들기 전에
  정책을 적는 순서)를 막는다 ③ 우회 비용이 이미 **두 정책 자리의 편집**이라 diff 가 보는 자리다. 등재한다.
- **「소스 import 정규식 0」 상시 단언.** 술어 공존을 막는 처방. 하지 않는 이유: 술어의 **부재**를 재는
  게이트는 그 자체가 텍스트 술어이고(CLAUDE.md 「문자열이 아니라 구조로」에 정면으로 걸린다), 10C·#134 도
  이식 완료를 **실측**으로 남겼다. 같은 자리를 `commands.md` 가 든다.
- **형제 여덟의 정규식 경계 고정.** 팀장 판정으로 범위 밖 — 신설 OPEN 으로 등재한다.
- **공유 헬퍼로 javap 호출을 모으는 것.** 열넷이 같은 helper 를 복제하지만, 그 파일들은 전부 **파일
  `private`** 이고 하나를 `internal` 로 여는 것은 크기 한도에 닿은 파일들을 만지는 다른 결정이다(10C 의
  같은 판단). 신설 OPEN 의 받는 자리가 그 slice 다.

### 미달 — 유지

- **두 목록이 옳은가** · **단일 출처화**(팀장 범위 밖) · **값이 흐르는 경로**.
- **dependency test 자체가 없는 adapters 패키지.** 이 slice 는 「열넷 전부가 두 층」을 세우지만, 열넷이
  adapters 의 패키지 **전부**라는 주장은 하지 않는다. 그 모집단(패키지 ↔ dependency test 전단사)은 다른
  축이고 `packageOwnershipGate` 가정과 겹친다.

### 미달 — 등재(신설 OPEN 하나)

- **`OPEN-M11-JAVAP-ROOT-REGEX-UNANCHORED`** — 형제 여덟(+`notification`·`persistence`)의
  `bidvector[/.][A-Za-z0-9_/.$]+` 가 **좌측 경계를 고정하지 않아** 중첩 네임스페이스 내부 이름의 가운데
  토막을 자기 좌표로 읽는다. 오늘 그 꼴을 만나는 축은 **0**(`contract.bidvector.*` 를 쓰는 adapters
  패키지는 `ml` 하나, 전수). 틀리는 방향은 **오탐**(막는 쪽)이므로 미탐이 아니다. 받는 자리: **다음에 그
  형제 술어를 만지는 slice(공유 헬퍼로 모을 때)**.

### 측정된 비용 — ⓑ 처분안의 실행 시간

열넷 축 패키지의 test class **559 개**를 그대로 `javap -p -v` 하면 **58초**다(실측) — 단위 test 에 둘 수 없다.
그래서 처분안은 **바이트 선별 + 일괄 호출**이다: class 파일 바이트에 `ALLOWED_ROOTS` 가 없으면 그 class 는
그 필드·getter 를 참조할 수 없으므로(상수 풀 UTF8 항목에 그 글자가 반드시 남는다) 상위집합 선별이고
**미탐이 없다**. 오늘 생존 **13/559**(실측), 일괄 `javap` 한 번이 **1.6초**다. 귀속은 `Classfile` 헤더로
한다(「바이트코드 코드 지도 레시피」).

## ⓑ 처분안 — 팀장 판정 대기

**제안: 닫는다.** 술어를 패키지가 아니라 **보유자**에 묶는다.

- 축 k 에 대해 `O_table(k)` = parity test 자기 상수 풀에서 뽑은, 패키지가 k 인 `getALLOWED_ROOTS` **소유
  class**(10C 의 4번째 단언이 이미 뽑는 값. **패키지마다 소유자가 하나**임을 함께 단언한다 — 둘이면
  값 식 메꾸기의 다른 꼴이다).
- `U_k` = **k 패키지의 test class 파일**에서 뽑은 `ALLOWED_ROOTS` 필드·getter 의 소유 class 집합.
- 단언: 축마다 **`U_k == { O_table(k) }`**.

**오늘 서는가 — 실측.** 심볼이 이미 `ALLOWED_ROOTS` 인 열한 축 전부에서 `U_k` 가 **원소 하나**이고 그것이
그 축 dependency test 의 file facade 다. `extraction`·`koneps`·`ml` 셋은 심볼명이 달라 오늘 `U_k` 가 비어
있고, 이 slice 의 개명 뒤 같은 모양이 된다. **축이 다른 축의 `ALLOWED_ROOTS` 를 참조하는 자리는 오늘 0**
이라 이 단언은 오늘 아무 축도 붉히지 않는다.

**무엇이 닫히는가.** `internal object AuditWide { val ALLOWED_ROOTS = …notice.ALLOWED_ROOTS }` 를 audit
패키지에 두고 표를 그 심볼로 바꾸면, audit 패키지의 보유자가 **둘**(제 facade + `AuditWide`)이 되어
등식이 깨진다. 표의 값만 바꾸는 한 줄로는 통과하지 못한다. **통과하려면 그 축 게이트가 실제로 그 집합으로
판정하도록 고쳐야 하고**, 그때는 바이트코드 층도 함께 넓어져 거짓이 사라진다(= 위 (2) 의 「양쪽을 함께
넓힌다」, (0) 가 경계로 선언한 자리). **닫지 못하는 것은 함께 적는다** — 보유자를 세는 기준이 `ALLOWED_ROOTS` 라는 **이름**이라,
판정을 **다른 이름의 심볼**이나 **호출 자리의 식**으로 옮기면 이 등식이 조용하다. 10C 가
「판정 집합을 다른 심볼로 옮기고 `ALLOWED_ROOTS` 는 장식으로」로 등재한 항목은 **열린 채
남는다**(verifier r1 H-1 실측, 팀장 처방 ①).

**대가.** parity test 가 **자기 패키지 밖의 class 출력**을 읽기 시작한다(오늘은 자기 class 셋만 읽는다).
같은 `:adapters:test` 출력이라 선언 입력은 그대로이고 비용은 위 측정대로 **1.6초**다. 엄격함의 대가가 하나
있다 — 어떤 축의 test 가 **정당하게** 다른 축의 `ALLOWED_ROOTS` 를 참조하면(예: 축 사이 교차 대조 test)
그 축이 붉는다. 오늘 그런 자리는 **0**이고, 생기면 그것은 두 층 등식이 가리키는 집합이 흔들리는 것이라
**봐야 하는 신호**로 본다.

**대안(채택하지 않는 쪽): 경계 밖 등재.** 사유로 들 수 있는 것은 「우회 비용이 새 파일 + 표 편집이라
리뷰가 평면으로 본다」이고, 10C 가 N-3 을 그렇게 등재했다. 그 등재를 유지하면 이 slice 는 ⓐⓒ 만 닫고
ⓑ 는 **다섯째 안 막힘**으로 남는다. 다만 ⓐ 를 닫는 이 라운드에서 ⓑ 가 **ⓐ 처방의 유일한 남은 구멍**이
되고(「값 식」을 막으면 다음 수가 「다른 보유자」다), 닫는 비용이 위 측정대로 작아 **닫는 쪽을 추천한다**.
