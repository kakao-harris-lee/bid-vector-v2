### 그래서 무엇이 일어났나

**일의 양은 늘지 않았다 — 식은 비용이 자리를 옮겼다.** 모집단 기계는 **모듈 적재 때** 전수 파싱을
한 번 했고 그 자리에서 첫 패스 웃돈을 물었다(원천의 `import` 비중 39%). 그것을 지우자 **첫 무거운
칸**(경로 술어)이 그 웃돈을 문다(이 판의 `import` 비중 22~23%). 조건 A 의 합이 거의 같고 조건 B 의
파일 총 소요가 줄어든 것이 그 설명과 맞는다.

**예열을 더하는 길은 처방이 아니다** — 웃돈을 hook·적재 쪽으로 되돌릴 뿐이다(M11/11E 실측).
줄이려면 **전수 파싱 자체를 줄여야 한다**: 오늘 세 칸이 같은 파일 집합을 **각자** 읽고 파싱하므로,
모듈 수준에서 한 번 파싱해 세 칸이 나눠 쓰면 두 패스(조건 C 로 약 2×140ms)와 칸 사이의 비대칭이
함께 사라진다. **이 slice 의 받는 항목 밖이라 구현하지 않고 수치만 올린다.**

## r1 실측 — verifier 지적 여섯의 처리 (2026-11-15)

### H-1 — 재현과 닫힘

같은 탐침 스크립트(확장자 토큰 없는 경로로 정본 하나를 읽는다)를 `package.json` 에 꼴만 바꿔
등록하고 `npm run` 으로 띄웠다.

| 꼴 | 첫 판 | `.npmrc` 선언 뒤 |
| --- | --- | --- |
| `NODE_ENV=test node …` | **READ 1613** | **REFUSED** |
| `true; node …` | **READ 1613** | **REFUSED** |
| `env FOO=1 node …` | **READ 1613** | **REFUSED** |
| 하위 디렉터리 config 로 띄운 spec | **READ** | **REFUSED** |
