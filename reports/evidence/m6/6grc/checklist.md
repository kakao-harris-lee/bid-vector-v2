## 낡는 좌표 — 역방향 파급

이 slice 가 편집한 파일을 `파일:줄` 로 가리키는 인용을 전수로 찾았다(`*.md`·`*.kt`·`*.kts`·
`*.properties`). 둘이 나왔고 **둘 다 밀리지 않는다**: 하나는 legacy 저장소의 다른 파일을
가리키고(이름만 닮았다), 하나는 runbook 의 **앞쪽** 줄을 가리키는데 이 slice 의 runbook 편집은
같은 줄 수의 제자리 치환(2 삽입 · 2 삭제)이라 뒤쪽 편집이 앞쪽 좌표를 밀지 않는다.
이 slice 의 evidence 는 자기가 편집하는 파일에 `파일:줄` 을 쓰지 않는다.

## 알려진 제한

1. **v1 은 보존되지만 적재되지 않는다**(D-6GRC-2). 새 키가 필수라 로더가 v1 파일을 거부한다 —
   v1 로 다시 돌리려면 그 파일에 상한 한 줄을 더해야 한다. v1·v2 구분 test 는 그래서 「v1 문면 +
   새 키」로 조립한 정책으로 version · checksum 차이를 잰다.
2. **S4 자리 probe 는 출하 배제 비율에서 거동 0 이다.** 출하 비율(0.98)에서는 이 판의 공사
   공고에서 순공사원가선이 S4 후보 격자 **아래**에 있어, 상한만 토글하면 투찰금액이 같다(실측).
   그래서 그 probe 는 선이 묶이는 비율을 깔고 상한을 가로지른다. 같은 사실이 **출하 전략 판에서
   이 값이 움직이지 않는 값 목록에 등재된 이유**이기도 하다.
3. **실데이터 백테스트는 돌리지 않았다.** 이 slice 는 규칙과 정책까지다 — 수정된 S0 · S4 의
   우위나 운영 채택은 주장하지 않는다(검증 계획 T2 이후, 별도 승인).
4. **`metrics.py` 의 docstring 한 줄이 in_scope 경로 목록 밖이다.** 계약의 「계획이 지목한 낡은
   코드 주석 · docstring」 항목으로 고쳤다(적격 정의가 「공사는 순공사원가선까지」라고 적혀 있어
   새 거동과 어긋났다). 경로 목록에 더하는 계약 갱신이 필요하다 — 팀장 판단 대상.
5. **DEC-10 레인의 Kotlin system property 는 그대로 v1 을 가리킨다**(D-6GRC-3). 밴드 값이
   v1 = v2 라 그 test 는 깨지지 않고, 경로를 v2 로 옮기는 것은 나중에 머지되는 쪽의 몫이다.
6. **계약의 in_scope 중 `floor.py` 는 적용 판정을 받지 않는다.** 적용 여부는 정책 객체의 술어와
   `rules.pure_cost_floor` 가 지고, `floor.py` 는 받은 실격선을 전부 보는 순수 산식으로 남는다 —
   두 자리에서 판정하지 않기 위해서다(docstring 에 그 사유를 적었다).
