## 알려진 제한

> **두 목록이 있다**(PR #73 low). 아래는 **이 checklist 의 제한**이고, runbook 의 §5 목록은 번호가
> 다르다(같은 번호가 다른 항목을 가리킨다). 그래서 이 문서의 참조는 전부 「이 checklist 제한 N」
> 또는 「runbook §5-N」으로 적는다 — 번호만 적힌 참조는 둘 중 어느 것인지 읽는 사람이 알 수 없다.

1. **`outbox` 의 `FAILED`·`ISOLATED` 행은 영구히 남는다** — 둘 다 종단이지만 **미발송**이라 A-4 의
   제외에 들어간다. `ISOLATED` 는 알림을 영구히 잃은 사건의 유일한 흔적이고 운영 조사 경로가 그
   행을 읽는다. 그 행 수가 자라면 처분이 결정 축이다(`OPEN-6B3-OUTBOX-UNSENT-RETENTION`).
2. **기한 안쪽 자식이 있는 부모는 그 run 에서 남는다**(우회 6 의 대가, CASCADE 간선 포함). 자식이
   기한을 넘는 다음 run 에서 함께 사라지고 그 수렴을 test 가 잰다.
3. **실패한 run 의 부분 계수는 이제 실패 줄에 실린다**(PR #73 P6 — 앞 판의 이 자리는 「남지 않는다」였고
   그것이 `OPEN-6B3-PARTIAL-COUNTS-ON-FAILURE` 의 내용이었다). 일괄은 각자 커밋되므로 도중에 죽은 run 이
   지운 행은 돌아오지 않고, 그 수가 `RetentionAborted` 에 실려 러너의 실패 줄에 **마침 줄과 같은 어휘로**
   찍힌다. **남는 한계는 창의 끝**이다: 터진 **그 일괄**의 수는 없다(롤백됐으므로 0 이 맞다) — 그러나
   「그 일괄이 몇 행을 지우려 했나」는 알 수 없고, 저장소가 커밋 **직후** 죽으면 그 일괄은 세어지지 않은
   채 커밋돼 있을 수 있다(계수와 커밋이 원자적이지 않다 — 그 창은 일괄 하나다).
4. **「이미 마스킹된 행 건너뜀」은 두 겹이고 각각을 단독으로 잠그는 test 가 없다**(M-14a·M-14b 생존).
   test 가 잠그는 것은 거동이고, 되돌릴 수 없음의 DB 층 보장은 트리거가 독립으로 진다(M-9).
5. **`payload` 읽기 자리 0 의 술어는 SQL 문자열을 본다** — 질의가 다른 형태로 조립되면 그 술어의
   모집단 밖이다. 공허 대조 둘과 음성 대조로 「술어가 아무것도 못 보는 상태」만 막았다.
6. **운영 DB 에서 한 번도 돌리지 않았다.** 모든 실행이 Testcontainers 위에서다 — 첫 실행의
   부풀음·소요와 V19 의 실제 적용 창은 측정되지 않았다(크기 측정 절차는 runbook §1.3·§2.2).
7. **수집 시점 마스킹은 하지 않는다** — 원문은 90일 동안 담당자 PII 와 **업체 식별 키 셋**을
   가진다(결정 문면 그대로 · runbook §1.1·§5-3 과 같은 문면).
8. **`notice_audit` 은 파기도 마스킹도 받지 않아 무한히 자란다**(cr M-3). 파기된 `notice` 행의 전체
   스냅숏이 90일 창 밖에도 남는다 — 담당자 PII 는 그 스냅숏에 없다(등식으로 잠근다).
9. **표지만 찍는 UPDATE 와 임의 내용 주입은 소유자에게 열려 있다**(cr L-2 · vr F-11). 막으면
   치환값이 원문과 같은 행에서 run 이 fail-stuck 이 되므로 **막지 않고 성질을 실측**했다. 소유자
   자격을 가진 주체의 임의 SQL 은 비방어 축이다(그 주체는 트리거도 DROP 할 수 있다).
10. **적재마다 트리거 함수가 한 번 더 돈다**(INSERT 관문 — 표지 검사 + 적재 시각 강제). 분기 셋이라
    행당 비용은 작지만 수집 처리량 실측은 M7 축이다.
11. **`CREATE INDEX CONCURRENTLY` 를 쓰지 않았다 — 실측으로 기각했다.** Flyway 아래에서
    `executeInTransaction=false` 를 줘도 그 문장이 **끝나지 않았다**(실측: 14분). 메커니즘은 「동시
    트랜잭션 전부를 기다린다」가 **아니라 「스냅숏을 쥔 트랜잭션을 기다린다」**다(vr R2-F5 가 독립으로
    재분해했다 — advisory 잠금만 쥔 idle 트랜잭션은 막지 않고 `REPEATABLE READ` 는 막았다). 즉 그
    정지는 Flyway 메타데이터 연결이 스냅숏을 쥐고 있었다는 뜻이다. `transactional.lock` 을 끄면
    풀리지만 **Flyway 호출 자리 넷이 전부** 그것을 알아야 하고 하나라도 잊으면 거기서 실패가 아니라
    **정지**한다. 실패한 `CONCURRENTLY` 는 INVALID 인덱스를 남긴다(실측). 그래서 V19 분리로 읽기
    차단만 없애고 **쓰기 차단 창**(열 표 전부 · V19 전 구간)은 runbook §1.3 이 측정 절차와 함께
    든다(`OPEN-6B3-INDEX-WINDOW`).
12. **시계는 신뢰 앵커다**(설계 검토 (0) 비방어).
13. **`SET LOCAL lock_timeout` 은 test 가 잠근다 — 다만 「상한이 있다」까지다**(vr R3b-L1 정정).
    앞 판의 이 자리는 「재는 test 가 없다 · 문서·파일 축으로만 선다」고 적었고 그것은 **거짓이 되었다**:
    `MigrationLockTimeoutTest` 가 V18(읽기 홀더)·V19(쓰기 홀더) 둘을 **거동으로** 잠근다 — 상한 안에
    실패하고, `55P03` 이고, 홀더가 놓은 뒤 재시도가 선다. 문자열 술어는 쓰지 않았다(세션 설정이
    카탈로그에 남지 않으니 그 길밖에 없다던 판단 자체가 틀렸다). 그 한 줄을 지운 상태의 실측은
    변이 표가 아니라 **「RED 먼저」 절**에 있다 — V18 은 라운드 2, V19 는 승인 전 정리에서 각각
    구현 전 RED 를 받았고(기다렸다가 성공 → 상한 추가 → 55P03) 그 RED 가 변이의 역할을 겸한다.
    **남는 한계는 값이다**: 그 test 가 거부하는 것은 「상한 없음(무한 대기)」과 「홀더 유지 시간보다 큰
    상한」이고, 0 과 경과 상한 사이의 어떤 값이든(예: `'1s'`, `'15s'`) 초록으로 지난다. 즉 **`'5s'`
    라는 수 자체는 잠겨 있지 않다** — 그 수는 정책 판단이고 runbook §1.3·§4.6 이 든다.
14. **마스킹 키 집합의 「전 개정 합집합」은 오늘 거동으로 보이지 않는다.** 수집 정책 entry 가 하나라
    run 날짜로 풀어도 같은 집합이 나온다(cr M-2 가 medium 인 이유). 이 축은 **구조**로 닫았다 —
    보존 저장소 공개 생성자에 기준일 인자가 **없다**. 변이로 양쪽을 쟀다(둘째 entry 를 더한 뒤
    합집합 유지 = 초록 · run 날짜 해소 = RED).
15. **CASCADE 기한 가드는 한 단계다**(vr R2-F7) — CASCADE 손자·마스킹 분류 CASCADE 자식이 생기면
    기한 안쪽 행이 부모와 함께 사라진다. 오늘 둘 다 없고 **그 부재를 빌드가 센다**.
16. **TDD 순서 — 이 라운드는 RED 를 별도 run 으로 실측했다.** 새 술어의 test 를 먼저 쓰고 구현 전에
    돌려 실패를 받았다(`commands.md` 「RED 먼저」). 앞 라운드의 이탈(테스트를 먼저 썼으나 RED 를
    재지 않음)은 반복하지 않았다.
17. **운영 DB 에서 한 번도 돌리지 않았다**(위 6 과 같은 사실) — 이 라운드의 조치 가운데 적재 시각
    강제와 두 열 allow-list 는 **적재 경로의 거동을 바꾼다**. Testcontainers 에서만 실측했다.

18. **분할 등식은 개념 단위다**(vr R3-F2) — 업체 식별을 나르는 새 rawName 이 **기존 비PII 개념
    아래로** 등재되면 그 키는 남김 집합에 들어오고 아무것도 붉어지지 않는다(`opengCorpInfo` 가 그
    꼴이었다). 오늘 계약 rawName 전수에 그런 키는 없다. 사람이 값 모양을 보게 되는 자리는 개념을
    **새로 만들 때**이고 기존 개념에 키를 더할 때는 강제되지 않는다.
19. **자유텍스트 개념의 비PII 분류는 측정이 아니라 가정이다**(cr L-1 · privacy F-11) — 분류 근거는
    「그 키가 담기로 한 것」이고 값의 내용을 본 적이 없다. `OPEN-6B3-FREE-TEXT-PII-AXIS` 가 운영 첫
    실행 전 재확인을 건다(그 뒤에는 영구다).
20. **값에 심은 상호는 두 열 모두에 남는다**(privacy F-10 의 닫을 수 없는 절반) — 마스킹은 키 이름으로
    고르므로 계약 키의 **값**에 넣은 이름·상호는 걸러지지 않는다. **값 축은 비방어**다.
