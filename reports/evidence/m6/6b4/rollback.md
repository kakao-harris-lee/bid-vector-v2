# M6/6B-4 되돌림

실측 HEAD: `7ee29347` (main 병합 커밋 — 이 slice 의 **현재 마지막 커밋**)

base: `e2232a75`. 브랜치 `m6-6b4/2026-10-13`. **복원 원본: `ae9b2f52`**(병합된 main SHA,
고정 — 움직이는 `origin/main` 을 쓰지 않는다).

## 복원 원본이 base 가 아닌 이유

이 브랜치는 PR #71 을 머지 가능하게 하려고 main(`ae9b2f52`)을 **병합했다**. 그래서
`git diff e2232a75..HEAD` 에는 **다른 slice 의 줄**(6E-2C · 하네스 핀)이 함께 들어 있고,
base 로 되돌리면 그 줄까지 지운다. 「병합된 main SHA 에서 복원」 규칙이 이제 성립 조건을
갖춘다.

**실행 전 단언 둘(기계 확인).**
- `git merge-base --is-ancestor ae9b2f52 HEAD` → **exit 0**(조상이다).
- 이 slice 의 커밋이 `ae9b2f52` 안에 **없다**: `comm -12` of
  `git rev-list e2232a75..HEAD^1` ∩ `git rev-list ae9b2f52` → **0 줄**(slice 커밋 63 개).

**하네스 경로는 되돌리지 않는다.** `git log --oneline e2232a75..HEAD^1 -- CLAUDE.md
.claude/ docs/harness/` 가 **빈 출력**이다 — 병합이 들여온 하네스 변경은 main 의 것이고
아래 목록 밖이다.

되돌림은 **머지 전**을 전제한다. 머지 뒤의 되돌림은 그 PR 의 머지 커밋 revert 다.

## 목록 — 기계 산출(손으로 쓰지 않는다)

```
git diff --name-only ae9b2f52 HEAD          # 복원 대상 = 병합 트리가 main 과 다른 자리
git diff --name-only e2232a75..HEAD^1       # 교차 확인 = 병합 전 브랜치가 바꾼 자리
```

두 산출은 **독립**이고(하나는 main 에, 하나는 base+병합 전 tip 에 걸린다) `comm -3` 가
**0 줄**이다. 산출: **40 경로** — `A` 16(삭제 대상) · `M` 24(원본으로 복원).
`A` 열여섯: 저널 값·코덱 모듈 하나 · 저널 **파일** 모듈 하나 · Python test 일곱 · runbook
하나 · 이 slice 의 evidence 여섯(계약 문서와 Codex 판정·preflight JSON 포함).
`M` 스물넷: Kotlin 계약 규칙·계약 test · proto · docker 둘 · ADR · 정책 YAML · Python src
여섯 · Python test 여덟 · `policy-values.md`.

**main 만 바꾼 경로는 목록에 들어오지 않는다**: `git diff --name-only e2232a75..ae9b2f52`
는 20 경로이고 그 중 19 가 main 전용이다(`comm -13`). 목록은 첫 산출이 곧 「병합 트리 ↔
main 트리의 차이」이므로 그 19 를 **구조적으로** 담을 수 없다.

**공유 파일은 하나다** — `docker/ml-serving.Dockerfile`(main 의 6E-2C 와 이 slice 가 둘 다
바꿨다). 나머지 39 경로는 base 와 `ae9b2f52` 에서 **같은 내용**이다
(`git diff --name-only e2232a75 ae9b2f52 -- <그 39>` 가 빈 출력) — 그래서 원본 하나
(`ae9b2f52`)로 40 경로를 한 번에 복원하는 것이 공유 파일에는 **필요**하고 나머지에는
base 복원과 **같다**. `A` 16 중 `ae9b2f52` 트리에 존재하는 것은 **0** 이므로 그 열여섯은
삭제된다.

**라운드마다 재산출한다.** 목록이 낡는 것이 이 결함의 실제 원인이고, 이번에는 base 가 아니라
**복원 원본**이 움직였다(병합). 앞 여덟 측정은 base 트리로 복원했고 그 전제는 이제 깨졌다.

**이 slice 의 evidence 디렉터리도 되돌림 대상에 넣는다**(`reports/evidence/m6/6b4/**`).
남겨 두면 원본의 누출 어휘 baseline 에 없는 문서가 트리에 남아 `leakPatternGate` 가 붉어진다.

## 명령 — in_scope 경로 한정(range revert 가 아니다)

```
git restore --source=ae9b2f52 --staged --worktree -- <위 목록의 경로를 개별 인자로>
git commit -m "revert(m6-6b4): in_scope 경로를 병합된 main 으로 되돌림" -- <같은 목록>
```

**복원과 커밋이 한 쌍이다** — 미커밋 복원은 `contracts/` 의 작업 트리를 더럽혀 `contractGate`
를 붉힌다(아래 보완 경로의 실측).

- **경로 수를 이 블록에 적지 않는다.** 수는 위 산출 절에만 적고, 명령은 그 목록을 가리킨다.
- 목록을 변수 하나에 담지 않는다(pathspec 이 하나가 되어 아무것도 매치하지 않는다).
- `git checkout <원본> -- <경로>` 를 쓰지 않는다 — 원본에 없는 경로마다 pathspec 오류로
  exit 1 이고 아무것도 적용되지 않는다.
- 신규 파일에 별도 `git rm` 이 **필요 없다** — `--source` 에 없는 경로는 `restore` 가 지운다
  (아래 ② 의 `D` 16 이 그 실측이다).

## 되돌린 뒤 남는 것 — 저널 파일

저널 형식은 이 slice 가 처음 만든 파일이라, 되돌린 코드에는 그것을 읽는 자리가 없다(모듈
둘 — 값·코덱과 파일 — 이 함께 사라진다). 런타임 디렉터리
(`<ML_ENGINE_ARTIFACT_OUT_DIR>/_journal/`)에 남은 저널 파일은 **무시된다** — 저장소가 프로세스
로컬 dict 로 복귀하고 그 파일을 읽지도 쓰지도 않는다. compose 볼륨도 되돌림 뒤에는 선언이
사라지므로 다음 `up` 에서 그 경로가 컨테이너 로컬로 돌아간다(기존 거동).

| ③ | `git diff ae9b2f52 -- <목록>` · 트리 전체 diff(작업·index) | **전부 빈 출력(0 줄)** |

### ④~⑥ 의 갈음은 「HEAD 초록」이 아니라 **트리 동일성**이다

복원+커밋 뒤 되돌린 트리의 해시가 **병합된 main 의 트리 해시와 같다**:

```
git write-tree / git rev-parse HEAD^{tree}   # 되돌린 트리(복원 뒤 index · 커밋 뒤 커밋)
git rev-parse ae9b2f52^{tree}                # 병합된 main 의 트리
```

실측: 셋 다 `c34915cd818a1c81a5e87aa897949a5ecb2b5000` — **같은 트리**. 커밋은 exit 0 ·
`git status --porcelain` **빈 출력** · `git diff ae9b2f52 HEAD` **0 줄**이다. 되돌린 트리가
main 의 트리 **그 자체**(main 에 머지된 상태로 CI 를 통과한 그 트리)이므로 그 트리의
compile·test·게이트는 main 의 측정이고, 이 slice 의 HEAD 가 초록인 것과 무관하다. 앞 여덟
측정은 base 트리(`c8d8f211…`)와 같았고 그 트리에서 ④~⑥ 을 실제로 돌려 통과를 얻었다 —
병합 뒤에는 대상 트리가 main 트리로 바뀌는 것이 정상이다.

### 빈 등식이 건전성의 증거가 아니다 — 음성 대조

목록에서 **한 경로만 빼고**(`ml-engine/src/ml_engine/training/jobs/store.py`) 같은 복원을
돌렸다: 되돌린 트리 `5525c688…` ≠ main 트리 · `git diff --name-only ae9b2f52` 가 **그 한
경로를 정확히** 출력 · 아래 표지 계수가 24 → 25. 등식이 **판별력을 갖는다**는 실측이다.
바꿔치운 뒤 전건을 다시 돌려 ①~③ 과 트리 동일성을 재현했다.

`git grep -l` 의 파일 수(플래그를 패턴 **앞**에 둔다 — 뒤에 두면 pathspec 으로 먹혀 조용히
0 이 된다, 실측):

### ⑥ 의 보완 경로 — **복원을 커밋해야 초록이 된다**

`contractGate` 는 `contracts/` 의 작업 트리가 비어 있을 것을 요구하는데 `git restore` 는
변경을 미커밋으로 남기므로 복원 자체가 그 게이트를 붉힌다. 게이트의 결함이 아니라 절차의
미완이다 — 되돌림은 미커밋 편집이 아니라 **커밋**으로 끝나야 한다. `contracts/` 를 만지는

**목록이 in_scope 를 넘지 않는지도 함께 세었다**(수정 라운드가 만든 새 파일 ↔ in_scope 대조):

## 실측 유효성 대조(verifier 용)

실측 HEAD 와 판정 SHA 가 다른 것은 구조적이다(evidence 커밋은 언제나 마지막 산출물 커밋 뒤에
온다). 대조할 것은 **그 사이에 되돌림 대상이 움직였는가**다:

```
git diff --name-only 7ee29347..<판정 SHA> -- <위 목록의 40 경로>
```

빈 출력이면 유효, 한 줄이라도 나오면 미검증. 제외 목록을 따로 관리하지 않고 **이 문서의 목록
자신**을 대조 경로로 쓴다. 이 술어는 빈 출력이 아닐 수 있다 — evidence 커밋이 되돌림 대상인
evidence 파일을 고치면 그 파일이 출력에 나온다. 그때 미검증으로 끝내지 않고 **판정 SHA 에서
다시 재는** 것이 절차다(경로 집합이 같으면 같은 트리를 만들므로 결론은 트리 해시 동일성이다).
