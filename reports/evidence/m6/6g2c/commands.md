- **import 그래프 게이트의 경계** — 동적 import 와 목록 밖 네트워크 경로는 두 층 모두 보지 못한다

### 새 public 표면 (설계 검토 (2b) 값 획득 축)

계약의 (2b) 는 「새로 public 이 되는 선언은 없어야 한다」였다. **넷이 생겼다** — 전부 읽기만 나른다.

| 표면 | 왜 생겼나 | 밖에 허락하는 것 |
|---|---|---|
| `RunStateLock.Unlockable` | 잠금 실패 사유를 둘로 가른다(D-2) | 읽기만 — 닫힌 어휘의 값 하나 |
| `CollectionExitCode.UNLOCKABLE` | 그 사유의 종료 코드(4) | 읽기만 — 열거 값 하나 |
| `UnusableRawRowCause` | 버린 원문 행의 원인 어휘(D-20) | 읽기만 |

### 이탈과 알려진 제한

- **in_scope 정정 둘을 받았다.** `workflow/build.gradle.kts`(test 입력 선언 블록만 — r3
  D-6G2c-33) · `config/quality/architecture-policy.properties`(r8 ①). 후자는 전송 표면 **쌍 셋
  등재**이고 키·뿌리·술어 무변경이다. 두 종류가 섞여 있다: 자물쇠 파일 분리로 **같은 참조가 새
  클래스 이름**으로 관측된 것(`RunStateLockKt->FileChannel`·`->FileLock`)과, 사유를 값으로 가르는
  분류가 생기며 **새로 선 참조**(예외 타입 셋 — 겹침·인터럽트 둘). 예외 타입이라 밖에 허락하는
  것은 없다. 분류를 파일 수준 함수로 뺀 뒤에는 그 셋이 전부 `RunStateLockKt` 에 선다 — 게이트의
  **양방향** 등식이 그 이동을 죽은 줄로 잡아 냈고(`RunStateLock->OverlappingFileLockException`),
  그 줄은 지웠다. 등재가 관측보다 넓어질 수 없다는 뜻이다.
- **D-6G2c-21 ⑦ 의 절반은 러너까지다.** 러너 단위로는 판독 불가 원장 + 밖에서 잠긴 디렉터리가
  `ALREADY_RUNNING` 으로 끝난다. **전 조립 기동**은 그렇지 않다 — 상한 원장 seed 가 Busy 경로에서도
  시도 원장을 읽으므로 그 읽기가 먼저 던진다. 고치려면 seed 를 늦추거나 Busy 에서 0 으로 시작해야
  하고 후자는 막아 둔 변이(KM3)와 같은 모양이라 하지 않았다. `OPEN-6G2C-BUSY-SEED-ORDER` 가 든다 —
  그 이름과 「러너까지」 한정이 `RunStateDirectory` 의 KDoc 에도 적혀 있다(저장소에 남는 문장과
  OPEN 이 갈리지 않게). 이중 결함(동시 기동 + 판독 불가 원장)에서만 보이고 호출은 0 이다.
- **러너 로그 줄의 칸이 아홉에서 열둘이다**(원인 셋). runbook 의 「계수 아홉」 문장은 팀장이
  「당시 코드」 한정으로 닫았다(이 slice 범위 밖).
- **D-6G2c-5** 는 코드 0 이다. 한 인스턴스를 여러 스레드가 쓰면 장부가 깨진다는 성질은 그대로이고,
  막는 것은 「쓰는 자리가 없다」와 프로세스 잠금이다.
- `adapters` 의 등재 ↔ 소스 양방향 등식은 **패키지마다** 서 있고 여섯(audit·evaluation·event·ml·
  profile·qualification)만 덮는다. 덮이지 않는 패키지도 **여섯**이다 — contract·extraction·koneps·
  persistence·snapshot·strategy. 그래서 snapshot 의 여섯이 게이트 밖에 있었다. 등식을 세우는 것은
  술어 확장이라 `OPEN-6G2G-REGISTRATION-PACKAGE-COVER` 로 6G-2g 가 받는다.
- **두 모드 동시 기동 test 의 잠금 해제는 Spring 의 실패 정리에 기댄다**(cr K-9). `refresh()` 가
  주입 모호함으로 깨질 때 두 실행 상태 빈의 `close()` 는 `destroyBeans()` 가 부른다. 공고 갈래가
  클래스 공유 디렉터리를 쓰므로, 그 정리가 바뀌면 같은 클래스의 뒤 기동이 조용히 `Busy` 가 된다.
- cr K-6(등재만·사후 승인 동의) · K-7(D-18 형식·판독 술어 무변경)은 수용이고 바꿀 것이 없다.
  vr I-1(반사로 `internal` 놓기 호출 가능)은 6G-2g 반사 OPEN 의 입력이다 — 계약 r9 가 정본이다.
