## 설계 검토 (2) 의 우회 ↔ 무엇이 막는가

| 우회 | 막는 것 | 실측 |
|---|---|---|
| 1. 역할 복원 생략 | 3중 — 역할 존재 단언 · `pg_restore --exit-on-error` · `privilegeMatrix` 등식(표·시퀀스·함수) | 앞 둘을 무력화해도 `등식 어긋남: privilegeMatrix / bidvector_app` 로 붉다. 시퀀스 USAGE·함수 EXECUTE 회수도 각각 붉다 |
| 2. manifest·백업 바이트 변조 | 복원 전 sha256 대조(`roles.sql`·`db.dump`) + **manifest 형식 단언**(object · `schema` · `measurements` object) + jq 실패를 받는 명시 분기 | 해시를 바꾸자 exit 1. manifest 를 깨뜨린 다섯 경우가 양방향 열 번 전부 exit 1 — 앞 판은 열 번 다 「일치」였다 |
| 3. IDENTITY 현재값 누락 | `sequences` 등식 | 값을 바꾸자 `등식 어긋남: sequences / api_request_audit_id_seq` |
| 4. 프로젝트 밖 컨테이너 지목 | **구조** — 원본은 지목한 compose 파일이 **만든** 서비스여야 하고(`config_files` 라벨 대 realpath, 이름 대조가 아니다) 읽기만 한다. 복원 대상은 라벨이 **존재하고** 값이 이 실행의 표식과 같은 컨테이너뿐이며, 비거나 공백뿐인 표식은 인자 검사에서 거부된다 | 같은 이름으로 띄운 foreign compose 프로젝트를 가리키자 exit 3 · 라벨 없는 컨테이너에 빈 표식·공백 표식·틀린 표식 전부 exit 3 · 모르는 서비스 exit 3 |
| 5. 자격 값을 argv·URL 에 실음 | 접속이 전부 소켓이거나 자기 컨테이너 netns 의 루프백이라 **자격 값이 아예 없다** · 백업 산출물 참조형 스캔 | 스캔 0 건. Flyway 호출자가 읽던 환경변수 갈고리도 없앴다 — 아무도 채우지 않는 이름이라 호스트에 우연히 같은 것이 있으면 조용히 쓰였다 |
| 6. 빈 DB 가 아닌 곳에 복원 | 대상 데이터베이스가 이미 있으면 거부 | exit 3 |
| 7. `pg_dump` 텍스트 골든을 게이트로 | 불채택 — 판정은 전부 카탈로그 질의 결과의 등식이다(D-3D-6 과 같은 선택) | 해당 없음 |

`functions`·`triggers`·`constraints` 축도 같은 방식으로 살아 있음을 확인했다(각각 값을 바꾸자 그 측정과
이름을 댔다). 손 안 댄 두 manifest 를 비교하면 「어긋난 측정 0」이므로 판정이 늘 붉은 것도 아니다.

## 새 public 표면

셸 스크립트 셋(`tools/db-backup.sh`·`db-restore.sh`·`db-rehearsal.sh`) · CI step 하나(S-23c) · runbook 하나.
**Kotlin 코드 0 · 새 마이그레이션 SQL 0 · 새 DB 객체 0 · 새 HTTP 표면 0 · 새 설정 키 0.**
임시 `V18`·`V19` 는 리허설이 임시 디렉터리에 만들고 지우며 커밋되지 않는다(`git status` 가 매 실행 뒤 깨끗하다).

## 지시와 구현이 갈린 두 자리 (r2 D-6B2-5 ③ 으로 **채택 처분**)

- **데이터 손실 축의 기대값을 리터럴 13 으로 박지 않았다.** 지시는 「`candidateLimit=13`·`revision` 이
  돌아옴을 단언」인데, 13 은 S-23b 가 보내는 본문의 값이라 그것을 리허설에 적으면 같은 수가 두 자리에
  살고 한쪽만 바뀌면 조용히 어긋난다. 대신 **원본에서 읽어 복원본과 맞추고**, 원본의 전략 행이 비어
  있으면 「쓰기 왕복이 선행하지 않았다」로 끊는다 — 매직 넘버 없이 같은 사실을 재면서 **step 순서까지**
  잠근다(S-23c 를 S-23b 앞으로 옮기면 붉어진다). CI 에서 그 값은 13 과 `revision+1` 이다.
- **축9 권한 행렬을 해시가 아니라 행렬 그대로 담는다.** 지시는 「질의 결과 해시」인데, 해시는 어긋났다는
  사실만 주고 **어느 역할의 어느 표인지**를 지운다. 판정 문면이 「어느 등식의 어느 이름」을 대야 하므로
  객체를 담는다. r1 뒤에는 표만이 아니라 시퀀스·함수까지 담는다(L-2).

## 알려진 제한

1. **역할 암호는 백업에 담기지 않는다.** 팀장 지시는 `pg_dumpall --roles-only` 를 「금지 역할 제외 없이
   그대로」라고 적었지만, 같은 지시가 요구하는 「산출물에 자격 값 0」과 충돌한다 — 맨 형태는 로그인 역할의
   SCRAM 검증자를 평문으로 적고 그 한 줄이 참조형 스캔에 걸린다(실측: 맨 형태 1건, 제외 플래그를 건 형태 0건 —
   플래그 이름의 정본은 `tools/db-backup.sh` 의 호출 줄과 runbook §2 이다. 이 문서는 그 어휘를 축어로 적지 않는다).
   **보안 요구를 택했다.** 역할 *필터링*은 하지 않는다(모든 역할이 그대로 담긴다). 대가는 runbook §2 에
   적었다 — 운영 복원 뒤 로그인 역할의 암호를 별도 경로로 설정해야 한다.
   **r2 D-6B2-5 ① 로 채택 처분됐다** — 지시 문면은 역할 *필터링* 금지의 뜻이었다.
2. **이 저장소의 worktree 끼리는 같은 compose 프로젝트를 공유한다.** 파일에 이름을 박으면 모든 checkout 이
   같은 `bidvector-v2` 를 든다 — 닫히는 것은 디렉터리 basename 으로 **다른 저장소**와 충돌하는 축이다.
   갈라야 하면 파일을 고치지 않고 `COMPOSE_PROJECT_NAME`·`-p` 로 가른다. **r2 D-6B2-5 ② 가 정본**이고,
   앞 라운드에 적었던 「계약 문면이 어긋난다」는 그 결정으로 해소됐다(수용란은 r2 가 정정했다).
3. **Flyway `validate()` 의 자리.** `db-restore.sh` 는 validate 를 부르지 않고 이력 행 집합 해시 등식을
   그 자리에 둔다(validate 는 이력 행과 파일 체크섬만 보는 순수 함수다). 실제 호출은 `db-rehearsal.sh` 가
   한다 — forward-fix 가 어차피 Flyway `migrate` 를 요구하기 때문이다. 운영 복원에서 validate 를 도는 것은
   앱 기동이다.
4. **리허설의 전제 둘.** 호스트에 `javac` 가 있어야 하고(CI 는 `setup-java` 가 JDK 를 준다) 앱 이미지가
   빌드돼 있어야 한다(CI 는 S-21b). 없으면 exit 2 로 그 사실을 댄다.
5. **`tables`·`columns` 는 이력 표를 재지 않는다** — `flywayHistory` 가 더 강한 측정으로 그 표를 전담한다.
   권한 행렬에는 그대로 남는다.
6. **복원 대상 클러스터의 슈퍼유저 이름이 원본과 같아야** 소유권과 `SECURITY DEFINER` 가 보존된다.
   스크립트가 manifest 의 소유자 이름으로 대상을 만들어 이 축을 닫지만, 손으로 복원할 때는 사람의 몫이다.
7. **착수 조사 노트의 줄 범위 하나가 낡았다.** S-23c 삽입이 `container` job 의 끝줄을 밀어
   `_workspace/m6-6b2/00_scout.md` 가 적은 그 job 의 줄 범위가 어긋난다(앞쪽을 가리키는 두 범위는
   그대로다). 그 디렉터리는 gitignore 아래의 읽기 전용 착수 노트라 이 레인이 고치지 않는다 —
   추적되는 문서에는 이 slice 가 편집한 파일을 줄 번호로 가리키는 자리가 없다(`git grep` 전수 0).
8. **논리 백업만이다.** PITR·WAL·보존 기간·암호화·저장 위치는 경계 밖(6B-3·M7, 운영자 결정 A-1 (a)).
9. **권한 행렬의 남은 범위.** r1 뒤 표·시퀀스·함수를 잰다(L-2). 스키마 자체의 `USAGE`·`CREATE`, 타입·도메인,
   기본 권한(`ALTER DEFAULT PRIVILEGES`)은 아직 재지 않는다 — 이 스키마에 그 선언이 없어 실측 경로가
   없었다. 어긋남 보고는 측정과 **역할 이름**까지 대고 그 안의 어느 객체인지는 대지 않는다(한 단계만 파고든다).
10. **리허설이 검사하는 마이그레이션은 이 checkout 의 것이다**(G-3 선택). Flyway classpath 에서
   `/jvm/migrations` 가 앱 이미지의 jar 보다 앞에 선다 — 낡은 이미지로 로컬 실행하면 체크섬에서 붉어진다.
   Flyway·방언·드라이버 자체는 여전히 출하 이미지의 바이트다.
