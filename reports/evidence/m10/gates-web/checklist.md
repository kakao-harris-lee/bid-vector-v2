  판보다 나빴다**. 「다시 썼으므로 두 판의 결함을 둘 다 피했다」가 축 전수 없이는 서지 않는다는

## 3. 알려진 제한

① **Kotlin 을 텍스트로 읽는다.** node 에 Kotlin 파서가 없어 이 모듈은 **Kotlin 주석 문법**만 다루고
문법 전체의 정확성을 주장하지 않는다. 다룰 수 없는 꼴은 **던진다** — raw string · **템플릿 식 안의
따옴표·주석 표지** · 닫히지 않은 문자열·문자 리터럴·블록 주석·백틱 식별자·템플릿 식 이다. 읽기
집합에 raw string 이 **0** 이고 템플릿 식 둘은 전부 따옴표가 없어 오늘 거동 공백은 없고, 그 꼴이
생기는 날 RED 로 사람을 부른다. 읽기를 넓히지 않은 근거는 `design-review.md` §3.

**r1 정정 — 이 열거에 축 셋이 빠져 있었다**(cr r0 HIGH 1 · LOW 2). 문자열 **템플릿 식** 안의
따옴표를 문자열의 끝으로 읽어 `"${f("//")}"` 를 절단했고(**앞 두 판과 같은 실패**를 물려받은
축이다) · **백틱 식별자** 안의 `'` 가 문자 리터럴을 열어 정당한 Kotlin 을 던졌으며(앞 두 판은
그 입력에서 우연히 옳았으므로 **앞 판보다 나쁜** 자리다) · **CRLF 의 `\r`** 을 주석과 함께 지웠다
(줄 수가 그대로라 아무 대조도 붉어지지 않는 **조용한 값 변경**). 축별 전·후 측정은
`design-review.md` §2b. 빠진 축은 열거의 부정확이기 전에 **미측정**이다 — 축이 없으면 그 축의
변이도 없고, 변이 없는 초록은 방어가 아니라 안 재 본 자리다.

**좁힌 꼴 하나를 명시한다**(r1, 팀장 승인) — **템플릿 식 안의 문자 리터럴** `"${c == '}'}"` 은
r0 가 **우연히** 옳게 냈는데 r1 은 **던진다**. 중괄호 깊이로 식의 끝을 찾으면 `'}'` 안의 `}` 가
식을 일찍 끊고, 끊긴 자리 뒤의 따옴표가 다시 문자열의 끝으로 읽혀 **HIGH 와 같은 절단이 그대로
다시 열리기** 때문이다. 우연히 맞는 답을 남기는 것보다 **거절이 이 층의 성질**이라 좁히는 쪽을
골랐다. 읽기 집합에 이 꼴은 **0** 이고, 그 입력을 test 가 축어로 든다.

② **사본이 되살아나는 축의 술어가 ~~텍스트다~~ — r2 가 구조로 옮겼다**(verifier r1 M-2).
r1 의 텍스트 술어는 **사본을 쓰는 한 가지 표기**(`replace(/\/\/…`)만 재고 있었고, 표기를 바꾼
변이 둘이 **초록으로** 지나갔다(`commands.md` 「r2 변이 실측」). 이제 공유 모듈이 **읽기까지**
소유하고(경로 표는 비공개 · 소비자는 키만 넘긴다) 술어는 **AST** 다 — `.kt` 경로 리터럴이 공유
모듈 밖에 있으면 RED. 뿌리를 **훑으므로**(목록이 아니다) 새 소비자가 조용히 빠지지 않는다.

**남은 미달은 하나로 좁혀졌다** — 경로를 **조립**해 만든(`'…Basis' + '.kt'`) 것은 리터럴 술어에
걸리지 않는다. 의도적 우회는 리뷰 소관으로 두고 등재한다. 이 미달은 가설이 아니다: **게이트
자신의 양성 대조가 그 조립을 쓴다**(통째로 적으면 그 파일이 자기 술어에 걸린다). 막는 것은
사고로 되살아나는 사본이고, 일부러 숨긴 경로가 아니다.

③ **값을 뽑는 쪽은 각 소비자에 남는다.** 공유로 옮긴 것은 주석 걷기 하나다 — 균형 괄호·전체
일치·헤더 계수는 복제가 아니라 서로 다른 함수다(§2b 의 「경계로 처리」 행에서 실측).

④ **걷어 낸 자리의 글자 하나를 바꿨다** — 줄 주석 뒤에 공백 한 칸이 남는다(주석 앞의 공백은 값 쪽
글자다). 줄끝은 **그대로 남긴다** — 블록 주석의 줄바꿈도(앞 두 판은 지웠다 — 줄 구조가 바뀌면
호출자의 다른 읽기가 엉뚱한 줄을 본다), **CRLF 의 `\r` 도**(r1 — 앞 두 판과 r0 판은 줄 주석과 함께
지웠다). 두 소비자가 줄 기반 읽기를 쓰지 않고(`indexOf`·`matchAll`·균형 괄호) 전부 `trim`·정규식을
지나므로 거동 차이가 없고, 읽기 집합 여덟에 CRLF 파일이 **0** 이라 오늘 바뀌는 값도 없다. 세 꼴을
test 가 축어로 든다.

⑤ **공유 파일 둘을 만진다** — 게이트 test 등록부(web 레인 전부)와 capability map(M10 네 레인).
**행을 고치지 않고 덧붙였다**(capability map diff 24 추가·0 삭제). 되돌림의 원천 조건은
`rollback.md`.

⑥ **10B 와 한 파일을 공유한다.** 10B 가 `money-vocab-cross-lang.test.mjs` 에서 명령 축을 걷는다.
이 slice 의 그 파일 편집은 **import 한 줄 + 지역 정의 삭제** 둘이고 호출부를 한 줄도 바꾸지 않아
10B 가 만지는 영역과 겹치지 않는다. 10B 선행 머지 시 main 을 병합해 해소하고, 접힘 여부를
**충돌 수가 아니라 계수**로 센다.

⑦ **이 slice 는 출하 코드를 바꾸지 않는다.** 변경은 게이트·하네스·장부뿐이라 거동 회귀의 자리가
없고, 그래서 ①~⑥ 의 어느 제한도 운영 경로에 닿지 않는다.

⑧ **`npm run test` 가 한 번 exit 1 을 냈고 원인을 모른다**(r1). 같은 실행의 요약은 **`889 passed`**
였다 — **통과 수와 종료 코드가 갈렸다**. r1 트리에서 **17 회 중 1 회**이고, 그 뒤 16 회(연속 10 회
포함)는 전부 exit 0 이며 어느 로그에도 `Unhandled`·`ERR_` 절이 없다. **그 한 번의 로그는 측정 중
지워 버려 원인 절을 보지 못했다** — 그래서 원인 미상으로 등재한다(추측을 결론으로 적지 않는다).
가설 하나는 있다: 이 묶음에는 **ESLint Node API 를 실제로 돌리는 test 파일**이 있어(`scripts/`의
선택자 게이트 test) 요약 **뒤에** 뜨는 비동기 오류가 vitest 를 exit 1 로 만들 수 있다. 그 파일은
**r1·r2 가 건드리지 않았다**.

**다른 레인의 비슷한 꼴과 같은 원인으로 접지 않는다**(팀장 결정 2026-11-12). 10B 가 본 것은
**서명 A** — 같은 ESLint test 의 첫 칸이 콜드 기동 timeout 으로 **failed ≥ 1 로 보고되는** 꼴이고
부하 민감성이 실측됐다. 이 slice 가 본 것은 **서명 B** — **전부 통과인데 exit 1** 이고 부하와
무관할 수 있다. 「ESLint test」라는 이름이 겹친다고 한 원인으로 묶으면 **하나를 고치고 다른
하나를 닫았다고 오판한다**. 두 서명은 M10 종결 장부의 **별건 후속**이고 이 slice 의 in_scope
밖이다 — 여기서는 서명 B 의 재현 조건과 분포만 사실로 남긴다.

**반복 실행 exit 분포** — r1 트리 **17 회 중 exit 1 이 1 회**(그 뒤 연속 16 회 exit 0) · r2 트리
**6 회 중 0 회**(전부 exit 0 · 900 passed). 합쳐 **23 회 중 1 회**이고 어느 로그에도 `Unhandled`·
`ERR_` 절이 없다. 기록은 `tee` + `PIPESTATUS` 로 남겼다 — 그 한 번만 로그가 없는 이유가 이것이다
(측정 형식을 고치기 **전**의 실행이었다).
