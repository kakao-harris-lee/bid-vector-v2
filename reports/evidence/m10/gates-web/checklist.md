## 2. 게이트의 힘 — 무엇이 RED 를 만드는가

전수와 수치는 `commands.md` 「변이 실측」. 요점 둘.

- **두 앞 판의 결함 집합이 서로 다르다** — 정규식 판은 URL 리터럴을 절단하고, 보존판은 그 축은
  맞지만 문자열 안 블록 주석 글자·escape·문자 리터럴에서 깨진다. 그래서 「보존판을 공유 자리로
  옮긴다」로는 닫히지 않았다(꼴별 전수는 `design-review.md` §2b).
- **통제군이 초록이다**(주석 한 줄만 바꾼 변이). 하네스가 「아무 변화」가 아니라 **거동 변화**에
  붉어지는 것을 그 줄이 잰다.
- **r1 — 전수가 전수가 아니었다.** 위 두 줄은 r0 에서 **상태 넷**만 돌아본 것이고, 문자열 안에
  코드가 들어오는 축(**템플릿 식**)·식별자 축(**백틱**)·줄끝 축(**CRLF**)이 빠져 있었다. 그 셋을
  넣고 재면 r0 의 공유 읽기는 템플릿·CRLF 에서 **앞 두 판과 똑같이 틀렸고** 백틱에서는 **앞 두
  판보다 나빴다**. 「다시 썼으므로 두 판의 결함을 둘 다 피했다」가 축 전수 없이는 서지 않는다는
  것이 이 라운드의 값이다.

## 3. 알려진 제한

① **Kotlin 을 텍스트로 읽는다.** node 에 Kotlin 파서가 없어 이 모듈은 **Kotlin 주석 문법**만 다루고
문법 전체의 정확성을 주장하지 않는다. 다룰 수 없는 꼴은 **던진다** — raw string · **템플릿 식 안의
따옴표·주석 표지** · 닫히지 않은 문자열·문자 리터럴·블록 주석·백틱 식별자·템플릿 식 이다. 읽기
집합에 raw string 이 **0** 이고 템플릿 식 둘은 전부 따옴표가 없어 오늘 거동 공백은 없고, 그 꼴이
생기는 날 RED 로 사람을 부른다. 읽기를 넓히지 않은 근거는 `design-review.md` §3.

**r1 정정 — 이 열거에 축 셋이 빠져 있었다**(cr r0 HIGH 1 · LOW 2). 문자열 **템플릿 식** 안의
따옴표를 문자열의 끝으로 읽어 `"${f("//")}"` 를 절단했고(**앞 두 판과 같은 실패**를 물려받은
축이다) · **백틱 식별자** 안의 `'` 가 문자 리터럴을 열어 정당한 Kotlin 을 던졌으며(앞 두 판은
그 입력에서 우연히 옳았으므로 **앞 판보다 나쁜** 자리다) · **CRLF 의 `\r`** 을 주석과 함께 지웠다
(줄 수가 그대로라 아무 대조도 붉어지지 않는 **조용한 값 변경**). 축별 전·후 측정은
`design-review.md` §2b. 빠진 축은 열거의 부정확이기 전에 **미측정**이다 — 축이 없으면 그 축의
변이도 없고, 변이 없는 초록은 방어가 아니라 안 재 본 자리다.

**좁힌 꼴 하나를 명시한다**(r1, 팀장 승인) — **템플릿 식 안의 문자 리터럴** `"${c == '}'}"` 은
r0 가 **우연히** 옳게 냈는데 r1 은 **던진다**. 중괄호 깊이로 식의 끝을 찾으면 `'}'` 안의 `}` 가
식을 일찍 끊고, 끊긴 자리 뒤의 따옴표가 다시 문자열의 끝으로 읽혀 **HIGH 와 같은 절단이 그대로
다시 열리기** 때문이다. 우연히 맞는 답을 남기는 것보다 **거절이 이 층의 성질**이라 좁히는 쪽을
골랐다. 읽기 집합에 이 꼴은 **0** 이고, 그 입력을 test 가 축어로 든다.

② **사본이 되살아나는 축 — r3 가 구조로 옮겼고, 남은 구멍을 측정으로 가른다.**
r1 의 술어는 **텍스트**였고 표기를 바꾼 사본 둘이 초록으로 지나갔다. r2 는 AST 로 옮겼으나
**그 술어도 반쯤 열거였다** — 뿌리 둘·확장자 셋을 손으로 적어, 그 목록 밖(`web/config/`·`.js`·
`.mts`)의 **조립 없는 완전한 리터럴 경로**를 보지 못했다(verifier r2 H-1). 게다가 「원문이 없으면
걷을 것이 없다」는 논거가 **틀렸다** — 걷힌 텍스트에도 문자열 안 `//` 가 남아 **덧씌우는 사본**이
살아 있었다(H-3).

**r3 가 닫은 것**(각각 변이로 실측 — `commands.md` 「r3 변이 실측」):
- 뿌리 = `web/` 전체에서 **생성물만** 제외 · 확장자 = **컴파일러 정의**의 JS/TS 전 계열.
- 경로 꼴 = **확장자로 끝나는 모든 리터럴·템플릿 조각**(`/` 요구를 버렸다 — `resolve(dir, 'X.kt')`
  는 난독화가 아니라 평범한 관용구다).
- **export 집합 전수**(모듈 네임스페이스 등식 — r4 부터 **셋**이다: 걷기는 내부 모듈로 갔다) — r2 의 설계 검토는 이 단언이 있다고 **적었지만
  없었다**(H-2). 경로 표·원문 reader 를 한 줄 더하면 이제 등식이 깨진다.
- **걷기 획득 축** — 걷기는 **내부 모듈**에 있고 공개 표면에 없다(r4). 그 **이름이 어느 리터럴에든**
  나타나는 파일은 소유 모듈과 그 단위 test 둘뿐이다(r5 — 지정자 수집을 버린 이유는 백틱·`new URL`·
  `import.meta.resolve`·상수 경유가 전부 지나갔기 때문이다).
- **경로 축** — 확장자 **토큰**이 어느 리터럴에든 있으면 RED(r5). 파일 이름만 쓴 꼴·셸 파이프·
  정규식 리터럴·중괄호 glob 이 그래서 닫혔다.

**r6 이 닫은 것**: 경로 토큰을 「점 바로 뒤 kt」에서 **단어 꼴**로 내렸다 — `*.{kt,kts}`(r4 가
닫았다가 r5 에서 **조용히 회귀**한 꼴) · 두 확장자 정규식 · 문자 클래스 · 점 없는 확장자가 함께
닫힌다. 그 회귀를 다시 놓치지 않도록 **네 꼴을 양성 대조에 상설**로 뒀다. 단언 전수는 **한 단계
중간 변수**까지 따라간다(실제 호출 열여덟 중 여덟이 그 꼴).

**닫히지 않은 것**(정직하게 — 미달 ①②⑤⑥⑧⑨**⑩**. ⑦ 은 r6 이 이름 축을 데이터 파일까지 넓혀 **닫혔다**):
- **글자 단위 조립**(`'.k' + 't'`). r2 의 미달 문면은 「경로 조립」이라 적어 조립 전체를 덮는 것처럼
  읽혔는데, 조립·템플릿·확장자 변수 **셋은 r3 가 닫았다**. 남은 것은 글자 단위 하나이고 거기서는
  「일부러」가 사실이 된다. 이 게이트의 양성 대조가 그 꼴을 쓴다.
- **import 없는 지역 사본**. 측정으로 갈랐다 — 줄을 끊는 꼴(`indexOf` 절단 · `replace(/\/\/…/)`)은
  **안쪽 `assertStrippedKotlin` 이 던지고**, 줄을 끊지 않는 치환(`replaceAll` 로 표지만 지우는 꼴)만
  **조용하다**(값은 `https://…` → `https:…` 로 망가진다). 그 구멍에 **표기를 찾는 텍스트 층**을
  2 차로 두되 **「완화」라고 이름 붙였다** — 표기를 바꾸면 열리는 층을 「닫았다」고 부른 것이 r1 의
  실패였다.

③ **값을 뽑는 쪽은 각 소비자에 남는다.** 공유로 옮긴 것은 주석 걷기 하나다 — 균형 괄호·전체
일치·헤더 계수는 복제가 아니라 서로 다른 함수다(§2b 의 「경계로 처리」 행에서 실측).

④ **걷어 낸 자리의 글자 하나를 바꿨다** — 줄 주석 뒤에 공백 한 칸이 남는다(주석 앞의 공백은 값 쪽
글자다). 줄끝은 **그대로 남긴다** — 블록 주석의 줄바꿈도(앞 두 판은 지웠다 — 줄 구조가 바뀌면
호출자의 다른 읽기가 엉뚱한 줄을 본다), **CRLF 의 `\r` 도**(r1 — 앞 두 판과 r0 판은 줄 주석과 함께
지웠다). 두 소비자가 줄 기반 읽기를 쓰지 않고(`indexOf`·`matchAll`·균형 괄호) 전부 `trim`·정규식을
지나므로 거동 차이가 없고, 읽기 집합 여덟에 CRLF 파일이 **0** 이라 오늘 바뀌는 값도 없다. 세 꼴을
test 가 축어로 든다.

⑤ **공유 파일 둘을 만진다** — 게이트 test 등록부(web 레인 전부)와 capability map(M10 네 레인).
**행을 고치지 않고 덧붙였다**(capability map diff 24 추가·0 삭제). 되돌림의 원천 조건은
`rollback.md`.

⑥ **10B 와 한 파일을 공유한다.** 10B 가 `money-vocab-cross-lang.test.mjs` 에서 명령 축을 걷는다.
이 slice 의 그 파일 편집은 **import 한 줄 + 지역 정의 삭제** 둘이고 호출부를 한 줄도 바꾸지 않아
10B 가 만지는 영역과 겹치지 않는다. 10B 선행 머지 시 main 을 병합해 해소하고, 접힘 여부를
**충돌 수가 아니라 계수**로 센다.

⑦ **이 slice 는 출하 코드를 바꾸지 않는다.** 변경은 게이트·하네스·장부뿐이라 거동 회귀의 자리가
없고, 그래서 ①~⑥ 의 어느 제한도 운영 경로에 닿지 않는다.

⑧ **`npm run test` 가 한 번 exit 1 을 냈고 원인을 모른다**(r1). 같은 실행의 요약은 **`889 passed`**
였다 — **통과 수와 종료 코드가 갈렸다**. r1 트리에서 **17 회 중 1 회**이고, 그 뒤 16 회(연속 10 회
포함)는 전부 exit 0 이며 어느 로그에도 `Unhandled`·`ERR_` 절이 없다. **그 한 번의 로그는 측정 중
지워 버려 원인 절을 보지 못했다** — 그래서 원인 미상으로 등재한다(추측을 결론으로 적지 않는다).
**r3 정정 — 원인이 측정됐고 ESLint 가설은 틀렸다.** verifier r2 가 `vitest run` 전건을 **52 회**
돌려 **6 회**를 재현하고 둘의 꼬리를 잡았다: `src/AppRoot.test.tsx` 에서 **jsdom 이 내려간 뒤**
tanstack query 의 지연 notify 타이머가 발화해 `ReferenceError: window is not defined` 가 요약
**뒤에** 뜬다. 그래서 통과 수와 종료 코드가 갈린다. checklist 가 적었던 **ESLint Node API 가설은
그 둘이 지지하지 않는다** — 원인 파일이 `web/src/**` 라 이 slice 의 in_scope 밖이고, **고치지
않는다**(M10 장부의 별건 후속). 10B 가 본 서명 A(콜드 기동 timeout · failed ≥ 1)와도 **접지
않는다**(팀장 결정 2026-11-12).

**반복 실행 exit 분포** — r1 트리 **17 회 중 exit 1 이 1 회**(그 뒤 연속 16 회 exit 0) · r2 트리
**6 회 중 0 회**(전부 exit 0 · 900 passed). 합쳐 **23 회 중 1 회**이고 어느 로그에도 `Unhandled`·
`ERR_` 절이 없다. 기록은 `tee` + `PIPESTATUS` 로 남겼다 — 그 한 번만 로그가 없는 이유가 이것이다
(측정 형식을 고치기 **전**의 실행이었다).

## 4. 수정 라운드가 만든 새 파일 ↔ in_scope 대조

이 slice 가 **새로 만든 파일은 일곱**이다 — 공유 읽기 모듈 · 그 게이트 test · evidence 다섯
(계약·설계 검토·명령·이 파일·되돌림). 전부 계약의 in_scope 안이고 계약 갱신이 필요 없다.

**r1**(cr r0 HIGH·MEDIUM·LOW 셋 · verifier r1 M-1) — **새 파일 0**. 고친 일곱 파일이 전부 이미
in_scope 안이라 계약 갱신이 없었다(기계 대조: 변경 경로 집합에서 in_scope 패턴 밖이 **0**).

**r4·r5** — r4 가 **새 파일 하나**(내부 걷기 모듈 `kotlin-comment-strip.mjs`)를 만들어 `scope.md`
in_scope 에 넣었다(게이트 test 가 아니라 **모듈**이므로 등록부 대상은 아니다). r5 는 새 파일 0.
복원 목록은 그래서 아홉 → **열**이다(cr r3 HIGH① · verifier r4 M-4).

**훑기가 `git ls-files` 라 생기는 성질 하나**(cr r3 LOW): **스테이징 전 새 파일은 훑기에 들지
않는다**. 그래서 로컬에서 심은 파일은 `git add` 뒤에 재야 하고(변이 하네스가 그렇게 한다), CI 는
추적 파일만 체크아웃하므로 거기서는 이 성질이 공백을 만들지 않는다.

**r3**(verifier r2 H-1~H-3·M-1·M-2·L-1 · cr r1 MEDIUM①② · LOW③④) — **새 파일 0**. 고친 여섯
파일이 전부 이미 in_scope 안이라 계약 갱신이 없었다(기계 대조: 변경 경로 집합에서 in_scope 패턴
밖이 **0**).

**r2**(verifier r1 M-2) — **새 파일 1**(`kotlin-source-ownership.test.mjs`)이고 **계약 갱신 셋**을
했다(`scope.md` §r2). 둘은 예정된 추가(소유권 술어가 닿는 소비자 파일)이고, **셋째는 게이트가
찾아냈다** — `journey-up.mjs` 가 Kotlin 정본을 자기 `readFileSync` 로 열고 있었고 r1 의 소비자
열거에 없었다. 새 test 파일은 **만드는 커밋에서** 등록부(`web/config/gate-tests.txt`)에 등재했다.
라운드가 새 파일을 만들면 이 절을 in_scope 와 **다시 대조**한다.
