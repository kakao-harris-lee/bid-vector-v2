# M7/7E-2 — 점검표

## 0. 설계 검토 (Phase 2.5 — 구현 전, 팀장 수령 2026-10-30)

### 0.1 이 slice 가 세우는 것 한 문장

**운영자가 상태를 바꾸는 유일한 길은 계약의 전이와 편집 세션이고, 화면은 그 결과만 보인다.**
그것을 지탱하는 것은 규율이 아니라 구조다: 탭·다음 행동·값 칸·세션 상태가 전부
`satisfies Record<계약 enum, …>` 표에서 나오고(계약이 늘면 `tsc` 가 멈춘다), 조회 자리에
폴백이 없고, 쓰기는 승인 목록으로 좁혀진 생성 타입 클라이언트 한 자리를 지난다.

### 0.2 위협 모델 경계

**방어한다**: ① 화면이 V2 API 밖에서 값을 얻음 ② 근거 없는 숫자·지어낸 기본값 ③ **상태를
클라이언트가 추론**(지난 일정 · 탭 분류 · 세션 만료 · 자격 세 상태) ④ CSRF·세션 우회(7D 경계
재사용) ⑤ 개인정보(사업자번호 자리) ⑥ 여정이 화면 대신 API 만 검증 ⑦ 쓰기 실패가 조용히
지나감 ⑧ CSS·스타일 읽기를 통로로 쓴 데이터 유입.

**방어하지 않는다**: 시각 디자인 품질(운영자 리뷰 몫) · 7A N-10(계산 조립 `fetch`) · XSS 일반 ·
브라우저 확장 · 단일 운영자 전제 위에서 계약이 받아들인 경합(시평액 행 수 상한의 검사-삽입 창).

### 0.3 열거인가 구성인가

| 축 | 구성 | 열거로 두지 않은 이유 |
| --- | --- | --- |
| 상태 → 탭 | `satisfies Record<상태 14, 탭 6>` | 「묶음을 갱신하자」는 규율로는 누락이 조용하다. 계약이 상태를 늘리면 `tsc` 가 그 자리에서 멈춘다(변이 M2a 실측) |
| 상태 → 다음 행동 | `satisfies Record<상태 14, {primary, secondary}>` + 행동 → operation 표 | 상태마다 `if` 를 더하면 예외가 쌓이고, 계약 전이표에 없는 쌍이 버튼이 되어 409 가 정상 흐름이 된다 |
| 편집 세션 칸 → 요청 칸 | `satisfies Record<칸 13, 칸 4>` | 계약은 「`field` 가 이름하는 칸 **하나**」만 받고 나머지는 400 이다. 분기로 적으면 빠뜨림이 런타임에만 드러난다 |
| 자격 사실 세 상태 | 서버의 두 boolean 에서만 파생 | 목록 길이로 추론하면 「면허 없다고 신고함」과 「아직 아무것도 적지 않음」이 같아 보인다 |
| CSS 를 지나는 데이터 | 읽기 금지(DOM 심볼 해소) + 값 모양 | 「CSS 에 자료를 적지 말자」는 규율은 diff 로만 보인다. 읽는 길을 끊으면 적어도 닿지 못한다 |

### 0.4 우회 ≥ 5 — 각각 무엇이 막는가 (전부 실측)

| # | 우회 | 막는 층 | 실측 |
| --- | --- | --- | --- |
| 1 | 화면이 값을 **리터럴**로 냄 | 표시 문면이 표에서만 나오고 단위 test 가 표의 값과 대조 + 여정이 DOM ↔ 같은 실행 API 응답 대조 | 변이 M1(상태 배지를 리터럴로) → vitest 1 · **여정 ④ 1**(받은 값 「관심」을 적어 보인다) |

| 8 | **CSS + 스타일 읽기로 데이터 유입** | 읽기: `getComputedStyle`·`getPropertyValue` 가 **DOM lib 심볼로 해소되면** 위반(이름이 같은 내 함수는 아니다) · 쓰기: custom property 값 모양 | 읽기 프로브 → 게이트 1(두 이름 **각각**) / 쓰기 프로브 → 게이트 1 / **음성 대조**: 같은 이름의 내 함수(문자열 3건) → **게이트 0** |

| 12 | **여정이 남의 건을 민다** | 여정마다 **자기 공고**를 쓰고 클릭·단언을 **자기 카드 안으로** 좁힌다 | 첫 실행 실측: 화면 전체 locator 가 건 1·2 를 함께 집었다(strict mode violation) → 좁힌 뒤 통과 |

### 0.5 (2b) 값 획득 축 — 새 public 표면 전수

| 새 표면 | 값을 어디서 얻는가 | 경계 |
| --- | --- | --- |
| `display/bidBoxDisplay` 의 표 넷 | 계약 enum 에서 키, 문면은 이 파일이 짓는다 | 입력은 상태 하나뿐이고 폴백이 없다. 행동 → operation 은 **승인 목록에서 파생한 집합과 등식** |
| `display/editSessionDisplay` 의 표 다섯 + `valueBodyOf` | 계약 enum·전략 응답 | 본문에 `field` 가 이름하는 칸 하나만 싣는다. 수로 읽히지 않으면 **보내지 않는다**(0 을 지어내지 않는다) |
| `display/profileDisplay` 의 표 넷 + `businessDetailsBodyOf` | 계약 enum·프로필 응답 | 세 상태는 서버의 두 boolean 에서만. 등록이 아니면 두 칸을 싣지 않는다 |
| `screens/BidBoxScreen`·`BidBoxCard` | 위 표와 `queries.ts` 에서만 | 숫자·상태 문면 리터럴 0(변이 M1 이 그 자리를 잰다). 전송은 행동 종류 전수 `switch` + `never` |
| `screens/SettingsScreen`·`StrategySection`·`ProfileSection` | 같음 | 확인 화면의 값 둘 · 「준비 중」 자리에 입력칸 0 |
| `e2e/journey/shared` | 하네스 맥락 파일 · **승인 목록** | 목록을 복제하지 않는다(복제가 갈렸던 실측이 이 추출의 근거다). 문면 표는 spec 이 **따로** 적는다 — 화면의 표를 import 하면 양쪽이 함께 틀려도 초록이다 |
| `e2e/harness/bundle-shape` 의 `assertDistRoot` | 실제 디렉터리 항목 | 허용 집합을 산출물에서 읽지 않는다(모양을 못박는다) |
| `scripts/check-src-tree` 의 바뀐 술어 넷 | TS 해석 · Vite 해석 · 실제 CSS 텍스트 | 문자열 grep 0. 판정하지 못하면 **게이트 실패**다(해석 실패를 통과로 두지 않는다) |

**「경계로 처리」 행의 실측**: 번들(`dist`) 전수에서 하네스·설정 어휘 **여덟**을 셌고 **각각
0 건**이다 — preview 입구 두 환경변수 이름 · 하네스 스크립트 이름 둘 · DB 사용자 · DB 이름 ·
자격 헤더 이름 · `process.env` 참조. 이 slice 가 환경변수를 더하지 않았으므로 7E-1 과 같은
계수여야 하고, 실제로 그렇다.

번들에서 **0 이 아닌 어휘 하나**는 `password` 4 건이고 그것은 **값이 아니라 속성 이름**이다
(로그인 입력의 `type="password"`) — 누출 스캔 절에 그 읽기를 적었다.

TS 에서 `object` 커널 주입에 해당하는 자리는 **모듈 전역**이고 이 slice 가 더한 것은 없다
(`client.ts` 의 CSRF 값 하나가 7D 에서 왔고 그대로다). 편집 세션의 진행 상태는 컴포넌트
state 이고 모듈 전역이 아니다. 표는 전부 `const` 라 가변 상태가 없다.

## 2. 알려진 제한

1. **`BidCase` 에 공고명이 없다** — 카드 제목이 공고번호·차수다. 7E-1 제한 1(공고 단건 조회
   operation 부재)과 같은 구멍이고 담당은 7C①. **후속 Kotlin 후보**: 입찰 건에 공고 제목을
   싣거나 공고 단건 조회를 여는 것.
2. **`listBidCases` 에 총수 헤더가 없다** — 탭의 수는 **받은 행의 수**이고 「전체 몇 건」이라
   말하지 않는다. 7E-1 제한 3 과 같은 축. **후속 Kotlin 후보**: 총수 헤더 또는 집계 operation.
3. **소급 기록 경로가 어느 화면에도 없다** — 계약 전이표는 `DEADLINE_PASSED_UNRECORDED` 에서
   기록 간선을 남기지만 화면 C 의 표도 그 상태에 행동을 두지 않았다(7E-1). D 는 그 카드를 C 로
   보내고, C 에는 그 버튼이 없다. 7B·7E 후속.
4. **대사 결과·결과 확인 화면이 없다** — `reconciliationCandidate` 는 boolean 이고 그 대사의
   **결과**를 내는 표면이 계약에 없다(ⓑ 7C⑤). 그래서 D 는 그 축을 표시하지 않는다.
5. **`/outcome-correction`·`/defer`·`/skip` 을 쓰지 않는다** — 요구표 D 행에 없어 목록에 두지
   않았다. 정정은 결과 확인(7E-3) 몫이고, 나중에·건너뜀은 담당 화면이 정해지면 그 slice 가 쓴다.
6. **409 사유 표만 키가 `string` 이다** — `ErrorBody.code` 가 `type: string` 이라 `tsc` 가 전수를
   보장할 자리가 없다(7E-1 제한 5 와 같은 꼴). 여덟 코드는 test 의 목록이 잠그고, 서버가 새
   코드를 보내면 **그 코드를 그대로** 보인다.
7. **`OPEN-7E-GATE-RESIDUAL` ⑤ 의 전제는 화면이 쓰는 전이에 한해서만 잠겼다** — 여정 ④ 가
   `caseVersion` 증가를 실측하지만 계약 전체의 단언은 아니다. 버전을 올리지 않는 쓰기가 계약에
   들어오고 **화면이 그것을 쓰기 시작하면** 그때 붉어진다. 서버 멱등 키(7E-1 제한 14 의 7C 후속
   후보)가 들어오면 그쪽이 정본이 된다.
8. **잔여 ④ 의 쓰기 축에 구멍이 남는다** — 인용 문자열 안에 쉼표로 적은 자료처럼 **토큰 모양을
   지키는** 쓰기는 값 모양 술어가 보지 못한다. 그것을 받는 것은 읽기 금지 층이고, 둘이 함께
   있어야 닫힌다(읽기가 이 층의 무게다).
9. **여정의 반복 실행은 CI 와 다른 갈래를 탄다** — CI 는 버릴 DB 라 여정 ④ 가 늘 전이 갈래를
   타지만, 같은 DB 에 두 번 미는 지역 실행에서는 그 건이 이미 개찰 대기라 **전이 단계를 건너뛴다**
   (D 쪽 불변은 그대로 잰다). 7E-1 의 담기 멱등 처리와 같은 관례다.
10. **설정 여정이 전역 전략을 만진다** — 끝에서 조건을 비워 되돌리지만, 그 왕복 사이에 **전략
    개정이 둘 오른다**. 개정 번호에 기대는 단언을 다른 여정에 두면 안 된다(지금 그런 자리 0).
11. **장비 전제 둘** — 여정 e2e 는 `docker`(버릴 Postgres)와 Playwright 브라우저 시스템 패키지를
    전제한다(7E-1 제한 8 그대로).
12. **`container` job 은 이 레인이 돌리지 않았다** — 새 devDependency 가 0 이라 builder 단계의
    `npm ci` 입력이 바뀌지 않았지만, 이미지 위생·취약점 게이트의 판정은 **PR 체크가 든다**.
13. **게이트 스크립트가 권장 파일 한도를 넘는다** — `web/scripts/check-src-tree.mjs` 가 base
    에서 이미 1024 줄이었고 이 slice 가 술어 둘을 더해 **1108 줄**이다(권장 500). 기계적으로
    쪼개지 않았다: 절들이 **한 TS 프로그램과 한 `fail()` 장부**를 공유하고, 쪼개면 「전제가
    깨진 자리에서 아래 단계를 건너뛴다」는 구조가 흩어진다. **후속 후보**: 게이트를 술어 묶음
    별 모듈로 가르고 프로그램·장부를 주입하는 형태(그 변경은 게이트 술어를 건드리므로 자기
    slice 와 재검증이 필요하다).
14. **설정 화면의 전략 절과 프로필 절이 같은 읽기를 두 번 걸지 않는다** — 설정 화면이 세션
    판정용으로 `GET /api/strategy` 를 걸고 전략 절이 **같은 질의 키**를 쓴다. 프로필 읽기는
    전략 읽기와 독립이라 401 판정이 전략 쪽 하나에 달려 있다(프로필만 401 인 상태는 계약상
    같은 세션 경계라 생기지 않는다 — 그 전제를 여기 적어 둔다).
