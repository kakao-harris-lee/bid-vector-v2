# M7/7C② rollback

**실측 HEAD: `e4d000ff`**(이 slice 의 마지막 **산출물** 커밋 — 그 뒤 커밋은 evidence 뿐이다) ·
**base: `46ac0949`**(7B·7C④ 가 든 main).

되돌림은 range revert 가 아니라 **in_scope 경로 한정 복원**이다. 버릴 clone 에서 실측했고 원본
worktree 는 읽기만 했다(실측 끝에 변경 0 확인).

## 목록 — 기계 산출

`git diff --name-only <base>..<실측 HEAD>` 에서 **이 slice 의 evidence 디렉터리만** 제외한다(그
디렉터리는 slice 자신의 장부다 — scope.md). 손 목록이 아니라 라운드마다 다시 산출한다.

| | 수 |
|---|---|
| 되돌릴 경로 | **44** |
| base 에 있던 것(복원 대상) | 20 |
| 이 slice 가 새로 만든 것(삭제 대상) | 24 |
| 목록 등식 `comm -23`(기계 산출 ↔ 실제 변경) | **빈 출력** |

r1 이 넷을 늘렸다 — **추적표와 capability map** 이 산출물 4 의 이행으로 in_scope 에 들어왔고,
어휘 계약 test 와 독립 enum 파일이 새로 생겼다. 그래서 앞 라운드의 40 이 44 가 됐다.

**복원과 삭제를 섞으면 안 된다** — base 에 없는 경로에 `git restore --source=<base>` 를 걸면
pathspec 오류로 멈춘다.

## ①~⑥ 실측

| | 내용 | 결과 |
|---|---|---|
| ① | `git restore --source=<base> --staged --worktree --` (20) · 새 파일 삭제 (24) | exit **0** · exit **0** |
| ② | 되돌린 뒤 실측 HEAD 대비 계수 | D **24** · M **19** · A 1 |
| ③ | `git diff <base> -- <44 경로>` | **0 줄** |
| ③' | base 에 있던 20 의 blob | **같음 20 · 다름 0** |
| ③'' | 새 파일 24 의 존재 | **사라짐 24 · 남음 0** |
| ④⑤⑥ | 되돌린 트리에서 `check` | exit **0** · FAILED **0** · 400 task · 26분 35초 |

**갈음은 종료 코드가 아니라 ③·③'·③'' 다.** exit 0 만 보면 「되돌릴 것이 없어서 0」과 구별되지
않는다. ④⑤⑥ 은 되돌린 트리가 **서는지**를 보는 것이고, 되돌림이 옳은지는 트리 동일성이 말한다.

### 블롭 계수 술어 — 파일 종류마다 다르다

**이 자리에서 두 라운드 연속으로 거짓 경보를 냈다.** 한 술어(「base 쪽 blob 과 같은가」)로 전부를
재면 base 에 없는 파일은 그 질문 자체가 성립하지 않아 **전부 「다름」으로 나온다**. 종류를 갈라야
한다: base 에 있던 것은 **「blob 이 같은가」**, 이 slice 가 만든 것은 **「지금 없는가」**. 위 표는
갈라 센 값이고, 실측 스크립트도 그렇게 고쳤다.

## 내 표지 0 · 남의 표지 보존

트리 동일성과 별개로, 되돌린 트리에 이 slice 의 어휘가 남지 않고 다른 레인의 어휘가 깎이지
않았는지 따로 센다(이 slice 의 evidence 디렉터리 제외 — 되돌리지 않는 자리다).

| 표지 | 되돌린 트리 | base | |
|---|---|---|---|
| 투찰가 요청 계열 · 어휘 계약 test · 전략 편집 이중체 파일 · test 조립 · 새 오류 코드 · 하한율 근거 상태값 | **0** | 0 | 내 표지 없음 |
| 7B 입찰 건 응답 · 7C①b 제안 use case · 7C④ 프로필 표 · 7C④ 미판정 축 타입 · 공유 test 앱 · 제안 스키마 | 전부 **일치** | | 남의 표지 보존 |

미판정 축 타입이 **0 이 아니라 base 와 같은 수로 보존**되는 것이 이 표의 요점이다 — 이 slice 는
그 어휘를 **만든 것이 아니라 합쳤다**. 되돌리면 7C④ 가 가진 상태로 돌아가야 하고, 0 이 되면 남의
것을 깎은 것이다.

## 유효성 술어 (verifier 용)

이 실측이 판정 SHA 에서도 유효한지는 **「실측 HEAD == 판정 SHA」가 아니라**(evidence 커밋은 언제나
뒤에 오므로 둘은 영원히 다르다) **그 사이에 되돌림 대상이 움직였는가**로 본다.

```
git diff --name-only <실측 HEAD>..<판정 SHA> -- <위 44 경로>
```

이 출력이 비어 있으면 유효하고, 한 줄이라도 나오면 미검증이다. 실측 시점 확인값: **빈 출력**
(그 사이 커밋은 이 slice 의 evidence 뿐이고, 그 디렉터리는 되돌림 대상이 아니다).
