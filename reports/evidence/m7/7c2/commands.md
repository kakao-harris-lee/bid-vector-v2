CI 는 매번 새 checkout 이라 이 차이가 없다.

**정본은 병합 둘이 들어온 뒤의 실행이다**(`cr r3 M-2`). 앞 판의 391 task 실행은 병합 **앞** HEAD 의
것이라, `557393af`·`f4afe17e` 가 고친 래칫 상수 · 정책 파일 · 게이트 등록부 · OpenAPI 해소를 재지

## 3. S-20(one-command) 커버리지 — **돈 것만 적는다**

S-20 은 acceptance 의 **상위집합**이다. 전건을 한 번 더 돌리면 한 시간 동안 락을 쥐어 네 레인을
막으므로, **그 안에서 새로 재는 것 하나**(`qualityBaseline`)만 남기고 나머지는 이미 돌린 실행으로
갈음했다. 아래는 단계별로 **어느 실행이 덮는가**와 그 결과다.

| S-20 단계 | 덮는 실행 | 결과 |
|---|---|---|
| Kotlin `check` | §1 clean 전수 + S-20 안의 재실행 | exit 0 / BUILD SUCCESSFUL |
| Kotlin `qualityBaseline` | **S-20 안에서 실측** | BUILD SUCCESSFUL |
| Python S-1·S-1b install·extras | S-20 안에서 실측 | 통과(다음 단계로 진행) |

`--no-daemon` 이 남긴 daemon 하나를 PID 로 확인해 정리했다(다른 레인 것은 건드리지 않았다).

## 4. 변이 — 등재 하나를 지우면 그 게이트가 붉은가

**바꿔치기**다(더하기가 아니다): 등재 항목 하나를 **지우고** 그 게이트 test 를 돌린다. 버릴
clone 에서 돌려 공유 worktree 에 변이가 남을 사정거리를 0 으로 만들었고, 변이 전 작업 트리가
깨끗한지(`git status --porcelain` 빈 출력) 스크립트가 먼저 단언한다.

**통제군은 맨 앞과 맨 끝 둘**이다. 앞 통제군이 붉으면 그 뒤 RED 는 해석 불능이라 즉시 중단한다.

| 통제군 | 결과 |
|---|---|
| 선행 | GREEN · 네 class tests 21·19·3·13 / failures 0 |
| 후행(복원 뒤) | GREEN · 같은 수 · **시각이 선행과 다름**(`--rerun`, cache 적중 아님) |

복원 뒤 clone 트리 변경 0 · 원본 worktree 변경 0.

### r1 추가 — 문서 enum ↔ 구현 어휘 등식의 변이 둘

`verifier r1 M-1` 은 **문서의 enum 값 하나를 개명하고도 초록을 받았다**(생성 타입도 같이 바꾸면
W-5 바이트 등식까지 선다). 그 자리를 닫은 뒤 **같은 바꿔치기를 다시** 걸어 붉은지 쟀다.

| # | 바꿔치기 | 변경 줄 | exit | 붉어진 단언 |
|---|---|---|---|---|
| MV1 | 문서의 하한율 근거 상태 enum 값 하나 개명(+생성 TS 동반) | 4 | 1 | enum 클래스 칸의 `entries` 전수 등식 |
| MV2 | 덮개 표에서 고지 칸 한 줄 제거 | 1 | 1 | **덮개 등식**(문서의 enum 칸 전수 ↔ 이 파일이 덮는 칸) |

통제군은 앞·뒤 둘 다 GREEN(class 3 · tests 32 · failures 0)이고 **시각이 서로 다르다**(`--rerun`,
cache 적중이 아니다). 변이마다 복원 뒤 clone 변경 0 · 원본 worktree 변경 0.

**MV2 가 있어야 MV1 이 뜻을 가진다.** 덮개 등식이 없으면 「표에 적힌 칸만 검사하는」 test 가 되어,
새 enum 칸을 문서에만 더하고 표를 잊는 길이 그대로 남는다. MV2 는 그 표가 실제로 문서 전수와
묶여 있는지를 잰다.

> **이 표 둘은 r1 시점의 측정이고, r2 가 그 술어 하나를 지웠다**(`cr r3 H-1` · `M-1`). r2 에서 덮개를
> 뒤집으며 `문서 enum 칸 == 구현 표가 덮는 칸` 등식을 **옮겨 적지 않았다** — 그래서 r2~r3 사이에는
> MV2 가 재던 방어가 없었고, 위 「묶여 있는지를 잰다」는 그 구간에 대해 **거짓**이었다. r3 일괄이 그
> 등식을 복원하고 서로소 단언을 더했으며, 아래 r3 표가 MV2 와 MD 를 다시 RED 로 실측한 값이다.
> **게이트 술어를 바꾼 커밋은 severity 무관 표적 재검증 대상**인데(CLAUDE.md Phase 4 예외) 내가 그
> 규율을 r2 에서 적용하지 않았다 — 적용했다면 그 자리에서 드러났을 결함이다.

### r2 추가 — 새 등식 셋이 각자 무언가를 막는가

r2 는 **사상 함수의 손 문자열**을 개명하고 초록을 받았다(문서·타입·생성 타입이 다 맞아도 응답에
실리는 값만 따로 틀어지는 축). 그 자리를 닫은 뒤 같은 바꿔치기를 다시 걸고, 함께 세운 등식 둘도
공허하지 않은지 쟀다.

| # | 바꿔치기 | 변경 줄 | exit | 붉어진 단언 |
|---|---|---|---|---|
| MR1 | 판정 불가 사유의 사상 문자열 개명(문서·타입 불변) | 2 | 1 | **sealed 칸의 출하 사상 결과 등식** ← r2 에서 초록이던 자리 |
| MR2 | 문서에서 nullable enum 의 `null` 하나 제거 | 1 | 1 | nullable **역방향** 단언 |
| MR3 | 분류되지 않은 새 문자열 칸을 문서에 추가 | 2 | 1 | **뒤집은 덮개 등식** + 키 집합 등식 |

### 「실제로 돌았다」는 XML 시각으로 보이지 않는다

앞 라운드들의 통제군 문면은 「시각이 달라 cache 적중이 아니다」였다. **그 근거는 약하다** — 캐시가
출력을 풀어 쓰면 그 시각도 실행 창 안에 찍힌다. 증거는 Gradle 의 **task 상태 줄**이다.

| 회차 | task 줄 | 캐시·최신 표식 | 실행 test |
|---|---|---|---|
| 통제군(선행) | `> Task :app:test` | **0** | class 6 · 71 |
| MR1·MR2·MR3 | `> Task :app:test FAILED` | **0** | class 6 · 71 |
| 통제군(후행) | `> Task :app:test` | **0** | class 6 · 71 |

표식 0 이 그 회차에 그 task 가 **실행됐다**는 뜻이다. 복원 뒤 clone 변경 0 · 원본 변경 0.

**필터를 축어로 적는다**(`verifier r3 L-2`). 위 r2 표의 「class 6 · 71」은 아래 좁은 필터의 값이고,
그것만으로는 재현도 대조도 되지 않았다.

```
# r2 표(좁다 — 이 slice 표면만)
:app:test --tests 'bidvector.app.http.OpenApiBidPrice*' --tests 'bidvector.app.http.BidPriceRequest*' --rerun
# r3 재측정(r2 폭으로 되돌렸다 — 아키텍처 게이트와 이웃 계약 test 를 함께 덮는다)
:app:test --tests 'bidvector.app.architecture.*' --tests 'bidvector.app.http.OpenApi*' --tests 'bidvector.app.http.*BidPrice*' --rerun
```

**좁은 필터의 초록은 「방어 있음」이 아니라 「안 쟀음」과 구별되지 않는다** — r2 에서 그 폭이 붉혔던
표면(사상 함수 둘)을 좁은 필터는 덮지 않는다.

**셸 인용 결함 하나를 겪었고 측정에는 영향이 없었다.** 큰따옴표 안의 백틱이 명령 치환으로 읽혀
그 자리에서 없는 명령을 실행했다. bash 는 stderr 에 한 줄을 내고 **그 자리만 빈 문자열로 치환한 뒤
계속 진행**했으므로, 깨진 것은 회차 제목의 한 구절뿐이고 세 변이는 모두 돌았다. `bash -n` 은
문법상 정상이라 통과한다 — **구문 검사는 이 종류를 잡지 못한다.** 홑따옴표로 고쳐 다시 돌려 같은
결과를 받았고(로그 빈 출력), 위 표는 그 깨끗한 실행의 값이다.

### r3 추가 — 복원한 등식과 서로소 단언이 막는가

`cr r3 H-1` 이 가리킨 자리를 닫은 뒤, **두 변이를 각각 그 등식에 겨냥해** 걸었다. 하나는 verifier 가
판정 SHA 에서 **초록으로 실측한** 바꾸기이고, 하나는 레인이 r1 에 RED 로 재고 **r2 에서 잃은** 것이다.

| # | 바꿔치기 | 겨냥한 등식 | 변경 줄 | exit | 붉어진 단언 |
|---|---|---|---|---|---|
| MD | 문서에만 enum 한 줄(`noticeStatus` — **allowlist 에 있는 칸**) | 서로소 | 3 | 1 | 복원한 덮개 **+ 서로소** (둘) |
| MV2 | 구현 표에서 고지 칸 한 줄 제거 | 복원한 덮개 | 1 | 1 | 복원한 덮개 |

**MD 가 두 단언을 동시에 붉힌다**는 것이 이 표의 요점이다 — 그 길이 이중으로 닫혔다. 뒤집은 덮개만
있던 r2~r3 구간에는 **둘 다 초록**이었다(그 칸이 allowlist 에 이미 있어 합집합이 변하지 않았다).

| 회차 | task 줄 | 캐시·최신 표식 | 실행 |
|---|---|---|---|
| 통제군(선행·후행) | `> Task :app:test` | **0** | class 26 · tests 292 |
| MD · MV2 | `> Task :app:test FAILED` | **0** | class 26 · tests 292 |

필터는 **r2 폭으로 되돌렸다**(위 축어 블록의 둘째) — class 26 · 292 test 로, r2~r3 의 좁은 필터(6 · 71)
보다 넓다. 복원 뒤 clone 변경 0 · 원본 변경 0.

**실행 로그가 두 번 「죽음」으로 읽혔다.** 변이 스크립트의 보고 함수가 결과 파일에만 쓰고 stdout 에
아무것도 내지 않아, 실행 로그가 **설계상 0 바이트**였다. 측정은 두 번 다 정상이었지만 지켜보는 쪽에서
구별할 수 없다 — 「빈 로그」와 「죽은 실행」이 같은 값이다. 보고 함수가 stdout 에도 쓰도록 고쳤다.

### 변이가 재는 것을 망가뜨리지 않게 한 두 가지

- **properties 의 마지막 항목**을 지우면 앞 줄의 이어붙임 `,\` 이 다음 줄로 흘러 **파일 구조가
  깨진다.** 그러면 RED 가 와도 「등재를 지운 탓」인지 「파일을 깨뜨린 탓」인지 말할 수 없다.
  삭제 뒤 **고아 줄 0** 을 단언하고, 마지막 항목이면 앞 줄의 이어붙임을 정리한다.
- **Kotlin 표의 한 항목은 2~3줄**(`"이름" to` + 사유, 사유는 `+` 로 이어지기도 한다)이고 같은
  파일의 짝 목록에도 한 줄이 있다. 키 줄만 지우면 사유 문자열이 떠서 문법이 깨진다. 항목
  **전체 + 짝 줄**을 지운다. 지운 뒤 괄호 균형과 표 항목 수(30 → 29)를 Gradle 없이 먼저 검산했다.

첫 회차에서 ④ 셋은 **초록도 RED 도 아닌 「안 돎」**이었다 — 위 첫 번째 술어를 Kotlin 파일에도
걸어 삭제가 늘 실패했다. 스크립트가 그것을 `SKIP` 으로 말해 주지 않았다면 「변이 열둘 RED」를
「열다섯 중 셋은 방어가 없다」와 구별하지 못했을 것이다. **적용 표지를 회차마다 남기는 이유가
이것이다.**
