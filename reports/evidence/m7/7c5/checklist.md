### 0.2 응답 상태 축 — 열거 하나, 소진 `when`

공고 하나를 물으면 답은 다음 중 **정확히 하나**다. 「수집 전 · 수집 실패 · 결과 없음」을 한 값으로 접지 않는다(COL-04 의 「요건 없음 ↔ 수집 실패」와 같은 원칙).

| 상태 | 뜻 | 판정 |
|---|---|---|
| (404) | 그 공고 자체가 수집되지 않았다 | `notice` 행 부재 |
| `NOT_OPENED_YET` | 아직 개찰 전이다 | canonical 행 부재 **그리고** 그 공고의 투찰 마감이 주입 시계의 지금보다 뒤 — 개찰은 마감 뒤라는 도메인 사실에서만 유도한다(마감 미상이면 이 상태가 아니다) |
| `OPENED` | 개찰 완료 | 진행구분 라벨이 정책이 등재한 「개찰완료」 |
| `FAILED_BID` | 유찰 | 같은 정책의 「유찰」 |
| `REBID` | 재입찰 | 같은 정책의 「재입찰」 |
| `PROGRESS_UNRECOGNIZED` | 진행구분이 등재 밖 라벨이다 — 판정 불가를 정상으로 접지 않는다 | 라벨이 정책 열거에 없다 |
| `RESULT_ABSENT` | canonical 행은 있으나 개찰 결과 축이 비었다 | 행 있음 · 진행구분 부재 |
| `OBSERVED_NOT_PROMOTED` | 원문 관측은 있는데 결과로 승격되지 않았다 — **오늘 production 의 답**(§0.1) | canonical 행 부재 · 그 공고의 개찰 축 원문 존재 |
| `NOT_COLLECTED` | 개찰 축 원문도 없다 | 둘 다 부재 · 마감 지남 또는 마감 미상 |

- 진행구분 라벨 셋은 **versioned policy data 로 등재**한다(매직 문자열 금지). 정본은 `policy-values.md` 의 진행구분코드명 행(*"진행구분이 유찰, 개찰완료, 재입찰로 구분 됨"*, provenance `authoritative`).
- 상류 라벨 **원문은 응답에 싣지 않는다** — 상태만 낸다. 원문을 통과시키면 클라이언트가 한국어 문자열로 분기하고, 그 분기는 계약이 아니다.
- 「수집 실패」는 이 축에서 `NOT_COLLECTED` 안에 접힌다 — **알려진 제한**(§0.1 다섯째 줄, DB 에 그 사실이 없다). OPEN 으로 등재한다.

### 0.3 응답 필드 — 잠정과 확정을 **다른 칸**으로

응답 본문은 **평탄 스칼라**다(D-6A1-38 게이트가 `$ref`·`oneOf`·`object` 속성을 거부한다) — 그래서 잠정/확정 분리는 중첩이 아니라 **접두사와 상태**로 한다.

- 공고 축: 공고번호 · 차수 · 상태(§0.2 열거).
- 확정 축(`confirmedAward…`): 낙찰금액 — 원·통화·basis·과세·provenance 다섯을 함께 낸다(R-BASIS-06, 7C① 선례 「값만 있고 출처가 없는 응답을 만들 수 없다」).
- 잠정 축(`provisionalRankOne…`): 결과 종류(미관측 · 순위 부재 · 순위 중복(건수) · 결정) · 투찰금액(원·통화·과세) · 투찰율(분수) · **그 축 자신의 관측 시각**.
- 관측 시각 둘(부모 관측 시각 · 잠정 축 관측 시각)을 함께 내 소비자가 낡음을 스스로 판정한다(V5 KDoc 이 요구하는 비교 — 파생 플래그를 만들지 않는다).
- 참가업체수 · 실개찰일시.
- **싣지 않는 것**: 업체 상호 둘(§0.4) · 예정가격 · 개찰 기초금액 · 사정률 · 예비가격 15 · 추첨번호 · 진행구분 라벨 원문 · 계정·투찰 축(그것은 -b).

### 0.4 privacy 판정 — 다른 참가자 식별 정보

| 값 | 오늘 어디 있나 | 이 slice 의 판정 |
|---|---|---|
| 사업자등록번호 · 대표자명 | **없다** — 계약 미등재라 수집 경계의 allow-list 반전이 담는 단계에서 버린다 | 구조적으로 응답에 들 수 없다(읽을 열이 없다) |
| 잠정 1위 투찰업체 상호 | canonical 열 하나 · 원문(90일 뒤 마스킹) | **응답에 싣지 않는다** |
| 최종낙찰업체 상호 | canonical 열 하나 · 원문(같음) | **응답에 싣지 않는다** |

근거 넷.

1. 운영자 결정 2026-10-14 가 **업체 식별을 90일 지움의 대상**으로 선언했다(`RetentionTableRegistry` 의 마스킹 규칙 · `COMPANY_IDENTITY_CONCEPTS` 셋). 그 값을 HTTP 로 내보내면 지움 결정의 **바깥에 사본**이 생긴다(클라이언트 캐시·브라우저 이력·중계 로그).
2. 기존 출하 표면이 같은 판정을 이미 했다 — ML 스냅숏의 투찰자 행에 *"상호·사업자번호·대표자명이 없다"*(D-6G-10)이고 그 부재를 「타입에 자리가 없다」 test 가 잠근다.
3. -a 의 사용자 가치(SET-02 「1위가 나인가」)는 상호를 **클라이언트에 보내서** 푸는 문제가 아니다 — SET-01 이 요구하는 것은 **서버의 상호 정규화 정확매치 판정**이고, 그 판정 결과(낙찰/패찰/유찰/판정 불가)만 -b 에서 나간다. 상호는 서버 안에서 커널까지만 간다.
4. 7C① 선례 — 공고 요약 DTO 는 *"투찰자 이름은 이 타입에 자리가 없다"* 를 키 집합 등식으로 잠갔다. 같은 형태를 잇는다.

막는 방식은 **구성**이다(열거 금지): ⓐ DTO 에 그 칸이 없다 ⓑ 질의의 SELECT 목록에 그 열이 **없다**(질의가 실제로 읽은 열 집합을 `ResultSetMetaData` 로 실측해 선언 집합과 등식) ⓒ 표지(sentinel) 상호를 행에 넣고 **응답 본문 전문에 그 표지가 없음**을 단언한다(값 수준 — 키 이름을 바꿔 피하는 길이 없다). 「지울 필드 목록」을 두는 쪽은 쓰지 않는다 — 열거는 새 운반자를 조용히 놓친다(`FieldConceptPiiAxis` 가 이미 그 대가를 치렀다).

### 0.5 읽기 전용 트랜잭션과 증인 — 재사용

- 어댑터는 7C① 이 세운 **읽기 전용 트랜잭션** 함수를 그대로 부른다(adapters 모듈 `internal`). 두 번째 사본을 만들지 않는다 — 술어가 한 자리여야 변이가 한 자리에서 잡힌다. 이름이 검색 축을 가리키는 것은 알려진 자리다(개명은 7C① 파일 편집이라 이 slice 의 in_scope 밖).
- 증인도 재사용한다(기록 프록시 · 면제는 「첫 문장 == 읽기 전용 문면」 하나). 7C① 의 알려진 제한 R4-L-1(무쓰기 지문이 공고 표 하나만 본다)을 **이 slice 가 읽는 표 전부**(결과 표 · 원문 표 · 공고 표)로 넓힌다 — 지문은 행 버전 축으로 재고, 음성 대조(읽기 전용이 아닌 연결의 같은 DML 은 통과하고 지문이 그 쓰기를 본다)를 함께 둔다.
- 쓰기 0 · 마이그레이션 0 — 인덱스도 만들지 않는다(§0.10 미달 ③).

### 0.6 (0) 위협 모델 경계

**방어한다**: 인증 없는 조회 · 다른 참가자 식별 정보의 응답 유출 · 잠정 값이 확정 칸으로 표시되는 오표시 · 「데이터 없음」과 「결과 없음」과 「아직 개찰 전」의 혼동 · 조회 경로가 쓰기를 쥐는 것 · 미등재 상류 라벨의 조용한 접기.

**방어하지 않는다**: 공개된 개찰 결과를 인증을 지난 단일 운영자가 읽는 것 · 상류 값 자체의 진위(수집 축 소유) · 공고 단위 수집 실패의 **사유**(DB 에 없다, §0.1) · 다중 계정 격리(-a 에 계정 축이 없다 — -b 가 그 축을 열 때 그 slice 가 잠근다).

### 0.7 (1) 열거인가 구성인가

- **상태는 열거**다 — sealed 결과 + 소진 `when`. 상태마다 가용한 칸이 다르다는 사실을 타입이 진다. 새 상태가 생기면 컴파일이 응답 조립 자리를 막는다.
- **무엇을 내보내는가는 구성**이다 — §0.4 ⓐⓑⓒ. 금지 목록을 쓰지 않는다.
- **진행구분 라벨은 열거**다(정책 데이터) — 등재 밖은 통과가 아니라 `PROGRESS_UNRECOGNIZED` 라는 결과다.

### 0.8 (2) 우회 ↔ 막는 것 ↔ test ↔ 변이

| 우회 | 막는 것 | RED 로 잴 test | 변이(무엇을 무엇으로) |
|---|---|---|---|
| ① 자격증명 없이 조회 | 필터의 전 경로 등록(구성) — 새 endpoint 가 필터 밖에서 태어나지 않는다 | 이 endpoint 401 + 기존 기계 전수 「등록된 모든 endpoint 가 자격증명 없이는 401」 | 필터 등록 패턴을 전 경로 → 전략 경로 하나로 |
| ② 다른 업체 상호를 응답으로 꺼내기 | §0.4 ⓐⓑⓒ 셋 | 키 집합 등식 + 읽은 열 집합 등식 + **표지 상호 부재**(값 수준) | SELECT 에 상호 열을 더하고 DTO 칸을 더한다 → 표지 단언 RED. 역대조: 표지 단언만 항진식으로 → 열 집합 등식이 혼자 잡는가 |
| ③ 잠정 값을 확정 칸으로 읽기 | 확정 칸은 최종낙찰 열에서만, 잠정 칸은 개찰 1위 열에서만 — 두 축이 다른 칸이다 | 잠정만 있는 행에서 확정 칸 전부 부재 + **잠정 관측을 더해도 확정 칸 불변**(저장소 왕복 뒤 두 번 읽기) | 확정 금액 읽기를 두 열의 `COALESCE` 로 |
| ④ 「수집 전」·「결과 없음」·「미개찰」 접기 | §0.2 열거 | 상태 전수 test(상태마다 한 사례) | 두 갈래가 같은 값을 돌려주게 |
| ⑤ 조회 어댑터가 쓰기를 쥐기 | 읽기 전용 트랜잭션(DB 가 DML 거부) + 전 문장 증인 + 표 전부 지문 | 실 DB 쓰기 거부 + 증인 「모든 문장이 읽기 전용 안」 + 음성 대조 | ⓐ 읽기 전용 문장 제거 ⓑ 호출을 첫 질의 뒤로 ⓒ `autoCommit=false` 만 남김 |
| ⑥ 미등재 진행구분 라벨을 「개찰완료」로 접기 | 정책 열거 + `PROGRESS_UNRECOGNIZED` | 등재 밖 라벨 test | 미등재 갈래를 `OPENED` 로 |
| ⑦ 상류 라벨 원문 흘리기 | 응답에 라벨 칸이 없다 | 키 집합 등식 | DTO 에 라벨 칸 추가 |
| ⑧ 금액을 값만 싣기 | 금액 칸 다섯이 함께 간다 | 계약 test(문서 ↔ DTO 키 등식) + 응답 값 test | provenance 칸 제거 |
| ⑨ 질의 해석으로 500 만들기 | 7C① 규율 재사용 — 질의를 읽는 자리 하나 · 같은 매개변수 반복 거부 · 퍼센트 인코딩 오류 400 | endpoint 400 네 꼴 + 실 DB 출하 조립 E2E | 읽기를 핸들러 밖으로 되돌리기 |
| ⑩ 개찰 축 아닌 표를 join 으로 끌어오기 | 읽는 열 집합 등식(표별) | 같은 등식 test | 질의에 감사 표 join 추가 |
| ⑪ 공고가 없는데 200 으로 답하기 | 공고 행 부재는 404 | 404 test | 404 갈래 제거 |
| ⑫ 「마감 전이면 미개찰」을 시계 없이 고정 | 시계 주입 + 경계(마감 == 지금) test | 경계 두 사례 | 판정을 상수 참으로 |
| ⑬ 원문 존재 질의를 공고 축 없이 전역으로 | 존재 질의는 공고번호·차수로 좁힌다 | 다른 공고의 원문이 이 공고의 상태를 바꾸지 않는다 | 존재 질의의 공고 조건 제거 |

### 0.9 (2b) 값 획득 축 — 새 public 표면 전수

| 새 표면 | 밖에 허락하는 것 | 허락하지 않는 것(구조) |
|---|---|---|
| `GET /api/opening-results`(controller) | 인증된 운영자의 **공고 단위 개찰 사실 읽기** | 쓰기·명령 없음(메서드 하나, 본문 없음). 미선언 메서드 405 · 받아들일 수 없는 `Accept` 406 은 기존 전수 test 가 잰다 |
| 읽기 포트(workflow) | 공고 하나로 개찰 결과 조회 | 읽기 메서드 **하나뿐** — 쓰기 통로가 없다. HTTP 층은 이 타입을 직접 받을 수 없다(게이트 거부 타입 — 조회기 경유만) |
| 조회기(app.wiring) | 포트 위임 하나 | 포트 호출 쌍 목록에 이 한 쌍만 — 다른 호출자는 게이트가 막는다 |
| 조회 어댑터(adapters) | 결과 표 SELECT 1 · 원문 표 **존재** SELECT 1 · 공고 표 SELECT 1 | 상호 열을 읽지 않는다 · join 없다 · 자식 표(예비가격)·추첨번호 열에 닿지 않는다(읽은 열 집합 등식) |
| 결과 타입(workflow, sealed) | 상태 + 그 상태에서 가용한 값 | 상태 밖 값 조합을 만들 수 없다(생성자 경로가 상태마다 다르다) |
| 상태 열거 | 아홉 값(§0.2) | 그 밖의 값이 없다 |
| 응답 DTO(app.http) | §0.3 의 칸 | 상호·계정·투찰·라벨 원문 칸이 **없다**(키 집합 등식 + 어휘 교집합 공집합) |
| 진행구분 정책 데이터 | 등재 라벨 셋 ↔ 상태 사상 | 값이 코드 분기가 아니라 데이터다 — 라벨이 늘면 데이터만 바뀐다 |
| **「경계로 처리」 행도 실측한다** | — | ⓐ 상호 두 열: 읽은 열 집합 등식이 부재를 잰다 ⓑ 계정 축: DTO 키 집합 등식 ⓒ 읽기 전용 트랜잭션 함수·증인: **기존 표면 재사용**이라 새 표면이 아니다(참조만 더한다 — 상수 풀 참조 단언으로 잰다) |

### 0.10 (3) 과잉·미달

**과잉으로 하지 않는 것**: 예정가격·개찰 기초금액·사정률·예비가격 15·추첨번호를 같이 내보내기(화면 E 가 요구하지 않고 ML 축이 소유) · 상태별 endpoint 분리 · 목록 조회(공고 단위 하나로 족하다, 목록은 7C① 가 가진다) · 인덱스 추가(마이그레이션 0).

**미달 — 선언하고 남긴다**:
1. **production 데이터가 0 이다** — 승격 경로 부재(§0.1). 이 slice 의 코드로는 닫히지 않는다. `D-7C5-1`·`D-7C5-2`.
2. **공고 단위 수집 실패 사유가 DB 에 없다** — `NOT_COLLECTED` 로 접는다. OPEN 등재.
3. **원문 존재 질의에 인덱스가 없다** — 원문 표 전수 스캔 1회가 요청마다 돈다(단일 운영자 전제). OPEN 등재.
4. 잠정 1위의 **순위 의미** 자체가 미결이다(결측·중복이 흔하다는 기존 실측) — 응답은 종류를 그대로 나르고 해석하지 않는다.

### 0.11 -b 설계 스케치 (선행 셋 머지 뒤 rebase)

- 입력 셋: 투찰 기록(7B — 내 투찰가와 고른 안을 보존) × 개찰 결과(§0.2·0.3 의 읽기 그대로) × 상호(7C④ 프로필) → SET-01 커널(상호 정규화 정확매치, **금액을 판정에 쓰지 않는다** — 커널 시그니처가 금액을 받지 않는다).
- 건별 결과: 낙찰 · 패찰 · 유찰 · **판정 불가**(낙찰가만 있고 낙찰자 상호가 없음 — 3-state) · **상호 미설정**(판정하지 않고 외부 조회도 하지 않는다, SET-01 acceptance).
- 응답은 **판정과 내 값**만 나른다 — 상대 상호는 서버 안에 머문다(§0.4 근거 3).
- 집계(투찰 대비 낙찰률): **표본 수와 함께** 내고 **분모 0 이면 「부재」**(M6 완료 조건) — 0 을 비율로 쓰지 않는다.
- 낙찰/패찰 확정 시 알림함 기록은 7C③ 포트 머지 뒤 배선(NOTI-04 의 기록 절반, 채널은 범위 밖).
- 선행 slice 의 커널·표를 흉내 내지 않는다 — 없으면 -b 를 열지 않는다.

### 0.12 게이트 계약 갱신 예상 (in_scope 밖 파일 — 보고 항목)

- `config/quality/architecture-policy.properties`: HTTP 표면 실측이 handler 집합 **등식**이라 새 컨트롤러가 목록에 없으면 RED. 같은 이유로 배선 층 · 조회기 · 주입 표면 · 포트 호출 쌍 · HTTP 층 허용 패키지 · 거부 타입이 각자 등식·부분집합 술어를 가진다(7C① 이 같은 자리에 같은 줄을 더했다).
- `config/quality/size-policy.properties`·`gate-tests.properties`·`api-type-policy.properties`: 필요 여부는 구현 중 게이트 실행으로 **실측해 결정**한다(미리 열지 않는다).
- 생성 타입(`web/src/api/generated/operator-api.ts`)은 OpenAPI 와 **바이트 등식** 게이트가 있어 문서 편집과 같은 커밋에서 재생성한다.
- 수정 라운드가 새 파일을 만들면 in_scope 와 대조해 계약을 갱신한다.

### 0.13 OPEN — 팀장 결정 요청 (각 항에 레인 추천)

| ID | 물음 | 레인 추천 |
|---|---|---|
| `D-7C5-1` | §0.1 귀결 — -a 를 **canonical 읽기**로 짓고 승격 부재를 상태(`OBSERVED_NOT_PROMOTED`)와 알려진 제한으로 정직하게 내는가, 아니면 -a 가 **원문을 직접 읽어** 지금 데이터를 내는가 | **canonical 읽기**. 원문 직접 읽기는 ⓐ 계약의 out_scope(정규화)이고 ⓑ 「어느 걷기의 행인가」를 DB 만으로 답할 수 없어 6G 가 다섯 라운드를 쓴 결함류(행 존재·행 시각으로 걷기 짐작)를 되살린다 |
