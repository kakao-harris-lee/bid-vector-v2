# M6 완료 조건 3 조정안 (M7/7A P-3, 2026-10-14, 팀장) — **운영자 결정 대상, 결정 전 효력 없음**

> **결정 2026-10-15 — 운영자 승인.** Q-1 구조 승인 · Q-2 (b) · Q-3 (b). Q-2 (b)로 DEC-03 이 G2 로 내려가 **G1 9 · G2 13** 이 된다.
> 정본은 `milestone-6.md` 완료 조건 아래의 결정 블록이다. 이 문서의 표(G1 10 · G2 12)는 결정 전 안으로 남긴다.

## 무엇을 묻는가

M6 완료 조건 3 「M0 필수 capability E2E 전체 통과」는 `V2 필수` 61 가운데 **13 이 측정 성립(ⓐ) · 2 가 잴 대상 없음(ⓑ) · 46 이 미구현(ⓒ)**
이다(`reports/evidence/m6/6e1/acceptance-trace.md`). 46 을 전부 M6 안에서 닫는 것이 정석이지만, 그중 상당수는 **M7 화면이 만들
표면**(공고 검색·알림함·실투찰 기록)이거나 **화면이 소비하지 않는 운영·ML 축**이다. 운영자 결정 2026-10-14 (나)는 7A 의 데이터
요구표(`docs/discovery/m7-screen-data-requirements.md` 「M7 소비 capability 집합」 30 = `V2 필수` 29 + BID-01)를 근거로 조건 3 의
판정 대상을 가르라는 것이다. 이 문서는 61 전건을 세 갈래로 나누는 안이다.

## 가르는 규칙 (재현 가능)

각 capability 에 두 물음을 순서대로 묻는다.

1. **M7 화면이 소비하는가** — 요구표 P-2 집합에 있는가.
2. **빈 자리가 무엇인가** — 추적표 행이 적은 「무엇이 비었는가」를 읽어, (가) **도메인·커널이 없다**(타입·해석기·판정 축·배선)
   (나) **표면·기록만 없다**(operation·조회 경로·사용자 기록 표 — M7 slice 의 산출 정의에 이미 있는 것) (다) **측정만 없다**
   (「후속: test 신설」) 중 무엇인가.

| 갈래 | 규칙 | 조건 3 에서의 처분 |
|---|---|---|
| **G1 · M6 에서 닫는다** | 소비함 × (가) 도메인 없음, **또는** 어느 쪽이든 × (다) 측정만 없음 | 조건 3 판정 대상에 **남는다** — 7B 착수 전 M6 잔여 slice 로 닫는다 |
| **G2 · M7 로 넘긴다** | 소비함 × (나) 표면·기록만 없음 — M7 의 7B·7C 산출 정의가 그 빈 자리를 이미 담는다 | 조건 3 에서 빼고 **M7 완료 조건**(「화면 다섯이 V2 API 만으로 여정을 닫는다」)이 잰다 |
| **G3 · 분리 등재** | 소비하지 않음 × ⓒ | 조건 3 에서 빼고 **「M6 잔여 — 운영·ML 축」 OPEN 묶음**으로 등재, 7F(운영 반입) 또는 별 마일스톤에서 판정 |
| (성립) | 추적표 ⓐ·ⓑ | 그대로 성립 — 처분 없음 |

### 계 (기계 대조 결과 — 아래 절차로 산출)

성립 **15**(ⓐ 13 · ⓑ 2) + G1 **10** + G2 **12** + G3 **24** = **61**, 합집합 61 · 갈래 사이 중복 0 · 추적표 61 과 집합 등식.

**규칙 예외 다섯(선언)**: ① **COL-04** 는 P-2 밖인데 G2 다(위 주). ② **DEC-02** 는 P-2 밖인데 G1 이다 — 규칙상 「소비하지 않음 ×
도메인 없음」이면 G3 이지만, DEC-05 메뉴의 근거 칸(어느 제약에 binding 됐는가)이 DEC-02 의 빈 자리 그 자체라 같은 slice 로
닫는 편이 싸다. ③④ **QUAL-08 · QUAL-11** 은 소비함 × **도메인 없음**(판정 축이 없다)이라 규칙상 G1 이다 — G2 배치는 **Q-3 답 (b)
(M7 은 입력만 받고 「아직 판정하지 않음」 표시)를 전제한 것**이다. Q-3 이 (a)면 둘은 G1 로 옮겨 G1 12 · G2 10 이 된다. ⑤ **STR-02** 는
소비함 × 도메인 없음(요건 원문 **데이터 축**이 V2 에 없다)이라 규칙상 G1 이지만, 그 축은 6F-5-b(실 LLM 요건 추출 — 별도 운영자 승인)
종속이라 M6 안에서 닫을 수 없다 — 화면 A 의 키워드 입력은 ⓐ 로 서고, 요건 축은 6F-5-b 가 열릴 때 판정한다(G2 에 두되 이 종속을 선언).
DEC-06·OPS-01 은 「측정만 없음」 규칙으로 P-2 와 무관하게 G1 이다(예외 아님).

ID 를 셀 때는 `OPEN-DEC-10`·`OPEN-ML-ANALYSIS-WIRING` 같은 OPEN 이름 속 부분 문자열을 capability 로 잡지 않는다(앞이 `-` 인
일치는 뺀다) — G3 설명 문장이 그 이름을 인용한다.

## 운영자에게 묻는 것

- **Q-1 구조 승인**: 위 세 갈래 규칙과 배치를 승인하는가(조건 3 = 성립 15 + G1 10 이 닫히면 성립, G2 12 는 M7 완료 조건, G3 24 는
  OPEN 묶음 두 개로 등재).
- **Q-2 DEC-03 의 크기**: 법정 하한율 해석기(기관 유형 × 시행일 × 추정가격 구간)는 규칙 데이터 수집까지 포함해 가장 큰 G1 항목이다.
  (a) G1 에 둔다(M7 7C 의 투찰가가 법정 하한율을 근거로 낸다) · (b) G2 로 내린다 — 화면 C 는 **게시 하한율만** 근거로 쓰고 「법정
  하한율 미해석」을 명시한다(DEC-04 의 정직 명세 규율로 표시). **추천 (b)** — 게시 하한율이 대부분 공고에 있고, 해석기는 M7 진행을
  막을 만큼의 가치가 실측되지 않았다.
- **Q-3 자격 축 둘(QUAL-08 지역 · QUAL-11 금액 capacity)**: (a) M7 7C 에서 판정 축까지 만든다 · (b) M7 은 입력만 받고 화면은 「이
  축은 아직 판정하지 않음」으로 표시, 판정은 후속. **추천 (b)** — 면허 축(QUAL-01)이 이미 서고, 두 축은 규칙 데이터가 없다.

## 기계 대조 (이 문서를 확정하는 절차)

verifier 는 ① 추적표의 61 ID 집합 == 이 문서의 「성립」+G1+G2+G3 ID 합집합(중복 0) ② G2 의 각 ID 가 요구표 P-2 집합에 있다
(선언 예외 COL-04) ③ G1 의 각 ID 는 P-2 집합에 있거나 「측정만 없음」(DEC-06·OPS-01) 이거나 선언 예외(DEC-02) ④ G3 의 각 ID 가
P-2 집합에 없다 ⑤ 규칙 「소비함 × 도메인 없음 → G1」을 어기는 G2 행은 선언 예외(QUAL-08·QUAL-11·STR-02)뿐이다 를 기계로 재고,
계를 이 문서에 기록한다. ID 는 OPEN 이름 속 부분 문자열을 빼고 센다(앞이 `-`·대문자인 일치 제외).
