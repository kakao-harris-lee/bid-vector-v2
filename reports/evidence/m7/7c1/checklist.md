# M7/7C① — 점검표

## 1. 계약이 요구한 선언 (전부 문서와 test 양쪽에 있다)

| 요구 | 선언 | 그 선언을 잠그는 test |
|---|---|---|
| 금액 범위가 **어느 금액**인가 | 기초금액(`Basis.BASE_AMOUNT`) · 원 · 부가세 포함 · 운영자 선언 provenance — 감시 경로의 예산 한계값과 같은 규약 | 조건 타입 test 의 「금액 범위의 basis 는 기초금액이고 과세·provenance 는 감시 경로와 같은 규약이다」 + 질의 조립 test 의 「금액 조건은 기초금액 열만 보고…」 + 실 DB test 의 「금액 범위는 기초금액으로 거른다」 |
| 값이 **없는** 공고의 포함 여부 | 금액 조건이 있으면 **빠진다**(0 으로 간주하지 않는다). 비교 불가(과세 불일치·provenance 미선언)도 같다. 조건이 없으면 전부 나온다 | 실 DB test 의 「금액 조건이 있으면 비교 불가·부재 금액은 빠진다」(같은 test 가 조건 없는 질의에서는 셋 다 나오는 것도 잰다) |
| `size` **상한** | 100(초과는 절삭이 아니라 400). 기본 20, `page` 기본 0 | 조건 타입 test 의 우회 ③ 절 + endpoint test 의 우회 ③④⑥ 절 + 계약 test 의 「선언된 한계 수치가 Kotlin 상수와 같다」 |
| **빈 결과의 두 뜻** | 응답 헤더 `X-Result-State`(MATCHED / NO_MATCH / NOTHING_COLLECTED). 본문 필드가 아니라 헤더인 이유는 본문이 요약 **배열**이기 때문이다 — 평탄 술어(D-6A1-20 ⓑ)를 넓히지 않으려고 총수·사유를 헤더로 보냈다 | 실 DB test 의 「빈 결과의 두 뜻이 갈린다」 + endpoint test 의 「빈 결과의 두 뜻이 헤더로 갈린다」 + 계약 test 의 「200 응답이 선언한 헤더 둘을 실제로 낸다 — 어휘도 구현의 전수와 같다」 |
| 전체 건수 | `X-Total-Count`(페이지 길이가 아니다). 마지막 페이지 뒤는 본문 0 · 건수 ≥ 1 · 상태 MATCHED | 실 DB test 의 「전체 건수는 페이지 길이와 다르고 마지막 페이지 뒤는 빈 페이지 + 맞음이다」 |
| 정렬 하나 | 마감 임박 순(마감 없는 공고는 뒤) + 공고번호·차수로 결정적 | 질의 조립 test 의 「페이지 질의는 LIMIT·OFFSET 을 바인딩 자리로 두고 정렬이 결정적이다」 + 실 DB test 의 정렬 절 |

## 2. 우회 ↔ test ↔ 변이 (설계 검토 (2))

각 변이는 **바꿔치우기**(더하기 아님)이고, 적용 직후 `git diff --numstat` 의 삭제 줄이 1 이상임을
확인했다. 복원은 사본에서 했고 복원 직후 numstat 은 빈 출력이다.

| 우회 | 막는 것 | RED 로 잰 test | 변이(무엇을 무엇으로) |
|---|---|---|---|
| ① 인증 헤더 없이 호출 | 필터의 와일드카드 등록(구성) — 새 endpoint 가 필터 밖에서 태어나지 않는다 | endpoint test 「우회 ① … 401」 + 기존 기계 전수 「등록된 모든 endpoint가 자격증명 없이는 401이다」 | 필터 등록의 url 패턴을 전 경로 → `/api/strategy` 하나로 |
| ② `q=%` 로 전수 조회 | 와일드카드·이스케이프 문자를 글자로 바꾼다 + `ESCAPE` 절 명시 | 질의 조립 test 「우회 ② … 글자로 바뀐다」 + 실 DB test 「우회 ② … 리터럴 검색이다」 | 패턴 함수의 이스케이프 세 치환을 없애고 원문을 그대로 감싸기 |
| ③ `size=100000` | 상한 초과는 **거부**(절삭 아님) | 조건 타입 test 우회 ③ · endpoint test 우회 ③④⑥ | 거부 규칙표를 빈 목록으로 |
| ④ `amountMin>amountMax` | 역전 범위 거부(마감 범위도 같다) | 같은 둘 | 같은 변이(규칙표) |
| ⑤ `q` 에 `'; DROP` | 질의 문면이 **값에 의존하지 않는다**(바인딩만) | 질의 조립 test 「문면은 조건의 유무만 보고 만들어진다(값이 달라도 같다)」·「입력 문자열은 문면이 아니라 값으로만」 + 실 DB test 「주입 문자열은 값이라 표가 그대로 남는다」 | 텍스트 술어를 바인딩 자리 → 값 삽입 문자열로 |
| ⑥ 아주 긴 `q` | 길이 상한(두 텍스트 칸 모두) | 조건 타입 test 우회 ⑥ · endpoint test 우회 ③④⑥ | 같은 변이(규칙표) |
| 추가 — 금액 축을 추정가격으로 옮기기(legacy 결함 재현) | 기초금액 열만 본다 | 질의 조립 test 금액 절 + 실 DB test 금액 절 둘 | 금액 술어의 열을 기초금액 → 추정가격으로 |
| 추가 — 비교 성립 전제 제거 | 과세 불일치·미선언 provenance 는 비교에 들지 않는다 | 실 DB test 「비교 불가·부재 금액은 빠진다」 | 비교 성립 술어를 항진 술어로 |
| 추가 — 빈 결과의 두 뜻 접기 | 두 뜻이 다른 값이다 | 실 DB test 「빈 결과의 두 뜻이 갈린다」 | 「수집 전」 갈래를 「조건이 좁다」로 |
| 추가 — 응답에 원시 관측 어휘 | 요약 키 집합 등식 + 어휘 교집합 공집합 | 계약 test 「키 집합이 완전히 일치한다」·「원시 관측·감사·투찰자 어휘가 없다」 | 계약 스키마의 필드 이름 하나를 원시 관측 어휘로 |
| 추가 — 선언한 상한을 안 걸기 | 문서 수치 ↔ Kotlin 상수 양방향 등식 | 계약 test 「선언된 한계 수치가 Kotlin 상수와 같다」 | 상수 100 → 50 |
| 추가 — 문서에만 있고 구현이 무시하는 매개변수 | 문서가 든 매개변수 전수가 조건에 효과를 낸다 | 계약 test 「문서가 든 질의 매개변수 전수가 조건에 효과를 낸다」 | 컨트롤러가 `size` 를 조건에 넘기지 않게 |
| 추가 — 검색 어댑터가 쓰기 경로를 쥐기 | 상수 풀에 공고 쓰기 좌표가 **없다**(문면 grep 이 아니라 컴파일된 참조) | 어댑터 의존 게이트의 「검색 어댑터의 상수 풀에 공고 쓰기 경로 좌표가 없다」 | (게이트 신설 — 양성 대조 둘이 같은 파일에서 술어가 실제로 걸림을 잰다) |

## 3. (2b) 값 획득 축 — 새 public 표면 전수

| 새 표면 | 밖에 허락하는 것 | 허락하지 않는 것(구조) |
|---|---|---|
| `GET /api/notices` (controller) | 인증된 운영자의 **공고 요약 읽기**(공개 공고 데이터) | 쓰기·명령 없음(메서드 하나, 본문 없음). 미선언 메서드는 405, 받아들일 수 없는 `Accept` 는 406 — 기존 전수 test 가 등록된 매핑 전부에 그 둘을 잰다 |
| `NoticeSearchPort`(workflow) | 조건 하나로 공고 페이지 읽기 | 읽기 메서드 **하나뿐**이라 쓰기 통로가 없다. 제한 층은 이 타입을 **직접 받을 수 없다**(게이트의 거부 타입 목록 — 조회기 경유만) |
| `NoticeSearchQuery`(app.wiring 조회기) | 포트 위임 하나 | 포트 호출 쌍 목록에 이 한 쌍만 있다(다른 호출자가 같은 포트를 부르면 게이트가 막는다) |
| `JdbcNoticeSearch`(adapters) | `notice` 표 **SELECT 3** (건수 · 페이지 · 「하나라도 수집됐는가」) | join 없음(원문 관측·감사·개찰 표에 닿지 않는다). 질의가 실제로 읽는 열 집합을 `ResultSetMetaData` 로 실측해 `notice` 선언 열과 등식으로 잠갔다 |
| `NoticeSummaryResponse`(DTO) | 공고번호·차수·상태·공고명·기관명 둘·기초금액(basis·통화·과세·provenance 포함)·마감 | 원시 관측·감사·투찰자·연락처 칸이 **없다**(키 집합 등식 + 어휘 교집합 공집합) |
| `NoticeSearchCriteria`·`SearchText`·`NoticeAmountBound`(workflow) | 검증을 지난 조건을 나른다 | 생성 경로가 파싱 하나뿐(`internal constructor` + `@ConsistentCopyVisibility`) — 패턴 문자열이 조건으로 들어와 질의에 닿는 자리가 없다 |
| `InvalidNoticeSearchException`(app.http) | 400 `INVALID_REQUEST` 로 옮겨지는 거부 | 메시지가 응답에 실리지 않는다(매핑표가 고정 문구만 낸다) |

위 일곱 밖에 **새 public 표면은 없다**(새 설정 키·새 환경변수·새 마이그레이션·새 표·새 쓰기 경로 0).

## 4. 쓰기·마이그레이션 0 확인

- 새 SQL 은 `SELECT` 셋뿐이고 `INSERT`/`UPDATE`/`DELETE` 문면이 없다.
- `adapters/src/main/resources/db/migration/` 에 새 파일이 없다(변경 목록으로 확인).
- 검색 어댑터는 `bidvector.adapters.notice` **자기 패키지**에 산다 — `adapters.persistence` 는
  `bidvector.workflow` 참조를 금지하는 게이트를 갖고(그 금지를 넓히지 않았다), 축마다 자기
  패키지를 두는 기존 관례(`evaluation`·`strategy`·`qualification` …)를 따랐다. 새 패키지의
  의존 게이트(`NoticeAdapterDependencyTest`)를 그 관례대로 신설했다 — 바이트코드 상수 풀을
  보는 쪽(소스 정규식이 아닌 쪽)으로.
- 기존 operation 의 문면을 바꾸지 않았다 — 계약 문서의 변경은 **새 operation 하나 + 새 스키마
  하나**의 추가뿐이다.

## 5. 게이트 계약 갱신 — in_scope 밖 두 파일을 만졌다 (보고 항목)

계약의 in_scope 는 「조회 포트·어댑터·controller 와 그 test」까지였으나, 새 endpoint 가 게이트를
지나려면 **게이트 계약 파일 둘**을 함께 갱신해야 한다(그 둘이 없으면 acceptance 가 성립하지 않는다).

| 파일 | 왜 필수인가 |
|---|---|
| `config/quality/architecture-policy.properties` | HTTP 표면 실측이 handler 집합 **등식**이라 새 컨트롤러가 목록에 없으면 RED. 같은 이유로 ① 층(wiring)·② 층(조회기)·주입 표면·포트 호출 쌍이 각자 등식·부분집합 술어를 가진다. 제한 층 허용 패키지에 `bidvector.workflow.notice` 를 **열고**, 그 안의 읽기 포트는 거부 타입으로 **다시 판다** |
| `config/quality/gate-tests.properties` | 등재 게이트가 「모듈의 test 모집단 ∖ 제외 == 등재」 등식이라 새 test 다섯이 목록에 없으면 RED |
| `app` 의 기존 게이트 test 둘(의존 게이트 · 비교 구조 게이트) | **술어는 무편집이고 데이터만 움직였다**: 의존 게이트의 면제 수 고정값(51 → 53, 근거 문단 동반)과 `Intrinsics.areEqual` 허용 목록 한 항목(공고 요약 응답의 data class 자동 `equals`, 개별 근거 동반). 둘 다 **집합·수 등식**이라 값을 늘린 사실이 목록에 남는다 — 전건 `check` 가 이 둘을 잡아서 알게 됐고, 수정 뒤 표적 재실행과 전건 재실행 둘 다 초록이다 |

이 갱신들은 **새 권한을 열지 않는다** — 허용 목록에 더한 것은 이 slice 가 만든 타입뿐이고,
`app.http` 의 허용 패키지 한 줄은 그 안의 포트를 거부 목록으로 되막아 조회기 경유만 남긴다.

## 6. 알려진 제한

1. **참가신청 마감이 응답에 없다** — `notice` 표에 그 열이 없다(마감은 `deadline_at` 하나).
   화면 B 의 「참가신청 마감이 있으면 먼저」는 열이 생긴 뒤의 일이고 이 slice 는 마이그레이션을
   하지 않는다.
2. **자격 판정·좁힌 사유가 응답에 없다** — `OPEN-6A3-EVALUATION-DETAIL` 소관(화면 B 의 카드
   ✅/❌ 행이 그 OPEN 을 함께 든다).
3. **provenance 미선언 기초금액 행을 실 DB test 로 만들지 못한다** — 도메인 경로(`Direct.of` 는
   게시 provenance 만 받는다)와 표 제약이 그 상태를 만들지 않는다. 그 술어의 존재는 질의 조립
   test 가 바인딩 전수로 잰다(실 DB 거동이 아니라 구조로).
4. **인덱스가 없다** — 조회 인덱스는 `OPEN-4B7-QUERY-INDEX` 소관이고 이 slice 는 마이그레이션
   밖이다. 큰 표에서 정렬·건수 질의가 느릴 수 있다(운영 데이터 0 인 지금은 측정값이 없다).
5. **투찰가 요청 결합·알림함·화면은 없다** — 7C ②·③·7E 소관(계약의 (3) 과잉 금지).
6. **건수 질의와 페이지 질의가 한 트랜잭션이 아니다** — 같은 커넥션에서 잇달아 돌지만 격리
   수준을 올리지 않았으므로, 사이에 수집이 끼면 `X-Total-Count` 와 페이지가 한 순간의 같은
   스냅숏이 아닐 수 있다(단일 운영자·읽기 전용 조회라 비용을 들이지 않았다).
7. `NoticeSearchPage` 의 `init` 단언은 어댑터 구현 실수를 기동 중 예외로 드러낸다 — 운영자
   입력으로는 도달할 수 없다(파싱이 앞에서 거른다).
