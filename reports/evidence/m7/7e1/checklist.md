# M7/7E-1 — 점검표

## 0. 설계 검토 (Phase 2.5 — 구현 전, 팀장 수령)

### 0.1 이 slice 가 세우는 것 한 문장

**화면이 보여 주는 모든 값은 V2 API 응답의 값이고, 「없음」·「아직」은 서버가 준 상태에서만
나온다.** 그 둘을 지탱하는 것은 규율이 아니라 구조다: 호출은 생성 타입 클라이언트 한 자리를
지나고(ADR 0011 D-2·D-3 의 두 층), 표시 문면은 `satisfies Record<계약 enum, …>` 표에서만
나오며(계약에 값이 늘면 `tsc` 가 멈춘다), 표 조회에는 **폴백이 없다**(표 밖의 값에 문면을
지어내지 않는다).

### 0.2 위협 모델 경계

**방어한다**: ① 화면이 V2 API 밖(legacy·하드코딩·목·정적 데이터 파일)에서 값을 얻음
② 근거 없는 숫자(「아직 산출 안 함」 자리의 수) ③ 상태를 클라이언트가 추론 ④ CSRF·세션 우회
(7D 경계 재사용) ⑤ 화면·콘솔·e2e 산출물의 개인정보·비밀값 ⑥ e2e 가 화면 대신 API 만 검증.

**방어하지 않는다**: 시각 디자인 품질(운영자 리뷰 몫) · ADR 0011 D-3 이 이미 알려진 제한으로
등재한 의도적 lint 우회(계산 이름·`Reflect`·`index.html` 인라인) · XSS 일반 · 브라우저 확장.

### 0.3 열거인가 구성인가

「V2 API 만」은 **ADR 0011 D-3 의 두 층이 이미 구조로 진다**(TS 프로그램 집합 등식 · 번들 그래프
간선 등식 + 카나리). 이 slice 가 더하는 구성은 셋이다.

| 축 | 구성 | 열거로 두지 않은 이유 |
| --- | --- | --- |
| 상태 → 표시 | `satisfies Record<계약 enum, StateDisplay>` 표 + 폴백 없는 단일 조회 자리 | 계약이 값을 늘리면 `tsc` 가 멈춘다(7C②-b 의 `IMPLAUSIBLE` 이 그 자리를 실제로 쓸 것이다). 「목록을 갱신하자」는 규율로는 누락이 조용하다 |
| 근거 없는 숫자 | **계약이 이미 닫았다** — `BidPriceRequestResponse` 에 3안 금액 칸이 없고 상태·사유만 있다 | 화면이 숫자를 내려면 리터럴을 써야 하고, 그 리터럴은 변이 test 가 잡는다 |
| 다음 행동 하나 | (상태 × 투찰가 보유) 2축 rule table | 상태마다 `if` 를 더하면 예외가 쌓인다. 표이므로 상태가 늘면 `satisfies` 가 멈춘다 |

| 하네스(`e2e/harness/*`) | 실행마다 난수 비밀값 · 출하 명령 인자 | production 코드에 fake·e2e 분기 0 — app 은 설정 값만 받는다 |

**「경계로 처리」 행의 실측**: 빌드 산출물 전수에서 e2e·하네스 어휘를 셌다 — preview 입구 두
환경변수 이름 · 하네스 스크립트 이름 둘 · DB 사용자 · 전략 칸 이름 · 자격 헤더 이름이 **각각
0 건**이고 `process.env` 참조도 0 건이다(번들에 들어가는 것은 `VITE_` 접두 공개 설정뿐이라는
ADR 0011 D-6 의 성질이 이 계수로 선다).

TS 에서 `object` 커널 주입에 해당하는 자리는 **모듈 전역**이고 이 slice 가 더한 것은 없다
(`client.ts` 의 CSRF 값 하나가 7D 에서 왔고 그대로다). 표는 전부 `const` + `satisfies` 라
가변 상태가 없다.

### 0.6 과잉·미달

- **과잉 아님**: 범위 밖 화면 넷(A·D·E·알림함)은 **빈 자리 그대로**다 — 자리 표의 `element`
  유무가 그 경계이고 test 가 「실화면은 B·C 둘」을 잠근다. 토큰은 Tailwind 테마 한 자리이고
  자체 디자인 시스템 라이브러리를 만들지 않았다.
- **미달 아님**: G2 13 행의 B·C 몫이 전부 test 로 선다(아래 §1).

## 2. 알려진 제한

1. **공고 단건 조회 operation 이 계약에 없다**(요구표 ⓑ, 담당 7C①) — 워크시트는 `q=<공고번호>`
   검색 뒤 번호·차수 일치로 한 건을 고른다. 7C① 후속 후보로 보고한다.
2. **`BidCase` 에 초안 금액 칸이 없다** — 그래서 「제출함」 폼이 초안 금액을 기본값으로 둘 수
   없고 운영자가 다시 적는다(가짜 기본값을 넣지 않는다). 7B 후속 후보.
3. **「진행 중 투찰 건수」를 서버가 세어 주는 표면이 없다** — 계약 전체에서 그 값은 **요청 칸과
   echo** 로만 나타나고 `listBidCases` 에 집계도 `X-Total-Count` 도 없다(실측). 그래서 운영자가
   선언하고 화면은 그 값을 그대로 싣는다. 클라이언트가 상태를 「진행 중」으로 분류해 세면 계약에
   없는 정의를 화면이 만드는 것이라 하지 않는다. **후속 Kotlin 후보**: 진행 중 건수를 내는 표면
   (`listBidCases` 의 총수 헤더 또는 집계 operation).
4. **쪽 넘김은 「더 보기」 한 방향이다** — 무한 스크롤·쪽 번호는 없다(§6.5 의 무한 스크롤은
   7E-2·3 이 다시 본다). 받은 수와 전체 건수를 함께 보이므로 「보이는 수와 닿을 수 있는 수」가
   어긋나지 않는다.
5. **`NoticeSummary.status` 와 `BidTimelineEntry.toState`·`command` 는 계약이 `type: string`
   이다** — 이 축들만 `tsc` 가 전수를 보장하지 못한다. 알려진 값에는 문면을 주고 모르는 값은
   **서버가 준 코드를 그대로** 보인다(문면을 지어내지 않는다).
6. **과세 구분에 기본값이 없다** — 고르기 전에는 초안·기록을 부르지 않고 무엇이 없는지 말한다.
7. **여정 ② 는 검색 경로로 닫는다**(D-7E-9) — 제안 카드가 `MATCHED` 로 뜨는 여정은 감시 조건을
   세우는 설정 화면이 서는 7E-2 다.
8. **장비 전제 둘** — 여정 e2e 는 `docker`(버릴 Postgres)와 Playwright 브라우저의 시스템
   패키지를 전제한다. 전자는 이 slice 가 더한 것이고 `one-command` 도 같은 전제를 받는다.
9. **`floorRateGroundsState` 의 `IMPLAUSIBLE`** — 진행 중인 7C②-b 가 더한다. 나중 머지 쪽이
   맞추고, 누락은 `satisfies` 가 컴파일로 잡는다(D-7E-4).
10. 번들 그래프의 모듈 종류 검사는 **그 모듈이 그래프에 들어왔을 때**만 센다 — 엔트리에서
   닿지 않는 파일은 번들에 들어오지 않으므로 그 층의 대상이 아니다(probe B 의 첫 측정이 그
   성질을 보였다: 죽은 코드는 build 초록).
11. **「폴백 0」은 `displayOrUnknown` 안에서만 잠긴다** — 호출 자리에서 `?? TABLE.X` 를 쓰는 것은
   어느 게이트도 보지 못한다(타입이 맞는 코드다). 그 자리는 리뷰 소관이고, 폴백을 쓸 이유가
   없도록 미지 상태를 **보이는 값**으로 만들어 두었다.
12. **`container` job 은 이 레인이 돌리지 않았다** — 새 devDependency 가 builder 단계의
   `npm ci` 를 바꾸므로 이미지 위생·취약점 게이트의 판정은 **PR 체크가 든다**(OQ-1). 런타임
   단계는 빌드 산출물만 복사한다(Dockerfile 실측).
13. **두 job 이 Gradle 캐시를 같이 쓴다**(OQ-3) — `setup-gradle` 이 job 별 키를 쓰므로 충돌이
   아니라 항목이 하나 느는 것이고, 캐시 용량·축출 영향은 재지 않았다.
14. **쓰기 재전송의 멱등이 서버에 없다** — 하네스로 직접 쟀다: `BID_RECORDED` 인 건에 같은
   본문을 다시 보내면 200 이고 기록 행이 하나 더 생긴다(금액이 달라도 받는다). 초안도 같고
   되돌림만 409 다. 화면은 `caseVersion` 으로 「이미 닿았다」를 가려 보내지 않지만 **창이 완전히
   닫히지는 않는다** — 전송 뒤 응답과 재읽기를 함께 잃으면 운영자는 상태를 모른 채 다시 누를 수
   있다. **후속 Kotlin 후보**: 멱등 키(요청 식별자)로 서버가 가리는 것.
15. **`publicDir` 를 끈 전제** — 이 slice 는 `web/public/` 를 쓰지 않고 게이트가 그 부재를
   단언한다. 정적 자산이 필요해지면 그 게이트를 먼저 바꿔야 한다(브라우저가 스스로 거는
   `/favicon.ico` 는 지금 404 이고, 여정은 그것을 「브라우저가 거는 요청」으로 따로 센다).
16. **`import.meta` 멤버 허용 목록이 {env} 하나다** — `glob`·`url` 이 필요한 기능이 생기면 게이트를
   먼저 고친다(그 자리가 정적 데이터의 입구였다).
17. **락 소유자 생존 판정은 Linux `/proc` 전제다** — 시작 시각을 읽지 못하는 환경에서는 「살아
   있다」로 기울어 **멈춘다**(남의 실행을 걷지 않는 쪽). CI 러너와 이 호스트는 Linux 다.
18. **번들 자산의 모양을 {js 1 · css 1} 로 못박았다** — 코드 분할·폰트·아이콘처럼 자산을 늘리는
   변경은 여정 하네스에서 **먼저 멈춘다**. 그것이 이 층의 값이다(허용 집합을 산출물에서 그냥
   읽으면 자산이 늘 때 양쪽이 함께 늘어 아무것도 깨지지 않는다). 상한을 올리는 것은 설계
   판단이고 `e2e/harness/bundle-shape.mjs` 를 고치는 diff 로 드러난다.
19. **`src` 안 test 파일은 `import.meta` 층에서 면제다** — 다른 층과 같은 면제이고, 전제는 「앱
   코드가 test 파일을 import 하지 않는다」(그 전제는 번들 그래프 층이 센다). 오늘 그런 자리 0.
20. **계산 조립 `fetch` 는 등재된 제한(7A N-10)이다** — 이 라운드가 닫은 두 우회(네임스페이스 ·
   CSS `url()`)의 **마지막 단계**가 그것이거나 캐스팅이다. 그 축은 7A 의 제한으로 남는다.
21. **`OPEN-7E-GATE-RESIDUAL`** — 게이트 술어가 아직 보지 못하는 **같은 계열 잔여 다섯**(손으로 쓴
   화면 코드 + 캐스팅 또는 7A N-10 을 거쳐야 열린다). 팀장 선 긋기(2026-10-29)대로 이 라운드에서
   고치지 않고 등재한다 — 아래 「4. OPEN」 절이 재현 꼴·처방·후속 자리를 든다. **7E-2 에서 함께
   닫기를 권한다**(그 slice 가 감시 조건 화면으로 `web/` 을 다시 열고, 다섯 가운데 셋이 그때
   바뀌는 파일에 있다).

## 4. OPEN — `OPEN-7E-GATE-RESIDUAL` (팀장 선 긋기, 머지 차단 아님)

> **종결(2026-10-30, M7/7E-2 · r1 검토로 범위 정정)**: 다섯 가운데 **①②③ 은 게이트 술어로
> 닫혔고, ④ 는 「재현 꼴(`getComputedStyle` 경로)만」 닫혔으며 ⑤ 는 실측 층으로 좁혀졌다**.
> ④ 의 남은 길(식별자가 아닌 접근 · CSSOM)과 `publicDir` 의 env 갈래는 7E-2 checklist §3.1 에
> ⑥·⑦·⑧ 로 등재했다. 처방은 아래 표의 것을 그대로 썼다(① TS 자신의 해석 + export 종류 전수 · ②③ Vite
> 해석 한 술어 + `dist` 루트 모양 · ④ 읽기 금지(DOM 심볼 해소) + 값 모양 · ⑤ 여정이 쓰기마다
> `caseVersion` 증가를 실측). 각각 별 커밋이고 양성 대조를 함께 쟀다 — ① 은 **구판 게이트가
> exit 0, 신판이 exit 1** 인 같은 재현 꼴로 쟀다. ⑤ 의 남은 잔여(계약 전체가 아니라 화면이 쓰는
> 전이에 한해서만 잠겼다)와 ④ 의 쓰기 축 잔여는 `reports/evidence/m7/7e2/checklist.md` 의 알려진
> 제한 7·8 로 **재등재**했다. 자리와 실측은 그 파일의 §3 표가 든다.


이 다섯은 **게이트 술어의 잔여**다. 공통 성질: ⓐ 산출물 거동 결함이 아니고(화면이 지금 하는
일에는 영향이 없다) ⓑ 열리려면 **손으로 쓴 화면 코드**에 캐스팅을 쓰거나 **계산 조립 `fetch`**
(7A N-10, 등재된 제한)를 거쳐야 하며 ⓒ 그 편집이 diff 에 남는다. 그래서 이 라운드에서 고치지
않고 등재한다 — 고치면 게이트 술어가 바뀌어 머지 전 재검증이 한 번 더 붙는다.
