# M7/7E-2b — 점검표

## 0. 설계 검토 (Phase 2.5 — 구현 전, 팀장 수령 2026-10-31)

### 0.1 이 slice 가 세우는 것 한 문장

화면 A 는 **서버가 판정한 체크리스트를 그리고**, 항목을 채우는 폼은 **설정 화면과 같은 컴포넌트**다 —
같은 필드를 두 폼이 따로 저장하지 않고, 화면이 완료를 추론하지 않는다.

### 0.2 위협 모델 경계

**방어한다** — ⓐ 클라이언트가 체크리스트 상태를 추론하는 것 ⓑ 세 상태가 두 상태로 접히는 표시
(선행 대기를 미완으로 셈 · 해당 없음을 미완으로 셈) ⓒ 같은 필드를 두 폼이 따로 저장하는 것
ⓓ 개인정보 노출(D-7E-6).
**방어하지 않는다** — 서버 판정의 옳고 그름(7C④-3 소관) · 시각 디자인 품질.

### 0.3 열거인가 구성인가

- 항목 어휘는 **생성 타입에서 파생**한다(`OnboardingChecklist['completed'][number]`). 단계 표·문면 표가
  `satisfies Record<OnboardingItem, …>` 라 계약이 항목을 늘리면 **컴파일이 멈춘다** — 새 항목이 조용히
  어느 목록에도 안 들어가는 일이 없다.
- 상태는 **세 목록의 멤버십과 그 여집합**이다. 넷째 목록도, 「해당 없음」 플래그도 만들지 않는다.
- 단계 → 폼은 `switch` 소진이다. 단계가 늘면 그 자리가 컴파일에서 멈춘다.
- 타입이 **못 드는 축이 하나** 있다: 항목의 **선언 순서**(유니온의 차례는 런타임에 남지 않는다).
  그래서 생성 타입을 AST 로 읽어 순서 상수와 맞대는 게이트를 둔다(`scripts/onboarding-vocabulary.test.mjs`).

`null` 인가 · `as const satisfies` 껍질을 벗기는가. 이것 없이 등식만 두면 「둘 다 같은 고정값을 냈다」와
구분되지 않는다.

### 0.5 (2b) 값 획득 축 — 새 public 표면 전수

표면 목록은 명령으로 낸다(`commands.md` 「새 public 표면 전수」 행). 각 표면이 **값을 지어낼 수 있는가**:

| 표면 | 값을 지어낼 수 있는가 |
| --- | --- |
| `readOnboardingChecklist` · `OnboardingChecklist` 타입 | 아니다 — 생성 클라이언트를 그대로 지나고 비-2xx 는 `ApiError` 로 올린다(빈 응답으로 접지 않는다) |
| `itemRowsOf` · `progressOf` · `firstStepWithPending` | 아니다 — 입력이 응답뿐이고 순수 함수다. 셋 다 변이로 RED |
| `ONBOARDING_ITEM_ORDER` | **순서만** 든다 — 계약과의 순서 등식 게이트가 덮는다(변이 M4) |
| `ONBOARDING_ITEM_STEP` · `ONBOARDING_ITEM_DISPLAY` · `ITEM_STATE_DISPLAY` · `ONBOARDING_STEPS` | 문면·배정뿐이고 판정이 아니다. 키 전수는 컴파일이 든다 |
| `OnboardingScreen` · `OnboardingBanner` · `ONBOARDING_QUERY_KEY` | 배너는 데이터가 없으면 **아무것도 그리지 않고**, 뜰 때 보이는 수는 서버의 `pending` 수다 — r1 에서 그 술어의 **음성 쪽을 세는 probe 넷**을 더했다(그 전에는 「조건을 지우고 항상 띄운다」가 전건을 지났다) |
| `useProfileWrite` · `attemptOf` · `ProfileWriteFailure` · `WriteAttempt` · 질의 키 둘 | 쓰기 배선뿐 — 본문은 호출자가 만든다. 본문 하나만 넘기는 것을 고친 자리(아래 알려진 제한 없음, 커밋 메시지에 근거) |
| `ProfileFactsCard` · `ProfileDetailsCard` · `ProfileCapacityCard` | 7E-2 의 폼을 **옮긴 것**이고 값 생성 로직이 없다(기본값을 지어내지 않는 성질은 7E-2 test 가 그대로 든다) |
| `useStrategyEditSession` · `StrategyEditPanel` · `StrategyFieldRow` · `StrategyWriteFailure` · `OpenSession` · `StrategyEditSession` · `STRATEGY_QUERY_KEY` | 7E-2 에서 **옮긴 것**. 확인 화면이 보이는 값은 여전히 둘(지금 값 · 보낸 값)뿐이다 |
| `collectContractItemOrder` · `collectDeclaredItemOrder` · `collectTableKeys` | 게이트 술어 — 읽지 못하면 `null` 을 내고 그 자리를 test 가 먼저 센다 |
| `clearStrategyTerms`(e2e) | 산출물이 아니라 여정의 teardown — 되돌리지 **못한** 사유를 문자열로 올린다 |

### 0.6 과잉·미달

- **과잉이 될 자리**: 범위 밖 셋에 입력칸·버튼을 만드는 것 · 미리보기 전용 API · 진행률 저장 · 단계마다
  별 화면. 전부 하지 않았다(빈 자리 + 「준비 중」, 입력칸·버튼 0 을 test 가 단언).
- **미달이 될 자리**: 선행 항목 이름을 안 보이는 것 · 항목 전수 대응이 test 없는 것 · 여정이 DOM↔API
  대조 없이 지나가는 것. 셋 다 단언으로 덮었다.

## 1. Phase 1 착수 실측 — 체크리스트 응답과 되돌림

하네스(출하 app.jar · 버릴 Postgres · fake KONEPS)에서 실제 응답으로 쟀다. 명령은 `commands.md`.

- **빈 계정**: 완료 0 · 미완 일곱 · 선행 대기 한 짝(시평액 ← 나라장터 준비). 진행률 분모는 **일곱**이다.
- **되돌릴 수 있는 항목 여섯**: 상호 · 소재지 · 나라장터 준비 · 업종 · 시평액 · 감시 관심 업종.
- **되돌릴 operation 이 없는 항목 둘**:
  - `BUDGET_RANGE` — 편집 값의 세 꼴(칸 생략 · `null` · 빈 어휘)이 **모두 400** 이다. 적용하면
    `GET /api/suggestions` 가 `WATCH_NOT_CONFIGURED` → `NO_MATCH` 로 영구히 바뀌어 여정 ②·설정 여정의
    출발 단언이 실행 순서에 따라 깨진다 → **여정 ① 은 그 단계를 걷되 적용하지 않는다**(D-7E2b-9).
    후속 `OPEN-7E2B-BUDGET-CLEAR`.
  - `LICENSES` — V12 행을 지우는 길이 계약에 없다. **여정 ②③ 에는 무해하다**(실측: 면허를 신고해도
    미신고로 돌려도 `licenseVerdict=UNCERTAIN` · `licenseValidity=NOT_VERIFIED` · 미판정 축 셋 그대로).

## 2. 알려진 제한

1. **쓰기 실패 얼굴의 자리가 바뀌었다**(리팩터의 귀결). 프로필 절 머리 하나에서 **그 폼의 카드 안**으로
   간다. 「운영자가 마지막으로 누른 쓰기를 다시 보낸다」(7E-2 CR r1 L-3)는 그대로이고 그 집합이 카드 안으로
   좁아진다 — 설정의 네 쓰기가 동시에 실패해 있으면 얼굴은 **최대 셋**이다(자격 사실 1 · 사업 정보 1 ·
   시평액은 쓰기 둘이 카드 안에서 하나로 접힌다, CR r1 LOW 정정). 기존 설정 test·여정은 그대로 초록이다.
2. **금액대는 화면으로 비울 수 없다**(위 1절). 운영자가 한 번 세우면 그 값을 지우는 길이 제품에 없다.
3. **면허는 되돌릴 수 없다**(위 1절). 체크리스트에서 영원히 완료로 남는다.
4. **진행률이 0/0 인 계정**이 이론상 가능하다(걸리는 항목이 전부 해당 없음). 오늘 어휘에서는 일어나지
   않는다 — 여덟 중 일곱이 무조건 걸린다.
5. **7E-2 `OPEN-7E-GATE-RESIDUAL` ⑨ 의 표면이 늘었다**: 그 처방은 `src/screens`·`src/display` 에서
   `Date.now`·`new Date` 를 lint 로 막는 것이고, 이 slice 가 그 두 디렉터리에 파일 넷을 더한다. 화면 A 는
   시계 판정을 쓰지 않으므로 위험은 0 이고 **덮을 표면만** 늘어난다. ⑥⑦⑧ 과는 교집합이 없다.
6. **설정 여정의 teardown 은 그대로 두었다**(D-7E2b-9 「남의 여정은 건드리지 않는다」). 그 결과 어휘 칸을
   비우는 절차가 `shared.ts` 의 공통 함수와 `settings.spec.ts` 안에 각각 있다 — 뒤 slice 가 설정 여정을
   만질 때 합치는 것이 자연스럽다.
7. **단계 → 전략 칸 배정이 커널의 완료 조건과 끈이 없다**(CR r1 OQ). 오늘은 `BUDGET → MIN_BUDGET·MAX_BUDGET`
   과 `WATCH → FOCUS_CATEGORY` 가 커널의 `BUDGET_RANGE`·`WATCH_CONDITIONS` 완료 조건과 맞고 화면 test 가 두
   배정을 행 testId 로 잡는다(r1 에서 `MAX_BUDGET` 단언을 더해 둘 다 덮었다). 다만 **커널이 어느 칸으로 완료를
   재는지 바꾸면 web 쪽에서 붉어질 자리가 없다** — 마법사가 그 항목을 채울 수 없는 단계를 보이게 된다.
   계약에 그 끈이 없으므로(항목 어휘만 wire 에 있고 「어느 전략 칸이 그 항목을 채우는가」는 없다) 이 slice 가
   닫을 수 있는 축이 아니다. 끈을 만들려면 계약이 그 대응을 내야 한다 — 7C 후속의 물음이다.
8. **단계 전환에서 포커스를 옮기지 않는다**(CR r1 LOW 의 일부). 진행률 `aria-live` 와 단계 버튼의
   `aria-controls` 는 넣었고, 전환 뒤 본문 머리로 포커스를 옮기는 것은 하지 않았다 — 키보드로는 모두 닿으므로
   차단이 아니고, 포커스 이동은 되돌리기 어려운 보조기술 거동이라 운영자 리뷰 뒤에 정하는 쪽으로 둔다.
9. **마법사 밖에서 버려지는 편집 세션은 그대로 남는다**(v r1 L-1 의 나머지 절반). 단계 **버튼**으로 떠나는
   길은 닫았다(세션이 열린 동안 단계 탐색이 잠긴다 — 그것이 설정 화면에 없던 새 노출이었다). 브라우저를 닫거나
   다른 화면으로 가는 길은 설정 화면과 같고 기존 `OPEN-6A2B-ABANDONED-SESSIONS` 안이다.

## 3. rollback 과 재실행

`rollback.md` 가 복원 목록과 ⓪~⑦ 실측을 든다. 되돌린 뒤에도 7A 의 셸 스모크와 7E-1·7E-2 가 세운
여정 여덟은 그대로 선다 — 이 slice 가 더한 것은 화면 하나·여정 하나·게이트 하나이고 앞 층을 치우지
않는다(되돌린 트리에서 vitest 가 406 으로 돌아가는 것이 그 계수다).
