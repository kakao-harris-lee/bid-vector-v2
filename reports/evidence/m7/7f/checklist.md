**로컬 TLS**: 프록시의 내부 발급(`tls internal`)이고 **실행 시** 만들어진다. 저장소에 키도 인증서도
없다 — 스모크가 컨테이너에서 뿌리 인증서를 꺼내 그 체인으로만 검증한다(`-k` 를 쓰지 않는다).

**도메인**: 환경변수이고 기본값 `localhost` 하나. 운영 도메인 값은 저장소에 없다.

## CI 판단 — `container` job 에 넣는다 (팀장 위임 결정)

- **결정**: 스모크를 job 의 **마지막 step(S-26)** 으로 넣는다. 한 번만 로컬에서 돈 스모크는 뒤따르는
  편집을 아무것도 막지 못한다(하네스 「안 돌린 게이트는 아무것도 막지 못한다」) — 우회 ①~⑤ 의 측정이
  매 PR 에 서야 의미가 있다.
- **비용**: 이 job 안에서 web 번들 빌드 한 번(이미지 안 `npm ci` + `vite build`)과 app+postgres 기동
  한 번. `web` job 의 설치·빌드와 겹치지만, 그 job 의 산출물을 아티팩트로 왕복시키는 배선보다 싸고
  이미지가 **자기 입력만으로** 재현되는 성질을 지킨다.
- **자리**: 마지막이다 — ① S-21b 의 앱 이미지를 쓴다 ② 여기서 붉어져도 앞선 판정이 이미 다 나왔다
  (앞에 두면 한 회차에 보이는 판정이 줄어 수정 라운드가 쪼개진다) ③ S-25 가 기본 프로필을 치운 뒤라
  포트·프로젝트가 비어 있다.
- **`tools/one-command-check.sh` 는 건드리지 않았다** — 그 스크립트가 축어로 따르는 것은 `check`·
  `ml-engine`·`web` 세 job 이고 컨테이너 축인 이 job 은 그 안에 없다. 그래서 축어 일치 의무도,
  `check` job acceptance 도 발생하지 않는다.
- **계약 갱신 요청**(구현 레인이 쓰지 않는다): 계약의 in_scope 는 ci.yml `container` job 을
  「계약 갱신과 함께」 열어 두었다. `scope.md` 「계약 갱신 이력」에 이 결정 한 줄이 필요하고, 그 파일은
  팀장 레인 소유다.

## 설계 검토 우회 ①~⑤ — 측정과 **바꿔치우는 변이** 실측

변이는 전부 **바꿔치우기**다(더하기만 한 변이는 초록이 된다). 각 변이는 사본에서 복원했고
(`git checkout --` 을 쓰지 않았다) 복원 뒤 `git diff --numstat` 이 빈 출력임을 확인했다.

| 우회 | 무엇이 막는가 (구조) | 스모크의 단언 | 바꿔치운 것 | 변이에서의 결과 |
|---|---|---|---|---|
| ① host 에서 app·db 포트 직접 접속 | 덧쓰기가 app·ml-serving 의 publish 를 `!override []` 로 비운다. postgres 는 기본 파일에서 이미 publish 가 없다 | (A) 해석된 설정의 publish 서비스 집합 == {proxy} · 포트 1개 · 루프백 / (A2) host 연결 거부 **+ 내부망 양성 대조**(app 401 · web 200) | app 의 publish 를 되살림 | exit 1 — 「host 포트를 여는 서비스가 프록시 하나가 아니다: [app,proxy]」 |
| ② 관리 경로를 프록시로 | **망 분리**(r1 vr F-1) — web 은 `edge`, app 은 `default`, 둘 다에 붙는 것은 proxy 하나다. web 에서는 `app` 이름이 해석되지 않는다. 그 위에 프록시의 **상류 집합이 둘**(web · app API 포트)이고 관리 포트는 상류가 아니며, 다시 그 위에 명시적 404 | (A3) **적응된 설정**의 `dial` 집합 등식 / (E) `/actuator*` 가 무인증·인증 모두 404 · 관리 표지 부재 **+ 내부 관리 포트 양성 대조**(그 표지가 실재함) | `/actuator*` 의 `respond 404` → app 상류 프록시 | exit 1 — 「프록시의 /actuator 가 404 가 아니다: 401」. (A3) 는 초록이었다 — (E) 가 **독립적으로** 물었다 |
| ③ 경로 정규화 우회 | 둘이다 — ⓐ 같은 상류 집합(관리 포트 부재) ⓑ **프록시가 경로 접두를 자르지 않는다**: `/api/*` 에 매치된 것은 상류에도 `/api/…` 로 가고 관리 표면은 `/actuator/…` 에 있다 | (F) 변형 여덟을 `--path-as-is` 로 **무인증·인증 양쪽** 던지고 관리 표지 부재를 단언 | `/api/*` 의 상류를 관리 포트 리터럴로 | exit 1 — (A3) 「상류 집합이 기대와 다르다: [app:18081, web:18090]」. **같은 변이 이미지로 수동 프로브**(스모크를 고치지 않고): `/api/..;/actuator/health` → 404·표지 없음, `/api/actuator/health` → 404·표지 없음 — ⓑ 때문에 **상류를 관리 포트로 바꿔도** 그 경로로는 관리 표면이 주소화되지 않는다. 즉 이 축은 구조로 두 겹이고, (F) 는 그 위의 실측이다 |
| ④ http 평문 | 리스너가 **https 하나**다(평문 리스너도, 80 리다이렉트 리스너도 없다 — 비-root 라 80 bind 도 못 한다) | (G) 평문 요청이 400 이고 셸 표지가 없고 **401 이 아니다**(= app 에 닿지 않았다) | 사이트 scheme 을 `http://` 로(+healthcheck 도 평문으로 — 그러지 않으면 기동 자체가 멈춘다) | exit 1 — 「로컬 CA 뿌리 인증서를 꺼내지 못했다 — 이 프로필에서 TLS 가 서지 않았다」 |
| ⑤ web 이미지가 root 로 실행 | `USER bidvector`(10001, 시스템 계정 범위) · `/srv` 는 root 소유 읽기 전용 | (H) 두 이미지의 `Config.User` **와 실제로 도는 프로세스 uid 전부**(선언만 보면 setuid entrypoint 를 놓친다) | `USER root` | exit 1 — 「bidvector/web:local 의 Config.User 가 root/미지정이다: 'root'」 |
| (추가) 자격 값이 접근 로그에 남는다 | 로그 인코더가 **헤더 객체 전체**를 지운다(열거가 아니라 구성 — 뒤에 늘어나는 헤더도 자동으로 로그 밖) | (I) 로그의 자격 값 일치 0줄 **+ 그 요청의 URI 존재**(양성 대조) | `format filter{…}` → `format console` | exit 1 — 「프록시 접근 로그에 자격 값이 16줄 남았다」 |

마지막 행은 계약의 우회 목록에 없지만 실측으로 발견했다 — Caddy 는 표준 인증 헤더 둘을 가리지만 이
스택의 운영자 자격은 **custom 헤더**로 오므로 기본 설정에서는 평문으로 남는다.

**r1 이 더한 축과, 그 축에 대한 정직한 상태 둘**

- **(A4) 망·상류·연결 셋**(vr F-1). 앞 판은 우회 ② 를 「프록시의 상류 집합」만으로 막는다고 적었는데,
  web 도 Caddy 이고 app 과 같은 망에 있어 `web.Caddyfile` 한 블록이면 프록시 https 로 관리 표면이
  무인증 200 으로 나왔다. 이제 ⓐ 망 교집합 공집합 ⓑ web 의 상류 수 0 ⓒ web→app 실제 연결 불가를
  각각 재고, ⓒ 에는 양성 대조 둘(web 자기 포트 200 · proxy→app 관리 200)이 붙는다. **두 층이
  독립이다**: 같은 변이를 넣고 ⓑ 를 떼어 본 실측에서, 망만으로도 그 경로는 **502** 이고 관리 표지가
  없다.
- **「이름마다 정확히 1개」는 오늘 아무것도 운동시키지 않는다.** `defer` 를 떼는 변이에서 스모크가
  초록이었고, 까닭을 직접 쟀다 — **app 은 네 헤더 이름을 하나도 보내지 않는다**(내부망에서 401 의
  헤더를 떠 확인). 그러므로 이 축의 값은 오늘의 탐지가 아니라 **app 이 뒷날 보안 헤더를 켜는 변경에
  대한 회귀 가드**다. 같은 실행이 cr OQ-1 을 닫는다(`defer` 는 `/api/**` 에도 걸린다).
- **(G) 의 `transport-error` 칸은 순서에 기댄다**(vr F-4). 평문 축은 구조상 TLS 앞 단계에서 먼저
  끊기므로, (B)·(C) 가 https 로 200/401 을 받은 **뒤**라는 순서가 그 칸을 공허하지 않게 만든다 —
  독립 단언만으로는 거의 붉어질 수 없다. r1 은 그 위에 **3xx 를 허용 집합에서 뺐다**(계약이 말한
  「하나로」를 잠근다).

**(E)·(F) 의 독립성에 대한 정직한 상태**: ② 의 변이는 (A3)가 초록인 채 (E)가 물었으므로 응답층 단언이
구조 게이트와 **독립**임이 실측됐다. ③ 축에서는 반대로, 관리 표면이 프록시를 지나게 만드는 변이가
**예외 없이 상류 집합을 바꾼다** — 그래서 (A3)가 늘 한 칸 앞에서 끊고, (F)의 변이 실측은 그 뒤를 보지
못한다. (F)의 술어가 공허하지 않다는 근거는 **매 실행 도는 양성 대조**(내부 관리 포트가 같은 표지를
낸다)이고, (F) 자신의 값은 「여덟 변형이 실제 스택에서 무엇을 받는가」를 수로 남기는 것이다.

## 양성 대조 (공허 방지)

막힘을 재는 단언마다 같은 표지의 양성 대조가 **매 실행** 함께 돈다 — 상류가 통째로 죽어도 「막혔다」로
초록이 되는 일이 없다: 내부망에서 app API 포트 401 · web 200 · 내부 관리 포트가 관리 표지를 냄 ·
프록시 로그에 그 요청의 URI 가 있음. 음성 대조는 위 변이 표 자신이다.

## 알려진 제한

1. **운영 TLS 가 아니다.** 로컬 CA 는 공개 신뢰 기점이 아니고, 실 도메인·공개 DNS·인증서 수명·갱신은
   7F 본편(운영자 승인 사항)이다. publish 는 루프백뿐이다.
2. **HSTS 를 보내지 않는다** — host 단위로 걸려 그 브라우저의 모든 localhost 평문 개발 서버를 함께
   막고, 로컬 CA 에는 HSTS 가 지킬 대상도 없다. 로컬에서 **부재**를 스모크가 단언한다.
3. **CSP 의 「브라우저 실행에서 위반 0」은 재지 않았다.** 스모크는 셸과 번들 자산이 https 로 200 임을
   재고, 실제 렌더에서의 위반은 브라우저가 필요하다 — 화면이 들어오는 7E 의 자리다. **다만 정책이
   오늘 번들과 맞는지는 출하 이미지에서 쟀다**: 셸에 inline `<script>`·`<style>` 이 0 이고, 참조는
   같은 출처의 JS 하나·CSS 하나뿐이며, CSS 에 `url(...)`·`@font-face` 가 0 이다(JS 안의 외부 주소는
   오류 문면 문자열이고 불러오는 자원이 아니다). 그래서 `'self'` 축만으로 충분하고 `img-src data:`·
   `font-src` 는 7E 를 위한 여유다.
4. **위생·취약점 게이트가 이 두 이미지를 본다**(D-7F-1·2 로 닫혔다 — 앞 판의 제한이 아니다).
   CI 의 네 step 이 매 PR 에 돌고, 남는 칸은 둘이다: ⓐ `apk` 가 금지 목록에 없다(사유는 아래 예외 절)
   ⓑ **allowlist 등재 8줄**(만료 2026-12-15) — caddy 바이너리의 Go toolchain·모듈 4건은 상류 재빌드가
   있어야 사라진다. 만료가 오면 다시 판단해야 하고, 상류가 먼저 고치면 등재가 stale 로 붉어져 스스로
   치워진다(실측).
5. **인증서는 컨테이너 수명이다** — 볼륨을 붙이지 않았으므로 재생성 때마다 CA 가 바뀌고, 브라우저
   신뢰 저장소에 넣은 뿌리는 낡는다(잔여 0 의 대가, runbook §9.3).
6. **read_only 루트·capability 축소를 적용하지 않았다** — 두 서비스 다 `no-new-privileges` 까지다.
7. **정적 응답에 캐시 정책을 두지 않았다** — 운영 도메인·CDN 선택과 함께 갈 판단이다.
8. **로컬 실측의 앱 이미지는 이 worktree 가 만든 것이 아니다**(스모크는 Gradle 을 돌리지 않는다).
   acceptance 의 `container` job 전건 실행에서는 **그 job 이 직접 만든** 이미지로 같은 스모크가 돌았다.
9. **덧쓰기 파일은 `!override` 를 아는 compose 를 요구한다**(v2.24 이후). 낮은 판에서는 파싱이 그 자리에서
   실패한다 — publish 가 조용히 남지는 않는다.
10. **allowlist 만료의 폭발 반경은 kind 하나가 아니다**(r1 vr F-5). 만료 검사는 kind 를 가리지 않으므로
   web 등재 한 줄이 만료되면 **그날 네 스캔이 모두** exit 1 이다(실측). 아래 「후속 — 날짜가 붙은 것」의
   2026-12-15 은 web·proxy 만의 일이 아니다. runbook §9.5 에 같은 문면이 있다.
11. **프록시가 `X-Forwarded-For` 를 신뢰 경계로 다루지 않는다**(r1 cr L-4). `trusted_proxies` 가 없어
   클라이언트가 보낸 XFF 뒤에 덧붙는다. 오늘 영향 0 — `app/`·`adapters/` 에 forwarded·`RemoteAddr`
   참조가 0건이다(r1 재실측). 앱이 클라이언트 주소를 읽기 시작하기 전 또는 7F 본편 반입 전에 닫는다.
12. **HTTP/3 를 광고하지만 UDP 를 publish 하지 않는다**(r1 cr L-5) — 브라우저는 h1/h2 로 폴백한다.
   기능 영향 없음. 운영에서 h3 를 쓸지는 실 host 와 함께 갈 판단이다.
13. **위생의 「싣고 있는 내용」 축은 파일 *내용*을 보지 않는다**(r1 cr L-6) — `find` 가 낸 **경로 목록**
   매칭이라, vite 가 번들 **안에** 인라인한 env 값은 `.env` 패턴으로 잡히지 않는다. 그 축을 닫는 것은
   빌드 입력을 줄이는 쪽이지 이 게이트가 아니다. 키·인증서 재료만은 다른 축이 파일시스템 전체에서 본다.
14. **위생 게이트의 셸 프로브 캐시가 이미지 키를 갖지 않는다**(r1 cr L-7). 한 호출이 이미지 하나만
   판정하므로 오늘은 맞지만 **그 전제가 코드가 아니라 호출 관례에 있다**.

## 후속 — 날짜가 붙은 것

- **2026-12-15**: web·proxy 의 allowlist 등재 8줄이 만료된다(D-7F-2, 운영자 승인). 그때의 선택은 셋
  이고 **날짜를 옮기는 것은 결정이지 정비가 아니다**(6E-2b 의 문면): ⓐ 베이스를 다시 올려 해소
  ⓑ 남아 있으면 사유·기한을 다시 판단 ⓒ 상류가 이미 고쳤으면 등재가 stale 로 붉어지므로 치운다.
- **첫 CI 실행**: `container` job 의 소요가 `timeout-minutes: 30` 에 얼마나 다가가는지 본다. 이
  장비의 3분 36초는 전부 더운 캐시의 수라 러너의 수를 대신하지 못한다(step 여섯이 늘었다).

## D-7F-1 — web·proxy 이미지의 위생·취약점 게이트 (운영자 결정으로 in_scope 추가)

계약 산출물 1 의 「6C 기준(고정 태그·non-root·**금지 패키지 0**)」을 OPEN 으로 넘기지 않고 이 slice 에서
닫는다. 자리와 판정은 기존 두 이미지와 **같은 스크립트·같은 공통 술어**이고, 갈라지는 것은 「금지」뿐이다.

| 자리 | 무엇 |
|---|---|
| `config/quality/image-hygiene-policy-web.properties` · `-proxy.properties` | 이미지별 위생 정책. 둘은 **같은 갈래**(`runtime.kind=caddy-site`)를 쓰고 값만 다르다 — 판정 형태가 같은 것을 두 벌로 만들지 않는다 |
| `config/quality/vuln-policy.properties` | 취약점 정책은 **한 파일**이고 kind 별 키를 갖는다. kind 둘(`web`·`proxy`)과 그 하한·배포판·Java DB 선언을 더했다 |
| `tools/image-hygiene-check.sh` | 새 갈래 `caddy-site` 추가. 「금지/필수 실행 파일」 두 축은 **공유 helper** 로 뽑아 `jvm-app` 분기도 그것을 쓴다(복사본 제거 — 문면·거동 보존) |
| `.github/workflows/ci.yml` | 이미지 빌드 `S-21c`(진입점 하나가 두 이미지를 만든다 — r1 cr M-5 로 `S-21d` 가 합쳐졌다) · 위생 `S-22b2`·`S-22b3` · 취약점 `S-22e2`·`S-22e3`. 번호는 위치 단조로 넣었고 기존 번호를 재배치하지 않았다. 스캔 둘은 SBOM 업로드 **앞**이라 넷 다 올라간다 |

**「금지」의 뜻**(이 갈래에서) — ⓐ **빌더 누출·베이스 교체**: `node,npm,npx,yarn,pnpm,gcc,cc,make` 가
실행되거나 PATH 에 있으면 위반(실행 시도 + PATH 조회 **두 축** — 변이 ⑦ 의 사유 그대로) ⓑ **싣고 있는
내용**: web 은 `/srv` 에 소스맵·소스·`.env`·설치본이 없어야 하고, proxy 는 `/etc/caddy` 에 키·인증서
재료가 없어야 한다(계약의 「저장소에 키·인증서 없음」을 이미지 축에서 다시 잠근다). 두 축 모두
**양성 대조가 먼저**다 — 파일 수 하한을 먼저 요구해 「목록이 비어 위반 0」을 막는다.

**예외 하나와 근거** — `apk`(패키지 관리자)를 금지 목록에 **넣지 않았다**. ⓐ 런타임 사용자(uid 10001)가
시스템 경로에 쓸 수 없고 compose 가 `no-new-privileges` 로 띄워 설치가 성립하지 않는다 ⓑ 그 도구를
지우면 패키지 DB 까지 지워지는 것이 보통이고, 그러면 **취약점 스캐너가 OS 패키지를 열거하지 못한다** —
그 상태의 「차단 0」은 깨끗하다는 뜻이 아니라 맞춰 보지 않았다는 뜻이다(`scan.os.family` 축이 판정
불가로 끊는다). 위생을 위해 스캔을 눈멀게 하는 거래는 하지 않는다. 사유는 두 정책 파일에도 적혀 있다.

### 음성 대조 다섯 — 게이트가 실제로 막는다

| 바꿔치운 것 | 결과 |
|---|---|
| web 런타임에 빌더의 `node` 복사(금지 패키지 투입) | exit 1 — 「금지 실행 파일 'node' 이 PATH 에 있다」 + 크기 상한 초과 |
| 위생 정책에서 `runtime.kind` 제거 | exit 2 — 「정책 키를 읽지 못했다」(fail-closed) |
| `scan.kinds` 에서 `proxy` 제거 | exit 2 — 「kind 가 scan.kinds 에 없다」(fail-closed) |
| allowlist 등재 하나 제거 | exit 1 — 「미등재 finding 1건」 |
| allowlist 만료를 과거로 | exit 1 — 「등재가 만료됐다」 |

사본과 바이트 동일, 나머지는 `git diff --numstat` 빈 출력). **도구 부재도 조용한 통과가 아니다** —
trivy 가 PATH 에 없는 상태의 스캔은 exit 2(판정 불가)였다.
