# M7/7D 정책 값 — 브라우저 접근

`BROWSER_ACCESS_POLICY` 의 `source` 가 이 문서를 가리킨다. **정본은 코드가 아니라 이 문서다**
(`EDIT_SESSION_POLICY`·`KONEPS_COLLECTION_POLICY` 관례) — 값을 바꾸려면 여기를 먼저 고친다.

## §1 값과 근거 (2026-10-16, 구현 레인 제안)

| 값 | 채택 | 근거 |
| --- | --- | --- |
| 유휴 창 | 30분 | 운영자 한 명이 공고를 보다 자리를 비우는 시간. 짧으면 작업 중 재로그인이 잦고, 길면 자리를 떠난 단말에서 세션이 산다. |
| 절대 창 | 12시간 | 「계속 쓰면 영구」를 끊는 상한. 하루 업무를 한 세션으로 덮고 다음 날에는 반드시 다시 로그인한다. |
| 실패 상한 | 5회 | 오타 몇 번은 통과하고 온라인 추측은 막는다. 잠기면 계수를 비운다 — 잠금이 겹겹이 길어지지 않는다. |
| 잠금 창 | 15분 | 운영자가 기다릴 수 있는 길이이자, 추측 속도를 시도/3분으로 떨어뜨리는 길이. |
| 해시 비용 | 12 | bcrypt cost 12 = 2^12 회. 2026년 장비에서 검증 한 번이 수백 ms 로 **의도적으로 느리다**. 10 미만은 너무 빠르고 16 초과는 로그인 한 번이 초 단위가 된다(생성 불변식이 그 범위를 받는다). |

**운영자 승인 상태**: 계약(`scope.md` 산출물 3)이 「값은 정책으로 적는다」로 레인에 맡긴 값이다.
운영자가 다른 값을 원하면 이 표를 고치고 정책 데이터를 그 값으로 바꾼다 — 코드에 숫자가 흩어져
있지 않으므로 바꿀 자리는 둘(이 표와 `BROWSER_ACCESS_POLICY`)이다.

## §2 쿠키 속성과 그 근거

| 속성 | 값 | 근거 |
| --- | --- | --- |
| `HttpOnly` | 켬 | 화면 스크립트가 세션 값을 읽지 못한다. CSRF 값은 본문으로 따로 주고, 그 값은 세션 값에서 단방향 유도라 새어도 세션이 되지 않는다. |
| `Secure` | 켬(기본) | 설정을 잊은 배포가 평문 구간으로 쿠키를 흘리지 않게 기본값을 안전한 쪽에 둔다. 로컬 http 개발 실행만 `bidvector.access.cookie-secure=false` 로 내린다. 운영 TLS 는 7F. |
| `SameSite` | `Strict` | 이 앱에는 다른 사이트에서 돌아오는 진입(OAuth 전환·외부 링크 복귀)이 없다 — `Lax` 가 사는 이유(교차 사이트 최상위 탐색에 쿠키를 싣는 것)가 이득이 없고, `Strict` 는 CSRF 요구 앞단에서 한 겹 더 막는다. |
| `Path` | `/` | API 와 화면이 같은 출처에 선다. |
| `Max-Age` | 절대 창과 같음 | 브라우저가 먼저 버려도 **서버 쪽 만료가 정본**이다(쿠키 만료에 인증을 의존하지 않는다). |

## §3 감사 주체의 값 규약

`api_request_audit.subject` 는 **열을 바꾸지 않고** 값으로 주체를 가리킨다(계약 산출물 1).
어휘는 셋이다 — `account:<id>`(세션 경로) · `operator`(기존 운영자 자격 헤더, 6A 와 같은 값) ·
`unauthenticated`(신원 없음: 인증 실패와 로그인 시도). 계정 식별자는 비밀이 아니다(쿠키·CSRF
값과 달리 추측해도 권한이 없다).
