## 먼저 재현할 것 (구현 전 — 결과에 따라 설계가 갈린다)

**가설 H: 운영 gid 구성에서 지금의 래퍼는 첫 run 에 `exit 3` 으로 죽는다.** runbook §14.1 이 만드는
root 는 `소유 deploy · group 10001 · 2700` 이고 `deploy` 는 group 10001 의 구성원이 **아니다**(그 group 에
사람이 없어야 한다는 것이 §14.1 의 요구다). 그 구성에서 r2 가 잰 사실 둘:

- 비구성원이 `chmod 2700` 을 치면 커널이 setgid 를 **지운다**(vr L-b: `700`).
- `mkdir -p -m 2770 <root>/notice-list/<달>` 한 번에 만든 잎은 `770` 이다(vr L-a — `mkdir -m` 이 만든 뒤
  chmod 를 한 번 더 치고 거기서 비트가 떨어진다).

래퍼는 조상을 `mkdir -p -m 2700` 으로 **따로** 만든다. 같은 기전이면 조상이 `700`(setgid 탈락)으로 서고
바로 뒤의 「갈래 디렉터리에 setgid 가 없다」 술어가 `exit 3` 을 낸다 — 그리고 그 문면의 처방(`chmod 2700`)은
같은 이유로 먹지 않는다. r2 의 두 레인은 잎만 쟀고 이 조합은 재지 않았다.

재현: 버릴 컨테이너를 root 로 띄워 scratchpad 디렉터리를 `1000:10001 2700` 으로 만든 뒤, host 의 `deploy`
(비구성원)로 래퍼의 `_collection_prepare_run_state` 와 같은 순서의 명령을 친다. **H 가 거짓이면** 구현 전에
보고하고 D-15V-2 를 접는다(나머지는 그대로 간다). 재현 표(구성 × 명령 × 결과 mode·gid)를 commands.md 에 남긴다.

## 결정

- **D-15V-1 root 도 술어 안으로 들인다.** 인자 검사 자리(생성보다 앞)에서 root 의 ⓐ setgid 있음
  ⓑ group 쓰기 닫힘 ⓒ other 쓰기 닫힘을 본다. 어긋나면 `exit 3` 이고 문면은 §14.1 의 `install -d` 줄을
  가리킨다. 사유: 조상에 건 논증 둘(그 비트가 group 을 아래로 잇는다 · 쓸 수 있으면 아래 층을 바꿔칠 수
  있다)이 한 층 위에도 그대로 선다(cr M-1 · vr L-h). root 가 심링크인 것은 지금처럼 받는다(실경로로 푼다).
- **D-15V-2 두 층은 `-m` 없이 만든다 — umask 를 좁힌 부속 셸에서 `mkdir` 한 번씩.** 조상은 `umask 077`,
  잎은 `umask 007`. `mkdir(2)` 는 부모의 setgid 와 group 을 물려주고, `-m` 이 없으면 뒤따르는 chmod 가
  없어 그 비트가 구성원 여부와 무관하게 남는다. 결과 모양은 지금 문서의 `2700`/`2770` 그대로다 — 바뀌는
  것은 만드는 법뿐이다. (H 가 참일 때의 처방이다. 이 방식이 구성원·비구성원 **두 구성 모두**에서 그 모양을
  내는지 재현 표로 보인다. 다른 방식이 더 좁게 닫으면 근거를 적고 그쪽으로 간다.)
- **D-15V-3 group 등식을 잰다 — 조상의 gid == root 의 gid · 잎의 gid == root 의 gid.** setgid 비트는
  「앞으로 만들 자리」만 묶는다. **이미 있는 자리**의 group 이 틀린 경우(cr M-1 의 귀결: 러너가 기동에서
  죽고 그 종료가 1 이라 예외와 섞인다)는 비트 술어가 보지 못한다. root 의 gid 는 운영자가 §14.1 에서 정한
  값이고 `stat` 으로 권한 없이 읽힌다. 어긋나면 `exit 3`. 조상 setgid 술어는 남긴다(다음 달의 자리를 묶는다) —
  다만 「새로 만든 경우에는 D-15V-2 때문에 늘 참」이라는 사정거리를 주석에 적는다.
  `OPEN-M15-COLLECTION-RUN-STATE-GID` 는 **「root 의 gid 가 이미지의 gid 인가」 한 칸으로 좁혀** 남긴다.
- **D-15V-4 처방 문면은 운영 gid 구성에서 실제로 먹는 명령만 적는다.** 래퍼의 `_die` 문면과 §14.9 표의
  `chmod 2700`·`chmod 2770`·「group 을 맞춘다」를 전수해, 비구성원 소유자가 `sudo` 없이 치면 먹지 않는
  것은 `sudo` 꼴로 고치고 각각을 재현 표에서 한 번씩 친다. §14.1 의 「`chmod 2700`·`chmod 0700` 은 setgid 를
  지우지 않는다(실측)」은 **구성원일 때만 참**이다 — 조건을 붙이거나 걷는다.
- **D-15V-5 §14.5 ③ 의 로그 파일은 `0600` 으로 먼저 만들고, ④ 끝에 지우는 단계를 둔다.** `tee` 앞에
  `install -m 600 /dev/null <그 경로>` 한 줄(`tee` 는 있는 파일의 mode 를 바꾸지 않는다 — 실측으로 확인),
  ④ ⓕ 뒤에 제거 한 줄과 「지우기 전에는 ⓕ 를 다시 셀 수 있다」는 순서 주. 자리는 `/var/tmp` 그대로 둔다
  (cr M-2). 등재 줄 목록이 따라간다.
- **D-15V-6 §14.5 ④ 의 전제 가드는 질의를 실제로 막는다.** 세 값 모두 「비어 있지 않다 · `null` 이 아니다」로
  보고, 질의 블록을 `if … then … fi` 로 감싼다(붙여넣기 셸에는 `set -e` 가 없다 — cr L-3 · vr L-i). 그
  토막을 뽑아 빈 값·`null` 에서 질의 명령에 닿지 않음을 가짜 `docker` 로 한 번 잰다.
- **D-15V-7 생성을 이름 충돌 검사 뒤로 옮긴다**(cr L-1). 「거절·미룬 run 은 자리를 남기지 않는다」 단언에
  그 꼴을 더해 전칭이 표본 셋 위에 서게 한다.
- **D-15V-8 공허하던 단언을 가른다.** 각각 r2 의 그 변이가 **RED 로 바뀌는 것**이 완료 기준이다:
  - 잎 심링크 거절(vr V6b) — 문면 단언으로 축을 못박는다.
  - `TimeoutStartSec` 부등식(vr V12c) — 가드 주석이 말하는 부등식을 코드로 세운다.
  - 「붙임의 원천은 실경로다」(vr V14 · cr L-2) — 글자가 같은 중복 단언을 걷고, **root 를 심링크로 준 꼴**
    (거절되지 않는 유일한 층)에서 `-v` 에 실린 값이 실경로임을 잰다. 래퍼 끝의 `RUN_STATE_DIR="$real"` 이
    여전히 값을 바꾸지 않는 겹이면 그 사실을 제한으로 등재한다(지우지 않는다 — 15U 주석의 사유 둘).
  - rc 만 보던 음성 셋 + 심링크 셋째 꼴(cr L-5) — `_expect_text` 한 줄씩.
- **D-15V-9 가드 fixture 정리를 trap 안으로**(cr L-4) — 저장소 안에 만드는 심링크 타깃을 `_cleanup` 이 지운다.
- **D-15V-10 KST 축 단언은 24시간 판별한다**(vr L-c) — 반대 방향 구역을 함께 써서 하루 어느 시각의 CI
  에서도 `TZ=Asia/Seoul` 제거 변이가 RED 가 되게 한다. 시각을 고정한 재현(가짜 `date` 또는 `faketime` 없이
  되는 방식)으로 창 밖 시각에서도 RED 임을 보인다.
- **D-15V-11 15U `commands.md` 의 라운드 이력 절을 걷는다**(vr L-g) — 절 제목을 주제 제목으로 바꾸거나
  본문을 주제 절로 접는다. 수치·명령은 건드리지 않는다.

## 설계 검토 (세션 모델)

- **(1) 열거인가 구성인가.** D-15V-3 은 비트 열거에서 **등식**으로 한 칸 옮긴다 — 「group 이 이어지는가」를
  비트의 유무(원인)로 재던 것을 gid 의 같음(결과)으로 잰다. D-15V-2 는 「구성원일 때만 먹는 chmod」에
  기대던 생성을 커널의 상속에만 기대게 한다.
- **(2) 우회 다섯 — 각각 가드 음성 한 꼴로 선다.** ⓐ root 에 setgid 없음 → 3 ⓑ root 에 group 쓰기 → 3
  ⓒ root 에 other 쓰기 → 3 ⓓ 이미 있는 조상의 gid 가 root 와 다름(비트는 있음) → 3 ⓔ 이미 있는 잎의 gid 가
  root 와 다름(mode 는 2770) → 3. 다섯 모두 문면 단언으로 축을 못박는다. gid 를 바꾸는 fixture 가 host 에서
  권한 없이 서지 않으면(비구성원은 `chgrp` 를 못 친다) 호출자가 **속한 다른 group** 을 쓰거나 가짜 `stat`
  으로 세우고, 어느 쪽인지 commands.md 에 적는다 — 세울 수 없는 꼴을 「통과」로 적지 않는다.
- **(2b) 값 획득 축.** 새 public 표면 0(새 인자·새 env·새 출력 값 없음). 새 `_die` 문면이 내는 것은 경로·
  mode·gid 숫자뿐이다. 새로 생기는 값의 자리는 runbook 의 로그 파일 하나이고 D-15V-5 가 mode 와 수명을 묶는다.
  **r2 가 더한 행 — 「가드가 문서 문면을 `bash` 로 돌린다」**(cr L-4). r1 이 ④ 래칫을 실행 층으로 내리면서
  **새 실행 표면**이 생겼는데 이 축에 적지 않았고, 그 빈칸의 귀결이 vr H-1 = cr H-2 다. 그 표면의 네 칸:
  **범위**(시작 표지가 든 펜스 안 · 종단자 필수 · 줄 수 상한 40 · 마지막 줄 `fi`) · **PATH**(`env -i` +
  전용 디렉터리의 열거한 이름만) · **cwd**(`$T/qrun` — 저장소 밖이라 `./tools/*` 가 해석되지 않는다) ·
  **stdin**(`/dev/null`). 위험 이름 다섯은 가짜를 두고 **호출 0 회**를 센다(「없음」은 호출을 막지 못한다).
- **(3) 과잉·미달.** root 를 「정확히 2700」으로 조이지 않는다 — 필요한 것은 비트 셋이고 운영자가
  group 읽기를 여는 것까지 막을 근거가 없다. gid 값 등식은 미달로 남는다(OPEN, 사유는 out_of_scope).

## 구현 레인이 정하고 근거를 적을 것 (채웠다 — 2026-11-28)

(수는 `commands.md` 가 든다 — 여기는 결정과 그 근거 한 줄이다.)

1. **H 의 재현 결과와 D-15V-2 의 최종 꼴.** H 는 거짓(계약 갱신 ①). D-15V-2 는 **유지**하고 꼴은 계약이
   적은 그대로다 — `-m` 없이 조상 `umask 077` · 잎 `umask 007`. 근거: 그 꼴이 **두 구성 모두**에서
   `2700`/`2770` 을 낸다. 만든 뒤 `chmod` 로 맞추는 대안은 **비구성원의 chmod 가 바로 setgid 를 지우는
   자리**라 같은 병을 다시 들인다.
2. **(2) ⓓ·ⓔ fixture.** `chgrp <호출자의 보조 group>`(`id -G` 의 primary 아닌 첫 gid). `chgrp` 는
   디렉터리의 setgid 를 지우지 않으므로 **비트는 멀쩡한 채 gid 만 틀린** 자리가 서서 mode 축과 섞이지
   않는다. 보조 group 이 없으면 **통과로 적지 않고 `exit 2`(판정 불가)**. 가짜 `stat` 은 쓰지 않았다.
3. **D-15V-10 의 구역과 창 밖 재현.** 반대 방향은 **`Etc/GMT+12`**(UTC-12) — UTC+14 는 KST 19:00~23:59,
   UTC-12 는 KST 00:00~20:59 에 날짜가 달라 합집합이 하루를 덮는다. 창 밖 시각은 **`date -d` 의 고정
   순간**으로 쟀다(가짜 `date`·`faketime` 없이). 게이트는 그 판별력을 **지금 시각에 대해서도** 센다.
4. **변이 표** — `commands.md`. r2 의 V6b·V12c·V14 와 새 술어마다 하나씩, 기대는 **그 축의 문면을 든
   실패**다.

## 알려진 제한 (구현 레인이 실측으로 채웠다 — 2026-11-28)

1. **gid 의 값 등식은 여전히 미달이다** — 「실행 상태 root 의 gid 가 **app 이미지의** gid 인가」. 두 층의
   gid 가 root 의 gid 와 같은가는 이 slice 가 등식으로 재게 했지만, 그 root 의 gid 가 맞는 값인지는
   이미지 조회가 필요하다(`OPEN-M15-COLLECTION-RUN-STATE-GID` 의 남은 한 칸). 어긋나면 fail-closed 는
   아니다 — 세 층의 gid 가 **일관되게 틀리면** 래퍼는 통과하고 컨테이너가 원장에 쓰지 못해 러너가
   종료 1 로 죽는다. 그 자리를 §14.1 의 운영자 확인(`stat -c '%g'` 와 `getent group`)이 든다.
2. **gid 축의 fixture 셋이 모두 보조 group 에 의존한다.** 가드는 `id -G` 에서 primary 가 아닌 첫 gid 로
   ⓐ 조상 불일치 ⓑ 잎 불일치 ⓒ **root 를 그 group 으로 세운 양성**(r1 에서 더했다 — 기준값이 `id -g` 가
   아니라 root 의 gid 임을 가른다)을 세운다. 보조 group 이 없는 계정에서는 **판정 불가(exit 2)** 로 선다 —
   건너뜀이 아니다. CI 는 `ubuntu-latest` 이고 그 러너의 계정은 보조 group 을 갖지만(`adm`·`docker` 따위)
   **이 레인이 CI 에서 직접 확인하지는 못했다**(그 축이 비면 `exit 2` 로 크게 말한다).
3. **운영 gid 구성 자체는 host 에서 세울 수 없다.** 가드의 fixture 는 **호출자의 group**(구성원 구성)으로
   서고, 비구성원 구성의 모양은 **버릴 컨테이너를 root 로 띄워** 소유·group 만 세운 재현 표가 든다
   (commands.md). 즉 **CI 가 매 PR 에서 재는 것은 구성원 구성**이고, 비구성원 구성의 「두 꼴이 같은 모양을
   낸다」는 이 라운드의 일회 실측이다. 그 축을 CI 에 넣으려면 러너에 특권이 필요하다.
4. **`RUN_STATE_DIR="$real"` 는 여전히 발화하지 않는 겹이다.** 두 층의 심링크가 거절되고 root 는 인자
   검사에서 이미 해석되므로 그 대입이 값을 바꾸는 판이 없다(r2 의 V14 가 GREEN 인 사유 그대로). 남겨 두는
   이유는 15U 주석의 둘이다 — 붙는 값과 재는 값을 한 값으로 묶는 규율 · 한 층이 뚫릴 때의 경계.
   **D-15V-8 이 더한 것은 「붙임의 원천이 해석된 경로다」를 root 를 심링크로 준 꼴에서 재는 단언**이고,
   그것은 `RUN_STATE_ABS` 의 해석을 잰다(그 대입이 아니라).
5. **검사와 사용 사이의 창은 그대로다**(runbook §11 제한 21) — root·두 층의 mode·gid·심링크를 본 뒤
   `docker compose run` 이 그 자리를 붙이기까지 수 초가 있다. 그 창에서 자리를 바꿀 수 있는 주체는
   `deploy`·root 뿐이고 위협 모델 경계와 같은 급이다.
6. **③ 의 로그 파일은 `/var/tmp` 에 남는다** — `0600` 으로 만들고 ④ 끝에 지우지만, 그 사이에 재부팅이
   들면 파일은 살아 있다(`/var/tmp` 는 재부팅에 지워지지 않는다). 자리를 `/var/lib/bidvector-v2` 로 옮기는
   쪽은 cr 이 선택지로 들었고 이 slice 는 **자리를 그대로** 두기로 한 계약(D-15V-5)을 따랐다.
7. **runbook 의 `_pages` 와 ④ 블록은 셸 `grep` 을 쓴다** — 이 host 의 셸 `grep` 은 ugrep 래퍼라 거동이
   다를 수 있다(운영 host 는 진짜 grep 이다). r2 가 finding 으로 올리지 않은 자리이고 이 slice 도 바꾸지
   않았다.
8. **KST 축의 「달」 단언은 달 경계에서만 하중을 받는다**(r1 · cr L-5). 판별력 대조는 세 구역의 **날짜**
   (`%F`)를 세므로 **날짜 축은 24시간 닫혔다**. 같은 루프의 달 디렉터리 단언(`…/${KST_MONTH}:`)은 두 구역이
   KST 와 같은 달인 날(한 달의 대부분)에는 아무것도 재지 않는다 — 변이 커버리지에 구멍은 없고(날짜 축이
   `TZ` 전달을 받는다) 「24시간 판별」이 **날짜 축 한정**이라는 점만 적어 둔다.
9. **진짜 `sudo` 의 감사 부작용은 재지 않았다**(r1 · cr open question). H-1 의 백틱은 가짜 `sudo` 로
   실행을 재현했고(두 번) 처방이 그 축을 닫았지만, 진짜 바이너리가 `auth.log`·journald 에 줄을 남기는지는
   이 레인이 `sudo` 를 쓰지 않아 미재현이다. 고친 뒤로는 그 호출 자체가 없다.
10. **gid 값 등식을 이미지에서 읽는 길의 비용은 재지 않았다**(r1 · cr open question). 래퍼는 manifest
   대조에서 이미 `docker image inspect … {{.Id}}` 를 부르므로 `.Config.User` 는 호출 하나 거리지만, app
   이미지가 그 칸에 gid 를 **숫자로** 선언하는지(이름이거나 base layer 의 `USER` 로만 있는지)는 재지
   않았다 — 재지 않고 권하지 않는다. `OPEN-M15-COLLECTION-RUN-STATE-GID` 가 그 자리다.
11. **`shred -u` 의 실효는 보장이 아니다**(r1 · cr open question). `/var/tmp` 가 ext4 journal·CoW·overlay
   위면 덮어쓰기가 보장되지 않는다. 주 방어는 mode 600 + 수명 제한이고 문면에 보장을 적지 않았다.
12. **이미 있는 root 에 `sudo install -d -m 2700 -o … -g …` 를 쳤을 때의 거동은 미재현이다**(r1 · vr).
   GNU coreutils 를 특권으로 돌릴 자리가 없어 재지 않았다(버릴 컨테이너는 busybox `install` 이다).
   §14.1 이 그 명령을 **처음 한 번**으로 적으므로 재설치 경로는 운영자 확인에 남는다.
13. **`/var/tmp` 고정 이름은 선점될 수 있다**(r1 · vr L-5). 다른 비특권 계정이 그 이름을 미리 만들면
   `install` 이 rc 1 로 끝나고, r1 에서 그 줄을 `&&` 로 이어 **거기서 멈추게** 했다. 이 host 에서는
   `fs.protected_regular=2` 라 `tee` 도 거부됐지만 **운영 host 의 그 sysctl 값은 재지 않았다**.

14. **④ 가 실행하는 글자는 등재본 한 장으로 고정됐다 — 남는 것은 전제 하나다**(계약 갱신 ⑥).
   가드는 runbook §14.5 ④ 펜스 본문을 뽑아 `config/quality/runbook-collection-step4-block.txt` 와
   **바이트로** 견주고, 다르면 아무것도 실행하지 않으며, 돌리는 것은 **등재본에서 자른 토막**이다.
   그래서 「무엇이 실행될 수 있는가」는 더 이상 검사기의 사정거리가 아니라 **저장소의 그 파일**이다.
   **남는 전제 하나**: 「등재본을 고치는 커밋이 리뷰를 지난다」. runbook ④ 와 등재본을 **같은 커밋에서
   같은 줄로** 고치면 등식은 통과하고 그 줄이 돈다 — 그 꼴은 **정적으로만** 확인했다(실행하지 않았다).
   위협 모델 경계상 게이트 입력을 임의로 쓰는 저자는 모델 밖이고 그 경계가 이 전제를 지탱한다(등재 줄
   래칫·기대 집합 파일과 같은 급이다).
   **깊이 방어로 남긴 것**: `env -i` · 전용 PATH(`cat`·`jq`·가짜 `docker`·위험 이름 가짜 다섯 —
   `bash`·`grep` 은 뺐다) · `bash -r` · stdin `/dev/null` · 저장소 밖 cwd · 위험 이름 호출 0 과 그
   양성 대조 · `-r` 양성 probe. **그 층들이 닫지 못하는 것 셋**: ⓐ 등재된 `cat`·`jq` 가 파일을 읽는
   것 — 그 사정거리가 **리뷰된 한 장**이라는 것이 이제 답이다 ⓑ **`-r` 는 자식에게 물려지지 않는다**
   (실측: 자식의 `$-` 에 `r` 이 없고 파일을 만들었다). 토막이 부르는 등재 도구가 스크립트면 그 안은
   restricted 가 아니다 — 오늘 그 자리는 가드가 만든 가짜뿐이고 shebang 이 절대 경로다 ⓒ 토막의
   stdout·stderr 가 `$T` 아래 파일로 가는 것(`mktemp -d` 0700 · EXIT trap 이 지운다 · 게이트 stdout 에
   찍히지 않는다).
   **이 칸은 앞서 두 번 거짓이었다** — 한 번은 「격리가 새면 「열거 밖 이름 미해석」 단언이 먼저
   말한다」(그 단언이 재는 것은 PATH 축 하나다), 다음은 꼴 검사가 그 축을 받는다는 서술(대입 접두 ·
   단일 `&` · 조립 경로 · PATH 의 `bash` 로 열렸고 리뷰가 게이트 GREEN 인 채 격리 밖 쓰기를
   실측했다). **열거로 닫으려는 시도가 세 번 같은 자리에서 열렸다**는 것이 ⑥ 의 사유다.
15. **백틱 스캐너가 받는 꼴은 정해져 있다**(r2, vr M-a). 받는 것: 줄을 넘어 이어지는 인용 · `$( )` 중첩 ·
   `<<'DELIM'` · `<<DELIM`. 그 밖(인용이 파일 끝까지 닫히지 않음 · 다른 heredoc 꼴)은 **STOP 으로 붉는다** —
   건너뜀이 아니다. 인용 heredoc 본문은 새 상태로 훑으므로, 데이터를 담은 heredoc 이 홀따옴표를 짝 없이
   품는 날 STOP 이 뜬다(그때 받는 꼴을 넓히거나 그 heredoc 을 고친다). `$( )` 치환은 금지하지 않는다 —
   모집단의 집안 관용구다. **보지 않는 경계 셋**(승인 전 묶음 — vr L-2 = cr L-1, 셋 다 실측):
   ⓐ **하위 언어** — `bash -c '…'` 의 인자는 단일 인용이라 0 으로 세지만 그 안의 백틱은 **실행된다**
   (인용 heredoc 본문은 셸로 훑으면서 `-c` 인자는 안 보는 비대칭이다). 현재 두 파일의 `-c '…'` 에
   백틱 0. ⓑ **데이터 heredoc** — 본문을 셸 프로그램으로 훑는 설계이므로 fixture·문서를 담은 본문의
   리터럴 백틱은 **오탐**으로 붉는다. 그 처방은 「걷기」가 아니라 **「단일 인용으로 감싸기」**이고
   `_bad` 문면이 그렇게 적는다(걷으면 fixture 가 망가진다). ⓒ `<<"DELIM"`·`<< 'DELIM'` 은 적법한
   꼴인데 STOP 이다. **ⓑⓒ 는 붉게 서지만 ⓐ 는 0 으로 세며 그 백틱은 실행된다** — 조용히 통과하는
   유일한 가지다(그래서 「현재 두 파일의 `-c '…'` 에 백틱 0」을 함께 적는다. 그 꼴이 들어오는 날은
   스캐너가 말해 주지 않는다).

## 계약 갱신

**① 가설 H 는 거짓으로 측정됐다(2026-11-28, 구현 전 재현).** 운영 gid 구성(root `1000:10001 2700` ·
래퍼 사용자는 비구성원)에서 지금의 `mkdir -p -m 2700` 은 조상을 `2700`/gid 10001 로 세운다(umask 네 꼴
전부). GNU `mkdir` 은 `mkdir(2)` 와 부모 상속으로 요청 모양에 **이미 닿으면 chmod 를 치지 않는다** — 조상은
그대로 닿아 비트가 남고, 잎만 chmod 가 붙어 setgid 가 떨어진다(`770`). 술어는 전부 통과하고 gid 만 같은
컨테이너가 원장에 썼다. **첫 run 은 `exit 3` 으로 서지 않는다** — 「무엇을 닫는가」의 그 문장과 「먼저
재현할 것」의 예측은 틀렸다(지우지 않고 여기서 정정한다).

**② D-15V-2 는 유지하되 사유를 바꾼다 — 「exit 3 방지」가 아니라 「문면과 현물을 하나로」.** 접으면
runbook §14.1 · 가드 fixture 의 잎 `2770` 과 운영 현물 `770` 이 어긋난 채 남고 설명이 구성에 따라 둘로
갈린다. `-m` 없는 방식은 두 구성 모두에서 `2700`/`2770` 을 낸다(재현 표). 거동 변화는 0 이어야 하고
그것을 가드 단언으로 보인다.

**③ cr M-1 은 독립 재현으로 참이다** — root 에 setgid 가 없으면 두 층의 gid 가 래퍼의 gid 로 박히고
`-m 2700` 이 조상 비트를 명시로 세워 술어가 전부 통과한 뒤 컨테이너 쓰기가 실패한다(러너 종료 1).
D-15V-1·3 이 이 slice 의 주 처방이다.

**④ 수정 라운드 1 의 갱신(2026-11-28).** 리뷰 둘(cr `request_changes` high 1 · vr `ready` medium 2 ·
low 6)의 지적을 **각자 재현**한 뒤 닫았다. 참으로 측정된 것: ⓐ cr H-1 — 새 `_die` 두 문면의 큰따옴표 안
백틱이 **명령 치환으로 `sudo` 를 두 번 실행**하고 그 단어를 출력에서 지웠다(`** 가 필요하다**`). `bash -n`
과 기존 문면 단언 어디에도 걸리지 않았다 · ⓑ cr M-2 — 가드의 `_ok`/`_bad` 두 줄이 같은 꼴이라 **초록 run
마다 stderr 에 구문 오류 한 줄**을 냈다(통제군으로 재확인: 괄호가 빈 채 출력되고 PASS 는 증가) · ⓒ vr M-1 —
④ 「구조 래칫」이 줄 **존재**만 세어 `docker exec` 를 `fi` 뒤로 옮기는 회귀를 통과시켰다 · ⓓ vr M-2 —
fixture 의 root gid 가 호출자 primary 와 같아 기준값을 가르지 못했다 · ⓔ vr L-1 — `_tss_minutes` 가
`1min30s`·`0.5h` 에서 **게이트를 죽였다** · ⓕ vr L-2 — D-15V-2 뒤로 「조상의 setgid 는 커널 상속으로
선다」가 거짓이 됐다(root 에 setgid 가 없으면 조상이 `700` 으로 생긴다) · ⓖ vr L-4 — 「지우는 줄」 계수가
주석을 셌다 · ⓗ cr L-1 — 새 `/var/tmp` sink 다섯 줄 가운데 **한 줄만** 등재 래칫에 들어왔다 · ⓘ cr L-3 —
`_col_no_residue` 의 새 표본 둘이 **다른 축**에서 끊긴다.
**새 파일 0** — 이 라운드가 만진 것은 in_scope 의 기존 항목뿐이다(`config/quality/runbook-prod-path-lines.txt`
가 처음으로 바뀌었고, 계약이 그 자리를 「바뀔 때만」으로 열어 두었다). 새 public 표면 0.
처방 가운데 **부류를 닫은 것 둘**을 적어 둔다: 문면 자리의 살아 있는 백틱 0 래칫(ⓐⓑ 의 부류)과,
④ 래칫을 문자열 술어에서 **실행 층**으로 옮긴 것(ⓒ — 정본 Phase 2.5 (1)).

**⑤ 수정 라운드 2 의 갱신(2026-11-28).** 리뷰 둘이 **같은 high** 를 독립으로 들었다(vr H-1 = cr H-2):
r1 이 ④ 래칫을 실행 층으로 내리면서 **실행하는 텍스트의 범위를 정하는 것이 앵커 하나**가 됐다. 정적
재현(실행하지 않고 추출 awk 만 적용): 닫는 `fi` 를 세 꼴로 고치면 추출이 **29 → 62 줄**로 넓어지고 그

받는다**. 이 host 에 `/etc/bidvector-v2` 가 있어 품질 게이트가 운영 타이머를 켜는 길이었다. **격리를 먼저
세워 커밋한 뒤에** 종단자 변이를 가드 전건으로 돌렸다(세 꼴 모두 추출 0 줄 · 실행 0 회 · RED).
그 밖에 참으로 측정된 것: ⓐ cr M-1 — ④ 의 여섯 조건 가운데 **둘**만 fixture 가 받았다 · ⓑ cr M-2 —
`_tss_minutes` 가 `2m30s` 에서 여전히 게이트를 죽였다(r1 의 닫힘 주장이 그 꼴에 거짓이었다) · ⓒ vr M-a —
백틱 래칫의 모집단이 열거라 미탐 셋이 있었다(둘째 인자 · `echo` 문면 · 연속 줄). **새 파일 0 · 새 public
표면 0** — 새로 등재한 것은 위 (2b) 의 실행 표면 한 행과 제한 14·15 다(그 등재 누락이 cr L-4 였다).

**⑥ ④ 실행 층의 설계를 바꾼다 — 「뽑아서 실행」에서 「등재본과 같음을 보고, 등재본을 실행」으로(2026-11-28,
세션 모델 결정).** 같은 축의 지적이 세 번 돌았다(범위 상한 없음 → 격리가 PATH 만 막음 → 꼴 검사가 대입
접두·`&`·조립 경로에서 열리고 자기 실패에서 통과). 세 번 다 처방이 **열거**였다 — 임의의 셸 문면을
실행하면서 「해로운 꼴」을 세는 한 꼴 집합은 닫히지 않는다(verifier 가 게이트 GREEN 인 채 격리 밖 쓰기를
실측했다). 구성으로 닫는다:

- runbook §14.5 ④ 의 그 펜스는 **등재 파일 한 장과 바이트로 같아야 한다**(`config/quality/` 아래 신설 —
  in_scope 에 더한다). 다르면 `_bad` 이고 **아무것도 실행하지 않는다.** runbook 의 ④ 를 고치는 사람은
  등재본을 함께 고치고, 그 diff 가 리뷰를 지난다(등재 줄 래칫과 같은 규율).
- 가드가 실행하는 것은 runbook 에서 뽑은 문면이 아니라 **등재본**이다. 실행되는 글자가 리뷰된 한 장으로
  고정되므로 「무엇이 실행될 수 있는가」가 꼴 검사의 사정거리가 아니라 **저장소의 그 파일**이 된다.
- 실행 전 꼴 검사는 **걷는다**(자기 실패에서 통과하던 층 — cr r4 M-1 · vr r4 L-a 가 함께 사라진다).
  `env -i` · 전용 PATH · `bash -r` · stdin 닫음 · 저장소 밖 cwd · 위험 이름 가짜와 그 양성 대조는 **깊이
  방어로 남긴다**. 전용 PATH 에서 뺄 수 있는 이름(`bash`·`cat`·`grep`)은 뺀다(가짜 `docker` 의 shebang 은
  절대 경로로).
- 등식의 비공허: 등재본이 비어 있지 않고 psql 호출 줄을 담는다는 것, 추출이 그 한 펜스라는 것(시작 표지 1 회).
- 변이의 완료 기준: runbook ④ 에 한 줄을 더하거나(무해한 주석 포함) 등재본만 고친 꼴 **둘 다 RED · 실행 0**.
  verifier 의 관통 다섯 줄은 정의상 등식에서 선다.

제한 14 는 이 설계로 다시 쓴다 — 남는 것은 「등재본을 고치는 커밋이 리뷰를 지난다」는 전제 하나다(위협
모델 경계: 빌드 스크립트·게이트 입력을 임의로 쓰는 저자는 모델 밖).
