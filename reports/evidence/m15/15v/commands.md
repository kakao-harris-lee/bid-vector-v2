# M15 / 15V — commands

실 운영 자원(조달청 API·운영 DB·운영 compose·systemd·`/etc/bidvector-v2`·`/srv`)을 **하나도** 부르지
않았다. `sudo` 0. 실측은 scratchpad 와 **버릴 컨테이너**(`busybox:1.36` · `--network none` · `--rm` ·
붙이는 자리는 scratchpad)에서만 돌았다. 출력 전문은 싣지 않는다.

## 구현 전 재현 — 가설 H 는 거짓이다

구성을 세운 법: 버릴 컨테이너를 root 로 띄워 scratchpad 디렉터리의 **소유·group 만** 세웠다. host 의
`deploy` 는 그 group 의 **비구성원**이다(`id -G` 에 10001 없음 · `getent group 10001` 빈 출력 — §14.1 의
요구대로다). 판정과 기전은 scope.md 「계약 갱신」 ①~③ 이 든다 — 여기는 **수**다.

| root 구성 | 만드는 법 | 조상 `notice-list` | 잎 `<YYYY-MM>` |
|---|---|---|---|
| **비구성원** `1000:10001 2700` | `mkdir -p -m`(앞 판) | **2700** / 10001 | **770** / 10001 |
| 구성원 `1000:1000 2700` | 같음 | 2700 / 1000 | 2770 / 1000 |
| **비구성원** | **D-15V-2**(`-m` 없이 umask 077/007) | **2700** / 10001 | **2770** / 10001 |
| 구성원 | D-15V-2 | 2700 / 1000 | 2770 / 1000 |

앞 판 두 줄은 umask **0022·0077·0000·0002 네 꼴 전부**에서 같은 값이었다. 래퍼의 술어 네 줄을
`tools/prod-collection.sh` 에서 **축어로 뽑아** 그 값에 먹였더니 비구성원 구성의 다섯이 **전부 통과**했고,
그 자리(조상 `2700` · 잎 `770`)에 `--user 10002:10001`(uid 다름·gid 같음 = 운영 모양) 컨테이너가 **원장을
썼다** → 첫 run 은 `exit 3` 으로 서지 않는다.

**cr M-1 축은 참이다**(독립 재현). root 가 `0700`/10001 이면 두 층의 gid 가 **1000**(래퍼의 gid)으로 박히고
`-m 2700` 이 조상 비트를 명시로 세워 **술어 다섯이 전부 통과**한 뒤, 같은 컨테이너가 그 자리에 **쓰지
못했다**(other 로 떨어진다) — 러너는 기동에서 죽고 종료는 `1` 이다. D-15V-1·3 이 그 자리를 겨눈다.

## D-15V-2·4·5·6 과 (2) fixture 의 전제 실측

- **D-15V-2**: 위 표 아래 두 줄 — **두 구성 모두** `2700`/`2770`. 거동 변화 0(비구성원 구성의 그 자리에
  운영 모양 컨테이너가 썼다).
- **D-15V-4**: 비구성원 소유자의 `chmod 2700` → **`700`**(setgid 가 서지 않는다) · **특권**으로 같은 명령
  → `2700`. 특권 쪽은 `sudo` 대신 **버릴 컨테이너의 root** 로 쳤다(같은 syscall 경로 · 같은 디렉터리).
- **D-15V-5**: `install -m 600` 으로 먼저 만들면 `tee` 뒤에도 **600** · 먼저 만들지 않으면 평소 umask 에서
  **644**(`tee` 는 있는 파일의 mode 를 바꾸지 않는다).
- **D-15V-6**: §14.5 ④ 의 가드 토막을 runbook 에서 **축어로 뽑아** 가짜 `docker`(argv 기록) 앞에서 네 꼴로
  돌렸다 — 정상 `docker exec` **1 회** · 빈 `P` / `null` `PGUSER_` / `null` `PGDB_` **0 회**(세 꼴 모두
  「질의하지 않았다」를 stderr 로 낸다). 앞 판의 `|| { …; false; }` 는 그 셋에서 다음 줄이 그대로 돌았다.
- **(2) ⓓ·ⓔ fixture**: `chgrp <호출자의 보조 group>`(`id -G` 의 primary 아닌 첫 gid — 이 host 에서 `4`).
  `chgrp` 는 **디렉터리**의 setgid 를 지우지 않으므로(실측 `2700/1000` → `2700/4`) **비트는 멀쩡한 채 gid
  만 틀린** 자리가 서고 mode 축과 섞이지 않는다. 보조 group 이 없는 계정에서는 세울 수 없고, 가드는
  통과로 적지 않고 **`exit 2`(판정 불가)** 로 선다. 가짜 `stat` 은 쓰지 않았다.

## D-15V-10 — KST 축의 24시간 판별

`Pacific/Kiritimati`(UTC+14)는 KST **19:00~23:59** 에만 날짜가 다르고 `Etc/GMT+12`(UTC-12)는 KST
**00:00~20:59** 에 다르다. 고정 시각으로 쟀다(가짜 `date`·`faketime` 없이 — `date -d 'TZ="Asia/Seoul" …'`):
다섯 순간(02:00 · 10:00 · 18:30 · 21:00 · 23:30)에서 **앞 셋은 UTC-12 가, 뒤 둘은 UTC+14 가** KST 와 다른
날짜였다 — 어느 시각에도 **적어도 하나**가 판별한다. 가드는 그 **판별력 자체**를 지금 시각에 대해 함께
센다(둘 다 KST 와 같은 날짜이면 그 자리가 붉다).

## 운영 host 에 하지 않은 것 · 크기

`/etc/bidvector-v2/*.env` 를 **읽지도 `stat` 하지도 않았다**(§14 의 확인 줄은 **문면**이다) · `sudo` 0 ·
`systemctl` 0 · 운영 컨테이너 `exec` 0 · 조달청 실호출 0 · 운영 DB 질의 0. 버릴 컨테이너는 전부 `--rm` ·
`--network none` 이고 붙인 자리는 scratchpad 아래뿐이다(잔존 0). 공유 잠금 자리는 만들지 않았다.
scratchpad: `…/scratchpad/m15v/`(임시 clone 하나 포함) — 지우지 않고 경로만 남긴다.

**크기는 두 읽기로 적는다**(판정은 verifier 몫이다): 이 레인이 쓴 둘(`commands.md`+`rollback.md`)은 산출물
(추가 306 · 바뀐 줄 350)보다 **작다**. `scope.md`(계약 — 세션 모델이 쓰고 이 레인은 두 절만 채웠다)를
합치면 바뀐 줄 수와 **비슷하다**. 15U 는 합산으로 쟀고(577 ≤ 1778) 그 slice 는 산출물이 컸다.
