**cr M-1 축은 참이다**(독립 재현). root 가 `0700`/10001 이면 두 층의 gid 가 **1000**(래퍼의 gid)으로 박히고

## D-15V-2·4·5·6 과 (2) fixture 의 전제 실측

- **D-15V-5**: `install -m 600` 으로 먼저 만들면 `tee` 뒤에도 **600** · 먼저 만들지 않으면 평소 umask 에서

- **D-15V-6**: §14.5 ④ 의 가드 토막을 runbook 에서 **축어로 뽑아** 가짜 `docker`(argv 기록) 앞에서 네 꼴로
  돌렸다 — 정상 `docker exec` **1 회** · 빈 `P` / `null` `PGUSER_` / `null` `PGDB_` **0 회**(세 꼴 모두
  「질의하지 않았다」를 stderr 로 낸다). 앞 판의 `|| { …; false; }` 는 그 셋에서 다음 줄이 그대로 돌았다.
  **그 측정을 가드 안으로 옮겼다** — 줄 **존재**를 셋으로 세던 래칫은 `docker exec` 를 `fi` 뒤로 옮기는

## 코드의 살아 있는 백틱 — 실행되고 그 단어를 지운다

큰따옴표 안의 백틱 짝은 **명령 치환**이다. 이 slice 가 더한 네 문면이 그 꼴이었다. 가짜 `sudo` 를 PATH
앞에 꽂고 그 줄을 **축어로 뽑아** `_die` 정의만 세운 셸에 먹였다(진짜 바이너리는 부르지 않았다):
**가짜 `sudo` 가 두 번 실행**되고 출력에서 그 단어가 사라졌다(`** 가 필요하다**` · `(setgid 를 함께
되세우려면  가 필요하다)`) — D-15V-4 가 겨눈 단어가 **그 문장에서만** 빠진다. `bash -n` 은 백틱 **안**을
파싱 시점에 보지 않아 rc 0 이고 기존 문면 단언은 뭉개진 자리보다 **앞**을 보므로, 이 slice 가 세운 어떤
층에도 걸리지 않았다.

가드 쪽 `_ok`/`_bad` 두 줄도 같은 꼴이었다. **통제군**(축어로 뽑아 같은 `_ok` 정의 아래): stderr 에
`syntax error: unexpected end of file` **한 줄** · stdout 은 `전제 가드()` 로 괄호가 빈 채 · `PASS` 는
정상 증가 · rc 0. **고친 뒤 초록 run 의 stderr 는 0 줄**이다.

**모집단은 열거가 아니다**(vr M-a · cr L-2). 호출 이름 + 여는 인용부호로 고르는 술어에는 실측된 미탐이
셋 있었다 — 전부 **가짜 `sudo` 를 실제로 실행하며 GREEN** 이었다: `_expect_text '…' "…"` 의 **둘째** 인자 · 래퍼의 `echo "collection: …"` · `|| _die \` 다음
줄의 문면. 이제 두 스크립트의 **모든 줄**(실측 **2913 줄**)을 셸 인용 상태를 따라가며 훑어 살아 있는 백틱이
0 인지 본다 — 단일 인용 밖 · 주석 밖 · 탈출 아님. 상태는 줄을 넘어 이어진다(이 저장소의 `awk '…'`
프로그램과 `"$(printf … \` 꼴이 여러 줄에 걸친다). 인용 heredoc 본문은 **그 자체로 셸 프로그램**이라
(이 파일의 heredoc 은 실행되는 가짜를 만든다) 새 상태로 따로 훑고, 비인용 heredoc 본문은 인용과 무관하게
백틱이 살아 있으므로 글자로 본다. 받지 않는 꼴(인용이 파일 끝까지 안 닫힘 · heredoc 꼴이 받는 둘 밖)은
**STOP 으로 붉는다** — 조용히 빠지는 가지를 두지 않는다. `$( )` 치환은 금지하지 않는다(모집단의 집안
관용구다 — 문면에만 스물둘).

**비공허를 줄 수가 아니라 대조로 잰다**(cr L-2 가 짚은 자리: r1 의 문턱은 `-ge 1` 인데 실값이 216 이었다).
미탐 셋을 그대로 심은 **양성 probe** 와 오탐 꼴 다섯(줄 끝 주석의 백틱 · 단일 인용 · `awk '…'` 안 ·
`${0##*/}` · 여러 줄 연속)의 **음성 probe** 를 같은 스캐너에 돌린다. 양성의 백틱은 **런타임에 끼운다** —
축어로 적으면 스캐너가 자기 fixture 를 집어 영원히 붉고, 그 꼴을 예외로 빼면 그 예외가 구멍이다.
그 대조가 **첫 run 에서 내 실수를 잡았다**: `printf '%c' 96` 은 인자의 첫 글자(`9`)를 낸다(awk 의 `%c` 와
다르다) — 양성이 0 자여서 붉었고 `printf '\140'` 으로 고쳤다.

## ④ 추출 범위 — 종단자가 어긋나면 어디까지 가는가 (정적 재현 · 실행하지 않았다)

연결 스트림(펜스 경계를 버린 전 코드 줄)에서 첫 `^fi$` 까지를 뽑아 평소 PATH·cwd 에서 **무조건** 돌리는
설계였다. 닫는 `fi` 를 세 꼴로 바꾼 **사본**에 r1 의 두 awk 를 그대로 적용해 **줄만
셌다** — 넓어진 토막은 한 번도 실행하지 않았다(이 host 에 `/etc/bidvector-v2` 가 있다).

| 종단자 | span | `-ge 10` | psql == 1 |
|---|---|---|---|
| `fi`(판정 SHA) | **29 줄** = ④ 펜스 정확히 | 통과 | 통과 |
| `fi  # 질의 끝` · `fi;` · 들여쓴 `  fi` | **62 줄**(세 꼴 모두) | 통과 | 통과 |

넓어진 토막에 든 줄(열거만): `shred -u …` · `sudo -e /etc/bidvector-v2/prod.env` ·
`./tools/prod-health.sh --env-file … --public` · 그 뒤로 `sudo systemctl enable --now …` 둘 ·
`./tools/prod-collection.sh --env-file … --koneps-env-file …`. **하한은 상한이 아니다** — 비공허 단언
둘이 넓어진 꼴을 그대로 받았고, psql 줄은 문서에 하나뿐이라 등식도 참이었다. 리뷰가 적은 것보다 한 칸
나빴던 사실: 구문 오류(`cd <저장소>`) **앞**에 오는 `./tools/prod-health.sh` 는 **상대 경로**이고 r1 의
실행 cwd 가 저장소 루트였으므로 그 자리에 진짜 스크립트가 있었다.

**격리를 먼저 세워 커밋한 뒤에** 종단자 변이를 가드 전건으로 돌렸다(아래 변이 표 r2 H 행).
격리의 네 칸: 펜스 동일성 추출 + 종단자 필수 + 상한 40 + 마지막 줄 `fi` · 실행을 `_ok` 가지 안으로 ·
`env -i` + 열거한 이름만 든 PATH(`bash cat grep jq` + 가짜 `docker` + 위험 이름 다섯) · cwd 는 저장소 밖 ·
stdin `/dev/null`. 위험 이름은 **가짜를 두고 호출 0 회**를 센다(「없음」은 호출을 막지 못한다). 그 계수의
양성 대조: 가짜를 직접 부르는 probe 에서 **5 회 기록** · 그 가짜 `shred`·`rm` 이 지나간 파일 **잔존**.
「없음」은 열거 **밖** 이름 넷(`sed awk paste bc` — 넓어진 토막이 쓰는 이름)이 그 PATH 에서 해석되지
않음으로 따로 쟀다.

## ④ 격리가 막는 축과 막지 못한 축 (무해 대상만)

r2 의 격리는 `env -i` + 열거 PATH 하나 + 저장소 밖 cwd + stdin `/dev/null` 이었다. 그것이 재는 것은
**PATH 축 하나**다 — 같은 격리 안에서 아래 일곱을 무해 대상으로 돌려 **전부 실행됐음**을 봤다(파일
생성·소켓 개방까지). 운영 자격 파일은 건드리지 않고 `/etc/hostname` 으로 갈음했다.

| 축 | 격리 PATH 만 | `bash -r` 를 더하면 |
|---|---|---|
| 열거 밖 이름 해석(`sed awk paste bc`) | 막는다 | 막는다 |
| cwd(`./tools/*`) · 환경 변수 | 막는다 | 막는다 |
| 절대 경로 명령(`/usr/bin/touch`) | **돈다** | 거절 — 「cannot specify / in command names」 |
| `command -p touch` | **돈다** | 거절 — 「command: -p: restricted」 |
| 출력 리다이렉션(`printf x > 파일`) | **돈다** · 파일 생김 | 거절 — 「cannot redirect output」 |
| `exec 3> 파일` | **돈다** · 파일 생김 | 거절 |
| `cd /` | **돈다**(뒤 `$PWD` = `/`) | 거절 — 「cd: restricted」 |
| `source` 절대 경로 | **돈다** | 거절 |
| `/dev/tcp` 소켓 | **열린다** | 거절 |
| `>&2`(fd 복제) · 인용 heredoc | 돈다 | **그대로 돈다**(restricted 목록 밖 — ④ 가 필요하다) |
| 파일 읽기(`cat 절대 경로` · `$(< 파일)` · `jq … 파일 인자`) | 돈다 | **남는다** |
| 자식 셸 | — | **물려지지 않는다** — 등재 도구가 스크립트면 그 안은 restricted 가 아니다 |

**`bash -r`** 가 위 일곱을 거절하고 그 사실을 **양성 probe** 로 잰다(restricted 줄 일곱 · 만들려던
파일 0 · `-r` 없는 통제군은 파일 둘을 만든다). 남는 두 칸(파일 읽기 · 자식 셸)을 **꼴 검사로 닫으려
한 것이 세 번째 열거였고 같은 자리에서 열렸다** — 다음 절의 등재본 등식이 그 자리를 대신한다.
전용 PATH 에서 `bash` 를 뺀 것이 자식 셸 칸의 처분이다(그 이름이 없으면 rbash 탈출의 뿌리가 없다).

## ④ 실행 층 — 등재본 등식 (계약 갱신 ⑥)

앞의 두 절이 이 설계의 사유다. 「임의의 셸 문면을 돌리면서 해로운 꼴을 센다」는 세 판 모두 같은
자리에서 열렸다 — 범위에 상한이 없었고(정적 62 줄), 격리가 PATH 축만 막았고(일곱 축 실행), 꼴
검사가 대입 접두·단일 `&`·조립 경로에서 열리며 **자기 실패에서 통과**했다(리뷰가 게이트 GREEN 인
채 격리 밖 쓰기를 실측했다). 꼴을 더 세지 않고 **실행되는 글자를 리뷰된 한 장으로 고정한다**.

- runbook §14.5 ④ 펜스 **본문 전체**를 뽑아 `config/quality/runbook-collection-step4-block.txt` 와
  **바이트로** 견준다(`cmp`). 다르면 `_bad` 이고 아무것도 실행하지 않는다.
- 돌리는 것은 **등재본에서 자른 측정 토막**이다(추출본이 아니다). 그래서 종단자·상한·psql 계수는
  판정이 아니라 **비공허 확인**으로 남는다 — 자르는 원천이 이미 리뷰된 파일이다.
- 등재본은 추출 awk 의 산출이고, 같은 구간을 `sed` 로 자른 것과 **바이트 동일**함을 양성 대조로
  확인했다. 한 글자만 달라도 `cmp` 가 선다(음성 대조).
- 비공허: 펜스 줄 수 하한 · 시작 표지가 문서에 **1 회**(추출이 그 펜스라는 진술) · 등재본의 psql 줄
  **1**(측정 대상을 담는다는 진술).
- 꼴 검사는 **걷었다**. 전용 PATH 에서 `bash`·`grep` 도 뺐다 — `bash` 가 있으면 restricted 셸이 그
  이름으로 부른 자식이 **제한 없는** 셸이다(rbash 탈출). 가짜 `docker` 와 위험 이름 가짜 다섯의
  shebang 을 절대 경로로 박았고, 그 필요는 **양성 대조가 잡았다**(`/usr/bin/env bash` 가 127 로 죽어
  가짜가 기록을 0 회 남겼다). `cat` 은 못 뺀다 — 가짜가 cfg fixture 를 그것으로 낸다(사유를 주석에).

## 변이 — 커밋 뒤 · 적용을 `numstat` 으로 먼저 확인 · 기대는 **그 축의 문면**

**이 표에 통과·어긋남 수를 적지 않는다.** 기준선이 라운드마다 달라 사본이 곧 낡는다 — 이 slice 에서
베껴 적은 수는 어긋난다 — 이 slice 가 그것을 네 번 겪었고(장부 건수 · 모집단 두 번 · 이 표의 종단자
행은 중간 HEAD 에서 재고 적어 판정 SHA 와 달랐다). 판정은 **붉음/초록과 그 축**이고 전건 수는
게이트가 찍는다. 수가 필요한 자리는 「크기」 절 하나이고 그 수는 **마지막 커밋에서 명령 출력으로**

범위 묶음으로 갈아치워져 **더는 없다**.

## 운영 host 에 하지 않은 것 · 크기

`/etc/bidvector-v2/*.env` 를 **읽지도 `stat` 하지도 않았다**(§14 의 확인 줄은 **문면**이다) · `sudo` 0 ·
`systemctl` 0 · 운영 컨테이너 `exec` 0 · 조달청 실호출 0 · 운영 DB 질의 0. 버릴 컨테이너는 전부 `--rm` ·
`--network none` 이고 붙인 자리는 scratchpad 아래뿐이다(잔존 0). 공유 잠금 자리는 만들지 않았다.
scratchpad: `…/scratchpad/m15v/`(임시 clone 하나 포함) — 지우지 않고 경로만 남긴다.

**크기(합산 — 정본)**: evidence 셋 합 **621 줄**(235+78+308) ≤ 산출물 추가 **814 줄**(바뀐 줄 866).
이 수는 **마지막 커밋에서 명령 출력으로** 채웠다(`wc -l` · `git diff --numstat` · 게이트 요약 줄) —
베껴 적은 수가 거듭 어긋났으므로 손으로 적는 자리를 남기지 않는다. 늘리지 않고
갈아 썼다: r2 는 걷은 술어를 말하던 행과 문단을 치웠고(vr L-d), 승인 전 묶음은 변이 표의 통과·어긋남
쌍 전부와 라운드 서술 문단·괄호 둘을 걷은 자리에(vr L-3) 격리 축 표와 묶음 행을 넣었다.
