전부 `tools/prod-guards-check.sh` 의 가짜 `docker`·`git` 앞에서, 또는 버릴 clone 에서 돌았다. 출력 전문은
싣지 않는다(핵심 결과 한 줄).

`tools/*.sh` 는 그 집합이 아니다(「초록인데 조용하다」가 아님을 입력 선언으로 확인했다).
비밀값 스캔은 참조형으로 돌렸다(`grep -rniE -f config/quality/leak-patterns.txt`) — 새 매치 0.

## 공유 술어 뽑기 — relay 의 거동 무변경

`tools/prod-env.sh` 로 뽑은 것은 둘째 env 파일 검사 일곱 축이다(권한 · compose 문턱 둘 · `jq` 문턱 ·
경로와 값의 `$` · 키 집합 · 통째로 버려짐 · 필수 키). 검사의 **순서·문면·종료 코드**를 그대로 옮겼다.

증인은 **버릴 clone 에서 돌린 착수 전 판**과의 대조다(`git clone` → `git checkout 06c4df271`):

| | 착수 전 | 뽑은 뒤 |
|---|---|---|
| 전건 | 통과 269 · 어긋남 0 | 통과 428 · 어긋남 0 |
| `relay` 라벨 단언 | 130 | 133 |
| 평가 커밋 라벨 단언 | 35 | 35 |

relay 가 +3 인 이유는 **라벨뿐**이다 — 종료 코드 등식 셋이 함수로 뽑히면서 `relay —` 접두를 얻었다.
접두 없는 옛 라벨 셋(`래퍼 case 의 가지` · `러너의 종료 코드 집합 ==` · `래퍼가 번역해 내는 값`)은
착수 전 로그에 각 1 건, 뽑은 뒤 로그에 각 0 건이다 — **1:1 대응**이고 relay 단언 집합의 내용은 같다.
그 등식을 먼저 따로 쟀다: 등식 함수만 뽑고 다른 변경이 없는 중간 판의 전건이 **269 · 0** 으로 착수 전과
같았다.

## 변이 — 바꿔치우기로, 적용 여부를 먼저 센다

규율: **더하기만 한 변이는 초록이 된다.** 그래서 전부 치환이고, 매 변이마다 `git diff --numstat` 으로
적용을 먼저 확인한 뒤 전건을 돌렸다. 변이 전 트리는 `git status --porcelain -- tools/ config/quality/
docs/runbook/` 이 빈 출력이었다(커밋 뒤에 변이했다 — `git checkout --` 가 미커밋 산출물을 함께 지우는
자리를 피한다).

| # | 변이 | 적용 | 결과 |

| ⑪ | `koneps` 기대 집합에서 한 줄을 뺀다 | 0+/1- | **RED** 427 · 1 |
| ⑫ | **음성 대조** — 머리말 주석만 고친다(거동 0) | 1+/1- | GREEN 428 · 0 |

**③ 의 GREEN 둘은 겹침이고 구멍이 아니다.** `:` 를 끊는 자리가 둘이다(인자 원문 · `readlink -f` 로
푼 실경로) — 한쪽만 열어도 다른 쪽이 받는다. ③c 가 그 축이 실제로 닫혀 있음의 측정이고, 그래서 이
표에는 **셋을 다 적는다**(한쪽만 적으면 「통과했다」가 구멍처럼 읽힌다).

**심은 결함이 결함이 아니었던 한 건을 적는다.** ⑧ 의 첫 판은 조건식의 치환 꼴을
`${stray_raw//[[:space:]]/}` → `${stray_raw//[[:space:]]*/}` 로 바꾼 것이었고 전건이 GREEN 이었다.
게이트 **밖에서** 씨앗을 먼저 재니 두 꼴의 조건값이 **같았다**(`BIDVECTOR_PERSISTENCE_JDBCURL` 둘 다) —
변이가 아무 통과도 만들지 않았다. 그래서 ⑧a·⑧b 로 바꿔 다시 쟀다(규율: 양성 대조의 씨앗 크기를 게이트
밖에서 먼저 잰다).

**⑧b 가 「공유는 단일 실패점」의 겹을 잰다.** 공유 술어 하나를 15Q 가 닫은 옛 꼴로 되돌리면
**relay 12 건과 수집 2 건이 함께** 붉는다 — 두 래퍼가 같은 함수를 각자 지나게 둔 것이 그 설계의 값이다
(한쪽만 재면 공유가 곧 단일 실패점이 된다).

## 계약 조사의 재확인 — 자리

「조사」 1~8 을 코드에서 다시 읽었고 여덟 전부 그대로다(자리는 `scope.md` 「계약 갱신」 ① 에 적었다).
조사에 없던 사실 하나가 설계를 정했다 — `RunStateDirectory` 의 `requireStateDirectory` 가 **디렉터리를
만들지 않고 거부**하므로 달 디렉터리는 래퍼가 만들어야 하고, 래퍼(`deploy`)와 컨테이너(uid/gid 10001)가
같은 원장에 쓰는 길은 **group 공유**뿐이다. 그 귀결이 `install -d -m 2770 -o "$USER" -g 10001`(운영자
한 번)과 래퍼의 `mkdir -p -m 2770`(매 run)이다.

## 운영 host 에 하지 않은 것

- `/etc/bidvector-v2/*.env` 를 **읽지도 `stat` 하지도 않았다**(§14.1 의 확인 줄은 **문면**이다).
- `systemctl` 을 한 번도 부르지 않았고 unit 을 하나도 깔지 않았다.
- 운영 컨테이너(`bidvector-v2-prod-*`)에 `exec` 하지 않았고 운영 DB 에 질의하지 않았다
  (§14.5 ④ 의 질의 여섯은 문면이고, 상태 어휘만 코드(`isBiddable`)에서 확인했다).
- 조달청 실호출 0 · 실행 상태 디렉터리 생성 0(가짜 앞의 fixture 는 `mktemp -d` 아래다).
- 공유 잠금 자리(`/run/lock/bidvector-v2`)는 **만들지 않았다** — 이미 있었고, 검사는 전용 이름의 잠금
  파일만 만들고 끝에 지운다.
