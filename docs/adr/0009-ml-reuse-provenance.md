# ADR 0009 — ML 재활용 출처를 어디에 기록하는가

- **상태**: **미결 (`OPEN-ADR-10`)** — 운영자 결정 대기. 기록 **의무**는 확정, 기록
  **위치**는 미결
- **작성일**: 2026-08-28
- **대응**: `milestone-0.md` §"Slice 0D" 결정 **9** (ML 재활용 출처 기록 위치 —
  `docs/discovery/legacy-reference-map.md` 통합 vs slice별 `reports/evidence/` 기록.
  **사용자 확인을 받아 결정한다**, 2026-08-22 지시)
- **관련 ADR**: 0001(재활용 경계와 이식 대상)

> **이 ADR은 결론을 담지 않는다.** `milestone-0.md`가 이 항목을 **사용자 확인 대상**으로
> 지정했고, 팀 리드 지시가 *"결론을 네가 정하지 말고 `OPEN`으로 남기고 선택지와 각각의
> 비용을 적어라"*고 못 박았다. 아래 §2가 **확정된 것**을, §3이 **선택지와 비용**을 적는다.

## 1. 맥락

### 1.1 기록 의무의 출처

| 문서 | 문면 |
| --- | --- |
| `v2-지침서.md` §3.2 「이식 규칙」 | *"**각 모듈에** 재활용 출처(원본 파일 경로와 기준 commit)와 수행한 튜닝·수정 내용을 기록한다."* |
| `v2-지침서.md` §7 「AI 작업 규율」 | Claude는 구현 전에 *"재활용할 코드(**출처 파일과 commit**)와 그대로 채택하지 않을 구조, 각각의 이유"*를 제출한다 |
| `v2-지침서.md` §9 「완료 정의」 | *"재활용한 ML 코드가 새 패키지 경계·M2 계약·래칫을 통과하고, **출처와 튜닝 내역이 기록됨**"* |
| `milestone-0.md` 「산출물」 | `docs/discovery/legacy-reference-map.md` |
| `agent-workflow.md` §6 | 각 slice의 `reports/evidence/<milestone>/<slice>/`에 남길 최소 항목 |

### 1.2 기록해야 할 대상의 규모

ADR 0001 §4.1이 이식 대상의 핵심인 **8개 수학 커널**(합계 2,166줄, 전부 `app/domain/`)을
고정했고, §4.2가 세 앵커 디렉터리 **56개 파일 13,388줄**을 측정했다. 커널을 쓰는 세
디렉터리 파일 **10개**가 함께 움직인다(`commands.md` **C-5.2c** (c)). **기록 항목은 수십 건
규모이며 M5의 여러 slice에 걸쳐 생긴다.**

### 1.3 이 결정이 왜 지금 필요한가

- M5 이식이 시작되면 **첫 이식 slice가 형식을 정해 버린다.** 나중에 바꾸면 이미 쓴 기록을
  옮기는 일이 생긴다.
- `v2-지침서.md` §9의 완료 조건이 *"출처와 튜닝 내역이 기록됨"*이므로, **어디를 보면
  그것이 확인되는지**가 완료 판정 절차의 일부다.

### 1.4 선택지가 셋이라는 관찰

`milestone-0.md`는 선택지를 **둘**로 적었다 — `legacy-reference-map.md` 통합 vs slice별
`reports/evidence/`. 그런데 `v2-지침서.md` §3.2의 문면은 **"각 모듈에"**이고, 그것은
**코드 옆(ml-engine 패키지 안)**을 가리키는 셋째 자리다. **두 문서가 다른 자리를
가리킨다** — 이 어긋남 자체가 운영자 결정이 필요한 이유의 일부다.

**이 ADR은 어느 문서가 맞는지 판정하지 않는다.** 양쪽을 병기하고 §3에 셋째 선택지를 뒀다.

## 2. 결정 — 위치와 무관하게 확정되는 것

### D-1. 기록 항목은 셋이다

어느 자리를 택하든 **원본 파일 경로** · **기준 commit** · **수행한 튜닝·수정 내용**
셋을 남긴다(`v2-지침서.md` §3.2). 기준 commit은 현재 `ed4b06c`다.

### D-2. 재활용 기록은 기대값 판정 근거가 아니다

`milestone-0.md` 완료 조건: *"재활용은 기대값 판정 근거가 아니라 **구현 전략으로만**
기록한다."* `v2-지침서.md` §1도 같다 — *"재활용한 코드의 기존 출력은 여전히 정답이
아니다."* **출처 기록이 "그래서 이 값이 맞다"의 근거로 쓰이면 안 된다.**

### D-3. `_workspace/`는 기록 자리가 아니다

`_workspace/`는 gitignore 대상이라 저장소에 감사 추적이 남지 않는다
(`reports/evidence/m0/0a2/decisions.md` 머리말이 같은 이유로 그 내용을 커밋된 사본으로
옮겼다). **어느 선택지도 `_workspace/`를 정본으로 두지 않는다.**

### D-4. `docs/discovery/legacy-reference-map.md`를 이 slice가 만들지 않았다

**그 파일의 존재 여부 자체가 선택지 (a)와 (b)를 가르는 것**이므로, 만들면
`OPEN-ADR-10`을 임의 해소하는 것이 된다. 현재 `docs/discovery/`에는
`capability-map.md`와 `regression-ledger.md`만 있다.

## 3. 대안 — 선택지와 비용 (**`OPEN-ADR-10`**)

### (a) `docs/discovery/legacy-reference-map.md` 통합

| | |
| --- | --- |
| **이점** | ① **단일 조회 지점** — *"V2의 이 모듈이 legacy 어디서 왔는가"*에 한 파일이 답한다. ② `v2-지침서.md` §9의 완료 판정이 **한 파일 대조**로 끝난다. ③ `docs/` 계층에 있어 ADR·capability map과 같은 **승인 대상 문서**로 관리된다. ④ `milestone-0.md` 「산출물」이 이미 이 경로를 적었다 — 다른 선택지를 택하면 그 목록에 **만들어지지 않는 항목**이 남는다 |
| **비용** | ① **M5의 모든 이식 slice가 같은 파일을 수정한다** — 병렬 slice에서 충돌 지점이 된다. ② 파일이 커진다. 같은 계층의 `capability-map.md`가 294KB·3,184줄이고, 그 크기가 **evidence 자기서술 오류의 표면**이 된 이력이 있다(0A2·0A3의 수정 라운드 대부분이 그 계열이었다). ③ **기록이 그것을 만든 diff와 다른 커밋에 있다** — *"이 커밋이 무엇을 이식했는가"*가 파일 diff를 거슬러야 답해진다. ④ **낡는다** — 이식 후 리팩터링으로 모듈이 이동·분해되면 이 파일이 실물과 어긋나고, 그것을 잡아 주는 검사가 없다 |

### (b) slice별 `reports/evidence/<milestone>/<slice>/` 기록

| | |
| --- | --- |
| **이점** | ① **기록이 그 이식 diff와 같은 커밋**에 있어 base/head로 고정된다 — Codex가 **같은 range 안에서** 확인할 수 있다(`agent-workflow.md` §5·§6). ② evidence는 **append-only**라 덮어쓰기가 없다(§5). ③ slice 간 충돌이 없다. ④ `agent-workflow.md` §6이 이미 evidence 최소 항목을 규정하므로 **새 규약을 만들지 않아도 된다** |
| **비용** | ① **전체 조회가 흩어진다** — *"ml-engine 전체의 출처"*를 보려면 여러 slice 디렉터리를 모아야 한다. ② `v2-지침서.md` §9의 완료 판정이 **전수 순회**가 된다 — 그 순회를 자동화하지 않으면 사람의 주의력에 기대게 되고, 그것은 §5의 규율과 충돌한다. ③ **어느 기록이 현재 유효한지 추적이 필요하다** — 같은 모듈이 두 slice에서 손질되면 두 기록이 생기고, 나중 것이 앞 것을 대체하는지 보완하는지가 규약으로 정해져야 한다. ④ `milestone-0.md` 「산출물」의 `legacy-reference-map.md` 항목이 **만들어지지 않는다** — 그 문서를 개정해야 한다 |

### (c) 모듈 안 (ml-engine 패키지) — `v2-지침서.md` §3.2의 문면

| | |
| --- | --- |
| **이점** | ① **§3.2가 문자 그대로 요구하는 자리**다("각 모듈에"). ② 코드와 함께 이동·삭제되므로 **낡지 않는다** — (a)의 비용 ④가 없다. ③ 이식된 코드를 읽는 사람이 **그 자리에서** 출처를 본다. ④ 기계 검사가 쉽다 — 모듈마다 필수 메타가 있는지 lint로 강제할 수 있고, 이는 §5의 *"회귀 방어를 사람의 주의력에 맡기지 않는다"*와 정합한다 |
| **비용** | ① **`v2-지침서.md` §5의 「주석 최소화」와 마찰한다** — *"변경 이력·작업 메모를 남기지 않는다(이력은 git이 소유)"*. 출처 기록이 주석이면 그 규율의 예외를 선언해야 하고, 별도 메타 파일이면 그 형식을 정해야 한다. ② **튜닝 내역**(수행한 수정)은 이력의 성격이라 코드 옆에 두면 계속 자란다. ③ 전체 조회는 (b)와 같이 흩어진다 — 도구로 모아야 한다 |

### (d) 조합 — (c) 최소 포인터 + (a) 또는 (b) 상세

| | |
| --- | --- |
| **이점** | 코드 옆에는 **원본 경로 + 기준 commit**만 두어 낡지 않게 하고, **튜닝 내역**은 이력을 소유하는 자리((a) 또는 (b))에 둔다. 각 자리가 자기 성격에 맞는 것만 든다 |
| **비용** | ① **두 자리가 어긋날 수 있다** — 어긋남을 잡는 검사가 없으면 (a)의 비용 ④가 형태만 바꿔 돌아온다. ② 규약이 하나 더 늘어난다 |

### 결정에 필요한 입력

- **완료 판정을 사람이 하는가 기계가 하는가.** 기계면 (b)의 비용 ②와 (c)의 이점 ④가
  판정을 지배한다.
- **M5 이식을 몇 개 slice로 나누는가.** 하나면 (a)의 비용 ①이 사라진다.
- **`milestone-0.md` 「산출물」 목록을 개정할 의사가 있는가.** (b)·(c)는 개정을 요구한다.

## 4. 결과 — 결정 전까지

- **M5 이식 slice를 시작하기 전에 이 `OPEN`이 닫혀야 한다**(§1.3). 닫히지 않은 채
  시작하면 첫 slice가 형식을 사실상 확정한다.
- 그때까지 재활용 출처는 **각 slice의 `reports/evidence/`에 남는다** — `agent-workflow.md`
  §6이 이미 그 자리를 규정했기 때문이지 (b)를 채택했기 때문이 **아니다.**
  이 ADR은 (b)를 선택하지 않았다.
- **ADR 0001 D-8**이 기록 의무를 확정하고 위치를 이 ADR로 넘겼다. 이 ADR이 닫히면
  0001을 갱신할 필요는 없다 — 0001은 위치를 주장하지 않는다.

## 5. 이 ADR이 등록하는 `OPEN`

### `OPEN-ADR-10` · ML 재활용 출처의 기록 위치

- **결정 필요 사항**: §3의 (a)/(b)/(c)/(d) 중 무엇인가.
- **결정자**: **운영자.** `milestone-0.md`가 *"사용자 확인을 받아 결정한다(2026-08-22
  지시)"*로 지정했다.
- **종료 조건**: 선택된 자리와 그 기록 형식이 확정되고, `milestone-0.md` 「산출물」
  목록과 어긋나면 그 문서가 개정되는 것.
- **차단하는 것**: M5 첫 이식 slice.

## 6. 확인하지 않은 것

- **(c)의 기록 형식을 설계하지 않았다** — 모듈 docstring인지 별도 메타 파일인지, 그 파일이
  ml-engine 패키징에 포함되는지.
- **(b)의 순회 자동화 가능성을 확인하지 않았다** — evidence 디렉터리 구조에서 재활용
  기록만 모으는 검사를 만들 수 있는지.
- **legacy 코드의 라이선스·저작권 표시 요구를 확인하지 않았다.** `bid-vector`는 같은
  사용자의 저장소로 보이나 이 slice가 라이선스 파일을 열어 확인하지 않았다. 요구가
  있다면 기록 위치 결정에 영향한다.
