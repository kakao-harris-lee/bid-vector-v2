# 공공데이터포털 활용사례 — 서비스 설명 (초안, M7/7E-3b)

**이 문서는 초안이다.** 포털 등록·운영계정 신청은 `milestone-7.md` 「M7 종결 뒤 — 공공데이터포털
운영계정」의 마일스톤 밖 절차이고, 이 문서와 `captures/` 가 그 절차의 입력이다.

**원칙: 아직 안 되는 것을 된다고 쓰지 않는다.** 아래 「하지 않는 것」의 각 줄은 저장소의 결정
id 나 OPEN 홀더 id 를 인용한다 — 그 홀더가 닫히면 **그 slice 가 이 문서를 고치는 것**이 일의
일부가 된다. 포털 쪽 값(데이터셋 번호 · 승인된 트래픽 · 서비스 URL)은 저장소 밖 근거라 빈
자리로 둔다.

## 1. 한 줄 요약

건설 공사 입찰에 참여하는 **소규모 사업자 한 곳의 운영자**가, 나라장터 공고를 자기 자격·전략에
맞춰 추려 보고 투찰까지의 과정을 기록하며 결과를 대사(對査)하는 **단일 사업자용 운영 화면**이다.

## 2. 무엇을 하는가

1. **공고 수집** — 공공데이터 입찰공고 정보를 주기적으로 받아 저장한다.
2. **자격 판정** — 운영자가 설정한 **업종·면허**로 각 공고의 참가 자격을 따진다. **지역·
   수행실적·시공능력은 입력만 받고 판정하지 않는다** — 화면이 그 축을 「아직 판정하지 않음」으로
   보인다(통과로도 미달로도 접지 않는다). 아래 「하지 않는 것」에 같은 줄이 있다.
3. **공고 워크시트** — 한 공고의 금액·마감·자격 근거를 모아 보고, 나라장터로 이동한 뒤 운영자가
   **스스로 낸 투찰을 「제출함」으로 기록**한다.
4. **내 입찰함** — 담기 → 투찰가 받음 → 투찰함 → 개찰 대기 → 심사 중 → 종료의 상태와 **다음
   확인 시점**(마감·개찰·서류 기한)을 관리한다.
5. **결과 확인** — 건마다 내 투찰가·개찰 결과·대사 판정·차이를 보이고, 투찰 대비 낙찰률을
   **운영자가 적은 결과**와 **서버 대사** 두 축으로 나란히 낸다.

이 서비스의 설계 원칙 하나를 먼저 적는다: **값이 없으면 빈 자리이고, 부재에는 사유가 붙는다.**
낙찰률의 분모가 0 이면 `0%` 가 아니라 「분모에 드는 건이 없음」이고 그 사유를 함께 보인다. 금액은
통화·기준·과세·출처가 함께 올 때만 숫자로 그린다.

## 3. 어떤 공공 API 를 어디에 쓰는가

| 공공 데이터 | 쓰는 자리 | 비고 |
| --- | --- | --- |
| 입찰공고정보 (공사) | 공고 수집 → 화면 B 「오늘의 공고」 · 화면 C 「공고 워크시트」 | 공고번호·차수·공고명·수요기관·기초금액·마감일시·개찰일시 |
| 낙찰정보 (개찰·낙찰) | 화면 E 「결과 확인」의 개찰 결과와 **대사 판정** | 아래 「하지 않는 것」의 대사 항목을 함께 읽을 것 |

- **포털 데이터셋 번호**: _빈 자리_ — 저장소 밖 근거다. 신청 시 포털에서 확인한다.
- **신청 트래픽**: operation 당 일 20,000(운영자 결정 `R-6`). 승인 여부는 제공기관 몫이라 M7 의
  완료 조건이 아니다.
- **서비스 URL**: _빈 자리_ — 도메인·TLS 반입은 7F 이고 별도 승인 사항이다(`R-9`).

## 4. 화면 흐름

캡처는 `captures/` 에 있다(데스크톱 1280×800 · 모바일 390×844 각 한 장). 전부 **합성 fixture 로
띄운 시험용 하네스**를 찍은 것이고 실 데이터·실 계정이 들어 있지 않다.

그 하네스는 **개찰 축을 수집하지 않는다**(`OPEN-7E3A-OPENING-AXIS-HARNESS`) — 그래서 캡처의
화면 E 에서 개찰 결과가 「아직 개찰 전」으로 보인다. 운영의 개찰 수집은 **별도 러너**가 돈다.
캡처의 그 자리를 운영 서비스의 상태로 읽지 말 것.

| 화면 | 캡처 |
| --- | --- |
| A 시작하기(설정 체크리스트) | `captures/a-start-desktop.png` · `captures/a-start-mobile.png` |
| B 오늘의 공고 | `captures/b-notices-desktop.png` · `captures/b-notices-mobile.png` |
| C 공고 워크시트 | `captures/c-worksheet-desktop.png` · `captures/c-worksheet-mobile.png` |
| D 내 입찰함 | `captures/d-bid-box-desktop.png` · `captures/d-bid-box-mobile.png` |
| E 결과 확인 | `captures/e-results-desktop.png` · `captures/e-results-mobile.png` |
| 알림함 | `captures/inbox-desktop.png` · `captures/inbox-mobile.png` |

`captures/manifest.json` 이 파일별 SHA-256 과 캡처 시각, 그때의 저장소 HEAD 를 적는다 — 캡처가
어느 판의 화면인지는 그 HEAD 로 읽는다.

## 5. 하지 않는 것

**이 절이 이 문서의 중심이다.** 화면에 자리가 있다고 기능이 선 것이 아니다 — 아래는 오늘
**실제로 동작하지 않는** 것들이고, 각각 그렇게 둔 근거가 있다.

- **나라장터 자동 제출을 하지 않는다.** 「이동 + 입력값 복사」가 상한이고 투찰 행위는 운영자가
  나라장터에서 직접 한다(`ux-journey-research.md` §5 「자동 제출 금지」 · `D-UX-2`). 로그인
  크롤도 하지 않는다.
- **알림을 채널로 보내지 않는다.** 알림은 앱 안 **알림함 기록까지**이고 메일·메신저 발송은
  없다(운영자 결정 `R-4` — 발송 활성화는 `OPEN-STR-12` 결정 뒤 별도 사항).
- **알림 트리거가 아직 발화하지 않는다.** 알림함 화면과 그 기록 표는 서 있으나 트리거를 출하
  조립에 배선하지 않아 오늘 항목이 만들어지지 않는다(`OPEN-7E3A-NOTIFICATION-TRIGGER-WIRING`).
  화면은 그 사실을 빈 얼굴과 사유로 보인다.
- **지역·수행실적·시공능력 자격을 판정하지 않는다.** 그 셋은 **입력만** 받고 화면이 「아직
  판정하지 않음」으로 보인다 — 통과로도 미달로도 접지 않는다(capability `QUAL-08` · `QUAL-10` ·
  `QUAL-11`; 서버의 `UnjudgedQualificationAxis` 가 그 목록의 정본이고, 판정이 생기는 날 그
  slice 가 거기서 값을 지우면 응답 계약 test 가 함께 붉어진다).
- **자동 대사가 아직 판정을 내지 못한다.** 낙찰자 상호를 견주어 낙찰/패찰을 가르는 판정은
  구현돼 있고 **개찰 결과도 수집·승격된다**. 없는 것은 **낙찰자 상호를 적재하는 경로** 하나다
  (`OPEN-SET01-AWARD-NAME-INGEST`) — 운영자 결정으로 그 수집은 **M7 종결 뒤로 미뤘다**
  (slice 계약 `reports/evidence/m7/7e3b/scope.md` 2026-10-31 「운영자 결정(낙찰자 상호 수집
  연기)」). 그래서 오늘 대사 축의 답은 전건 「아직 판정 못 함」이고 화면은 그 사유를 그대로
  보인다 — **판정 불가를 패찰로 접지 않는다.**
- **투찰가 3안(추천 금액)을 내지 않는다.** 화면 C 의 그 자리는 「아직 산출 안 함」으로 서 있고
  근거 없는 숫자를 내지 않는다(`OPEN-ML-ANALYSIS-WIRING`). 결과 화면의 「추천 3안 중 고른 안」이
  언제나 「직접 입력」인 것도 같은 뿌리다.
- **역산(「이 금액이면 이겼나」)을 하지 않는다.** 그 계산의 전제를 뒷받침할 데이터가 없다는
  판정이다(capability `SET-03` = `근거 부족`) — 뒤에 오는 기능이 아니라 **영구히 두지 않는**
  자리다.
- **추천 정확도 리포트를 내지 않는다**(capability `SET-05` = `후속`).
- **다수 사업자를 받지 않는다.** 가입·초대·요금·탈퇴 파기가 없고 계정은 하나다(운영자 결정
  `R-2` — 소유 경계는 처음부터 두되 전환은 별 마일스톤).
- **다른 업체의 상호·사업자등록번호·대표자명을 보이지 않는다.** 낙찰자 상호는 서버 안에서 대사
  판정에만 쓰이고 화면이 받는 응답의 **어느 칸에도 없다.**

## 6. 데이터 취급

- 운영자 **한 계정**이고 로그인·세션·CSRF 가 서 있다. 가입 화면은 없다(계정은 운영 명령으로
  만든다).
- 화면이 부르는 서버 operation 은 **승인 목록 하나**로 묶여 있고, 목록 밖 호출은 컴파일과
  여정 test 두 층에서 막힌다.
- 화면·로그·캡처에 사업자등록번호·토큰·세션 쿠키 평문이 **0** 이다. 캡처는 찍기 **직전** 그
  화면의 DOM 에 같은 검사를 걸고, 하나라도 걸리면 파일을 쓰지 않고 멈춘다.
- 위 캡처는 합성 fixture(`SYN-` 접두)로 띄운 하네스를 찍은 것이라 실 사업자 정보가 없다.

## 7. 알려진 제한

- 위 「하지 않는 것」 전부.
- 캡처는 **그 시점 HEAD 의 화면**이다. 화면이 바뀌어도 캡처가 자동으로 낡음을 알리지 않으므로,
  제출 직전에 `npm run capture:usecase` 로 다시 뜬다(이미지 차분 게이트는 두지 않았다).
- 낙찰률 비율은 서버가 **문자열**로 내고 화면이 그대로 보인다(퍼센트로 환산하지 않는다) —
  분자·분모를 곁에 두어 읽는 사람이 스스로 센다.
