# M7 화면 데이터 요구표 — 화면 다섯 + 알림함 ↔ V2 계약 (M7/7A, 2026-10-14)

- **정본 지위**: 이 문서는 `docs/adr/0008-frontend-disposition.md` D-4 의 물음 1·2(「V2 계약이 화면의 데이터 요구를
  덮는가」·「덮지 못하면 legacy 에만 있던 요구인가, V2 가 누락한 capability 인가」)에 대한 7A 의 답이다. 물음 3(어댑터)은
  R-1(a)로 「어댑터 없음」이고 그 게이트는 `docs/adr/0011-web-frontend-stack.md` 가 진다.
- **입력**: 화면 정의 `docs/discovery/ux-journey-research.md` §5~§6 · V2 계약 `openapi/bidvector-operator-api.yaml`(이 문서
  작성 시점 operation 아홉 — `readStrategy`·`evaluateDryRun`·편집 세션 여섯·`unmatchedPath`) · capability
  `docs/discovery/capability-map.md` · 측정 상태 `reports/evidence/m6/6e1/acceptance-trace.md`(6E-1 추적표).
- **작성**: 세션 모델 단독(운영자 지시 2026-09-04 — 기획 문서). 운영자 결정 2026-10-14 (나)의 근거 문서다.

## 판정 어휘

| 판정 | 뜻 | 처분 |
|---|---|---|
| **ⓐ 덮음** | V2 OpenAPI 의 operation·필드가 이미 그 값을 낸다(또는 화면 안 계산·정적 문구로 닫힌다 — 그때는 「클라이언트」로 적는다) | 7E 가 그대로 쓴다 |
| **ⓑ V2 누락** | V2 에 그 capability 가 있어야 하는데 계약 표면이 없다(데이터가 DB 에 있어도 API 가 없으면 ⓑ) | 담당 slice 가 만든다 — 열이 비면 안 된다 |
| **ⓒ legacy 전용** | legacy 화면에만 있던 요구이고 V2 여정이 버린다 | 만들지 않는다 |
| **─ 범위 밖** | capability 분류가 `후속`·`근거 부족`이라 M7 이 만들지 않는다(화면은 빈 자리 + 「준비 중」 문구) | 해당 capability 의 분류 결정이 바뀔 때 |

「capability」 열은 capability map 의 ID 다(`BID-01` 은 §6.1 초안 — 7B 가 정식 등재한다). 「담당」의 7B·7C·7D·7E 는
`milestone-7.md` 「구현 대상」의 slice 다. 여러 capability 가 같은 필드를 받치면 **주 capability** 하나를 앞에 둔다.

**D-4 물음 1 의 답**: V2 계약은 화면 다섯의 데이터 요구를 **덮지 않는다** — 전략 편집(감시 조건·임계치) 하나만 덮는다.
**물음 2 의 답**: 덮지 못하는 요구는 거의 전부 **V2 가 누락한 capability(ⓑ)** 다. legacy 전용 요구는 목록 이원화 하나다.
누락은 두 겹이다 — (가) **표면만 없는 것**(데이터·커널은 V2 에 있고 operation 이 없다: 공고 조회·자격 사유·프로필) 과
