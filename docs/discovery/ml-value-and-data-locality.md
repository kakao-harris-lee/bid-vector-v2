## 0. 요약

1. **이 장비에는 학습된 모델도 수집 데이터도 사실상 없다.** 있는 것은 2026-05-19 자 PostgreSQL dump
   하나(23MB, 약 2만 행)와 손으로 정한 계수 수준의 예측기 JSON 뿐이다. 진짜 ML 모델(낙찰률 GBM)과
   임베딩 가중치(약 470MB)는 없고, **서버 접속 수단은 어느 문서에도 없다**(§1).
2. **V2 계약은 이미 「하이브리드」를 전제한다.** ADR 0010 D-8 은 학습 입력을 「불변 dataset 참조 +
   checksum」으로, milestone-5 는 「운영 DB 직접 학습 query」를 범위 밖으로, data-extract.md 는
   「DB 행 커밋」을 금지로 못박았다. 따라서 선택지는 「DB 사본을 가져오느냐 / 서버에서 개발하느냐」가
   아니라 **「서버가 만든 dataset 스냅샷을 어떻게 이 장비에 건네느냐」**다(§1.4, §4 D-DL-1).
3. **운영자의 직감은 절반 이상 옳다.** 복수예가 4/15 추첨으로 예정가는 기초금액 ±2.3% 안에서
   무작위이고(표준편차 0.5~0.8%), 하한 밴드 안에 들어온 입찰자들 사이의 승부는 시뮬레이션에서
   **거의 정확히 1/(n+1) 의 추첨**이다. 밴드 안 무작위와 앵커 전략의 차이는 잡음 수준이다(§2).
4. **그러나 「100% 근처 무작위」는 어느 100% 인가에 따라 결과가 갈린다.** 기초금액의 100% 는 낙찰
   확률 0 이고, 발주처 생성범위가 비대칭(−6~0% 등)인 곳에서 범위를 모르면 확률이 30분의 1 로
   무너진다. **학습이 아니라 「표 조회 + 규칙」이 성패의 대부분**이다(§2.3).
5. **legacy 의 실측도 같은 방향이다.** 문서화된 정확도 개선 셋(3.56→0.55% · 3.33→0.31% ·
   3.51→1.84%)은 전부 규칙 변경이고, ML 을 베이스라인과 붙인 유일한 측정(GBM)은 저자 스스로
   절반 이상을 레짐 상쇄로 귀속한 뒤 홀드아웃 100% 중첩이 드러나 「판정할 창이 없다」로 되돌아갔다.
   승격 결정은 없었다. 학습이 남는 자리는 「예정가 맞히기」가 아니라 **「하한 위 몇 bp 에 설 것인가」**
   하나이고, 그것도 부분셀 n=80 < 150 에서 멈춰 있다(§3).
6. **결론(추천)**: DL 은 근거 없음, GBM 은 미증명(못 쟀다), 분포·통계 커널은 유지. 무엇이 유리한지는
   **사전 등록한 결정 실험 하나**로 닫는다 — 밴드 내 무작위 / 규칙 앵커 / 분포 predictor / GBM 을
   같은 out-of-time 창에서 실격률·하한 대비 bp·would-have-won 으로 비교. 이 실험이 서버 데이터를
   요구하므로 §1 과 §2 는 한 결정이다(§4).

## 2. 복수예가 추첨 게임의 구조 — 「뽑기」는 어디까지 맞는가

### 2.1 규칙(문헌)

- 발주처가 기초금액을 중심으로 **생성범위**를 정하고 15 구간으로 균등 분할, 구간마다 예비가격 1개.
  입찰자마다 2개를 고르고, **가장 많이 뽑힌 4개의 산술평균이 예정가**. 낙찰하한가 = 예정가 × 하한율
  (예: 87.745%). 적격심사에서는 하한 이상 **최저가**가 1순위(밀집 게임).
- 생성범위는 발주처마다 다르다(강·류, 2015, Table 1 — 2014년 기준): 지자체 **−3~+3%** · K-Water·KEPCO
  ±2.5% · **조달청·KORAIL·농어촌공사·인천공항 ±2%** · 철도시설공단·KOGAS **−5~0%** · **도로공사·LH −6~0%**.
- 같은 논문의 시뮬레이션(2만 회): 균등분할 4/15 평균의 표준편차는 ±2% 에서 **0.51%**, ±2.5% 0.64%,
  ±3% **0.77%**; ±3% 의 실현 범위는 97.68~102.34% (**±2.3%**). 지자체가 쓰는 비균등분할-A1(100% 아래
  8구간·위 7구간)은 평균이 **99.9%** 로 0.1% 낮다.
- 국가계약은 사정률 −2~+2%, 지방계약은 −3~+3% 가 통상 서술이다.

### 2.2 시뮬레이션 (이 문서의 계산, `scratchpad/lottery_sim2.py`)

가정: 15 균등분할 4개 평균으로 예정가, 하한율 87.745%, 경쟁자 n 명은 70% 가 기대 하한 근처 정규 밀집
(sd 0.4~0.6%), 30% 가 −1~+3% 균등 산포. 승리 = 하한 이상 최저가. 각 3만 회.

| 발주처형 · n | 기초금액 100% | 밴드 내 무작위 (−1~+2%) | 하한×1.0+0.3% (범위 모름) | 하한×E[사정률]+0.3% (범위 앎) | 완전정보 최적(상한) | 1/(n+1) |
| --- | --- | --- | --- | --- | --- | --- |
| 조달청형 ±2% · 30 | 0.000 | 0.031 | 0.028 | 0.027 | 0.070 | 0.032 |
| 조달청형 ±2% · 100 | 0.000 | 0.010 | 0.008 | 0.008 | 0.024 | 0.010 |
| 지자체형 ±3% · 30 | 0.002 | 0.033 | 0.029 | 0.029 | 0.076 | 0.032 |
| 지자체형 ±3% · 100 | 0.000 | 0.011 | 0.010 | 0.009 | 0.041 | 0.010 |
| **LH·도로공사형 −6~0% · 30** | 0.002 | 0.036 | **0.002** | 0.027 | 0.083 | 0.032 |
| 소수 경쟁 ±2% · 8 | 0.025 | 0.099 | 0.102 | 0.108 | 0.171 | 0.111 |

읽기:

1. **기초금액의 100% 는 0 이다.** 하한 위에 있는 누구에게나 진다. 「100% 근처 무작위」가 이것을 뜻한다면
   틀렸다.
2. **하한 밴드 안에서는 뽑기다.** 무작위·앵커·범위-앎 전략이 전부 1/(n+1) 근처이고 차이는 잡음이다.
   운영자의 직감은 여기서 옳다. 「학습해서 예정가를 맞힌다」는 목표는 구조상 성립하지 않는다.
3. **범위를 모르면 무너진다.** 생성범위가 비대칭인 발주처에서 하한율을 기초금액에 그대로 곱하면
   0.2% 로 떨어진다(하한보다 2.6% 위에 서서 모두에게 진다). 이것이 정보의 가치인데, **학습이 아니라
   표 조회**(규정 범위 + 개찰 결과의 발주처별 사정률 집계)다. legacy 실투찰 2건의 패인(§3.3)도 같은
   계열이다 — 하한율을 예정가가 아니라 기초금액에 곱했다.
4. **경쟁 밀도를 완전히 알면 2~3배까지 오른다** — 그러나 이 수치는 경쟁자 분포를 가정한 상한이고,
   참가업체별 투찰가는 KONEPS 가 주지 않아 수집 불가다(§3.4). 실제로 얻을 수 있는 것은 「낙찰자가
   하한 위 몇 bp 에 착지했는가」의 경험 분포뿐이며, 그것이 legacy 의 win-proxy/KDE 트랙이다.
5. **한계**: 경쟁자 분포는 가정이다. 실측 대체는 §4 의 결정 실험이 한다.

### 2.3 그래서 「학습」은 무엇에 쓰이는가

### 3.2 ML 대 베이스라인 — 유일한 측정과 그 철회

- commit `ceea4e1`: GBM 이 `category × amount band` 그룹 평균 대비 RMSE **11.2%** 개선(t −19.9), 5개
  origin 전부 8~15%. **그러나 같은 커밋 본문이 분해해서 부정한다** — 잔차 sd 축소 −8.3% 만 실재 신호,
  편향 축소는 레짐 상쇄(상승 레짐에서 부호 반전). 잔여 편향 공사 +1.63%p · **용역 +5.91%p** · 물품 −2.59%p.
- commit `5d38ac1`: 5개 origin 홀드아웃이 **100% 중첩**이었음이 드러나 주 단위 창으로 재설계. 남은 두 창:
  145행 창은 seed 5종 부호 반전 0/5 통과, **MDE 8.60% > 관측 4.62%** — 「못 이겼다」가 아니라 **「못 쟀다」**
  (유의성에 483행, 80% 검정력이면 약 850 필요). 357행 창은 폴백 21행이 지고 셀이 찬 336행만 보면
  +3.25%, t −1.37 미통과. 두 창은 out-of-time 이 아니라 **out-of-regime**(공사 수집 2026-06-30 개시).
- 사전 선언 게이트(t 2.58, 「사후에 느슨하게 만들지 않는다」)에서 **승격 결정은 내려진 적이 없다**. 라이브
  노출은 실험 플래그·`.env` 선호·아티팩트 경로 3중으로 닫혀 있고 `AUTO_PROMOTION_EXCLUDED` 가 자동
  승격을 막는다. **즉 사용자에게 도달한 ML predictor 는 현재 없다** — 서빙은 `historical`(규칙·통계 조합).

### 3.3 실투찰 3건

- `R26BK01627948` / `R26BK01628093`: **52위 / 25위**, 둘 다 적격이나 밀림. 낙찰률 88.001% / 88.019%(예정가
  기준 = 하한 밀착). 사정률 0.99727 / 0.99326. 실투찰가 +0.252 / +0.697%p, 추천 +0.340 / +0.679%p.
  **패인 = 하한 0.88 을 예정가가 아니라 기초금액에 곱함**(사정률 < 1 이면 하드 floor 가 실현 하한을
  구조적으로 초과). 반대로 라이브 monitor 경로는 `award_floor_rate` NULL 폴백으로 −0.66 / −0.33%p
  **실격 방향**. 같은 공고에서 경로에 따라 과추천과 실격이 갈린다.
- 3번째: 사정률 **+0.558% 추첨으로 실격**. 「정확한 floor 와 안전한 floor 는 양립하지 않는다」(floor-anchor
  판정문).

### 3.4 코드가 스스로 적은 구조적 한계

- *"예정가는 시계열 예측 대상이 아니라 복권형 생성 메커니즘"*(운영자 판정 2026-08-09, LSTM 은퇴).
- *"패인은 앵커 정밀도가 아니라 사정률 추첨을 맞히는 게임(축소 불가능한 랜덤)"*.
- **참가자 수는 피처가 아니다** — `opening_participant_count` 보유 3 / 91,364. 참가업체별 수집은
  KONEPS 표적조회 불가로 2026-07-19 종결. P(랜덤 참가자를 이김)·승리 마진·게임이론 효과는 **식별 불가**
  로 선언.
- 사정률 실측: 코어 532쌍 평균 0.9974(p5 0.9838 ~ p95 1.0100, 37.6% 가 1 초과). 카테고리 mean 공사
  0.99345(n=11,952) · 용역 0.99876 · 물품 0.99957. **발주기관별 값은 사실상 없다** — 291개 기관 전부
  최소표본 20 미달, 학습 코어 1,837곳 중 91.9% 가 n<10. 발주처별 생성범위 비대칭(±2 대 ±3 대 −6~0)의
  서술은 저장소에 **없다**(OPEN).
- 낙찰자 착지: 하한 대비 중앙값 **공사 +55.5bp · 용역 +13.3bp**. 소박한 argmax 지점의 실격확률 공사
  32.5% / 용역 52.6% — α-제약(실격 예산)을 둔 이유.
- 오차 귀속: basis 불일치 하나가 전체 +0.35%, 공사 +0.66% 초과추천을 설명한다
  (`docs/design/stored-bidrate-basis-alignment.md`). 실투찰 관측 +0.34/+0.68%p 와 정합.

### 3.5 증거의 판독

- **증거**: 문서화된 개선은 전부 규칙. ML 은 베이스라인을 이긴 적이 없는 것이 아니라 **잰 적이 없다**(MDE
  미달, 레짐 단절). 발주처 축은 표본이 없어 「못 본다」.
- **추론**: 학습이 남을 수 있는 자리는 「하한 위 어디에 설 것인가」(착지 분포) 하나이고, 그것은 GBM/DL 이
  아니라 경험 분포(KDE)와 실격 예산 α 의 정책 문제다. 실질 레버 셋 — basis 정합, 착지 정책의 group-scope
  (공사 base / 용역 conservative), α 명시 선언 — 은 전부 **계약·정책**이다.

## 5. 첫 스냅샷 반출 계획 초안 (data-extract.md §5 형식 — 승인 대상)

- **대상 테이블·컬럼**: `projects`(공고번호 해시, 발주기관 코드, 업무구분, 기초금액·추정가격·basis 태그,
  마감·개찰 일시, 게시 하한율, 예비가 15개, 복수예가 여부) · `tender_results`(예정가, 낙찰가, 낙찰률, 개찰
  1위 여부, 참가자수, 개찰 시각) · `historical_data`(위와 조인되는 낙찰 이력, basis 태그).
- **제외**: 상호·사업자번호·담당자·연락처·자유 텍스트 본문. 발주기관은 코드로, 낙찰자 상호는 제거
  (SET-01 대사에 필요한 상호 정규화는 서버 쪽 job 이 맡는다).
- **row limit**: 없음(전 기간). 대신 **row count·min/max 일자·checksum** 을 manifest 에 동반한다.
- **masking**: 공고번호·사업자번호는 salted hash. 금액·비율은 원값(학습 대상).
- **보관**: 이 장비의 저장소 밖 디렉터리(예: `~/.local/bid-vector-snapshots/<date>/`) + parquet. **V2 저장소에
  커밋하지 않는다**(data-extract §7). fixtures 의 `observed` 층은 여기서 **소수 case 만** 비식별 인용.
- **재현**: manifest 에 서버 git SHA, 추출 query 텍스트, 추출 시각. 같은 query 를 나중에 다시 돌리면 같은
  스냅샷 id 가 아니라 **새 스냅샷 id** 다.

## 6. 확인하지 않은 것

- 서버의 실제 접속 수단·OS·디스크 여유·V2 빌드 가능성(JDK/Gradle) — 문서에 없다. D-DL-3.
- 시뮬레이션의 경쟁자 분포는 가정이다. 실측 대체는 D-ML-2.
- 발주처별 생성범위의 **현재** 값(논문은 2014년 기준). 차세대 나라장터(2025) 에서 바뀌었는지 확인하지
  않았다. D-ML-3 의 authoritative 층이 공고문에서 읽어야 한다.
- 저장 `base_amount` 의 66% 파생 주장 — 측정 스크립트 미확인, 사실로 승격하지 않는다.
- win-proxy(would-have-won) 실측 집계 수치 — `reports/` 가 ignore 라 원자료 부재.
