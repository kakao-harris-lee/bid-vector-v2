**증명의 한계**: would-have-won은 실제 반사실이 아니다. 우리가 입찰했다면 경쟁자 행동이 달라졌을 가능성을 재지 못한다. 적격심사의 가격 외 점수와 실제 계약 이익도 이 실험만으로 확정되지 않는다.

## 2. 투찰가에서 규칙과 ML의 책임

### 규칙이 담당할 것

```text
예정가격 = 선택된 복수예비가격 4개의 산술평균
A값 미적용 하한가 = 예정가격 × 낙찰하한율
A값 적용 하한가 = (예정가격 - A) × 낙찰하한율 + A
순공사원가 추가 규칙 = CONSTRUCTION && 예정가격 < 100억원
```

시행일, A 공개 시점, 예가 범위, 실격선, 원 단위 올림, 적격 판정, 동가·유찰 처리도 규칙으로 고정한다. ML이 이 값을 추정하거나 완화하게 하지 않는다.

### ML·통계가 담당할 후보

- 경쟁자 투찰률 분포와 참가자 수 추정
- 경쟁자 밀집 구간을 피한 후보 가격 선택
- 불확실성과 표본 부족 공시

사정률 예측 자체는 기본 가치 가설로 두지 않는다. S2·S4가 기준선을 이기지 못하면 규칙+S0을 유지한다.

## 3. 판정 구조와 통과 기준

### 전략

- **S0**: 규칙 범위 안 균등 난수 — 기준선.
- **S1**: 고정 규칙 앵커 — 보조.
- **S2a/b/c**: 출하 분포 엔진 — 주 가설, 세 후보 각각 채점.
- **S3 GBM**: 학습 산출물과 유효한 비교 데이터가 없는 동안 N/A.
- **S4**: 제도 분포 + 실측 경쟁자 분포 몬테카를로 — 보조 가설.

### 기존 M6/6G 사전 등록 값

- 주 지표: 공고 단위 would-have-won 비율의 S0 대비 상대 개선 **20% 이상**.
- 창: 비중첩 주 단위, embargo 1주, 최소 3개 창, 창당 최소 483건.
- 검정: 창별 McNemar 정확 단측 검정, α=0.05. S2 세 후보는 Bonferroni α/3.
- 검정력: 0.80. 부족하면 Failed가 아니라 `NotEvaluable(UNDERPOWERED)`.
- Passed: 창 과반 통과 + 합동 통과 + 실격률 비열등(S0 대비 악화 +1%p 이내).
- seed: 고정된 5개에서 판정 부호가 갈리면 `NotEvaluable(SEED_UNSTABLE)`.
- S1·S4는 보조 가설로 별도 공시하며, S4 보조 통과를 S2 주 가설 통과로 바꾸지 않는다.

정확한 값의 정본은 실행 시점의 버전 관리된 정책 파일이다. 결과를 본 뒤 Δ·α·창·seed·전략 상수를 바꾸지 않는다. 변경이 필요하면 실험을 중단하고 새 version으로 다시 승인한다.

### T2. 실데이터 수집 계약과 품질 관문

**공고당 필요 축**

- 공고 키 해시, 업무·낙찰방법, 공고일·마감·개찰일.
- 투찰 시점 기초금액과 개찰결과 기초금액을 구분한 값.
- 예가 범위 시작·끝, 예비가격 15개, 추첨 번호 4개, 실현 예정가격.
- 실제 낙찰하한율과 시행일 판정에 필요한 값.
- 공사 A 적용 여부·A 합산·공개일시, 순공사원가.
- **전체 참가자별 투찰금액·순위**, 참가자 수, 진행 구분.

**품질 관문**

- 업무별 개정 시행일 이전과 이후를 섞지 않는다.
- 대상 공고와 같은 날 또는 이후 개찰 데이터는 전략 입력에서 제외한다.
- 결측·재입찰·유찰·동가·적격자 없음은 사유별로 계수하고 전략 간 같은 제외 집합을 쓴다.
- 기초금액 두 출처 불일치, 육 축 채움률, 원가·A 결측을 공시한다.
- 스냅숏은 저장소 밖 불변 입력으로 두고 id·행 수·sha256·표본 목록 해시를 기록한다.
- 상호·사업자등록번호·담당자 등 식별 정보는 산출물에 넣지 않는다.
- 실 KONEPS 호출은 별도 승인된 범위·호출 상한 안에서만 실행한다.

**중단 조건**

- 표본 최소 수·호출 예산·창 수 미달이면 성능 판정 대신 멈춘다.
- 제도 분포 적합도가 거부되면 모델 비교를 계속하지 않는다.
- 전체 투찰자 행이 없으면 S4를 실측 경쟁자 전략이라고 부르지 않는다.

### T3. 데이터 누출·재현성 검증

**자동 테스트**

- 대상 공고의 결과를 이력에 심으면 경쟁 표본에서 사라져야 한다.
- 같은 날 개찰분은 `<` 절단으로 제외되어야 한다.
- 전략 입력 타입에 대상 예정가격·추첨 번호·실제 참가자 수·투찰자 행이 없어야 한다.
- S2 캐시 키는 경쟁 표본 내용 해시를 포함해야 한다.
- 같은 스냅숏·정책·seed의 반복 실행은 동일한 금액과 verdict를 내야 한다.
- 처리 순서를 바꿔도 공고별 난수와 결과가 달라지지 않아야 한다.

**수동 대조**

- 무작위 표본 일부의 예정가격 = 선택된 예비가격 평균을 원자료와 대조한다.
- 하한가·순공사원가·A 적용을 공식 규정과 대조한다.
- 집계 보고에 식별자가 없는지 확인한다.

### T4. C1 — 사정률 제도 분포와 단순 예측 기준선 검증

이 작업은 **보조 진단**이며 기존 주 판정을 RMSE로 바꾸지 않는다.

1. 실현 사정률을 공고별 예가 범위 `[0,1]` 위치로 정규화한다.
2. 기존 KS·구간 비율 검사로 제도 분포 적합도를 확인한다.
3. 시간으로 분리한 과거 구간에서만 후보를 만들고 이후 구간에서 평가한다.
4. 단순 기준선 `E[R] = 1 + (begin + end) / 2`와 비교해 사정률 RMSE·편향을 공시한다.
5. ML이 단순 기준선을 이기지 못하면 사정률 예측 가치를 주장하지 않는다.

적합도 미기각은 무작위성의 증명이 아니라 “현재 검사에서 제도 분포와의 차이를 기각하지 못함”으로 기록한다.

### T5. C2 — 규칙 계산의 독립 검증

- A=0/A>0, 대칭/비대칭 예가, 업무별 시행일 경계를 검증한다.
- 예정가격 100억원 경계와 원가 결측을 검증한다.
- 하한가 정확히·1원 미만·1원 초과의 적격 경계를 검증한다.
- 동가 최저·적격자 없음·기권의 채점을 검증한다.
- 규칙 계산은 ML 유무와 무관하게 같은 입력에서 같은 결과를 내야 한다.

### T6. C3·C4 — 동일 스냅숏 전략 백테스트

```bash

```

**보고 항목**

- seed 5개 결과, 선택·제외된 모든 창, 제외 사유와 미판정 축.
- S2a/b/c의 주 가설 결과와 S1·S4의 보조 결과를 구분한다.
- 정책 version·checksum, 코드 SHA, 스냅숏 id·sha256, 명령과 종료 코드.

동일 스냅숏이라는 이유로 v1과 v2 수치를 직접 섞지 않는다. v1은 참고 이력이고 채택 판정은 수정된 v2로 내린다.

### T7. 사전 정의한 민감도·ablation

다음은 결과를 보고 새로 고르는 탐색이 아니라 실행 전에 고정하는 보조 분석이다.

- 예가 범위: 대칭/비대칭, 기존 wide-reserve 제외 판.
- 공사: A=0/A>0, 순공사원가 규칙 적용/미적용, 100억원 인접 구간.
- 경쟁 정보: S4 전체 vs 참가자 수만 사용 vs 경쟁자 분포 제거.
- 표본 계층: 발주처→업무→전역 수축의 사용 계층과 최소 표본 미달 기권.
- 지자체 추정 제외 판은 추정 규칙이 없으면 판정 불가로 공시한다.
- 업무·낙찰방법·하한율 레짐별 결과를 공시하고 소표본의 우연한 승자를 골라 주 가설로 승격하지 않는다.

ablation에서 경쟁자 분포를 뺐을 때 이득이 사라지는지 확인해야 C4를 지지한다. S4 단독 개선만으로 원인을 단정하지 않는다.

### T8. C5 — 비용 효율 판정

**실측 항목**

- 공고당·전체 백테스트 CPU 시간, wall time, 최대 메모리.
- 운영 후보의 컨테이너·CPU·메모리·저장·관측 비용.
- 데이터 수집 호출 수와 실패·재수집 비용.
- 학습이 있는 후보는 학습 주기와 학습 비용을 별도 공시한다.
- 운영·장애 대응·정책 유지에 필요한 인적 비용은 추정치와 실측치를 구분한다.

**계산식**

```text
증분 기대 낙찰 수 = Σ(후보 낙찰확률 - S0 낙찰확률)
증분 기대이익 = Σ[(후보 낙찰확률 - S0 낙찰확률) × 공사별 기대이윤]
순 증분 기대이익 = 증분 기대이익 - ML 운영·수집·유지비용
```

이 계산에는 별도로 교정된 낙찰확률이 필요하다. 백테스트의 would-have-won 비율을 실제 낙찰확률로 간주해 그대로 대입하지 않는다. 공사별 기대이윤, 교정된 확률, 실제 비용 입력이 없으면 **비용 효율 NotEvaluable**로 보고한다. 이윤을 임의로 0이나 고정값으로 채우지 않는다. 승률 Passed와 비용 효율 Passed는 별도 결과다.

### T9. C6 — 통과 후 shadow 검증

오프라인에서 Passed한 후보만 대상으로 하며 실 투찰·자동 추천은 하지 않는다.

- 운영 요청 조립이 오프라인과 같은 과거 표본·정책·A값·기초금액을 쓰는지 대조한다.
- 같은 요청의 오프라인·서빙 금액과 불확실성을 대조한다.
- 결측·지연·타임아웃 시 규칙 결과와 합쳐져 조용히 성공으로 둔갑하지 않는지 확인한다.
- shadow 기간과 허용 오차·중단 조건은 시작 전에 별도 승인한다.
- shadow 불일치나 비용 초과가 있으면 운영 승격을 중단한다.

### T10. 판정 보고와 후속 결정

`reports/evidence/m6/6g/verdict.md`에 공고 식별자 없이 집계 결과를 남기고, 선행 조사 문서의 후속 절에서 다음 중 하나를 기록한다.

- **S2 Passed**: shadow만 검토. 바로 운영 배선하지 않는다.
- **S2 Failed**: 분포 엔진 미배선, 규칙+S0 유지. S4는 보조 결과와 별도 귀결로 판단한다.
- **NotEvaluable**: 부족한 창·불일치 쌍·필요 표본 수를 근거로 수집을 연장한다. 실패로 바꾸지 않는다.
- **비용 효율 NotEvaluable/Failed**: 기술 성능과 무관하게 운영 도입 근거가 부족함을 명시한다.

결과에 맞춰 사전 등록 기준이나 문구를 바꾸지 않는다.

## 5. 실행 순서와 의존성

```text
T0 정책·귀결 고정
  → T1 규칙 수정
  → T2 실데이터 관문 + T3 누출·재현성 검증
  → T4 제도 분포 진단 + T5 규칙 검증
  → T6 전략 백테스트
  → T7 민감도·ablation
  → T8 비용 효율
  → (기술 Passed인 경우만) T9 shadow
  → T10 최종 판정
```

T2~T5의 준비는 병렬로 할 수 있지만 T6 이전에 모두 끝나야 한다. T8은 입력 비용과 기대이윤이 없으면 계산하지 않고 미판정으로 남긴다.

## 6. 최종 증명 패키지

ML 효과가 있다고 보고하려면 다음이 모두 필요하다.

1. 수정된 규칙과 경계 테스트 통과 기록.
2. 불변 실데이터 스냅숏의 식별·해시와 품질·제외 집계.
3. 누출 없음·재현성·제도 분포 검사 결과.
4. v2 정책과 사전 등록 기준을 통과한 S2 대 S0 결과.
5. S4와 경쟁자 ablation의 보조 결과.
6. seed·창·업무·민감도 결과와 실패·미판정 사유.
7. 비용 효율을 주장한다면 실제 비용·기대이윤 입력과 계산.
8. 운영을 주장한다면 shadow 동등성 결과.

1~4 없이 ML 효과를 주장하지 않고, 7 없이 비용 효율을, 8 없이 운영 준비 완료를 주장하지 않는다.
