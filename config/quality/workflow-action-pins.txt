# M15/15S(D-15S-3) — 워크플로가 쓰는 GitHub Action 의 **commit SHA 핀**. 한 줄에
# `액션<공백>SHA<공백>판` 이고 `#` 로 시작하는 줄은 주석이다. 한 액션은 한 핀이다.
# 게이트: `tools/workflow-action-pins-check.sh .github/workflows` — 워크플로가 쓰는 집합과
# 이 파일의 집합이 같아야 하고, `uses` 줄의 꼬리 주석이 셋째 칸과 같아야 한다.
#
# **핀을 올리는 법** — 두 파일(이 파일과 워크플로)을 **함께** 고친다. 한쪽만 고치면 게이트가 붉는다.
#   1) 태그가 가리키는 커밋을 조회한다. annotated tag 면 한 번 더 벗긴다.
#        gh api repos/<owner>/<repo>/git/ref/tags/<태그>        # .object.type 이 commit 이면 그 sha
#        gh api repos/<owner>/<repo>/git/tags/<sha>             # type 이 tag 면 여기서 .object.sha
#   2) 그 커밋을 가리키는 **가장 구체적인 릴리스 태그**를 셋째 칸에 적는다.
#        gh api repos/<owner>/<repo>/git/matching-refs/tags/<major>   # 같은 커밋을 가리키는 태그 대조
#   3) 워크플로의 그 액션 줄을 `@<sha>  # <판>` 으로 바꾼다.
#   4) 게이트를 돌린다.
# 조회에 이 저장소의 이름·값을 싣지 않는다 — 위 셋은 전부 상류 저장소의 공개 정보다.
#
# **이 핀은 「바뀌지 않음」이지 「검토됨」이 아니다.** 막는 것은 상류의 태그 이동이고(2026-03-19
# GHSA-69fq-xp46-6x23), 핀한 그 커밋이 이미 나쁜 경우는 막지 못한다. 핀은 또한 **낡는다** — 올려
# 주는 봇이 없으면 상류의 보안 수정도 함께 멈춘다(15S 알려진 제한 2).
#

# 안에서 다른 액션을 부르는 전이 `uses` 가 없다. 복합 액션이 들어오는 날은 게이트가 워크플로
